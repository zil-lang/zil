# 编译效率专项

目标是冷编译、驻留复编、进程重启、重启首改和用户缓存盘量全面超越 Rust。按用户实际等待的绝对秒数、发生频率和工程规模排优先级；分钟级等待优先于毫秒级倍率。保留负结果，不以对象命中或局部计时冒充整链收益。

## 直接实施

先读仓库 AGENTS、goal workflow 与精简恢复检查点，核当前分支、源码和现存收据。复用与当前差异无关的已过收据，不重复整套旧测试。

针对已确认短板，先阅读相应 Rust/Cargo 实现，明确省去了哪种实际工作，再改 ZIL 的完整生产与消费链。可请 Astra处理语义或架构疑点；不要只返回策划、重复报告或通用框架。重启首改落后时优先消除全量恢复、重复解码/复制、上下文重建、机器规划与分区物化，不能只增加 LLVM 对象命中。

用户已指定原生直接首改为主目标时，不用无改重启/口径报告代替首改施工。对象命中须同时看实际代码量、非空单元分布和 optimize/emit 耗时；15个空对象命中、1个大单元承担全程序，不算有效缩小重编工作。参考 Rust 的按需导入与稳定 CGU，改真实大单元；完整 O2、当前输入检查及运行质量门保持，策略变化显式记录。

跨单元缩小导入后必须复核运行质量；缺少上层调用可见性会使编译局部变快、程序却退化。优先在当前完整机器图上传递可独立证明的返回范围等事实，保留原调用、求值、trap 和 ABI；未知、freeze、所有 PHI 分支及可能溢出的结果按保守范围处理，不能靠放宽运行门保住编译数字。

一批完整逻辑先收齐所有消费者，再冻结源码、统一做必要回归/严格检查/release和性能验收。不逐行修改后重跑全矩阵。发现真实失败或新的主要逻辑问题就修复；机械修正仅补受影响检查。

保持独立 Verify、当前完整输入绑定、原默认预算与费用、完整 O2 和代码质量。研究开关不默认开启；不以持久 Source→Machine 权限跳过当前义务。唯一施工分支按用户指定，goal/archive 不合 main。

## 精简记录，默认不打包

默认只提交精简结论、源码/工具链身份、关键命令、通过/失败计数和必要的失败定位；及时推送源码与简短结果。可恢复的缓存、SDK副本、所有逐请求文件和完整运行目录不自动打包、上传或做全量 fresh-restore。

用户明确要求归档/迁移恢复时才安排全量证据包。不得让打包、重复哈希、复制 SDK、上传大包或维护归档延后已知短板的代码修复。已有本地原始结果可暂留，清理时保留唯一必要资料；整理研究文件不计为编译或产品磁盘收益。

## 验收与比较

只比较实际 main、当前候选和 Rust；native 同 O2/CGU16/compiler jobs1，check/native 分开。`cargo check` 的 dev/default opt0 要明确记录，不把原生 O2 标签套在 check 上。源码、二进制和数字严格绑定；不将旧版本、跨窗口漂移或 profile 诊断转记为新版本正式收益。

重启无修改必须检查 Cargo 的真实 rustc 命令和 compiler-artifact.fresh。Cargo Fresh 与 ZIL 当前独立 Verify 的耗时可比较实际用户等待，不能解释为同等编译器工作量的倍率。另加保留缓存、源码字节不变、仅更新时间戳的对照，要求 rustc 确实执行；不得用清缓存、换 flags 或清理 target 强制失效。真实重启首改仍单独验收，不能被该对照替代。

普通 CLI 的重启对照要让双方计时都覆盖进程启动到退出。驻留协议的 request 时间与启动单列仍可保留，但须与完整 CLI 耗时分开；记录普通 CLI 默认会话与实验 resident capacity，不能把两种调用模式的差额全归为启动成本。

至少观察冷编译、无修改、连续私改、接口/广改、缓存进程重启及紧接着的首次修改。重启与首改按真实连续流程合计，不拼接不相邻请求。按绝对等待和区块差额判断，不只看倍率。

普通 CLI 每次启动新编译器，必须单独覆盖“关闭进程→先修改源码→新进程首个编译请求”。不能以“重启后先无改预热，再修改”代替这个高频路径，也不把两次请求合计冒充一次直接首改。原始布局或缓存产品只能选择候选，当前完整输入、原预算和独立检查仍决定准入。正式直接首改对照使用实际 main/当前/Rust；profile 诊断不作跨窗口比值。

用户盘量包括实际 semantic/object cache、最终产物和 Rust target，注明采样边界；不用 SDK/宿主 target/证据清理冒充产品节省。规模应逐步覆盖大项目，未测工业多 crate、proc-macro/build.rs、分钟级/GB级场景要明确，不能宣称覆盖完备。
