# draft19：以语言借入接口为主体，按完整成本检验图边界

2026-10-25（Asia/Shanghai）。本轮有两条独立交付：089冻结schema15研究，090–092推进生产schema16。ZUI需求帮助识别通用缺口，本轮实现对象是ZIL语言；没有新增框架组件或用平台包装替代语言机制。

## 1. 为什么先做切片

固定数组的长度属于类型。没有运行时长度借入接口，普通库函数要么为每个长度重复签名，要么把指针/长度和活性约束交给不受核验的外部约定。现在`&[T]`、`&mut [T]`让同一普通函数消费不同数组及其动态区间，所有者仍负责实际存储。字节流、批量记录和未来文本缓冲都可使用这层语言接口。

本轮窗口是有限Copy元素的借入值，不拥有存储。共享/独占、来源、活性、最后使用、父子重借与普通参数来源返回继续由独立Verify核验。两个不相交下标区间仍按整个后备来源保守检查；长度读取也会读取当前窗口，不能借元数据绕过活动子借用。

LLVM使用`{ ptr, i64 }`，无隐式堆分配。端点从左到右各求值一次，检查`0 <= lo <= hi <= len`后才作偏移，索引另核`index < len`；零尺寸元素使用已有聚合字段布局。机器验证覆盖普通跨对象调用、八fatptr加scalar、共享/可变返回、复合元素步长、空区间、闭包局部窗口和普通错误清理。边界trap仍终止进程，不制造unwind承诺。

三模块流式消费者按实际填充前缀处理数据，并与独立Rust程序逐字节比较。它验证通用语言组合，不宣称Vec、Unicode字符串库或ZUI框架已完成。泛型可转发共享切片；泛型正文的范围运算和赋值仍需要后续符号检查。普通实例方法与source closure同函数的既有推断缺口也未隐去。

## 2. 图边界研究本轮检验了什么

K把成功Parse的值身份与本请求token/node资格分开；L让发现模块的阶段只读复用已发布不可变AST；KL组合。深度、源字节、路径/文件/模块身份、规则与其它预算仍保留，当前预算不足或资格未知时回原解析路径。逐请求逻辑预算依旧收费，所有完整请求重新执行独立Verify。

这一设计借鉴了两类已有原则：[Rust增量查询](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html)区分输入改变和结果改变；[新trait solver缓存](https://rustc-dev-guide.rust-lang.org/solve/caching.html)会记录资源上下文和已达到深度，避免不合格的热结果跨上下文复用。ZIL的ResourceLimit是可观察失败，不能照搬其它求解器的歧义语义。

65个源文件时，B/K四请求实际解析都是65次；L为65/0/1/65，KL为65/0/1/2。513个源文件有对应513/0/1/2结果。默认capacity32阴性控制保持每次65次，原缓存清空条件没有被提前查找绕过。实际lexer/parser入口计数与缓存命中分开，因此机制是否消除了工作已经可以回答。

完整成本给出不同判断：KL在513文件公开编辑请求的配对比为0.9109，但冷请求1.0787、原样请求1.0395、四请求完整进程1.0170。L在部分真实消费者的原样Verify请求有收益，helper完整Build请求却有1.1328的退化。所有144个API比较、36个进程比较及七个配对原数保留；七对样本的bootstrap区间只是探索性描述，没有多重比较校正，不是Rust比较。

因此K/L/KL都保持生产NoGo。研究通过表示实验边界、原始数据和结论可以接受，不表示候选已经足以合入生产。旧080生产优化保留原身份；本轮源码中未留下新解析缓存策略。

## 3. 下一次实验必须更具体

源码可数的事实是：关闭磁盘缓存、未触发容量清空且资格足额时，单文件Parse身份的摘要构造由B的3次变成K4、L6、KL8；L/KL的发现与Parse入口重复构键和查找。这个事实尚未给出CPU占比。不能因为解析已减少就把剩余退化断言为hash造成。

下一实验先直接记录摘要次数、字节数、查找次数和临时分配；然后分别比较“本请求已读字节身份/资格快照复用”与“相同Debug字节的流式摘要”。两项要独立控制，保持键语义、错误/预算/取消与完整Verify，不在一次候选中混入多项未经分解的改动。观察对象仍是完整API和进程，包含冷路径、真实Build、缓存析构及退化规模。

更长期的责任图方向继续保留实际读写支持分解、SCC和事件关系的增量更新。[Polonius规则](https://rust-lang.github.io/polonius/rules/loans.html)所展示的保守关系预分析可以启发缩小后续求解范围，但它没有证明可以省去ZIL其它责任条件。删除推导边、递归自支持、跨资源共享条件与完整反例覆盖须有独立oracle；粒子位置或流动的类比本身不授予释放权限或复杂性保证。

## 4. 语言下一阶段的具体优先级

| 方向 | 要解决的语言问题 | 可以独立推进的工作 |
|---|---|---|
| 动态拥有存储 | 分配失败、已初始化前缀、唯一释放责任、移动/重分配后的旧视图失效 | 先冻结拥有存储/借入合同；源面、独立核、真实分配失败/清理消费者分写集推进 |
| 字节与字符串 | 序列接口与编码不变量、索引含义、有效前缀及错误传播 | 先完成字节容器；Unicode保证不能从字节通行推导 |
| 泛型与推断组合 | 泛型正文中的范围/写语句及实例方法与闭包的组合 | 补符号检查与有限能力条件，保持未使用模板检查和既有预算，不靠实例化后偷偷接受 |
| 保存与外部回调 | 环境/拥有值与注册、注销、排空的完整关系 | 使用真实生命周期协议验证；静态函数指针或句柄不作为对象存活证明 |
| 编译图效率 | 有效依赖边、身份与实际工作之间的差异 | 按089下一实验计完整成本，再决定生产准入 |

以上是后续分解，不是已实现功能。本轮实际代码增强了语言库接口，仍不足以替代成熟通用语言和GUI栈。完整语言NotSatisfied、产品NotRun、B0 Doing与原量化门保持；正式数量、冻结实现和独立审核以收据为准。
