# 076 驻留引擎的不变量与成本解释

设完整物理位向量为s，逻辑关系名为k。原071直接集合是R[k]中的完整行。
076保存驻留表A和ID集合I[k]，要求：

`s ∈ R[k]  ⇔  存在 id ∈ I[k]，A[id] = s`。

1. 驻留表的相等是完整字长与全部u64逐字相等；哈希只定位探测起点。碰撞仍比较字。
   扩容只改变bucket，不改变A及其ID；确定性遍历使同输入的逻辑工作数可重放。
2. 初始化调用原候选的initial和完整rows展开，每一初始行驻留后加入entry关系。
3. 工作队列保存(p,id)。出队使用A[id]的原始完整前态，全部abort/fault谓词都在该前态
   上求值；每个可观察故障独立入对应关系，重复实参/捕获没有预先集合化。
4. 正常像仍由原071候选direct::image生成，所有RHS/free谓词读同一前态。保存到下一点
   之前完整驻留，只有首次新增(p,id)入队。后继/终态guard仍读完整后态。
5. 集合只增不减；循环直到无新成员。总关系成员达到限额时ResourceLimit，不因驻留
   同一行而折减这个限额。unsupported多incarnation保留完整前态，不能算Complete。
6. 最终逐成员展开A[id]并按原始位向量排序；所有point包括空集合都存在，未触发的
   fault/abort/exit关系保持缺省。公共checker和canonical物化接收原有相同结构。

上述是候选数据结构层面的等价归纳；事件编译器仍是071候选实现。独立raw oracle
没有共用该编译器、抽取或固定点；逐字核验和反例套件提供有限执行证据，不替代整个
语言的证明。两个控制点可引用同一行ID，两个点的成员和边仍分别存在。

## 工作数和真实成本

`076-interned-row-v1`与`071-direct-row-v1`是不同确定性模型。自定义哈希表逐字hash、
逐bucket探测、实际碰撞字比较、重哈希和恢复均显式收费。有序ID集合/关系计划沿用
规模相关收费方式，未给std容器内部比较器加仪表；Vec元数据维护使用确定性按成员
计费。因此逻辑N只用于限额重放，不能当CPU指令数、分配字节或跨引擎速度比。

complete candidate计时覆盖全部真实构造与销毁，包括标准容器的实际成本、计划、
驻留表、展开为旧集合、独立核对、canonical字节、指纹和普通BDD形状统计。所有行
最终展开的费用不会从计时删除。`intern_stats.unique_row_words`只说明内部行负载；
它不含哈希bucket、ID节点、Vec元数据、临时完整后态和最终展开，不等于峰值内存。
进程VmHWM还包含前端与独立oracle，不能用它宣称候选分配器的精确占用。
