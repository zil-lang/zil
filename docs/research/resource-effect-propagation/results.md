# 080 结果：实际生产资源效果调度已出现有限净收益

## 结论

当前候选使实际 ZIL 源码检查中的资源写效果沿依赖边传播，保留全部最终 Verify 检查。128 层反向调用链的完整 `compile_path` 冷检查中位数由 **61.851ms 降为17.594ms**；相同会话原样复用由 **21.078ms 降为1.804ms**。对应配对时间比为0.288和0.084，分别约3.5倍和11.9倍的配对改善。这里的检查含读文件、前端、失效/指纹与独立 Verify，不是只测一个集合操作。

收益属于当前 schema13 生产资源效果求解中的特定传播瓶颈。真实 owned_component 三入口的 Verify/Build 多数区间跨1，**尚不能说这些组件整体明显更快**。这是可供生产独立审核的工程优化，不把076研究 BDD 的88.8倍写成生产收益，不宣称 Rust 对标胜出或新的图切割定理。

- 14源码族、17模式单元；每单元2版本×(1预热+7保留)，共272进程，34预热、238保留。每进程4场景，共1088真实编译请求，全部成功且各自Verify运行一次；未删除异常或离群样本。
- 功能准备另有136请求，68对完整输入/接口/阶段产物hash相同；3实际组件×2版本×4场景=24次原生行为相同。准备计时不当性能数据。
- “冷”指空编译器会话，未清OS文件页缓存；private/public edit分别追加未调用的私有/公开函数。此实验不代表所有编辑形状。
- API时间含实际compile_path；完整进程wall另含runner源码记录、结果序列化与session销毁。VmHWM是四场景进程总高水位，不能当候选阶段独占内存。

## 正确性、预算和失败

- 两阶段分别保留仅测试使用的旧轮扫，穷举512个三函数有向图（包括自环及参数置换），比较完整写效果行和所有最终诊断；另外有长链、星形、重复边、不连通、递归、不可达块、五种具体闭包入口和公开helper边界。
- 传递写入拥有捕获的Shared Fn仍拒绝；借入捕获Fn允许相同外部写。不同请求改写根效果会重新构图，不保留旧摘要。普通源、公共raw/wire和最终集成的独立审核分别记录，不把图单测称为全语言安全证明。
- 受影响两crate限定测试277项通过（Analyze21单测+12预算+5Package预算，Verify234单测+5文档）；其中16项新测试。clippy和runner clippy通过。不是本轮正式全量语言门。
- 48函数反向链每阶段实际求解95次，旧轮扫2352次；这是控制工作量，不是CPU倍数。
- 完整公共请求预算Analyze N=2766、Verify N=1969；N通过、N−1 ResourceLimit，第二进程同N复现。无Package但注册资源的标量责任pass精确费用从10/258变22/394，新的N/N−1均锁定；默认额度未改。
- 首轮原预算测试失败、新测试误用Verify诊断词、runner把FileId当Display的两次编译失败均保留。预算测试按root批准的真实工作变化修订，未放宽生产语义。

## 合并含义与下一步

本候选只替换生产资源效果的函数间调度。它按有限单调摘要的实际消费依赖减少重复求解，依旧让Analyze/Verify独立构图、独立检查，所有最终validate保留。研究作者建议进入精确提交的非作者审核，由root决定生产合入；作者不自审、不自行宣布正式验收。

076联合关系候选继续NoGo。事件局部子态更新、语义条件分解和跨阶段不可变事实仍是独立研究对象，必须面对强dense-direct和完整输出成本。080的结果说明应从生产真正的语义依赖和重复工作出发，而不是预先要求成果都叫图切割。

四目标反思：安全只保持当前有限实现的语义等价证据；语言运行时和程序内存没有改变，也没有新增Rust同级证明；维护收益是避免全球轮扫，新增算法/测试代码也有维护成本；编译成本在上述传播形状上有完整请求实证，但现有组件没有普遍净收益。没有新的原创复杂性定理或产品级Rust胜出，B0/FullLanguage/Product状态不由本片自动提升。
