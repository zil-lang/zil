# 组合优化：输入复用、容量与重复遍历

本片基线为 `5d7c1eeb2b74052eb239e19529dc5a943c6622a3`，继续首片声明依赖优化；不叠乘旧研究线性能数字。CP33、CP34、CP35 分别复用自 `675d1ac9`、`9fe23d71`、`de0eefdc` 的可适配部分，原作者候选身份保留。未引入旧线磁盘 checkpoint 或覆盖当前语言实现。

## 实现与边界

- **Parse 费用收据**：记录成功解析实际需要的节点费用。只在 Parse 身份中中和 token/node 配额，命中仍检查当前额度并扣除项目总费用；不足时回原解析器以保持首错、Span、恢复与诊断顺序。Source、文件/模块/路径、深度、其他额度及构建上下文仍参与身份。下游阶段仍用完整额度。收据不进入 syntax Debug 产物。
- **有界 raw 历史**：请求结束按访问次序淘汰，而非下次请求开始整批清空。raw 项数不超过 `with_capacity`（最小8）。数据库仅保留 raw 根可达依赖收据；淘汰原始值不抹去仍被其他缓存阶段需要的输入身份。活动查询存在时不 GC。若项目模块数+4超过容量，构造新 epoch 前先删除同 root ModuleId 的过时整项目语义快照，保留 Parse 与精确当前 epoch，避免私有编辑时两套大 IR 同时存活；不同项目复用 root=0 时可能保守互相淘汰，不同 root 的旧项目仍可保留。依赖收据数和字节数不等于 raw capacity：单个整项目快照仍可能很大，尚无字节预算或精确按函数保留策略。
- **流式指纹**：4 KiB 缓冲直接送入原 SHA 编码；v27 冻结编码器逐变体/缓冲边界对照。公开指纹字节、域和 schema 不变。它减少临时分配，不声称减少全部哈希遍数。
- **共享 Verify 原始输入**：`Arc<TypedModule/TypedProgram>` 与 `Arc<CandidatePlan>` 仅共享不可变数据。每次请求仍以当前目标和额度调用完整独立 Verify，取消检查和授权生命周期不变。无 Verified 对象缓存。
- **借用 Lower**：新增公开原始 `LirView` 与 `lower_view`，保留全部 Lower 接纳检查，借用当前 VerifiedModule 的 CFG、闭包、资源，免去深复制。公开 owned API 保留。后端两种入口均绑定完整字段；相同不可变 slice 的精确别名可证明数据相等，其他输入逐元素比对。指纹不能单独授权。Debug 产物与 owned LIR 相同。LLVM machine preflight 未跳过。
- **类型 DAG**：LLVM 前置检查原 DFS 会对 `Tn={Tn-1,Tn-1}` 重走指数条路径。现在在单次请求中保存成功命名子图的最大高度；每次仍检查 `depth+height<=128`，额度不足回原顺序 DFS，失败不存缓存，活动栈仍拒绝循环。共享子图只保留一份高度，元数据 O(V)，不跨请求缓存安全结论。直接机器 IR 控制不冒充源码可达性能收益。
- **项目声明索引**：展开前按原遍历顺序构造一次只读 aggregate 索引，各模块借用，保留 first-win 与后续正常检查；避免每个模块重扫完整声明列表。逻辑额度扣费不变。

## 限定验证

机制控制覆盖 28/29/40/128 模块、容量8/32、48轮连续编辑、失败与取消后的 fresh 等价、历史收据回收；Parse 当前额度/深度、源位置、路径和导入变化；Verify owned/shared 诊断与 Lower 对照；raw LIR 篡改在创建产物前拒绝；资源、闭包、CT、泛型、O0/O2 对象缓存与原生结果。每个完整成功请求必须 `verification_runs=1`。

独立审核还将旧 LLVM 前置检查与新实现对 200,000 次固定种子图/深度/顺序组合作精确 Result 比较；最终结论必须绑定精确提交。施工方不跑正式全量、不改产品门、不自行合入 main。

## 计量协议

`session_probe.rs` 与 `build_probe.py` 可链接两个已构建的 release 编译器库。Session 报告完整请求墙钟、请求后 RSS、每阶段完成事件间隔及执行/复用数。事件间隔包含中间 driver 工作，不是排他 CPU profile。源码构造和原生结果检查在计时外；Verify/Lower/后端/链接/发布均在完整 build 计时内。单独 CLI 计量包含进程和文件读取，不能与常驻接口混称。

最终冻结数据与正负结果在同目录结果文档及 evidence 中交付。早期筛选值不作为产品结论。

## 尚未解决的主问题

私有体编辑仍使全项目 Expand/CT/Types/Analyze 重算；当前方案尚非函数级语义增量。默认32项无法保留大项目全部 Parse 值。全部 Verify 仍有线性成本；对象命中仍发生在机器 IR 构造后，链接仍执行。本片不声称这些问题已完成。

下一架构边界需稳定声明身份、Signature/Body/Layout/Effect/CT 分面、包含负名字查找的实际依赖与结果等值截止；匿名/泛型身份不可靠时保守回退。旧 CP32 在整项目外包 memo 的实测没有净收益，不能仅追求命中数量重复该路线。图切割/zit 应服务上述真实语义边界，而非用调度器替代语言依赖设计。

安全和运行语义通过限定对照，语法无变更；完整 Rust 四目标合取及产品突破仍须独立产品验收，不能由本片测试数或单次速度数字推导。

## 第一窗口反馈后的修正

第一冻结窗口（d66a3142，1560请求）确认暖 Session check 大幅收益，但512模块连续私有编辑 RSS 比基线上升约40%，部分时延退步。原因是旧整项目 owners 在请求结束前一直存活。追加 prepare_project 只执行保守淘汰，既不改查询身份，也不授权缓存结果；Weak 生命周期控制验证过时 TypedProgram 在新 Parse 开始前已释放。最终窗口另行完整重跑，第一窗口原始数据保留，不择优替换其中单个样本。
