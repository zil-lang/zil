# 首片：只导入实际消费的外部符号声明

基线 `21058d0e331de764e3a1b9123c3e1edf5e55a1aa`。实现为 `machine_cgu::partition` 的结构化依赖筛选，不修改机器IR schema、LLVM版本、语言接受规则或产品门。

## 问题与改动

此前每个CGU都复制所有外部函数/全局声明。只在末模块添加一个未调用extern，也会改变全部对象键。现在按定义的实际符号引用挑选外部声明，引用包括取地址及全局初始化；ABI签名和属性原样保留，跨单元定义仍生成其直接必要的prototype。内部连接属性的同址约束不变。

筛选前对仅声明的视图执行一次现有机器预检，保证即使没有单元消费，非法声明也不能消失。检测到符号重复或声明视图非法时，保留原整个module供通常验证拒绝。每个实际单元仍执行原机器预检，当前请求仍经过独立ZIL Verify；没有复用旧安全授权。

NamedType本片仍复制到每单元，完整类型依赖闭包尚未完成。新增声明预检有真实成本，尚未测端到端净收益；不能仅凭对象命中率宣称整体变快。

## 新控制

生产源码测试覆盖O0/O2：三个实际单元冷构建；在末模块新增未用extern、修改其签名，均全部对象命中、执行返回42、ELF逐字节相同。真正调用abs时只miss一个单元且执行返回43。错误实参数量仍在前端拒绝，不能从旧缓存获得产物。

原始新增测试在旧实现上真实失败，保存before日志；修复后通过。机器IR控制包含外部地址、私有全局初始化、ABI属性保留；无用的local函数声明、void参数、错误ABI属性、未知命名类型、与定义冲突及非法全局alignment仍拒绝。机器IR控制与生产源控制分开报告。

## 限定完整构建A/B

两份release CLI均用Rust1.99.1、LLVM23.1.4、相同Cargo配置构建，编译器构建不计时。计时前所有已知构建/测试完成。冻结脚本为 `tools/research/incremental-compilation/slice1_bench.py`，2种规模×5个ABBA/BAAB区块×4臂×5请求，共200次完整O0 CLI构建，另有200次计时外真实原生执行；均通过且每请求Verify=1。固定两个允许CPU，8CGU/2jobs，实际4/8单元；不改变默认语言预算。

源位置在每个规模的两臂间相同，每个臂序列使用独立冷对象目录；没有同时运行本会话编译/测试。每个格先求同区块同臂两次均值，再取五区块中位数，最后相除。下表单位ms，数字为描述性小范围screen；不是Rust对照、正式产品门或普遍收益承诺。
