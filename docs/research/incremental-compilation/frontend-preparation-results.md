# Stage 7：恢复环境后的集中优化

实现：`0691a186e`；基线：`66f15461`。专项分支及 [PR #13](https://github.com/zil-lang/zil/pull/13) 继续保留，未合入 main。

结论：保留本次“当前 Verify 后、机器表示展开前的标量常量摘要”。三个 8192 函数分布中，专项 O2 保留符号模式暖构建减少 **23.3%**、编辑减少 **14.6%**；显式封闭模式暖构建减少 **24.4%**、编辑减少 **15.7%**。这些是同场配对时间比的几何平均，不叠乘旧窗口收益。

均匀大模块编辑仍是明确短板：保留符号模式为 Rust 的 **2.07 倍**，显式封闭模式为 **1.36 倍**。未全面追平 Rust；下一优先级是编辑后的前端整项目失效，尤其 Expand/CT 和稳定声明环境，而不是仅针对约 75 ms 的 Types 阶段做大型缓存重构。

## 实现与边界

在 `bind_lir` 精确绑定当前独立 Verify 后，以同一请求内的只读、有界解释计算纯标量函数结果；只将成功的零参数函数替换成保留原符号/ABI的常量返回。局部读写、条件分支、有限执行的循环和纯调用可参与；外部效果、地址、资源、不支持操作、递归、溢出及预算不足均走原机器生成路径。原 LIR 不变，当前 Verify 和机器预检继续执行。

这借鉴了在较高层 IR 消除确定工作、再交给 LLVM 的原则，并未复制 Rust 某个 pass。现有四项 LLVM 修复已恢复，实际动态库 SHA256 仍为 `7b5c5ef8…fa9a98`。本轮没有新增图切割或 zit 内核集成；收益归于提前减少机器图构造，不能归于旧图算法。函数级持久语义增量仍未完成。

## 当前诊断与取舍

对单模块 8192、8×1024、偏斜 8 模块，以及动态输入 2048 分支函数做了冷/暖/编辑诊断。均匀分布编辑的基线粗计时：读源/Parse 44 ms，Expand 92 ms，CT 51 ms，Types 74 ms，Analyze 38 ms，Verify 43 ms，机器 lowering 73 ms，后续标量处理及原模型预检 133 ms，代码生成等待 418 ms。父阶段和工作线程时间不能相加。计时补丁仅存在于私有诊断编译器；确认窗口使用无插桩二进制。

动态输入分支样本的 LLVM 长尾约 11 秒，但同场 Rust 冷构建诊断约 53 秒，因此不是本轮“落后 Rust”优先项。最终只做一组 6 请求保护屏：结果均正确；编辑后的基线/候选原生可执行文件逐字一致。单次计时不作为该类性能收益结论。

旧经验的调整：图分区能减少跨单元工作，却不能修复完整项目查询键的失效；zit 的稳定身份、实际依赖与等值屏障仍适合后续语义增量，但必须连同名称/类型/效果环境及费用重放设计。此次先验证直接热点，冻结一个实现后一次确认，未重跑旧千次矩阵。

## 完整小规模确认

三种分布各 3 个独立缓存序列，每序列 cold → warm → edit。ZIL 两实现×两可见性合同共 108 请求，Rust 共 27 请求，总计 **135**；全部构建、当前 ZIL Verify 和原生 oracle 有效。default/closed 共用同一组 Rust 观察，不当作额外 Rust 样本。

所有 ZIL 臂都显式启用 `--opt O2 --incremental-o2 --function-merging after --codegen-units 8 --codegen-jobs 2` 及对象/语义缓存。“保留符号/default”只表示不加 `--closed-executable`，并非 CLI 默认配置。Rust 1.99.1 / LLVM 23.1.1，O2、8 CGU、增量、overflow-checks=yes、panic=abort；ZIL 为 LLVM 23.1.4 加既有四 TU 修复。Rust 的私有 helper 可删除，closed 更接近该可见性合同；两列都保留。
