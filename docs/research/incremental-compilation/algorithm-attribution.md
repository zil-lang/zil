2026-10-31（北京时间）。广分布实现身份为801933a9e，后续当前机器预检实现为59d8753dc；本页区分历史冻结实验、本轮机制复现和当前生产代码，历史时间没有重测或换算为本轮收益。当前同工作负载结果见 [DISTRIBUTION-RESULTS.md](DISTRIBUTION-RESULTS.md)。

| 资源效果沿反向依赖传播 | [080](../080/RESULTS.md) 128层反向链完整冷检查61.851→17.594 ms，同Session原样检查21.078→1.804 ms；真实组件多数区间跨1 | 依赖工作队列解决了特定重复轮扫，有真实端到端收益；不是Rust比较，也不是新的图切割定理 |
| 本轮机器IR支配查询 | 801933a9e保留原idom求解，为大图建立当前支配树DFS区间；逐次祖先爬链变成常数次区间比较 | 消除一个实际最坏二次成本；属于经典树祖先索引，不能重标为旧切割算法的贡献 |
| 后续高扇入支配合并 | 59d8753dc在一次当前idom树合并内缓存祖先投影；仅高且密的扇入支付O(V)准备费，函数内查找改标准HashMap | 针对共享trap出口的重复长链，属于当前输入内工程优化；不是跨源码版本增量，也不宣称整个CHK算法线性 |

076数字属于4172d61b研究候选、schema10执行；080属于c4c30764→473c32fc、schema13。它们不属于当前schema或本轮五个窗口。当前 `zil-analyze/src/resources.rs::effect_consumers/infer_effects`、`summary_graph` 和独立 `zil-verify/src/resources.rs::effect_dependents` 仍使用相关依赖调度思想；Analyze和Verify分别计算，不共享可信结论。

切割适用于边界小、局部关系可紧凑表达的图。若合同要求输出每一点完整联合状态，结果本身可能指数增长，任何切割都不能消除该输出下界。计划、抽取、索引、恢复、核对的总成本，以及小图、稠密图退化必须一并计入。以前在弱基线上的大倍数，不足以证明继续堆复杂图结构会使当前完整编译更快。

## zit：四项机制可复用，循环判定不能照搬

本轮从冻结分支e739f583b63ba8fa44fa26a937d36afb9cbaea2a的 `evidence/research/compile-performance/COMPILE6/mechanisms/` 恢复原 `zit.ts` 和已有机制探针。原文件SHA256为 `719a914356a24ac1edbeb1ffe6637d22311c9299e6be9ddbcdf3f7fdddf1474f`。Node24.19执行原同步数值内核，擦除TypeScript并替代缺失的DOM/工具导入；不涉及异步、DOM或性能结论。源码、探针、输出和原CP25审计均在 [stage5证据](../../../evidence/research/incremental-compilation/stage5/README.md)。

| 复现 | 观察 |
|---|---|
| 拉取时刷新脏祖先 | 下游最初未标脏，直接读取仍得到当前值 |
| 相等结果停止传播 | 中间节点运行2次，结果相同的下游只运行1次 |
| 菱形批处理 | 多次输入写入后左右节点、汇合点各累计运行2次，避免同批重复运行 |
| bond游标复用/剪除 | 3条稳定边复用；重排保留匹配前缀，删除的producer不再触发consumer |
| 动态无环图反复换边 | 1100次换向，每个当前图都无环；高度累加至1101/1102/1103，产生103次 `zit_dep_cycle` 报警 |

最后一项是实际反例。`hUp`只升不降，并用高度超过1000报警；高度不是环的证明。编译器需要真实环/SCC语义，递归效果分析还需要固定点。全局同步 `$w/$b` 上下文也不能直接用于并行查询。

最值得采用的组合是：稳定的逻辑计算身份、计算期间记录实际读取、成功后事务提交依赖、结果等值才通知直接消费者。它与Rust red-green、Salsa/Adapton的原则一致。编译器还必须记录负名字查找、CT读取、布局/效果/泛型实现依赖，并在失败和取消时保留上一成功版本的边。不能把zit的异常后剪边行为原样替换编译器事务。

**当前ZIL没有直接运行zit内核，也没有可归给zit移植的本轮速度收益。** 原CP25最新分支的施工日志报过混合build比约1.0053，但只恢复3/4实现分片、crates树未变化、独审NotRun；既不能称为已核验候选，也不能说历史上完全没有测过。来源见 [开工审计](audit/compile-speed-review.md)。

## 为什么换调度器还不够

当前查询主体仍是多个Parse汇入整个项目Expand→CT→Types→Analyze。一个私有函数体改变会触发大块语义工作；给这些粗节点增加反向链或高度队列，不能让其他函数自动停止重算。每次普通CLI还创建新的Session，进程内订阅边不会跨进程存在。

历史CP32虽复用6940/9222个函数，完整Session混合比仍为1.003583、峰值RSS为1.202026；周边整图工作抵消了局部收益。这是“命中数很多”不足以证明“端到端更快”的直接例子。不能只移植缓存表而保留所有全量构造、编号映射和核验成本。

后续真正的架构边界应是稳定声明/实例身份，加签名、布局、效果、CT值和正文的独立结果面。相等结果停止传播必须发生在真实消费者读取的边上；对象和链接动作应有独立的完整输入身份。每次独立Verify仍是当前授权条件，未经设计和核对的哈希命中不能替代它。若要求端到端接近O(变化量)，还需要独立可核的分段证书或明确的新核验生命周期，而不是默认把整个Verify缓存掉。

## 本轮如何参考Rust并落实

[固定版本外部研究](audit/external-notes.md)包含Rust稳定DefPath身份、red-green结果等值、projection查询和CGU work products，以及Zig的细粒度依赖种类。此次先修复实测暴露的三个具体成本：

1. **5189f0975：O0大文件CGU粒度。** 同一FileId不再强制只有一个单元；按256个非foreign LIR函数固定分块，局部链接依赖仍合并。私有编辑可以只重发受影响对象。它不是函数级语义增量，只有LIR函数集合和顺序未变时保证该局部稳定性。
2. **c6a60d3ec：显式封闭可执行文件。** 从旧CP13（e7b492c6）移植 `--closed-executable`，让LLVM删除/内联不需要导出的实现，接近Rust普通可执行文件的可见性条件。保留跨CGU调用、取地址、全局初始化引用和foreign；默认关闭，仅Linux build。放弃生成符号的外部导出合同，不能把它记作默认模式收益；不改变O2优化管线。
3. **801933a9e：当前支配树区间。** 大CFG重复SSA use合法性检查避免逐次爬长链；仍执行完整当前机器预检，保留不可达、phi和首错规则。独审4,525图、1,497,729块对及1,540完整模块差分通过。

以上三项源码均有精确提交独审；801只改变祖先查询，不宣称原idom构造也变为线性。五窗继续发现命中后的机器预检成本，于是追加59d的高扇入路径投影/函数内查找；其独立5087图、5975139块对和26320次完整preflight控制保持旧结果与首错。05e仅32入边门槛的过渡方案因潜在重复O(V)准备费而在测量前收紧为同时不少于ceil(V/4)，原记录保留。

端到端收益、内存成本和不利单元分别由801五窗、59d三个后续窗口决定，不能把历史倍数、微算法复杂度和新构建时间相乘。
