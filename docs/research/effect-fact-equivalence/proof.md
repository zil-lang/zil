# 146：效果事实图等价边界

在当前资源分析transfer、check=false下，State（来源、责任、生命状态）和CFG工作表不读效果结果；只有直接调用和具体闭包调用把被调者摘要转为 `record_write` 输出。写摘要集合是只增的参数位与借入捕获位；操作均为并集，不存在负条件、删除或“两个条件同时成立”的事实。

故每个函数的固定点方程可以写为 `E_f = Seeds_f ∪ ⋃ T_call(E_callee)`。T_call是按已求出的来源集合替换参数/捕获，既保并集又保持空集。一次运行同一来源流，保存每个 substitution 的正边；闭包原规则为“任意borrowed field有写”，以一个析取节点表达。局部CFG来源扩张时只追加新边，去重不丢事实。

从Seeds启动逐事实传播得到该有限正图的最小闭包，等于原函数工作表/全扫从空集合达到的最小固定点。最终有序责任检查继续用完整所得摘要执行；独立Verify未改、未导入Analyze求证函数。

边界：仅当前正向效果域；不自动推广到保活、独占、可删除事实或并发。helper公共合同仍切断私有摘要依赖。未来若transfer让State读取摘要，必须重新证明/拒绝此快路。

费用：提取需要一次各函数局部流；传播每个事实入队最多一次、每条有效边处理一次，另有有序集合/索引log开销。不是整个编译器O(V+E)，构图、核验、哈希和后端仍计入完整请求测量。预算按实做收费，ResourceLimit边界单列。首个prepare-cache候选未获得明显收益，保留在单独分支与原始收据。

验证：保留原frontier和全扫调度oracle（tests only），对所有三点有向图、参数交换、循环、借入/拥有捕获、公共helper切边和大32/64/128节点组合对拍；最近安全反例必须到独立Verify，不能仅在Parse失败。
