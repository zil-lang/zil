# draft15：从位置唯一性到局部域与直接转移

日期：2026-10-24。071研究交付核心固定04f7861，生产依赖固定400a082/schema10；生产字段更新使用另行核验的schema12。两条线路共享工作区调度，代码、构建、输入、计时与裁决隔离。精确采样和原始失败见071/RESULTS及其收据。

## 本轮结论

图研究从“一个资源责任token只有一个当前拥有位置”的不变量出发，已经找到可执行的结构改进：先缩小每个token可能到达的位置域，再直接执行完整联合状态上的同步更新，避免为每个事件构造庞大的前态/后态关系乘积。五方法在相同观察合同下对照，完整输出包括每个点、故障前态、abort、正常/错误出口和不支持状态。

四guard输入的候选完整成本中位数从dense/fused的322.422061毫秒降到local/direct的3.833945毫秒，约84.1倍；整进程包含前端及独立参考求解器，中位比约0.02413，即约41.4倍。整进程RSS中位16720→4272 KiB。候选费用包含抽取、局部域、事件/计划构造、固定点、完整关系核对、输出物化及释放；RSS不是候选独占内存。7族、5方法、2预热+7保留产生70预热和245正式进程；小样本与固定语料限制保留。

这支持继续投入这条研究路线，尚不授权替换生产安全核。完整关系输出接口天然有利于显式枚举；优化dense-explicit、MDD/LDD、生产块分析和同能力Rust尚未作对照。当前方法也没有消除指数状态空间，不能写成原创复杂性突破或ZIL整体编译加速84倍。

## 为什么这次比单纯压缩坐标有效

067已经验证位置编码保持完整有限关系，但全局位置编码的BDD因子支持更宽，主要样例反而更慢。071保留该回归作为控制，分别检验两个因素：

| 因素 | 改变 | 不改变 |
|---|---|---|
| token局部位置域 | 参数/制造点为种子，沿原始Store、Take、捕获、give边计算保守闭包；不生成不可能的身份/位置组合 | 原始身份、分支条件、Desc根、故障与清理观察 |
| 直接联合态转移 | 对一个完整前态求所有RHS，再一次性更新对应坐标；精确去重并求CFG固定点 | 相关性、所有出口、故障前态和同步赋值语义 |

令token t的可达位置过近似为D(t)。位置编码所需位数可从完整incidence矩阵约|T|×|L|，降为各t的ceil(log2(|D(t)|+1))之和；额外位置表示当前不在任何拥有载体。位数减少只是可能性，不能单独推出更快。071真正的大头收益来自省去中间关系构造，而非只换编码。

direct不是把每个token独立求解后拼起来。它保留完整状态行，因此“分支A拥有x、分支B拥有y”与“同一路径同时拥有x/y”不会混淆。所有赋值都读同一个原始前态；若把搬移分成先删除再读取，就会错误丢失token。本轮有针对同步更新、重复实参/捕获、同载体多个token和旧故障前态的控制。

对于域缩减，归纳义务是：初始位置在种子中；正常事件只保持、制造、退休或沿登记边搬移，因而正常后态仍在闭包内。实现若发现域外正常写入或位置唯一性破坏，必须报Mismatch，不能删去坏行再宣称精确。论文提供研究启发，不能替代这些逐条实现义务。

## 物理直觉中最有用的部分

有身份粒子的轨迹、局部相互作用和守恒，比把程序直接套成连续流体更适合当前安全分析。一个释放责任可沿载体移动，描述符可有多个别名；拥有责任的唯一位置和描述别名的多重性必须分别表示。数量守恒仍不足以证明目标实例正确：旧Desc、释放类别、最后使用与清理次序同样可观察。

彩色Petri网缩域研究提供了相邻的严格先例：先过近似哪些颜色能出现在各place，再排除不可能组合。071采用可达域思想，没有合并不同资源身份。PINS的读/可能写/必写/复制依赖则启发把局部更新与未变化坐标分开处理。两篇来源分别见：

- Bilgram等，2023扩展版，§4与Lemma4.2/Theorem4.4：[Methods for Efficient Unfolding of Colored Petri Nets](https://arxiv.org/html/2204.07039v3)。
- Meijer等，HVC2014：[Read, Write and Copy Dependencies for Symbolic Model Checking](https://research.utwente.nl/en/publications/read-write-and-copy-dependencies-for-symbolic-model-checking/)。

更激进的物理粗粒化仍可研究，但需要观察等价或可检查的恢复证明。均值、密度、概率或独立边缘分布通常丢失分支相关性，当前最多用于排序与成本预测，不能直接决定程序安全。区域消元须保留边界联合关系与内部故障，不是看到CFG切口小就假定资源交互宽度小。

## 下一轮的可证伪实验

1. **加入更强的显式基线。** 比较dense-explicit与global/local-direct，分离编码、集合结构和执行内核的贡献。现有raw oracle是独立参考解释器，合同/计费/输出流程不同，不能直接把它当优化显式基线。
2. **让共享结构承接行爆炸。** 若完整行数成为主成本，比较MDD/LDD的共享前缀与事件局部饱和；保持同一完整关系接口，计入唯一表、缓存/回收、输出展开和核对成本。当前尚未实现这些引擎。
3. **再检验区域切割。** 当真实资源交互边界窄、区域内部密集时，用精确边界摘要替换内部重复传播；恢复全部要求观察，再测含摘要构建/失效的总成本。当前直接引擎还不是跨CFG区域消元。
4. **迁移新语言形状前先迁移语义。** schema12的部分Package可把(local,field)视作具体拥有位置，但071没有覆盖它。须先在独立raw oracle加入字段实例、空壳、条件清理、RHS失败与完整ABI边界，再让候选影子消费，不能直接用旧schema10成绩背书新功能。

## 纵向共享应共享什么

068已减少重复解析、Typed中转复制和输入身份构造，但普遍稳定的整请求收益仍未建立。071的候选BDD/direct共用事件公式，是实验内部复用；它没有让生产Types/Analyze/Verify共用证明。

下一种值得测的生产结构，是同一请求中的不可变原始事实与局部依赖表：源位置、名义类型身份、原始事件、读写支持只物化一次，消费者用有界视图访问。候选摘要必须带依赖身份和明确观察边界；独立Verify仍从原始事实重建自己的合法性条件。共享数据不能变成共享未经核验的结论。

增量机制也需要纵向看：一次编辑究竟改变了哪些事实、哪些摘要的支持不再成立、哪些循环需要重求，分别记录新增与删除事实。只展示命中率会隐藏失效传播、摘要重建和独立核验费用。若LLVM/链接主导冷构建，有限关系分析再快也不能直接改善全部时间；下一次全链剖面要保留前端、分析、Verify、代码生成和链接的同一次请求总账。

## 与本轮语言施工的衔接

072–074完成直接Managed字段的取走、条件清理和补入，以及有限Copy字段更新。新资源先用真实临时责任准备，成功后才清旧字段、提交；失败保留旧责任，已发生副作用不回滚。部分形状只在局部存在，完整参数/返回/SSA均须补齐。精确字段Desc的未来使用阻止该字段实例被替换，兄弟字段描述可以继续使用。

机器表示保留完整inline struct ABI；只对需要字段操作的局部包分配入口固定flag，whole转移同步更新全部字段责任。Drop前先清标志，空字段不再释放。20固定输入×ZIL/Rust各O0/O2覆盖80次行为观察，并用真实dup/close验证资源关闭。独立审核还检查宽Copy字段重复更新的深比较费用，不能让一次类型预检替代每次实际遍历的配额。

这使“组件替换某个资源”成为真实语言能力。接近ZUI的后续前置仍包括容器/字符串、拥有环境与组件组合、可复用平台FFI和事件注册/注销排空，再到窗口、绘制和字体。同步文本内核不能提前标成GPUI同级框架。
