# 101 正式R确认：在独立A/A后冻结的协议修订

这是候选R第一份正式成本样本之前的修订；旧合同、全部三组诊断/校准原件和
失败均保留。生产BASE24ca、R的c9863bd5、907b2c3c Rust harness、十九模式单元
及功能对拍没有改变。正式确认使用`confirm.py`，不执行`run.py sample`的旧
64双进程模板；`run.py`继续作为已经冻结的构建/功能/单进程请求工具。

## 独立选择依据

diag001的同SHA相邻执行已经显示1%难以辨识。cal001固定960进程排除了“父进程
每次立即压缩导致全部波动”这一单一解释，推迟处理没有改善；无major fault，
P0/P1无块读入；多数单元wall波动伴随child CPU变化，不能全归因调度等待。
阶段调用和工作量一致，零效果体的模块请求在digest/展开/其余Types仍有实际
工作和波动，空效果求解本身仅数百纳秒。

最后的campaign001固定660进程、含20预登记暖进程，样本SHA为
`d0d7de73414fc632b20e3c72c2e9d10b3dc4ad2efeb773ca77ad2b8112bbd4cd`。
C1同case连续campaign的单块绝对log比差中位0.0507577173，C0交错为
0.0728832995；50项块中位偏离1%为31/37项。故选C1布局，但它没有证明环境
足以辨识1%。不再继续校准，也不把该结果当R的性能证据。

## 固定正式采集

- 十九模式单元及四请求逐项沿原输入身份，真实consumer体修改/恢复和三个
  16函数结构不删减，原128逆链不扩大。无探针BASE/R binary，CPU2，root独占。
- 每模式单元连续完成：先两预热对，即一个四进程BASE-R-R-BASE暖块，再64个
  保留ABBA/BAAB块。每臂每块两次完整进程，随机种子101使各模式32次ABBA、
  32次BAAB；case顺序同样在采样前冻结，Warm块全保留。
- 总4940进程/19760请求；76暖进程/304请求、4864保留进程/19456请求。
  每个进程仍执行完整四请求并销毁session，API与进程计时边界不缩短。
- 每次退出后立即核对并压缩完整报告。控制器改为每块追加JSONL原始索引，
  不随样本增长反复重写全部历史；最后生成同值JSON数组。该变化发生在被测
  子进程之外，避免二次复杂度的日志工作，不声称因此排除环境噪声。
- 所有失败、慢样、调用顺序、原始报告和输出均保留。源码/输入/bin/source
  manifest、原构建harness和新controller协议分别绑定，不把后者冒充重建编译器。

## 估计量和冻结准入

对每个块、每个完整API或进程终点，先把同一臂两次完整成本取算术平均，再求
R/BASE；两臂数量相同，等价于成本和之比。统计量是64个块比值的中位数。
原双进程比值改为四进程块比值是本次事前修订，不在R结果后改变。

仍为76个API加19个完整进程、共95项家族，主要收益为reverse128完整进程。
64比值用二项次序统计区间与Bonferroni：k=17，排序第18和47项，名义95%同时
覆盖。任一同时区间下界>1.01为NoGo；全部上界≤1.01且主要收益上界<1才满足
本片性能条件，仍须非作者审核。其他为Inconclusive。任何功能/身份/Verify
或失败清理不一致仍为NoGo。全部>1%点估计独立列出，不靠平均抵消。

逐项报告原64块/128次每臂成本、顺序、前后半段漂移、全部VmHWM。统计解释
仍依赖稳定性与块间足够独立；当前A/A明确显示这一精度存在实际困难，所以
不能将名义覆盖包装成消除了宿主波动的保证。该风险不授权放宽1%或删掉tiny、
unchanged或Build。预登记固定一次确认；若精度不足则如实Inconclusive，不扩样。

R若不满足生产准入，净回退所有生产与crates测试改动，保留候选、功能、统计
和失败历史。独立107的摘要身份优化另有来源与确认；不能借107收益改判本次R。

## 采样前独审修正：输入完整性

root在任何R样本之前指出：旧9bab统计器只数每臂两条，复制R-position1替代
position2仍可能进入统计。该控制器/协议原件保留为superseded版本；v2不改变
采集方案、估计量或阈值，只强化验证。analyze先核全部已冻结source/bin/输入/
工具身份及start/finish/协议、样本JSON与JSONL哈希，再将4940行逐个与冻结
schedule展开值匹配，要求case/mode/block/warmup/variant/position和唯一报告
路径一致。四scenario顺序完整、wall/API为正整数，拒绝bool/float冒充整数。
样本JSON与JSONL、affinity及schedule也递归要求同类型相等；额外保留只改
journal数值类型并重封其SHA的反例，避免Python的`1000 == 1000.0`绕过。

随后核每条原report压缩/原字节SHA、真实runner命令/退出状态、完整请求状态/
Verify1/active0和记录指标严格同类型相等。全语义观察与已通过功能门的BASE
计数版记录对照，Build的LLVM另核固定哈希；timed仍必须无计数/阶段探针。
同一冻结规则的完整合成数据为正控制，复制/缺失/重排/失败/错误指标/错误封条
为负控制。它们不运行编译器，也不计入功能或性能样本。
