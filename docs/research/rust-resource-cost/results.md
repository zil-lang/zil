# 104：同合同 Rust 成本实测结果

本片完成了一套冻结的有限消费者对照。**三个 4 MiB 运行单元未达到既定的单例效率门；九个编译单元的中位数均低于 Rust。** 内存已改用通过负控制的小型独立启动器采集，不能用最初受父 Python 进程污染的 RSS 值论证内存同级。

精确生产源码为 `24ca9583d8789cfdfe3ccdbfe3eeff614bf56429`。这不是后续101/103/105/107/108或最终集成版本的性能数字，后续改进须单列新身份与结果。

## 合同和证据身份

三个消费者共享实际 C stdio 输入/输出和明确 EOF 约定；拥有缓冲均从8字节开始按需翻倍，分配失败走相同有限错误分支。Rust使用惯用安全 Vec 与普通保存闭包，FFI仅封装stdio。保留闭包会读取保存的历史内容，防止变成无用分配。输入、源码、编译器、工具、环境、顺序均在采样前冻结。

- 无探针运行使用 O2；冷构建和真实私有体修改使用 O0、无调试符号，不能解释成完整调试器能力对比。
- 冷检查是新进程和空项目缓存；Rust直接调用rustc生成metadata，不额外计Cargo启动。私有修改两边都先建立自己的缓存，再改实际被调用的私有函数体。
- 时间为完整进程spawn到wait4，包含编译器及其链接工具；输入/输出文件在计时前打开。每单元2对预热、30对保留，顺序15次ZIL先/15次Rust先。共960次臂观察，900次保留。
- 95%区间是每单元配对中位数的描述性精确区间，不宣称15单元同时95%覆盖。不删除慢样本，不按结果扩样。
- 第一次221条观察遇到并发构建，未查看性能汇总即中断并明确作废；正式结果来自同一冻结身份和完整顺序的新目录，未复用其中任何样本。

计时身份 SHA256：`3f93941e5121987e7de68259696a79bf3346299ba3e7c37670407dc9ba6915ea`。原件、每单元p95、逐条命令及输入/输出散列见 `evidence/impl/104/author-result.json`、`timing-summary.json` 与完整原始证据包。

## 目标进程内存与保留

## 结果怎样改变施工

运行不足已从整体数字追到真实机器差异：原ZIL的getchar/putchar走PLT，Rust保留GOT函数地址；ZIL还保留规范要求的u8范围检查。108只研究前者及其启动/绑定时机代价，不删检查、不为外部函数附加未经证明的纯性。该推断有反汇编依据，是否产生净收益仍由108独立冻结实验决定。

四目标的结论仍是合取：有限安全路径有新实现与负控制；运行门存在上述失败；编译有清晰有限优势；表达/维护的六演进族尚无冻结成本比较。不能把编译优势或较低有限RSS抵消运行失败，也不能把本片写成完整产品已胜过Rust。
