# 063 架构判断：把切口放在语义接口上

## 1. 先分清用户等待的任务

“Rust编译最慢在哪”没有与源码无关的固定答案。check失败反馈、未优化原生构建、优化构建、干净依赖构建和小改动增量，是不同工作。类型/trait目标、MIR借用、具体实例化、LLVM优化与机器码、链接分别影响它们。阶段观测需明确任务、源码、工具链、缓存状态和优化级别；嵌套计时不能直接相加成总成本。[Rust profiling](SOURCES.md)也不支持把rustc自身的LLVM占比外推全部用户工程。

063的研究核有完整独立raw oracle，主要用于检验表示和求解机制；它不是生产编译器默认任务。另一个`pipeline063`探针直接调用实际public driver，观测cold、unchanged、注释编辑与真正私有函数体编辑。进度回调位于query结束点，其间隔包含上一个query的发布、指纹、格式化等工作，**不是独占pass profiler**。Link间隔包含LLVM输出和外部clang/link。完整函数计时包括前端、核对、材料化，进程wall另列。

Amdahl约束仍适用：若可优化阶段只占总时间p、局部加速s，则总加速上限为`1 / ((1-p)+p/s)`。本轮找到的未请求Debug格式化属于实际流水线工作；即使安全分析本身大幅加速，这种外围开销不去掉，用户仍会等待。相反，移除它不等于减少必要的缓存指纹或安全核验。

## 2. 图切割真正解决的问题

对有限迁移关系，可以写成

\[
R'(x_U,x'_D)=\exists x_D.\;R(x)\land\bigwedge_j f_j(x,x'_j).
\]

`x_D`是被覆盖的旧状态坐标，`x_U`是保留状态，`f_j`是各输出方程。若某旧变量已经不会出现在后续因子中，可以立即存在量化；保留全部边界变量及其联合关系，就无需先构造巨大的整体连接。fused把一次AND和Exists合并，wire在唯一新鲜输出且最后关联条件满足时直接进行等值/取反代换。这些恒等式不允许复制一个共享guard为两个独立选择，也不允许提前删掉token身份、Desc来源、cleanup order或异常出口。

因此相关宽度不是单纯CFG的边数。一个分支很少的程序也可能在owner×token关联、共享guard和输入联合关系中形成密集耦合。一个看似网状的程序则可能具有小的语义分隔集。原物理论文的唯一输出结构给出寻找稀疏边界的启发；实际编译器必须先证明相应分解条件。知识编译的width研究支持按结构选表示，但其特定公式族下界不证明任意ZIL程序一定困难。[来源及适用域](SOURCES.md)

本轮原型把问题拆成受控变量：算法、内部BDD顺序、安全边界GC。规范坐标和全部输出不变。若GC开启后mono也成功，就应首先记作表示生命周期问题已修复；只有同等GC/顺序下cut相对mono的净收益，才可归给切割。若只减少中间节点却增加总扫描/核对成本，也不能称总体编译加速。


### 原论文中最值得迁移的结构

Deng/Hani/Ma v3的命题8.14给出free/fixed切口下的算子复合，随后提醒一般不能交换复合顺序。定义11.10的UP包含全局低到高选区、区域内部高到低处理；命题11.12依赖端点方向的单调不变量，不是把任意图倒序遍历即得结论。这里仅提取这条结构事实，完整前提仍属于原物理模型。[原论文§§8、11](https://arxiv.org/pdf/2408.07818)

对ZIL的具体推论是：应先找“切后不新增反向依赖”的区域，再在区域内部按最后使用消除状态；外部保留足以重新组合的完整接口。这比全函数统一倒序更有希望。SSA值虽然定义唯一，责任token却可能经过选择、闭包捕获、调用和返回；唯一定义不能自行证明切口保留了这些相关性。本轮fused/owner/GC尚未实现论文UP，不将普通BDD早消元重新命名为UP。下一步可以为具有可证方向不变量的责任流建立区域计划，并把未满足前提的部分交给一般求解器；同精度强基线与完整反例继续保留。

## 3. 责任唯一性可能带来的下一步表示

现有稠密表示为每个carrier×token配一个关联位。语言的合法状态往往要求每个真实责任token只有一个当前carrier，转移近似一个稀疏部分函数。候选替代可把“token现在在哪”表示为位置变量，并把区域内转移编译成局部置换/消费关系；这样可能减少冗余Boolean组合。这个判断是**待验证假设**，本轮没有实现新的安全表示。

最重要的障碍是：如果编码只能表达合法唯一归属，就可能根本无法表达伪造IR中的重复责任，因而静默删除本应被拒绝的见证。任何稀疏编码必须额外保留非法态通道，或独立证明从原始输入到该表示的检查覆盖了所有多重责任。跨区域摘要也必须保留Hold、调用的责任转移、相同地址的不同incarnation、仍活跃的Desc、错误/正常出口，以及成功初始化的偏序。不能用边缘可达集合替代这些联合条件。

本轮重复条件清理观察进一步说明：有限研究query的违规标签也可能比当前生产条件清理合同更严格。双方对各自query算对了，不代表接受集合已相同。先实现完整表示与双向关系核对，再研究更细查询，不以“唯一”两个字跳过语义桥接。


可以把下一原型的假设写得更精确。若每个token在合法可达态中满足`sum_c incident(c, token) <= 1`，则owner×token矩阵中的一列可用`location[token] ∈ {absent, carrier_0, ...}`编码，从约`T*C`个关联位变为`T*ceil(log2(C+1))`位；一个闭包持有多个token仍允许多个token指向同一carrier。这是对该关联子表示的位数判断，不包括生命周期、Desc、初始化顺序，也不保证BDD节点按同倍数减少。

为了使它成为可核算法而非直觉压缩，下一实验应给出到旧完整状态的解码D，并分别验证：初态集合相同；每一步正常迁移、fault、abort和exit经D后与原query一致；D保持并集与所求最小固定点。若违规在迁移发生前被检查并记录全部输入关系，合法状态编码可能仍能完整重建反例；这需要逐条证明原始IR指令的失败通道，不能仅靠类型正确假定。最近的重复责任、已清理合流、同址再激活和guard关联反例可直接复用。按此合同通过后，才能与本轮`mono:owner:gc`比较构造、核对、解码和完整输出总成本。

## 4. 编译器中更大的切口：已核语义结果

Rust red-green查询和Zig减少over-analysis的共同启示，是让失效穿过**实际语义依赖**，而非凡文本变化就穿过整模块。ZIL已有query层、不同依赖种类及已核接口，仍可继续精化：私有body改变时重新核验该body；若公开类型、效果、布局和责任摘要原字节不变，下游仅依赖这些结果的查询可复用。这不是当前已完成承诺：现有project路径保守依赖PrivateImplementation，064的lazy补丁只减少无用序列化，没有扩张缓存权限。

未来可把局部证据规范化：将局部SSA/token/区域名字作alpha-renaming，缓存输入边界关系到输出约束/义务的完整摘要，匹配具体实例时重建局部对应关系。缓存键至少包括语义/schema、目标、公开合同、必要环境及结果验证版本。Rust新solver的canonicalization说明为何响应必须带约束；其缓存设计也提醒：递归深度和循环暂态会影响结果，ResourceLimit不能缓存成全局“不成立”。[原始来源](SOURCES.md)

一个有价值的研究方向是**边界充分性证书**：摘要声明哪些输入影响哪项安全义务，独立checker验证切口未漏掉语义因子；重编译只让改变的边界结果继续传播。这比单纯对CFG做min-cut更接近整体架构收益。它尚未实现，不应写成已缩小了实际依赖。

## 5. 查询特化与输出下界

完整逐点联合关系是强校验接口，却可能本身拥有指数个显式输出行。若任务仅询问“是否存在泄漏或冲突”，生产求解器未必需要材料化所有无关标量组合。可以探索按安全义务投影、区域复合或不同知识编译表示；但必须证明被投影掉的变量不影响该义务，并完整保留反例重建信息。输出格式变窄不是免费加速，也不能与本轮完整输出baseline直接报倍率。

因此下一阶段可用两套互补合同：小规模完整关系作为不可删的语义oracle；大规模义务query用独立证书检查，明确其不同输出与成本。结构突破的候选单位是“义务所需的边界联合关系”，并非所有世界状态的笛卡尔积。

## 6. 优先顺序与当前裁决

1. 生产可独立吸收：把未请求dump变惰性；继续验证原emit字节、取消和冲突合同。实际测量见RESULTS，root另单吸收。
2. 研究强基线：先让GC/顺序/关系积有完整费用和反例，保留旧爆限；再评cut的独特增益。
3. 下一项有结构价值的实验：token位置表示加显式非法态；按语义因子图的分隔集做边界摘要；与owner排序的mono+GC比较，禁止弱基线。
4. 更大架构研究：已核公开摘要驱动red-green失效、局部证据共享，以及debug机器码/链接路径。Rust/Zig显示这些是互补的层，不会由一个图算法全部替代。

**目前关系求解器仍为NoGo入生产核。** 本轮解决的是实际瓶颈诊断和有限原型的可行性，尚未证明完整ZIL语义闭合、一般内存管理算法突破、生产整体性能门或胜过Rust。
