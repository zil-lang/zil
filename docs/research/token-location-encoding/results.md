# 067 结果：精确可逆压缩成立，当前性能候选不进入生产

## 结论

本轮实现的global binary token-location编码通过完整有限关系对照，但当前版本在所有含所有权的预定计时族上增加完整候选耗时。生产准入结论为 **NoGo**；保留实验及全部反例，不能把位数下降包装成编译器加速或通用图算法突破。

## 为什么压缩反而慢

固定四guard的`independent`函数，dense与location均输出1440个完整行、113个程序点、110460字节canonical结果。20个carrier、4个token的关联位从80降至20，全部状态位从272降至212。然而下列成本同时发生：

| 指标 | dense fused | location fused |
|---|---:|---:|
| 候选完整抽象工作 | 22255624 | 38072796 |
| 创建过的BDD节点 | 766701 | 1789718 |
| GC抽象工作 | 6704276 | 17231080 |
| 单因子最大布尔支持变量数 | 3 | 7 |
| 最大逐点可达BDD非终结节点 | 2724 | 1989 |

原先局部关联位的等值关系变成对完整二进制位置的测试；更少的位携带更复杂的依赖。逐点表示确实更小，最终物化阶段比值约0.852，但求解阶段约1.898，抵消了收益。这里测到的是因子支持与实际BDD/GC成本；不能从这些数字声称已经求出了图treewidth。

同名owner启发式在不同坐标中诱导不同变量和因子次序，因此这是当前完整候选与当前dense控制的比较，不是纯粹“少60位”的孤立因果实验。dense控制已经采用063有价值的owner顺序和安全边界GC，而非故意选择弱基线。

## 研究决策

保留精确codec、独立oracle、完整观察合同和反例库，**不将本候选用于生产路径**。图切割/物理启发仍有具体待检验的机会，当前失败缩小了范围：

1. **token局部位置域。** 从原始事件建立保守可达carrier支持，避免每个token都共享全C位置。必须保留raw重复事件，并对域外正常像做显式失败检查，不能用未经证明的唯一性删状态。
2. **直接搬移。** 在有限位置域上把一次转交表示为受前态约束的重命名/搬移，探索部分双射的直接关系像；避免先生成全dense矩阵表达式，再编码成更耦合的二进制因子。退休、制造和清理仍需完整观察与单独证明。
3. **共同计划层。** 以真实因子支持、临时节点与全链成本选择精确表示/消元计划。所有规划、编码和最终输出成本计入，不能因局部BDD较小就默认总链条更快。

这三条未实现；不预支收益。相关物理/数学论文与映射见[SOURCES.md](SOURCES.md)。
