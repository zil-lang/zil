# CP02 默认关闭探针：最终分支开销对照

在 CP01、CP04 均被否决后，可合流生产树只保留 CP02 的可选计时能力。此前 CP04 为隔离单个 pass，双方都含 CP02；它不能回答“整条最终分支相对 main 的默认开销”。本窗口专门解决该剩余风险。

测量前冻结：A 为 `ad509b5003d9d2a303428f9d01732292988084d8` 的独立 release，B 为 `6c3b950e6e534fd276d199a4b1bce8302f5a79ee` 对应 CP02 release。最终回退后的 crates 与 B 完全相同。LLVM/Clang 17.0.6、O0、1 CGU/worker；双方不传 `--timings`，对象缓存均关闭。五语料、四请求、原权重和三个 ABBA/BAAB 区块沿用 CP03，分别测 check/build，共 480 请求；预检 80 请求。

不新增优化，不和 CP01/CP04 混合统计，不对之前窗口乘算。检查完整 CLI wall/CPU、所有格和生成程序摘要，保留任何不利项；若出现稳定开销，应改进默认关闭路径或将计时实现撤回，不能用“基础设施”标签隐去成本。有限样本未观察到稳定退化不等于证明零开销，实际点估计与区间都报告。开启探针的收集/序列化成本明确属于诊断模式，不用本窗口推定。

性能窗口只由根运行，团队停止额外编译/测试/分析重负载。产品门仍 NotRun；此控制只支持本次研究分支的有限合流判断。
