# CP10：复用单次请求内相同的声明查找表

2026-10-30阶段定位发现，每个模块重复构造整个项目的聚合声明表，以及callable/state参数名字表；标量树语料中两表为空，仍反复扫描全部声明。LLVM23单次探针用于定位，不作为正式性能成绩。

- Expand入口按照原顺序构造聚合声明表一次，保留first-declaration-wins及borrowed引用，传给每模块内部展开。
- Types聚合解析入口按照原规则构造callable/state名字集合一次，供各模块readonly contains；单模块API维持原行为。
- 两项分别提交，最小写集分派给/root/llvm_strategy，不改变IR/schema、源码接受性、错误优先级、逻辑预算、每请求Verify、跨请求缓存或旧NoGo依赖索引。
- 不能借此跳过任何带预算扣费的声明遍历、SourceMap验证、enum解析或模块正常类型检查。集合仅在同一次不可变项目请求中复用。
- 限定测试包含多模块聚合、重名优先级、callable/state推导、错误源和N/N-1预算边界；独立审核比较旧新接受/诊断/工作量，随后quiet窗口测完整请求。五语料全部保留，不仅报告大合成树。
