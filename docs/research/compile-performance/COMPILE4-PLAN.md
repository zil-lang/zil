## 环境与真实执行

新沙箱没有 Rust/LLVM，且磁盘不足以容纳工具链；源码与已有 Git 历史从 GitHub Actions 的可恢复 artifact 取回。实际 Rust/LLVM 构建、限定回归和性能测量在同一 GitHub Actions runner 内串行执行。记录 LLVM/Clang/LLD、rustc、CPU、实际 affinity、编译器 hash、源码 commit/tree、全部命令与原始结果。不能把远端 CI 可用或本地静审记成构建通过。

## 预先确定的验证顺序

1. 合入新主线并保留冲突及解决依据，运行静态交接检查；新增候选先走限定测试和非作者审查。
2. 同一 runner 构建合流后基线和候选，在 CP14 不生效的 O0 桥接窗口单独检验 CP15，在 O2 窗口检验组合。编译器本身构建时间不混入 ZIL 源码编译时间。
3. 复用原五语料、5/15/30/30/20 权重和既有 cold/unchanged/private/public 请求权重；完整进程计时包括 Verify、LLVM 与链接。先固定 3 个配对区块筛查，无删慢样本；明确属于研究窗口。
4. CP14 对旧单 CGU O2 做直接原生运行比较，对大于阈值语料核对旧分区及代码产物；逐语料稳定退化则 NoGo，不能由低权重掩盖。默认非 closed/O0 代码需保持。
5. 新候选与 Rust 原生配置同时报告；LTO off 仅作为独立对照，不能择优替代。运行语义、优化等级、溢出检查、CPU、安全与调试配置尽量一致，不能统一的差异明确列出。
6. 记录失败、缓存、产物和样本身份；证据不完整不评分。不扩充或放宽既有 product-gates。

## 终态边界

本轮不把减少复制称作细粒度增量已完成；私有编辑仍可能使项目查询失效。CP14 只处理小程序分区的具体反例，跨 CGU 优化与整体 O2 领先需要本轮实测。完整语言与 Rust 四目标继续依现有正式门判定。
