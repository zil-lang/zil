四个 Rust 对照计划各自还执行独立的 Rust/ZIL 原生运行窗口，每个 100 行，比较相应预检产物；这些不替代两个直接旧新 ZIL O2 质量窗口。矩阵共有 940 行正式完整编译时间、600 行正式原生运行时间。加上 110 次编译预检和 20 次直接质量产物构建，共 1070 次顶层编译请求。`bench.py` 固定启用 `--cache-dir` 原始源码候选缓存，因此 main 桥接窗口不能称为严格无缓存；它不启用机器对象或 CP12 前端检查点。

Rust 保持原生 CGU/链接器选择，另有原计划显式的 overflow-checks=on、panic=abort、debuginfo=0、embed-bitcode=no、target-cpu=x86-64。ZIL 的 8/4 是显式研究配置，不称为 CLI 全默认。cold 指每次新进程、无编译缓存；OS 页缓存保持暖，不是冷磁盘启动。增量 unchanged 也重新运行编译器并完成链接，不是 Cargo 无工作检查。

所有窗口保留原五语料及 5%/15%/30%/30%/20% 权重；增量四请求为 cold/unchanged/private/public，权重 10%/35%/40%/15%。CP12 只有 unchanged 可以命中前端检查点；两个编辑必须 miss。分请求、分语料、retained 单独结果及剔除最大树的敏感性分析必须同时披露，不用事后改权重取得优势。

## 实施与裁决

完整构建使用 CPU 0–3；原生运行固定 CPU 0。编译与运行质量窗口分开，正式计量前停止所有代理编译/测试。全部计划、输入、执行顺序、工具/二进制和 runner/helper SHA 在预检前冻结。预检可以和非计量回归并行，其耗时不评分；全部语义/oracle/每次 Verify=1、模式真实生效、缓存状态及身份检查通过之后才计量。

O2 主配置在观察本轮结果前确定为 closed 8/4。不会根据本轮两个配置的时间择优，再把最优配置称为已确认。若主配置出现语义失败或稳定的运行退化，保留并报告失败；任何次要配置晋升都要求新的确认窗口。每项成绩保留自己独立的版本/优化/缓存边界，不将不同模式的最好成绩拼成一个总体数字。

运行质量必须直接比较旧 e8 O2 单 CGU 产物，不从两批 Rust 比值间接推断。结果报告逐语料墙钟、CPU、配对区块及加权比值；有限样本未发现稳定退化不等于证明所有程序没有退化。语义失败不评分，完整性/身份/记录缺失禁止评分。慢样本、失败尝试和负结果全部保留。

配对区块 bootstrap 区间只描述此共享宿主、有限语料的窗口；不升级语言、平台或产品门。合成调用树占 80% 权重，不能称为行业工作负载。所有结果由非作者独立复算，精确源、二进制、原始日志、输入/oracle、产物和完整收据保留。main 不合流。
