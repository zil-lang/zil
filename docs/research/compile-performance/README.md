# LLVM 编译性能研究

最新结果：[LLVM23-RESULT.md](LLVM23-RESULT.md)。生产测量源码固定为 `6e8e63a5ceae861447d0447c325bed78b59c3f42`，LLVM/Clang/LLD 23.1.4，对照 rustc 1.99.1（LLVM 23.1.1）。

- 五语料 O0 无编译缓存、请求 8 CGU / 4 jobs：ZIL 544.769 ms，Rust 706.857 ms，耗时低 **22.93%**；描述区间低于 1。五个 O0 生成 ELF 与上一轮 e8 逐字相同。
- main 到候选的独立桥接：完整构建加权墙钟低 **13.25%**、CPU 低 **14.25%**；两臂均开启原始源码候选缓存，不是严格无缓存窗口。
- O0 增量总体仍慢 **16.22%**。未变请求已领先，私有/公开编辑仍落后；完整分项保留。
- O2 closed 8/4 点估计快 5.84%，但区间跨 1，且相对旧 e8 O2 单 CGU，最小语料运行稳定慢约 27%，采用判定 **NoGo**。该研究开关默认关闭；单 CGU 探索配置也未达到编译目标。

最终确认包含 940 次完整编译计时、600 次原生运行计时，三方独立复算。组合回归工作区 feature 等效唯一覆盖 2,805 项，额外 API-off 控制后共 2,806 项。57 行磁盘耗尽的失败窗口完整保留为 NoScore。main 未合流，产品门 NotRun。

### 当时已建立的证据边界

三个互不混合的完整 CLI 窗口共 1,200 次正式请求，另有 100 次原生运行质量样本；全部成功不代表性能达标。五语料与四请求权重预先冻结，失败或缺格禁止评分，bootstrap 重采样完整配对区块。独立审核重新实现 Decimal 算术并核对原始日志和输入摘要，不靠同一个聚合函数自证。

CP04 作者定向测试 12 项、根独立影响闭包 27 项通过；CP02 精确实现另有 driver/CLI/timing 9 项作者测试与非作者静审；测量工具控制为 8+14 项，根独立执行通过。没有把有限测试、实际输出一致或 LLVM Verify 解释为全语言/全目标证明。全量产品门 NotRun；主线基线的全局 handoff 既有 1,138 项历史记录问题，本专项没有宣称修复或通过。

原始资料按实验置于 `evidence/research/compile-performance/`。`raw-evidence.tar.xz` 包含冻结语料和原始请求/运行日志，压缩只改变包装；CP04、最终 control 的完整文件清单另外压缩保存。各 summary 的生成时独审字段保留原值，后续审核见独立 JSON。跨环境复现应新建计划和窗口，不能直接复用旧进程时间或旧二进制身份。

### 当时提出的下一轮施工顺序

1. **先解决 CP02 合流接受项。** 复核默认关闭成本；检查关闭路径的调用、栈布局和编译器代码布局影响。评估编译期开关将收集实现完全移出默认构建的方案，重新绑定编译器身份并对 main 开独立 check/build 窗口，不能只选较快结果。
2. **查清 O0 机器码质量。** CP04 的大样例 optimize 增加约 85ms，emit 只省约 12ms；运行端还有不同规模的相反结果。先检查指令选择、寄存器/栈使用与函数布局，再决定直接 SSA 构造的范围。现有 ELF 尺寸只是线索，没有硬件计数器证据支持具体 cache-miss 归因。
3. **按项增量与持久会话。** 借鉴 Blaze 的函数身份/源码位置解耦和 Rust red-green 机制；先建立持久 Session 的完整编辑请求窗口、重算数量和端到端时间。每请求独立 Verify 保持，不能拿本轮新 CLI 窗口代替持久会话收益。
4. **版本和分规模瓶颈分开实验。** LLVM 升级、CGU/并行、链接器/进程启动分别冻结配置。小消费者单次定位中链接占主要部分，大工程则需同时看前端、机器 IR 和对象发射。每个后端改动继续跑原生运行质量，不能只看 LLVM IR 条数。

不可变共享 Verify 输入的设计已做只读梳理，暂不优先实施：现有大 build 的整个 Verify（含复制）约 95ms，尚未隔离纯复制成本；不能把该范围全部认作可消除开销。[一手来源与适用边界](SOURCES.md) 记录了 Rust、Blaze、LLVM 的具体依据。
