# ZIT 点依赖机制与 ZIL 查询运行时的对应

审查者：`/root/incremental_review`。ZIL 基线为 `485301e1f1dcdfb0b4e24f6249355104243c3fe3`；ZIT 来源为本轮用户上传的完整 `zit.ts`。本报告是源码与机制审查，不是已完成全部增量实现或性能验收的声明。

## 一、ZIT 的价值在计算图的执行方式

`bond`、`trig`、`recalc/write`、`read/flush` 必须一起看：读取时记录实际依赖，输入变化只触达直接消费者；消费者重算后只有结果变化才继续通知；读取仍未被直接标脏的远端结果时，先确保其上游已稳定。缓存只是保存这些计算结果的载体。

| 源码机制 | 精确行为 | ZIL 对应与差距 |
|---|---|---|
| `bond`，101–108 | 一条 WD 同时位于消费者的有序读取链和生产者的订阅链；用当前游标试下一条和上一条边，复用稳定读取顺序 | 当前 `query()` 接收事先组好的依赖 slice，执行后转成 `Vec<Dependency>`；缺少运行中读查询自动记录边的 collector |
| `unbond/bdTrim`，111–113 | 已知边可以 O(1) 从两端摘除；重算后删除本次未读的尾部 | 当前快照依赖 Vec 不变，替换快照时整批替换；需要先有稳定 QueryId，才能保存跨编辑的边身份 |
| `trig`，94 | 只遍历当前生产者的直接订阅者，将未脏节点置脏并去重入队 | `Database::invalidate` 当前直接删除整个传递后继，失去了中间结果不变时保留远端结果的机会 |
| `recalc→write`，74–88、55–65 | 重算后值相同就停止传播 | 当前 `FingerprintKind` 能按结果面选择依赖，但 driver 实际全部观察 PrivateImplementation，语义等值边界未接通 |
| `hq/flush`，277–301 | 低高度先执行，节点已在队列时不重复加入；高度变化的节点出队时重新入正确桶 | 适合已知无环查询图的 ready 调度；不能直接替代编译器中的 SCC/固定点求解 |
| `read`，52 | 先 flush 到当前节点前一层，再按需重算自己 | 若只对直接消费者标脏，远端 clean 不代表值已是当前值；ZIL 必须增加 ensure-current 屏障 |

### bond 复用的具体范围

旧读取序列 `A,B,C` 再读 `A,B,C` 时，三条边可全部原地复用；改成 `B,A` 时，它不会搜索并搬动任意旧边，而是为当前游标之外的 B 建新边、复用随后对位的 A，最后删掉未使用尾部。其优势是常见稳定读序不分配，读序变化仍只进行局部插入和顺序清理。

因此不应简单宣称“全量依赖 diff 变为 O(1)”。每次仍要访问实际读取的 k 条依赖，成本至少 O(k)；减少的是哈希去重、全表搜索、重复分配和无关边处理。

当前 ZIL 的干净 query 命中本来就不会重建依赖 Vec，只有真实执行后才构建。因此立刻把 Vec 换成双向链表可能使冷编译变慢。需要先拆分稳定的查询身份与可变的输入版本，再考虑边游标。Rust 中可用 arena 索引和反向位置完成 O(1) 摘边，不需要 unsafe 指针。

## 二、点对点传播与读取屏障不能拆开

设 `X → B → D`，修改 X 后只把 B 标脏，D 此刻仍可保持 clean。如果此时读取 D 就直接返回缓存，会拿到旧值。ZIT 通过 `flush(D.h-1)` 先执行脏祖先；若 B 输出改变，才把 D 标脏；若 B 输出不变，D 原结果继续有效。

ZIL 当前 `Database::read` 只能校验快照，没有执行查询的 provider，因此不能仅修改 `invalidate` 为“标脏直接邻居”就完成这个迁移。应由 Session 增加 `ensure_current(QueryId)`：先令依赖结果达到当前请求版本，再比较所观察的结果指纹，必要时才执行当前查询。一次请求内可复用已经验证过的节点，避免重复遍历菱形的共同祖先。

ZIT 的按高度读取屏障会处理该高度以下所有已排队节点，可能包括当前读结果的无关分支；它并不是严格只拉取当前结果的祖先。编译器可以使用需求作用域内的屏障或按需依赖验证，避免不相关目标互相拖累。

## 三、按高度 flush 的收益与边界

菱形 `X→A/B→D` 中，A、B 先执行；D 首次收到变化通知后只入队一次，等两边稳定后再算，从而避免中间态和重复计算。其并行条件是同层节点之间不存在依赖，而且查询没有未记录的共享可变状态；同层本身不能证明任意编译器代码可以安全并行。

新边可能在运行时发现，因此旧高度只能作为调度提示。读到尚未完成的新依赖时必须等待/挂起，继续执行之前校验实际 wait-for 图。资源效果、递归函数等允许成环的语义图要按 SCC 处理：SCC 内用原固定点求解，SCC 间再按无环层级调度。

上传版本的 `hUp` 只抬高、不降低高度，`h>1000` 调用错误钩子，并没有完成可靠的环判定。只在两种分别无环的依赖方向之间切换，高度仍会逐次升高。编译器不能把这一阈值当安全判定，也不宜沿用不会回落的稀疏桶高度；应有真实循环检测和层级重整，或采用就绪计数队列。

## 四、ZIL 已有的真实对应

以下机制已经存在，不应当成此次新实现：

- `crates/zil-types/src/resource_effects.rs` 的 `solve_worklist`：提取 caller 边，直接调用者入队、queued 去重，效果集合不变就不继续通知。
- `crates/zil-analyze/src/resources.rs` 的 `infer_effects_frontier`：按函数结果变化通知直接消费者。
- `crates/zil-analyze/src/resources/summary_graph.rs`：以 `(function, Argument/BorrowedField/AnyBorrowed)` 为点，事实新增沿具体边传播，seen 防止重复。每个单调事实只需传播一次，已经比整函数广播更细。
- Verify 保留独立图与求解，不共享 Analyze 的证明权限。

ZIT 的新参考价值主要位于跨请求：保留计算节点、边和结果；编辑后局部更新；结果不变截断远端失效。效果删除还需要撤回机制：不能在旧 effects 上继续 union，否则把写操作删除之后，旧写效果永远留着。可先保守重置受影响 SCC，再局部重求解；后续再考虑更细的贡献计数。

## 五、可落地顺序

1. **CP21/CP23：消除确定无须遍历的路径。** 缺失 producer 的失效早退，缺失/无依赖查询直接读取；保留 active 与非叶祖先校验。CP21 是历史084候选重测，不是新理论成果。
2. **CP22：逐模块持久解析复用。** 去除前序模块剩余预算对身份的污染，以成功资源收据回放原费用。这是实际跨进程解析增量，Expand/CT/Types 仍全项目执行。
3. **下一片：稳定查询身份与事务化依赖 collector。** 在现有 CompilationSession 上将 QueryId 与输入 fingerprint 分离，先为一个真实结果面接线；按读取顺序复用边，重算成功后原子发布结果与新依赖，再删除旧边。取消/失败保持节点不可读，不能照搬 ZIT 的 finally trim 后继续使用旧成功结果。
4. **接入直接变化队列和 ensure-current。** 通知边必须包含结果面，例如 signature、layout、effect、body；泛型/CT 读取 body，普通调用者依赖明确接口，名字枚举与缺失查找也必须有边。
5. **需求范围内的拓扑/SCC 调度。** 在正确依赖图上测菱形、多源合并、动态重连和循环场景，只有端到端收益成立再推广。

## 六、原源码同步路径实测

测试脚本 `zit-mechanisms.mjs` 执行上传源码的响应式函数本体，仅剥离 TypeScript 并为未上传 utility 模块提供同步数值路径所需替身；未测 DOM、异步、完整项目功能或性能。

| 场景 | 结果 |
|---|---|
| `X→B→D`，X 修改后立即读取仍 clean 的 D | 先稳定 B 再更新 D，返回当前值 |
| 中间节点取 `%2`，源由0改2 | 中间节点共计算2次，终点仍只计算1次，等值截断成立 |
| 菱形中连续写源两次再 flush | 两侧和终点都只增加一次计算 |
| 保持3条依赖的读取顺序 | 3个 bond 对象全部复用 |
| 改读序，再移除一项依赖 | 复用对位边、重建移位边，移除后的生产者不再触发 |
| 在两种分别无环的方向间切换1100次 | 值始终正确；最终高度1101/1102/1103，产生103次 `zit_dep_cycle` 告警 |

这些是机制证据，不应折算成 ZIL 的提速百分比。

复跑命令（需要支持 `stripTypeScriptTypes` 的 Node；原始上传文件由调用者提供，不把私有依赖替身当作完整zit环境）：

```sh
node evidence/research/compile-performance/COMPILE6/mechanisms/zit-mechanisms.mjs /path/to/zit.ts /path/to/new-result.json
```

结果包含原始文件SHA256与Node版本；临时模块在加载后清理，输出文件禁止覆盖。

本轮也逐字归档了原始 `mechanisms/zit.ts`，其SHA256与机制结果中的source_sha256一致；脚本可直接以该文件复跑。原始上传文件未修改。
