# LLVM23 编译性能研究结果

日期：2026-10-30。研究分支：`research/compile-performance`。本轮测量的生产源码固定为 **`6e8e63a5ceae861447d0447c325bed78b59c3f42`**；后续提交只增加独立审核、报告和原始证据。编译器 SHA-256 为 `764f592fcee5a7e9780fd774b3d93f168ddf52ba2a2f7d11d125909e43eb46a3`。

## 结论

**在冻结的五语料 O0 无编译缓存对照中，ZIL 完整编译耗时比 Rust 低 22.93%，五个语料的点估计均更快。** 相对 LLVM23 主线基线，本轮组合改动在另一个完整构建桥接窗口中降低加权墙钟耗时 13.25%、CPU 耗时 14.25%。五个保留的 O0 可执行文件与第一轮 e8 候选逐字相同。

增量总体仍比 Rust 慢 16.22%，差距集中在私有和公开编辑。O2 主配置的完整编译点估计快 5.84%，区间跨 1，而且相对旧 e8 O2 单 CGU，最小语料的原生运行稳定退化约 27%；该配置的采用判定为 **NoGo**。单 CGU O2 探索配置仍需 Rust 约 3.13 倍的编译时间。不能据本轮宣称所有优化级别、所有增量场景都超过 Rust。

全部结论限于这里明确的源码、配置、语料及共享宿主窗口。main 未合流，产品门保持 **NotRun**。CP12 与 CP13 的研究开关默认关闭。

| 完整构建窗口，A=Rust / B=ZIL | Rust 加权 ms | ZIL 加权 ms | B/A | 配对区块描述区间 | 结论 |
| --- | ---: | ---: | ---: | --- | --- |
| O0 cold，ZIL 请求 8 CGU / 4 jobs | 706.857 | 544.769 | **0.770692** | [0.742399, 0.921476] | 本组对照领先 |
| O0 incremental + query，8/4 | 398.318 | 462.923 | **1.162195** | [1.096128, 1.197077] | 整体仍落后 |
| O2 closed，8/4，预注册主配置 | 949.934 | 894.494 | **0.941638** | [0.865947, 1.020763] | 编译领先未确认；运行质量 NoGo |
| O2 closed，1/1，次要探索配置 | 1017.406 | 3186.845 | **3.132322** | [3.026138, 3.258903] | 编译目标未达到 |

上述百分比指耗时下降，不是吞吐提升。各行独立测量，不能把某行最快的配置与另一行的缓存/优化配置拼成一个总分。[原摘要](../../../evidence/research/compile-performance/LLVM23-ROUND2/summaries)及[独立 Rust 复算](../../../evidence/research/compile-performance/LLVM23-ROUND2/independent-rust/README.md)保留完整数字。

## 环境、比较对象与计量方法

沿用当前主线的 LLVM23 系列工具链，未回退旧版。ZIL 使用独立 LLVM/Clang/LLD **23.1.4**；Rust 为 **rustc 1.99.1**，内部 LLVM **23.1.1**。这不是同一份 LLVM 二进制，也不能把两种语言的差异全部归因于前端。

Rust 采用其原生 CGU 与链接器选择；另外明确设置 `overflow-checks=on`、`panic=abort`、`debuginfo=0`、`embed-bitcode=no`、`target-cpu=x86-64`，不是笼统的“所有选项全默认”。ZIL 的 8/4 同样是显式研究配置，CLI 本身默认 1/1。8 CGU 是上限：tree4x2 实际 7 个，retained 实际 3 个且 jobs=3，其余三个树为 8/4，均无 fallback。

完整编译固定 CPU 0–3，原生运行固定 CPU 0。Rust 对照中的 cold 模式指新编译器进程、无编译缓存；OS 页缓存保持暖。增量 unchanged 仍删除旧产物、重新启动编译器、执行当前 Verify 和链接，不是 Cargo 的无工作检查。编译计时从创建 CLI 进程前到 wait4 返回后，包含前端、Verify、LLVM 与链接；输入准备和 oracle 执行在编译计时外。

五语料权重预先固定为 5% / 15% / 30% / 30% / 20%，依次为 tree4x2、tree32x8、tree256x8、tree1024x8、retained。最大树共 1,027 个模块、9,222 个函数。合成调用树占 80% 权重，retained 占 20%；它们不代表行业或全语言负载。

Rust 对照和直接运行质量均为五个 ABBA/BAAB 配对区块；main 桥接为三个。估计量先求区块内每臂两次观测的均值，再对每个语料/请求/臂取区块中位数，随后按原权重加权绝对成本，最后求 B/A。bootstrap 重采样完整配对区块，不独立打散样本。所有区间都是共享宿主有限样本的描述，不是产品总体保证。后台平台活动不受此任务独占控制。

执行前的[冻结计划](LLVM23-ROUND2-MEASUREMENT-PLAN.md)明确：O2 8/4 是主配置，1/1 是探索配置，不能观察结果后择优替换主配置。独立审核还穷举了五区块的 3,125 种有序重采样作为敏感性检查。

## O0：收益覆盖全部五个编译语料

| 语料 | Rust ms | ZIL ms | ZIL/Rust | ZIL 耗时下降 |
| --- | ---: | ---: | ---: | ---: |
| tree4x2 | 64.409 | 38.403 | 0.596242 | 40.38% |
| tree32x8 | 109.191 | 67.608 | 0.619176 | 38.08% |
| tree256x8 | 454.552 | 301.328 | 0.662912 | 33.71% |
| tree1024x8 | 1786.132 | 1447.145 | 0.810212 | 18.98% |
| retained | 75.266 | 40.829 | 0.542462 | 45.75% |

加权 CPU 比值为 **0.808436**。剔除最大树、将剩余权重除以 0.7 后，编译墙钟比值为 **0.646866**。这项事后敏感性未替换主结果，也没有删除最大树。

main `25506bd61a681d41b02f1cd98a5a614e9c058787` 到候选的桥接窗口，两臂均为 O0 8/4、原始源码候选缓存开启、object/query/closed 关闭。加权墙钟 **615.061 → 533.554 ms**，B/A **0.867481 [0.826829, 0.895042]**；CPU **799.804 → 685.795 ms**。去最大树后，墙钟比值为 **0.924547**。

桥接的 cold/unchanged/private/public 耗时分别下降 **1.27% / 10.07% / 18.38% / 17.74%**；部分 cold 单元仍略慢，不能写成每个主线冷请求都明显改善。该桥接包括 CP07 的系统默认链接器到配套 LLD 的变化，不隔离任何单项优化贡献。[独立桥接审核](../../../evidence/research/compile-performance/LLVM23-ROUND2/independent-main/RESULT.json)核验了实际链接 argv，并区分只读链接器诊断与历史 execve 记录。

另直接读取 e8 与 6e 五个保留 O0 ELF，全部逐字相同，大小依次为 **8,600 / 55,160 / 395,832 / 1,566,264 / 9,856 字节**。它们还与正式 B/base 记录的哈希一致。这证明这些实际程序的代码产物未变，不外推到所有源码或跨窗口运行时间。

## 增量：未变请求已领先，编辑请求仍是主要差距

| 请求 | 原权重 | Rust ms | ZIL ms | ZIL/Rust |
| --- | ---: | ---: | ---: | ---: |
| cold_process，含缓存建立 | 10% | 938.730 | 782.029 | **0.833071** |
| unchanged | 35% | 325.758 | 301.892 | **0.926736** |
| private_edit | 40% | 343.142 | 510.606 | **1.488032** |
| public_edit | 15% | 354.486 | 498.770 | **1.407025** |

CP12 只复用完整相同输入。50 次正式 unchanged 均命中 query；150 次 cold/private/public 均 miss 并成功保存，每次当前语言 Verify 都严格为 1。新键包含完整源码 SHA-256、路径、模块/导入顺序、全部 11 个 Limits、schema/rules/target、选项及可信安装的生产者身份。缓存不恢复 Verified 包装或接口验证资格。

最大树的增量加权比值为 **1.297983**；剔除它后整体变成 **0.871502**。因此剩余差距主要落在较大项目的编辑重编，不能用小项目或未变请求的成绩替代主结果。旧 `disk_cache` 字段反映最后处理的模块，不能当成整项目命中率；本轮 query 报告独立核对。

全部正式窗口结束后，以同源码、单独启用 `timings` 的编译器做了一次最大树诊断。未变请求跳过 Expand/CT/Types/Analyze，仍执行约 68 ms 的当前 Verify；私有编辑再次执行这些前端阶段约 **129 + 88 + 139 + 63 ms**，公开编辑约 **143 + 88 + 141 + 70 ms**。对象缓存已分别命中 7/8 和 6/8 个单元，前端全输入失效仍支付较大成本。

这份诊断开启 profiling，且允许其他审核工作运行，只用来定位；其秒数不能与正式中位数相减，也不是新的加速成绩。父阶段包括子阶段，worker 时间重叠；对象 key/preflight 纳秒和不是关键路径墙钟。[原始阶段记录](../../../evidence/research/compile-performance/LLVM23-ROUND2/timing-diagnostic/RESULT.json)保留全部四请求和 oracle。

## O2：完整保留运行退化，主配置 NoGo

O2 原先 e8 单 CGU 在第一轮 Rust 对照中为 **4.2448 倍**。本轮 closed 8/4 接近 Rust，但不能用不同窗口的比值直接声称一次孤立优化提升了多少。新的单 CGU仍为 **3.1323 倍**，说明多 CGU 配置对这批大语料的成本有重要影响。

运行质量直接比较 **旧 e8 O2 1/1** 与 **候选 closed O2**，没有从两批 Rust 比值间接推断。

| 直接运行质量 B/A | closed 8/4 主配置 | closed 1/1 探索配置 |
| --- | ---: | ---: |
| 加权墙钟 | 0.987449 | 0.992552 |
| 加权墙钟描述区间 | [0.916458, 1.036777] | [0.992552, 1.061060] |
| tree4x2 墙钟 | **1.272744** | 1.040457 |
| tree4x2 墙钟区间 | **[1.205266, 1.376242]** | [0.914403, 1.267734] |
| tree4x2 CPU | **1.282923** | 1.042404 |

主配置 tree4x2 的五个区块全部慢，墙钟比值约 **1.251 / 1.376 / 1.360 / 1.243 / 1.205**，CPU 也全部同向退化。其他语料或低权重不能抵消这一事实。按事前规则，**closed 8/4 不推荐默认开启或合入 main**；默认关闭的研究开关与负结果保留。

closed 1/1 的逐语料区间均跨 1，但其五个逐区块加权墙钟比值其实全部高于 1：**1.0611 / 1.0167 / 1.0022 / 1.0106 / 1.0142**。原估计量先逐语料/逐臂取中位数再加权，中位数与求和不可交换；不能把 0.992552 称为稳定运行加速。独立收据同时保留原估计量、逐区块数据和配对几何比敏感性。[运行质量独审](../../../evidence/research/compile-performance/LLVM23-ROUND2/independent-quality/README.md)给出完整依据。

独立 Rust/ZIL 原生运行窗口也保留：O0 两组加权比值约 **0.707 / 0.686**，O2 两组约 **1.024 / 0.969**。O0 较小的两个合成程序仍比 Rust 慢约 32%–35%；去最大树后的 O0 原生运行总体接近 1。这些是两种语言的实际程序对比，不是本轮 O0 改动造成的退化；五个旧新 ZIL O0 ELF 相同的事实单独成立。

## 已实现的改动及边界

| 实验 | 实现 | 保留的合同 |
| --- | --- | --- |
| CP05 | 未启用 timings 时编译移除计时收集器；诊断改为显式 build feature | 默认报告明确关闭；未编入时请求 timings 明确拒绝 |
| CP06 | LLVM 局部值名称丢弃；验证依赖顺序后走原指令顺序快路 | 全局/ABI/sidecar 名称保留；前向引用仍走完整拓扑路径 |
| CP07 | Linux 默认选择指定 Clang 配套的 LLD，保留显式 system/路径配置 | 无效链接器、失败、取消和旧产物保护不降级 |
| CP10 | 每请求共享不可变的聚合/可调用名称查找表 | first-wins、原预算扣费、错误顺序和源位置保持 |
| CP11 | SourceMap 源索引复用；移动已拥有的规范化 AST、机器参数/签名 | 每个 map 仍完整检查与扣费，模型/诊断及真实产物有差分验证 |
| CP12 | 显式可信私有本地的完整输入前端检查点 | 默认 None；重新发现/解析/导入、重扣 CT、当前 Verify、成功后原子保存 |
| CP13 | 封闭 Linux 可执行文件的精确候选函数内部链接 | 默认 false；真实跨 CGU 引用保留 External；外部 emit/raw API 不改 |

CP12 的生产者识别依赖可信、不可变的本机安装；payload SHA-256 检测损坏，不认证恶意同用户写入者。当前 Verify 验证候选 IR，不被描述为对任意伪造缓存证明源码对应关系。Wire27 外部格式和已核包装构造权限未变。check/run/不支持的目标或阶段不暗中采用新模式。

CP13 使用原 `default<O2>` 管线和全部必需机器预检，没有降低优化级别。它在原 partition 后按当前 LIR 的非 foreign FunctionId 生成候选，扫描实际函数与全局初始化器引用，保留跨单元目标。内部化计数是优化前 linkage 变化数量，不是 DCE 数量。

## 正确性、独立审核和失败保留

所有生产候选都有非作者精确提交审核。组合回归的最终覆盖为 **2,805 项工作区统一 feature 等效唯一测试**，再加一个 API-off 控制为 **2,806 项唯一测试**；零失败、零忽略、零过滤。总执行次数 4,791 包含重复，439 是 Cargo 调用次数，不能将它们当成不同测试数。

拆分回归最初没有为独立 driver 分组带上 `llvm-api`，因而遗漏工作区由 CLI 统一启用的条件测试。原日志保留，后来补跑全部 216 个 driver integration target 以及 lib/doc/examples 的 `--features llvm-api` 配置。独立审核核对 439 份日志、目标与测试名称。e8 历史拆分存在同一覆盖区别，已追加说明，不改写其原 2,744 条通过记录。

最终确认窗口有 **940 次完整编译计时 + 600 次原生运行计时**；另有 110 次预检编译、20 次运行质量产物构建，均不评分。计入短 oracle、启动和预热，总计 4,080 次基准产物执行。正式编译的临时产物在哈希和 oracle 后由冻结 runner 删除；预检保留的可执行文件用于正式运行窗口，并实际重新读取核验。

第一次正式尝试因 ENOSPC 在 57 条记录后中断。原始日志、失败和 `IncompleteOrFailed_NoScore` 摘要完整保存，没有任何得分字段；回收已完成测试的可再生产物后，用原计划和全新目录从头重跑。没有删慢样本、替换语料或改权重。独立审计脚本自身早期的两次报告假设错误也保留，并明确区别于正式记录失败。

Rust 对照独审核验 39,887 个文件及 132,219 项检查，独立数值最大差约 1.02e-15；main 桥接独审核验 10,482 个文件，122 个数值最大差约 3.83e-16；O2 质量独审核验 3,521 个文件绑定。三方未调用原聚合函数复算，也没有用重新编译的产物替换计量中的产物。

## 使用与复现

在已配置的 LLVM23 环境中构建默认 release，再使用已测的 O0 配置：

```sh
cargo build --release --locked -p zil-cli
./target/release/zil build project/main.zil -o program \
  --backend llvm-api --opt O0 --codegen-units 8 --codegen-jobs 4
```

显式研究完整输入检查点时，增加 `--cache-dir .zil/source-candidates --object-cache .zil/objects --query-cache .zil/queries`。它适合这里验证的可信私有本地目录；完整增量混合仍未超过 Rust，不应把该命令描述成已解决编辑重编。

完整复现必须新建计划，冻结本机实际编译器/库/链接器身份、可用 CPU 和源输入，再执行 preflight、measure 与独立 runtime。不能把本次绝对时间移植到其他机器。参见 [Rust 对照运行器](CP08-BENCHMARK.md)、[显式模式冻结](CP12-13-RUNNER.md)、[直接运行质量协议](CP13-RUNTIME.md)及[事前矩阵](LLVM23-ROUND2-MEASUREMENT-PLAN.md)。

完整证据位于 [LLVM23-ROUND2](../../../evidence/research/compile-performance/LLVM23-ROUND2)。原始包 **9,296,704 字节**，SHA-256 为 **`8a37eb7a01f83e4abb47535ace6ababa034e4f40ddb56a86451a28b2ea5feb0b`**，包含 53,853 个原始文件、原计划/输入/oracle、保留 ELF、失败与确认窗口、全部日志及执行脚本；解包位置映射见 `ARCHIVE.json`。打包后逐文件读取并与归档前 manifest 核对，不只检查压缩包能否打开。

第一轮 e8 的 360 次构建、180 次原生运行及未达标结果也保留在 [LLVM23/e8-rust](../../../evidence/research/compile-performance/LLVM23/e8-rust)。本轮提供了 O0 的具体、可复算领先结果；细粒度编辑重编和满足运行质量条件的 O2 领先仍是未完成项。
