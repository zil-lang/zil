## 当前结论

CP25 没有独立性能对照，它仍是稳定 owner、事务采边等机制的可行性设计。ZIT 的依赖维护、确保上游当前、结果不变停止传播有参考价值，不能把这些机制控制当作 ZIL 编译提速。

本轮已经实际实现并审核六个独立候选，均单独对同一 CP28 基线计量，没有叠加后混淆归因。CP29 的有限 Types memo、CP30 的无 active 查询快读、CP32 的有界部分 Types 留存均未建立完整净收益。CP33 消除了公开编辑后由剩余预算身份造成的无关 Parse 失效，公开编辑和完整七请求序列有有限正收益；其预先冻结的四请求主混合区间仍跨 1，保留研究候选、默认采用 Hold。

CP34 已将 TypedModule 指纹改为精确等价的缓冲流式编码；前端主混合点估计有利，但完整七请求 CPU 和完整 CLI 点估计不利。CP35 已消除 fresh Verify 输入的深复制，保留每次完整核验；完整 CLI 冷请求和编译峰值内存有局部收益，主混合 wall/CPU 未建立净提速。CP29/30/32/34/35 本轮默认速度采用 NoGo，CP33 有限收益/Hold；这不否定保留其源码或后续研究价值。没有改变原权重、正式产品门或语言接受规则。

状态口径：独审原收据统一使用 Hold，含义是尚不默认采用；根协调者的 NoGo 是对其中五项“本轮默认速度采用”的具体否决。两者没有不同的测量或产品门结论，原独审措辞保留，不追改为另一份结果。

## 正式会话口径

所有候选各自与同一 ee72 基线配对，沿用原 210 语料的五类样例：tree4x2、tree32x8、tree256x8、tree1024x8、retained。语料权重预先冻结为 0.05/0.15/0.30/0.30/0.20，没有因 Types memo 的适用范围筛掉不利样例。

每个进程执行 cold、unchanged、private、public、restore、private_again、restore_again 七个请求。主混合只用前四种，权重 0.10/0.35/0.40/0.15；后三种恢复请求单列。默认 query 容量与 8192 分别报告，不混算。

每候选完整测量 200 个序列、1400 个编译请求，另有 20 个不计分控制序列，即 140 个持久请求与 140 个 fresh-session 对照。五个 ABBA/BAAB 区块内先求同 arm 两次观测均值，再取各绝对成本格的五区块中位数，最后按固定权重汇总 A、B 并相除。没有平均速度比，也没有从不完整窗口挑选样本。

主计时覆盖完整 `compile_path` 到 Verify，包括当前项目发现和读取；每个请求确实重新 Verify。编辑文件复制、session 初始化、报告成本另外保存，完整七请求进程的 wall/CPU/maxRSS 也保存。**这一口径不含 LLVM 发射、优化、对象文件和链接，不是全 AOT 或 Rust 对照。** 控制比较报告、诊断、输入、源文件与接口观测，不冒充新的全 Typed/native oracle；后者由候选限定正确性证据分别说明。

五区块配对重采样区间只是共享宿主上的探索统计，不是修改后的 product-gates 或总体保证。CPU/RSS 来自七请求进程，不能硬分配为四请求加权混合的 CPU/RSS。加权 RSS 指每类进程峰值中位数的描述性加权值，不是同时运行进程树的实际峰值。

### CP29 与 CP32：机制命中并不等于总成本下降

CP29 在 tree256 私有编辑中确实复用了 2305 个函数，只检查 5 个；但最大语料超过其整体 64 MiB 条件，未留下 memo。其默认主混合仍慢 7.07%，不采用。

CP32 把“全图语言适用性”和“存得下哪些模块”分开，稳定顺序保留整个模块，超过容量的模块跳过；预算保持 64 MiB。先选择再复制，并在完整 Core/环境相等后复用源权重收据。独审实际覆盖保留集合 812→805→812、未保留末模块公开环境改变、完整 Typed 与 fresh 相等以及失败保持旧 epoch。

在原 210 的 tree1024x8 中，CP32 实际保留 773 模块、67,058,682 B；私有编辑复用 6940/9222 函数。该语料 private 成本在 default/8192 分别下降约 2.83%/7.32%，但公开编辑仍全量检查，冷请求和内存成本增加。五语料默认主混合约持平且加权峰值 RSS 增 20.20%，8192 主混合慢 6.03%，保持 NoGo。前述 812 模块属于另一个容量压力控制，不能冒充原基准结果。

### CP30：图不变量成立，整体收益未建立

只在没有 active 求值时直接读取已发布快照；active 非空保持原 DFS 与错误顺序。独立 DAG/失效/Arc 隔离控制通过，但默认完整主混合未下降。其首次正式窗口在 114/200 序列后遭遇 live 目录清理 `ENOTEMPTY`；原 traceback、114 条前缀和显式 Incomplete_NoScore 保留。失败原因未充分归因，没有归罪编译器，也没有复用该前缀计分。之后新 `/tmp` 目录的完整计划、控制与 200 序列从头执行并单独计分。

### CP33：公开编辑失效范围得到收窄

前部文件的公开编辑增加 token，会改变后面文件的剩余 max_tokens/max_nodes。旧 Parse 查询键绑定这两个余额，未改文件因此可能失效。CP33 保存真实 ParseUsage，稳定 Parse 身份只分离这两个可回放额度；命中前要求当前余额足够，不够则回原解析路径。其余九项 Limits、规则、源、位置、路径、FileId/ModuleId 继续绑定；后续 CT/Types 等阶段仍使用完整身份，项目当前读取/导入歧义/累计计费照常执行。

独审复跑 61 项原控制，并新增 3 个外部 consumer，包括 81 组联合预算边界；真实覆盖 Parse 命中但当前 CT 应失败的相同错误及 Span，跨入口预热、当前导入歧义与 fresh Verify。另有第二位代理仅静态复核。没有增加磁盘 AST 缓存或恢复前轮 CP22 的磁盘费用。

公开编辑的五语料加权耗时 default 为 213.293→177.084 ms，B/A=0.830239，约下降 16.98%，探索区间 [0.775313,0.842487]；8192 为 271.262→187.541 ms，B/A=0.691366，约下降 30.86%，但该容量公开编辑的探索区间 [0.563575,1.163807] 跨 1，只保留为有利点估计。默认完整七请求进程 wall/CPU 分别为 0.933959/0.933983，五个区块均低于 1，探索区间分别为 [0.914474,0.989732]/[0.914200,0.995285]；加权峰值 RSS 下降约 9.35%。同时 cold 成本点估计增加约 4.74%，private 约增加 0.75%。因此可以报告有限公开编辑及完整序列收益，不能把这些有利子项替换为预先冻结的四请求主混合，或直接宣称全 AOT 提速。当前不默认采用。

### CP34：去掉整块编码暂存，仍须遍历并哈希全部内容

生产改动只在 IR 指纹编码入口：将完全相同的 V27 字节流经 4 KiB 缓冲送入既有 FingerprintBuilder，未更换 SHA 算法、字段顺序、标签或位置身份。原 29,038 B Vec 编码器及两个标签 helper 冻结为等价 oracle，覆盖 90 种指令、26 种 Type 变体。非作者复跑 42 项原控制并增加 2 个外部 consumer，涵盖跨 4096 B 边界、Unicode/NUL 和真实 Typed 输入。

它消除完整临时 Vec，没有缓存指纹或减少完整遍历。默认主混合 211.139→203.867 ms，B/A=0.965558，但区间跨 1；完整七请求 wall/CPU 为 1.025822/1.025361。下述完整 CLI 主混合点估计约慢 5.11%，因此不能把局部前端点估计升级为整体提速，本轮不采用。所有受测构建、41 文件 CLI 扩展静态核对及独立复算保留。

### CP35：去掉 Verify 输入深复制，当前核验保持

私有 VerifiedInputs 同时支持旧 Owned 路径、共享 Arc<TypedModule> 和 Arc<TypedProgram>，后者直接借读内嵌 module；CandidatePlan 也共享原 Arc，checkpoint 解码结果移动进入 owner。旧 Owned API 不增加无谓 Arc 分配。每次仍执行原 check_module，检查主体后缀 93,313 B 逐字相同；raw 缓存不持有 Verified、成功位或验证票据，Program interfaces/root mapping 不升级为已核权限。

作者首次 7 项控制有 1 项测试预期错误，原日志保留；改用真实地址形态及精确七轴额度后通过，生产规则未放宽。非作者复跑最终 7 项并增加 3 个 consumer，覆盖 Arc COW/释放、当前额度、目标/schema 和伪造接口。其中复跑的 native 控制实际执行 2 次非作者 Clang 消费，两个 fresh session 的 checkpoint miss/hit 均 Verify=1、输出 42，取消时 Verify=0 且既有输出不变；它们不另计为两项新测试。只保留了最终 warm ELF，不声称重新读到两份 ELF。

默认会话主混合 B/A=1.005305，完整七请求 wall/CPU=1.007575/1.007507，默认内存也未改善；8192 的完整序列峰值 RSS 为 0.954683。完整 CLI 冷请求/内存的局部收益见下节，不泛化至默认持久会话或整体速度。

## CP25、ZIT、Rust 与 Blaze

CP25 的静态可行性不回填性能。前轮 CP22/原485 的完整 wall 比 1.020513、CP26/CP22 的 0.993843、CP22+26+27/原485 的 1.075838 属于相应候选；CP28 只有限定正确性证据，没有独立速度数字。本轮没有重测或改写这些历史结论。

ZIT 原 731 行文件的五组同步机制控制已重跑：稳定双向依赖边与读游标、结果相等截止、确保上游当前、DAG 调度去重、动态旧边裁剪。1100 次切换两种各自无环方向会积累高度并触发 103 次 cycle 警告，说明固定高度阈值不能承担编译器递归判定。控制仅覆盖同步数值路径，不扩称 DOM/异步或编译性能。

可迁移的核心是稳定 owner、真实语义结果面和事务发布。ZIL 当前 driver 的实际依赖仍观察完整实现身份，文件 Parse 之后仍有全项目阶段；仅增加队列或反向链不会自动让 Types 少做。现有 resource_effects 已有 caller worklist、去重和结果相等截止，不能再将这部分作为新发明。Rust 红绿查询强调结果等值与实际依赖读取顺序；稳定函数身份、签名/布局/effect/body 分面、真实读取依赖、负查找与插入重排的处理仍需工程落地，不能称 CP25 已完成。

Blaze 当前架构包含常驻函数查询数据库与代码生成，不宜仍只描述为 rustc 外层包装。函数代码缓存的稳定键还需要后端、优化、目标、调试、overflow、函数路径和泛型 crate 身份；磁盘缓存主要保存机器码、重定位、unwind 与行表，不等于保存完整分析结果。跨编辑的磁盘复用与同一 daemon 中未变函数复用应分开。相对函数体位置和迟绑定 anchor 能缓解插行导致的位置失效，但全文件解析/anchor 重建仍有成本。逐函数 LLVM 还可能影响跨函数内联，需同时观察编译和产物运行成本。Blaze 的默认 Cranelift、LLVM 实验与我们的 LLVM-API O0 也不能直接同口径比较。

外部一手资料及具体映射见 [COMPILE7-REFERENCES](COMPILE7-REFERENCES.md)。外部项目的平台、后端、常驻内存、冷启动与运行成本口径不相同，其公开倍数未用于推导 ZIL 收益。

## 已定位的下一处成本：只交静态结论，尚未实施

两位代理分别完成 `TYPED-FINGERPRINT-CALLMAP.md` 和 `IMMUTABLE-FINGERPRINT-FEASIBILITY.md`。对同一最终 runtime TypedModule，成功项目 compile_path 冷路径有 2 次完整指纹计算，整个 Types/Analyze 查询命中及磁盘 checkpoint 路径各有 1 次；直接 compile_source 冷路径为 3 次，而单文件 compile_path 仍为 2 次。CT 等其他 owner 可另有计算，不能把这些数称为整个请求总数。Lower/emit/bindLir 读取 Verified 已存指纹，不再重算 Typed。

有条件可研究私有不可变 raw owner 的惰性纯数据指纹，但必须由实际内容计算，禁止接收 CandidatePlan/wire 自称的摘要；Analyze 原 preflight 和逻辑计费、Verify 原检查点前后全部规则/当前额度仍保留。Arc COW 与 owner 不可变性是前置，较晚验证失败留下纯指纹也不能变成成功权限。checkpoint 每次解码的新 owner 不自动得到跨请求复用。这需要修改 checker 的取指纹位置，不能再宣称其主体逐字不变。该方向本轮仅静态分析，没有实现、测试、计时或预估提速；不以调用次数推算性能。
