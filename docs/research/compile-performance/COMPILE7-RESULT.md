# zil 编译7：增量编译专项记录

日期：2026-10-31。状态：CP29–CP33 完整实验已完成，CP34/CP35 施工中；本页将随本轮最终交付更新。所有数字均为实际冻结实现的测量，不是预计收益。当前准备合流的生产源码仍为 CP28 基线；本轮未写 main。

## 当前结论

CP25 没有独立性能对照，它仍是稳定 owner、事务采边等机制的可行性设计。ZIT 的依赖维护、确保上游当前、结果不变停止传播有参考价值，不能把这些机制控制当作 ZIL 编译提速。

本轮已经实际实现并审核四个独立增量候选。CP29 的有限 Types memo、CP30 的无 active 查询快读、CP32 的有界部分 Types 留存均未建立完整净收益，保留源码和负结果，不默认采用。CP33 消除了公开编辑后由剩余预算身份造成的无关 Parse 失效；公开编辑和完整七请求序列有有限正收益，预先冻结的四请求主混合仍存在跨过 1 的探索区间，继续保留为候选。当前进一步将成本调查落到 TypedModule 指纹的完整临时编码与 Verify 输入深复制，分别实施 CP34/35，不提前叠加。

## 正式会话口径

所有候选各自与同一 ee72 基线配对，沿用原 210 语料的五类样例：tree4x2、tree32x8、tree256x8、tree1024x8、retained。语料权重预先冻结为 0.05/0.15/0.30/0.30/0.20，没有因 Types memo 的适用范围筛掉不利样例。

每个进程执行 cold、unchanged、private、public、restore、private_again、restore_again 七个请求。主混合只用前四种，权重 0.10/0.35/0.40/0.15；后三种恢复请求单列。默认 query 容量与 8192 分别报告，不混算。

每候选完整测量 200 个序列、1400 个编译请求，另有 20 个不计分控制序列，即 140 个持久请求与 140 个 fresh-session 对照。五个 ABBA/BAAB 区块内先求同 arm 两次观测均值，再取各绝对成本格的五区块中位数，最后按固定权重汇总 A、B 并相除。没有平均速度比，也没有从不完整窗口挑选样本。

主计时覆盖完整 `compile_path` 到 Verify，包括当前项目发现和读取；每个请求确实重新 Verify。编辑文件复制、session 初始化、报告成本另外保存，完整七请求进程的 wall/CPU/maxRSS 也保存。**这一口径不含 LLVM 发射、优化、对象文件和链接，不是全 AOT 或 Rust 对照。** 控制比较报告、诊断、输入、源文件与接口观测，不冒充新的全 Typed/native oracle；后者由候选限定正确性证据分别说明。

五区块配对重采样区间只是共享宿主上的探索统计，不是修改后的 product-gates 或总体保证。CPU/RSS 来自七请求进程，不能硬分配为四请求加权混合的 CPU/RSS。加权 RSS 指每类进程峰值中位数的描述性加权值，不是同时运行进程树的实际峰值。

### CP29 与 CP32：机制命中并不等于总成本下降

CP29 在 tree256 私有编辑中确实复用了 2305 个函数，只检查 5 个；但最大语料超过其整体 64 MiB 条件，未留下 memo。其默认主混合仍慢 7.07%，不采用。

CP32 把“全图语言适用性”和“存得下哪些模块”分开，稳定顺序保留整个模块，超过容量的模块跳过；预算保持 64 MiB。先选择再复制，并在完整 Core/环境相等后复用源权重收据。独审实际覆盖保留集合 812→805→812、未保留末模块公开环境改变、完整 Typed 与 fresh 相等以及失败保持旧 epoch。

在原 210 的 tree1024x8 中，CP32 实际保留 773 模块、67,058,682 B；私有编辑复用 6940/9222 函数。该语料 private 成本在 default/8192 分别下降约 2.83%/7.32%，但公开编辑仍全量检查，冷请求和内存成本增加。五语料默认主混合约持平且加权峰值 RSS 增 20.20%，8192 主混合慢 6.03%，保持 NoGo。前述 812 模块属于另一个容量压力控制，不能冒充原基准结果。

### CP30：图不变量成立，整体收益未建立

只在没有 active 求值时直接读取已发布快照；active 非空保持原 DFS 与错误顺序。独立 DAG/失效/Arc 隔离控制通过，但默认完整主混合未下降。其首次正式窗口在 114/200 序列后遭遇 live 目录清理 `ENOTEMPTY`；原 traceback、114 条前缀和显式 Incomplete_NoScore 保留。失败原因未充分归因，没有归罪编译器，也没有复用该前缀计分。之后新 `/tmp` 目录的完整计划、控制与 200 序列从头执行并单独计分。

### CP33：公开编辑失效范围得到收窄

前部文件的公开编辑增加 token，会改变后面文件的剩余 max_tokens/max_nodes。旧 Parse 查询键绑定这两个余额，未改文件因此可能失效。CP33 保存真实 ParseUsage，稳定 Parse 身份只分离这两个可回放额度；命中前要求当前余额足够，不够则回原解析路径。其余九项 Limits、规则、源、位置、路径、FileId/ModuleId 继续绑定；后续 CT/Types 等阶段仍使用完整身份，项目当前读取/导入歧义/累计计费照常执行。

独审复跑 61 项原控制，并新增 3 个外部 consumer，包括 81 组联合预算边界；真实覆盖 Parse 命中但当前 CT 应失败的相同错误及 Span，跨入口预热、当前导入歧义与 fresh Verify。另有第二位代理仅静态复核。没有增加磁盘 AST 缓存或恢复前轮 CP22 的磁盘费用。

公开编辑的五语料加权耗时 default 为 213.293→177.084 ms，B/A=0.830239；8192 为 271.262→187.541 ms，B/A=0.691366。默认完整七请求进程 wall/CPU 分别为 0.933959/0.933983，五个区块均低于 1，其探索区间也低于 1；同时 cold 成本点估计增加约 4.74%。因此可以报告有限公开编辑及完整序列收益，不能把这些有利子项替换为预先冻结的四请求主混合，或直接宣称全 AOT 提速。当前不默认采用。

## CP25、ZIT、Rust 与 Blaze

CP25 的静态可行性不回填性能。前轮 CP22/原485 的完整 wall 比 1.020513、CP26/CP22 的 0.993843、CP22+26+27/原485 的 1.075838 属于相应候选；CP28 只有限定正确性证据，没有独立速度数字。本轮没有重测或改写这些历史结论。

ZIT 原 731 行文件的五组同步机制控制已重跑：稳定双向依赖边与读游标、结果相等截止、确保上游当前、DAG 调度去重、动态旧边裁剪。1100 次切换两种各自无环方向会积累高度并触发 103 次 cycle 警告，说明固定高度阈值不能承担编译器递归判定。控制仅覆盖同步数值路径，不扩称 DOM/异步或编译性能。

可迁移的核心是稳定 owner、真实语义结果面和事务发布。ZIL 当前 driver 的实际依赖仍观察完整实现身份，文件 Parse 之后仍有全项目阶段；仅增加队列或反向链不会自动让 Types 少做。Rust 红绿查询强调结果等值与实际依赖读取顺序；Blaze 的常驻函数查询、机器码缓存与相对语法位置/迟绑定 anchor 提供实现参考。稳定函数身份、签名/布局/effect/body 分面、真实读取依赖、负查找与插入重排的处理仍需工程落地，不能称 CP25 已完成。

外部一手资料及具体映射见 [COMPILE7-REFERENCES](COMPILE7-REFERENCES.md)。外部项目的平台、后端、常驻内存、冷启动与运行成本口径不相同，其公开倍数未用于推导 ZIL 收益。
