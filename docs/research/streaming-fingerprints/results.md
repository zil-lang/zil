# 093 裁决：停止两个错误前提，保留有明确接口的研究路线

本轮达到一个有限而关键的裁决点。它不是图切割算法进入生产安全核，也没有取得
相对 Rust 的产品级性能突破。

1. **完整显式联合关系不能无条件消除状态积。** n 个独立二态分量若所有组合
   可达，输出本身就有 2^n 行。内部切割不能降低同一显式输出接口的这个下界。
2. **Lab 0.5 的重复调用展开不是当前生产弱点。** 直接复用原 0.6 实现，再用
   真实生产源码观察到双调用 DAG 深度 0–64 的函数体求解访问线性增长。
   既有有限效果摘要与 080 调度已解决这组重复展开。
3. **相同身份的流式 SHA 候选 H 为 NoGo。** 功能与字节身份通过，但正式完整
   成本出现真实生产 cold 和大项目整进程回退，无稳定整进程收益。生产源码已
   恢复冻结基线，原候选提交和完整 patch 保留。

实际工具链为 rustc 1.99.1，外部 clang 包为带日期/`exp1` 标记的 23.1.5 开发
构建；它不是“官方最新稳定 LLVM”的声明。完整版本输出和宿主信息留在身份收据。

计数版与计时版分开构建。完整控制包含 128 次 B/H plain/count 编译请求、
各 142 次旧 089 guard 请求、16 次实际原生执行；全部通过。成功完整请求每次

3 个为 SHA 已知答案、Debug/Unicode 和任意分块等值测试；driver 跨单源/项目

正式窗口 `draft20-093-exclusive-001` 由 root 协调其他构建/验证暂停；实际 UTC
为 2026-10-25 06:57:19 至 06:58:40。固定 128 进程、512 请求，其中 16 进程为

全部 32 个 API 单元与 8 个整进程单元见 [完整表](ALL-CELLS.md)。区间仅为
7 对样本的预登记探索性 bootstrap，未做多重比较校正，不能外推普遍性能定理。

| 保留的回退 | 配对 H/B 中位比 | 探索性 95% 区间 |
|---|---:|---|
| 真实 slices-main / Verify / cold | 1.123659 | [1.030189, 1.297980] |
| modules512 / Verify / 整进程 | 1.023721 | [1.011815, 1.062166] |

真实 owned-main Build 整进程比为 0.996930，slices-main Build 为 0.964131，
两者区间都跨 1。所有 8 个整进程单元都没有区间完全低于 1 的改善证据。
唯一 API 局部区间低于 1 的单元是 64 模块默认容量 32 的 cold，配对比为
0.945581，区间 [0.882955, 0.995835]；它不抵消生产 cold 与整进程回退。
全部 40 单元中 1 改善、2 回退、37 跨 1；真实 owned/slices 的 20 单元中
0 改善、1 回退、19 跨 1。按预登记维持 NoGo，不通过事后挑选“生产子集”改判。

512 模块父进程 VmHWM 中位值由 26,080 KiB 到 25,060 KiB，方向符合省去大型
格式字符串的目的，但只是父进程描述性观察，不能当成生成程序运行内存或包含
clang 的整体峰值。H 仍做相同 SHA 字节与查询工作，不是消除了跨阶段身份成本。

真实计数进一步限定下一步范围：512 模块 cold 有 4,631 次 SHA，输入
4,321,009 字节，其中 raw Debug 3,573,547 字节；unchanged 虽已无 raw Debug，
仍有 2,573 次 SHA、468,838 字节和 5,150 次 snapshot lookup。候选 H 对后者
不减少工作。今后任何身份纵向共享需把新增记录构造、资格核对、保活/释放也
计入总成本，不能从本轮字节比例直接推导 CPU 耗时比例。

## 图结构命题与设计接入

[结构边界](STRUCTURAL-BOUNDARY.md) 给出受限异步积定理的双向证明：初始是积、
每条转移只读写一个分量、没有共享 PC/guard/配额/错误出口约束时，可达集合等于
局部可达集合之积。两二态分量的全部 2,304 个系统与 36,864 个局部坏谓词查询
由独立全局队列和局部 Warshall 闭包核对。它不是任意 CFG/堆/别名的普遍安全证明。
共享 guard、提前 abort 和删除唯一外部种子后的 SCC 自支持反例全部保留。

因此局部安全查询可以有合法的分解机会，但须先声明观察接口与真实支持；
控制、别名和错误不能只因数据字段分开就消失。责任唯一性约束每条真实执行中的
守恒，不自动意味着只有一个静态释放语句或所有跨对象状态独立。

[设计反馈](DESIGN-FEEDBACK.md) 详列原包 147 测试函数、511 程序/12,168 查询
的重放，以及 18 个真实生产源案例和额外 16 个项目请求。两种递归前后写的实际
signature/contract hash 相同、implementation hash 不同，明确说明现有普通
函数合同还不是一般有序 prefix/返回可达性接口。现有实现依赖保持，所以未据此
发现不安全缓存；本例阻止缺少新合同的 contract-only 优化。

下一轮有意义的研究契约是：以生产真正需要的危险 prefix、正常返回和后状态
观察为范围，保留真实别名/控制支持，先核对完整接受集合，再选择因子化表示。
已有 U/K/D 直接沿用原 Lab，不再次重建为“新突破”；当前生产资源写效果与独立
Verify 不因研究类比而替换。

## 失败透明记录

三次研究工具故障均有原源码/命令/输出，未擦除，也不算成编译器语义反例：

- 首次有限模型 runner 重复消费初始迭代器，导致全局工作队列为空；修复后
  全部系统检查通过，原失败仍在 `structure-001/`。
- 首次计数构建的 `let ... else` 右侧块缺括号；冻结 source 和编译错误保留在
  `frozen-001/`，修复只影响计数注入。
- 第二次计数 H 错把 cfg(test) 的旧摘要 oracle 当生产方法，导致
  `raw_debug_calls` 为 0；计数门当场拒绝继续。限定生产方法后只重建 H-counted；
  其他三个二进制的所有编译输入逐字相同，带收据复用。旧失败在 `frozen-002/`。

最终 `frozen-003` 功能与计数门全部通过后才正式取样。原始归档包含失败、
原 Lab ZIP、四种最终冻结源码/bin、计数、全部正式样本、所有实际命令与阶段产物。
仅删除可重建 Cargo target，清理前保留实际单测可执行文件，并写逐文件清理收据。

## Rust 四目标与停止位置

| 目标 | 093 实证 | 本轮结论 |
|---|---|---|
| Rust 同类安全 | 原 Lab 重放、生产最近正反例、H 不改变接受/诊断/Verify | 不构成全语言安全证明；安全核没有替换 |

| 至少一项实质突破 | 输出下界停止错误强路线；重复调用生产前提被实测纠正 | 阶段研究裁决完成，尚无原创图定理或产品级净突破 |
