# 050：区域、联合边界关系与重组

## 当前结论

**已有可执行 Rust 原型和独立慢 oracle；尚未接入生产 TypedIR，尚未证明 ZIL 编译性能优于 Rust。** 这是有限状态关系的研究切片，不是语言功能完成项，也不是把 046 的工作列表改名。

原型真正消去了区域内部变量，并在边界保留联合关系。2048 个随机模型、256 次非单调表编辑和 18 个固定形状均通过完整输出关系对照；另有闭包、替换、trait 共同变量、预算、篡改和失效反例。初次冻结版本的测试函数共 16 个，不计作 16 项生产编译器能力，更不把随机样本计成新增语言用例。原始身份、命令和输出见 `evidence/impl/050/author-checks.json`。独审后的 050-R1 另增加 3 个缓存预算回归，修前/修后记录在 `evidence/impl/050/r1/`。

固定 release 实验支持一个有条件的方向：窄链与带状状态图可以显著减少中间关系；小状态、密图和宽观察边界不能统一受益。链 16 的单体精确关系基线完整操作为 12.4772 ms，区域法为 0.05731 ms；密图 12 则从 0.10062 ms 退化到 0.53706 ms。这里的对照是**同一个研究程序中的单体关系连接**，不是生产 ZIL、Rust、Polonius、SAT 或 BDD。完整形状、离散度和阶段成本见 `RESULTS.md`。

**性能身份保持历史归属：** 上述数字及1512条样本只对应 `bef7d9f`。050-R1 修复后源码已不同，本轮没有重新计时，不能将旧数字归于当前 head。冻结 `CONTRACT.md`、input-manifest、配方和原采样保持原样。当前预算补充规则见下文，不回写历史冻结合同。

## 算法与可证明范围

设原始模型为有限变量上的约束合取：

\[
\Phi(V)=\bigwedge_i F_i(S_i).
\]

对一个区域 R，内部变量 I 只在区域内出现，边界 B 包含所有跨区变量和必须观察的结果。摘要定义为：

\[
\Sigma_R(B)=\exists I.\bigwedge_{i\in R}F_i(S_i).
\]

摘要是一组完整的边界元组，不是每列的 may-set。两个区域的组合是在相同变量身份上连接，再对不再需要的内部变量投影。若同一变量两侧被错误地改成两个独立变量，就已经破坏合同。

当前实现使用确定性的 min-fill 顺序，每次消去一个非观察变量 v。收集所有包含 v 的活动关系，将它们连接成 J，再用 `exists v. J` 替换这些关系。其它活动关系不含 v，所以可以把存在量词移过它们。由此保持不变量：**已消去变量上的原式投影，与当前活动关系的合取完全相等**。最后所有剩余变量恰好是观察集，得到完整答案。空关系与只含一个空元组的零变量关系严格区分。

每个投影行保存一个被消去值。按消元顺序逆序恢复时，该节点的边界变量已全部恢复，因此可以选出相容的内部值。最后逐个检查所有原始约束。这个恢复逻辑对每个输出行给出可行见证。

**见证检查不证明答案完整性。** 删去一个坏结果之后，剩余见证仍可全部合法；测试中直接演示了这一点。完整性现由独立枚举 oracle 对照，不能将这套见证检查接进生产后声称已经完成全路径安全证明。未来若用局部证书，核验器还需独立检查覆盖全部原始约束、切口变量身份和每个区域摘要的双向等价性。

独立 oracle 不调用候选的 join、project、计划或缓存。它把原始表解码成值元组，按变量顺序枚举，只在一个原始约束的所有变量已赋值时剪枝；所有完整可行赋值直接投影到观察集。它是正确性参考，不是性能基线。

## 为什么复杂状态和闭包必须保留联合边界

研究模型的 a、b 最初都 Live。f、g 创建时捕获描述；一次调用要求目标 Live，并将它 Closed。最终清理关闭仍然 Live 的目标。两个模型如下：

| 模型 | 捕获的联合关系 | f 的边际 | g 的边际 | 调用 f 后再调用 g |
|---|---|---|---|---|
| distinct | `(a,b)` 或 `(b,a)` | `{a,b}` | `{a,b}` | 两次正常，最终无剩余目标 |
| alias | `(a,a)` 或 `(b,b)` | `{a,b}` | `{a,b}` | 第二次失败，最终清理另一个目标 |

边际完全相同，行为不同。观察关系保留捕获目标、两次调用后的 a/b 状态、正常/错误结果、失效阶段与最终清理效果。第三个 mixed 模型包含两类执行：存在正常执行不能推出安全；安全问题是是否存在可达坏结果。

Owned 闭包模型进一步区分 Outer、Environment、Closed，覆盖创建转交、从未调用、两次读取、消费调用和再次调用。每条完整执行恰好产生一次关闭效果。有限协议中的 Consume 直接关闭资源；它**不宣称复现一般 ZIL give ABI、退出展开或实际 FnOnce  lowering**。跨闭包存储、任意循环、异常展开、取消、并发和重入均没有在原型中建模。

时间先后由不同版本的变量表达，不能把同一个变量的 Live 与 Closed 简单并集后用于任意时点。静态身份替换反例还要求旧捕获继续指向旧定义；它不引入运行时世代计数、租约或旧 ZIL 架构。

## 非单调编辑与复用

计划仅依赖域、约束 scope 和观察集。内容编辑时，直接逐表比较输入；改变一个输入，就重算所有依赖它的摘要。旧结果被替换，不做并集。scope、域或观察集变化时重建整个计划；上下文身份变化时全部失效。所有新结果先放在暂存状态，完整成功后一次发布；预算失败保留旧状态，不能留下半更新缓存。

实际反例把同一闭包体的 Preserve 改为 Consume：旧 normal 结果消失，新结果包含第二次调用错误；未受影响的创建节点仍复用。另有 256 次随机删除/新增关系行及失败事务测试。这里的缓存只在进程内服务模型，没有长期缓存协议、磁盘命中或生产可信复用声明。

050-R1 补充：rows/scope 上限同样检查本次复用的每张摘要和最终输出。复用前先检查形状，并按复制的关系行和消元见证条目计入既有 work 限额，之后才克隆该节点。新状态按拓扑顺序构造；脏节点直接重算，避免先复制可能超过新上限的旧表。任一步失败均不发布，新上限不会使旧缓存被破坏；恢复原预算后仍可复用。新增回归分别覆盖最终答案和内部摘要的 rows/scope 收缩，以及复制工作量超限。限额仍是有限研究工具的容量规则，不是生产语言接受性规则。

kill 转移在固定模型的 powerset 格上可以单调，例如 `F(S)=(S−K)∪G`。编辑 K、G 或动作语义改变的是函数本身，旧不动点或旧摘要不能因此直接当成新结果的下界。这两个层次不能混称“kill 非单调”。

## trait、替换与特化的边界

最小反例是两个共享 T 的目标：A 仅在 `T=0` 成立，B 仅在 `T=1` 成立。分别存在化都为真，合取却无解。因此摘要要保留替换关系，以及共享变量是否相同；布尔“目标成立”不足。第二个模型保留 T/U/V 的相关约束。候选表修改与上下文修订的实验验证旧响应失效。

当前 `_zil_design.md` §18 明确不默认提供重叠 impl specialization，且代码生成专门化不得改变 impl 选择。原型中命名为 specialization 的测试只是**有限候选选择表被修改后的失效反例**，并未实现或建议暗中开启此语言功能。必须区分：

| 问题 | 050 实际覆盖 | 尚未覆盖 |
|---|---|---|
| 共同推断变量 | 精确联合替换关系 | 一般一阶类型项、关联类型规范化 |
| 候选集合变化 | 表内容和上下文修改后失效 | coherence、重叠 impl 的合法性 |
| 代码生成单态化 | 无实际实现 | 实例图、布局依赖与代码体共享 |
| impl specialization | 仅研究候选表反例 | 现行 ZIL 不默认支持；需要独立设计决定 |
| 递归目标 | 无 | 归纳/共归纳、宇宙、区域义务、循环栈、溢出 ambiguity |

Rust next solver 的可吸收之处是带约束的 canonical response、共同变量映射、外部区域约束和严格缓存上下文。不能把有限表模型等价性提升为对该完整求解器的替代。主源定位和具体启发见 `SOURCES.md`。

## 宽度、密度与不能压缩的边界

最大域 d、消元 separator 宽度 w 下，显式摘要最多 `d^w` 行；消元时的 bag 还包括被消去变量，可能物化 `d^(w+1)` 行。最后 q 个观察变量也可能有 `d^q` 条答案。当前实现还为增量实验保留所有摘要，因此总常驻表并非单张最大表。排序、哈希索引、计划构造、恢复和最终检查都有额外成本。

这个指数描述是显式表表示的最坏情况，不是对 BDD、SAT、统一/线性代数或所有符号表示的普适下界。一个紧凑等式可能描述很宽的关系；同样，也不能保证任意相关关系都有紧凑表示。应先利用语义结构，再以实际表密度和宽度决定是否物化。

密图反例尤其重要：min-fill 只看到图结构，忽略各约束的选择性。本例候选先生成 514 行中间关系，单体连接只需 33 行。因此“边少/宽度低”不是唯一指标，更不能用最后答案很小推断中间关系也小。预算返回明确 ResourceLimit；测试验证大中间表不会被截断成成功或空关系，独立枚举可作为有自己的预算的显式回退。

## 生产潜在入口与下一步

当前真实入口是 `crates/zil-verify/src/resources.rs`。`check_function` 在 CFG 上重复执行 transfer、克隆状态并合并；`merge` 对 debt/fresh 按槽并位，对 Desc 根集合和 newer 顺序边做集合并。`clone_state/state_cost/merge` 成本随状态槽、根和顺序边增长，newer 在密集资源顺序下可有二次数量的边。这里是机制上可定位的候选成本，**本轮没有 profiler 证据证明它已成为当前程序的 CPU 主热点**。

第一处可考虑的接入边界是：无挂起、无未知调用、非逃逸、边界中 live Managed/Desc 及创建/调用/清理相关状态数量有界的结构化区域。将区域内部状态消去，只保留跨区责任、目标身份、顺序和出口结果。这比为每个块携带所有内部对象状态更有机会减少工作，但也可能增加关系密度。

下一片应先做生产 TypedIR 的只读抽取和分布测量，给出实际 bag/边界宽度、各区域输入/输出行数、状态克隆/merge 次数和总检查占比。随后用真实源码正反例验证模型抽取是否保留全部出口；影子比较不得改变接受集合。只有真实语义图表现出低宽度且总成本净下降，才值得批准生产写集。分析器摘要仍是未核信息，Verify 必须独立重建；想减少 Verify 成本还需独立的局部等价核验，不能共用本研究 solver 绕过核验。

对 trait，应等一般求解图真实存在后再考察目标/SCC 的切分。当前可以先固定返回共同替换和约束的接口，避免未来只有 bool 响应；不应现在为了缓存或“图切割”建一个全面通用框架。
