## 固定八单元

| 输入 | 目的 | 入口 |
|---|---|---|
| tiny | 小请求与固定开销 | Verify |
| modules512 | 已存在的多模块查询闭包家族 | Verify |
| forward128 | 按被调先定义顺序的资源调用链 | Verify |
| reverse128 | 调用者先定义的同一资源调用链 | Verify |
| owned-main | 既有完整拥有组件消费者 | Verify、Build |
| bytes-main | 既有真实字节存储消费者 | Verify、Build |

每个进程按 cold、unchanged、private_edit、public_edit 四次真实 `compile_path`
执行。编辑通过增加私有/公开未使用函数改变相应输入；这属于固定的接口失效
工作负载，不能宣称覆盖所有实际编辑分布。递归、交换描述参数、词法别名及
先消费后访问保留在 `impl097_resource_effects` 功能控制，不以大链替代真实程序。

每轮以四臂轮换顺序执行，四轮后反向；一轮预热、七轮保留，共256进程、1024
请求。完整进程时间包括记录和销毁；API时间包含发现、文件读取、解析、身份、
Types、Analyze、Verify及选定Build链接。源编辑在API计时外，包含于进程计时。
cold指新session，不清OS缓存。VmHWM只描述父进程，不包含clang子进程峰值。
root明确授予独占窗口并固定CPU后才能取样。禁止观察结果后增加轮数或挑选子集。

## 正确性与工作计数

正式取样前四臂比较完整报告中的安全观察、接口、查询事件和所有阶段产物哈希；
计时/计数版本也必须一致。每个成功请求恰好执行一次独立Verify，active query
归零。两个Build消费者各四种情景在四臂执行，合计32次原生输出对照。

复用089的真实请求防护控制，覆盖取消、失败、缓存污染、配置变化和N/N−1。
B必须与B0逐项相同，AB必须与A逐项相同。A登记了不同的实际逻辑计费，所以
仅analysis预算二分/边界记录允许不同；其他记录仍四臂相同，分别保留每臂
精确N、N−1及恢复请求。默认最大限额不增加。

计数版直接记录Types函数体访问、Database调用/DFS出栈/快路返回/查询表读取/
resident active探测、Analyze和Verify资源函数体访问。两后者必须四臂相同。
计数不是CPU耗时，手工Core图不是生产源码证据，模型测试与完整请求数分别报告。

## 裁决与停止

任何安全观察/接口/产物不一致、缺独立Verify或留下active query，立即停止相应
候选。所有失败和样本保留。分别报告A/B0、B/B0、AB/B0及AB/A、AB/B的完整成本；
七对样本用固定种子探索性bootstrap，不作多重比较校正，不当成普遍性能定理。
任何单元探索性区间下界大于1列为回退并按原提案维持该候选NoGo；无回退仍需
结合真实完整请求收益、独立审核与root裁决，不能只凭大链加速准入。

可重建Cargo target逐个构建、在保存实际二进制及收据后清理；源码、原始日志、
逐请求报告、全部IR与正式样本仍保留。实际准入不能在本契约阶段提前填写。
