# 131：删除效果后的有限边界重算

## 为什么换问题

101已证明当前有限Desc参数效果扫描可以化为种子可达性，123也已证实只降低初始化transfer次数没有建立整编译优势。本单不重做冷求解器，而针对编辑期间**删除**写种子/依赖后的精确复用：递归环不能拿上一版自己的真值证明自己仍然为真。

这与递归Datalog的删除/重推导问题相关，不是新的通用图理论。参考Motik等（AAAI 2015，DOI 10.1609/aaai.v29i1.9409）及Hu等（AAAI 2018，DOI 10.1609/aaai.v32i1.11554）。仅依据两文的出版页面摘要区分DRed/B/F和计数法限制；本实现不是其完整算法复现，也没有把论文的加速数据当作ZIL结果。

## 精确命题

令旧/新图为G0=(V,E0)、G1=(V,E1)，直接写种子为S0、S1；R0为旧最小可达集。节点是稳定的(FunctionId,Desc参数位置)，不是运行时地址/世代。

D取每条变化边的**目标**与每个变化种子节点。A=Reach(E0∪E1,D)。定义新边界种子

    B = (S1∩A) ∪ {v∈A | 存在u∉A，u∈R0 且 (u,v)∈E1}
    R1 = (R0\A) ∪ Reach(E1限制于A,B)

该式恰为新图的最小可达集，不仅是安全上近似。

证明分三步。A对新旧所有后继闭合，所以任何受变更影响的路径不能离开A；外部种子与边未变，外部可达性保持。新可达路径进入A时，要么起于A内新种子，要么第一次通过新边从外部可达节点进入；这正是B。反过来B的每个元素都有真实新图支持，从B沿内部新边传播得到的每个事实也有支持。两向包含给出等式；从B开始而非从旧A真值开始，保证无种子环为空。

例：A→B→A只有直接种子A。删种子后若将旧A、B当边界，会错误保活。实现先清内部事实，仅保留真正外部支持，结果二者都false。另一条外部到B的路径仍存在时，环应继续可达，不能一律清零。

## 实现及失败原子性

批次同一边/种子末写覆盖，先对比旧图去掉净无操作。旧邻接表不克隆；增边存于稀疏overlay，删除边在新传播时过滤。BTree集合仅保存脏锥及输入变更，不每次清空全V数组。所有可能返回Budget/InvalidNode的位置都在发布之前；发布的访问额度也提前一次扣足。失败后邻接、反向邻接、种子和事实全部与旧状态一致。标准Rust分配失败的abort不在这个返回式回滚合同内。

work是研究引擎的逻辑访问计数，不是生产ZIL的预算、CPU指令、时间或内存字节。树集合比较与分配成本另有对数/常数开销；不得据work直接计算编译加速倍数。

## 成本边界与反例

更新工作取决于编辑量、脏锥顶点、脏锥出边和入边；BTree带对数因子。链尾删一边只影响一个点，而删链首唯一种子影响全部V。更强反例：一个脏节点有N条外部入边，脏节点数虽为1，边界扫描仍是O(N)。完整建图、AST来源提取、完整结果物化均未消失；完整Writes若每次重建/摘要仍至少访问其输出。固定节点宇宙下的算法不能自动解决新增函数/签名变更后的稳定身份问题。

## 和生产编译器的边界

`source_anchors.py`只对明确可翻译的四函数、两Desc参数族建立端口边，包含参数交换、同参别名、递归和种子删除；逐端口读真实TypedIR的Fn/FnMut，并经真实Verify和原生执行核对。它不是任意Core AST提取器。新引擎尚未插入CompilationSession，独立Verify没有复用Types证明，默认额度/接受集均未变。增量无命中时的建图成本、raw_digest、跨版本身份和整个check/build回归尚未验收，因此生产准入为false，整体性能为NotMeasured。
