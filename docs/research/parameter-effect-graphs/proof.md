# 101：当前有限写摘要的关系表示

本证明针对冻结schema17的`zil-types::resource_effects`转移。它不证明完整
语言安全，不改变Verify，不对任意程序状态关系或物理分子图声称同构。

## 1. 量、观察与边界

每个参与函数f的事实为`(f,i)`，i是它的一个Desc参数位置；事实为真表示
当前保守源扫描器认为函数可能通过该参数写资源头。W_f是这些位置的集合，
最终消费者仍得到全部函数的Writes，包括没有写的空条目。没有删除某个
消费者尚未声明“不观察”的信息，没有把独立边际冒充完整联合状态。

每次扫描的局部Origin是当前局部名字可能来自的入口Desc参数位置集合。
设D_f为该扫描中不依赖callee摘要的直接写，O_(c,j)为调用点c第j参数的
局部Origin。若c直接解析到g，只有签名中Desc参数位置j消费W_g；未知调用
按原规则把实际参数Origin直接加入D_f。没有参与求解的callee没有写事实，
与旧扫描查不到摘要时的空集合一致。

## 2. 局部Origin为何不依赖W

冻结源码中摘要唯一读点是`Call`分支的参数写判断。该读点只决定是否调用
`record(origins)`；record只修改writes与工作预算，不修改作用域。分支访问
顺序和局部循环收敛条件也不读取writes。以下论证针对额度足以完成的执行；
预算不足的行为在第5节单独处理。

| Core构造 | Origin规则和独立性 |
|---|---|
| 参数、Name、Binding、Sequence | Desc入口给单元素集合；名字查询、绑定和顺序表达式只复制或并这些集合 |
| Name赋值 | 按原规则并入既有局部Origin；右值Origin不依赖W |
| 非Name赋值、place、Member、Index、Slice | 保留原place来源及对子表达式的访问；普通资源payload成员读取是Copy快照，不产生Desc来源 |
| If表达式 | 两分支Origin取并；条件和两个分支都按原保守顺序访问 |
| If、IfLet、Match及嵌套块 | 保留词法作用域、pattern空绑定及全部可见分支；不增加路径独立性假设 |
| While、ForRange、WhileLet | 仍对作用域Origin做原有限并闭包；循环稳定条件不含W，所以访问序列和最终Origin独立于W |
| Call | 实参Origin独立于W；直接callee解析只依赖作用域是否存在名字、imports和签名；返回Origin仍为空 |
| ByteBuffer primitive | 原`reserve/push/view_mut`第一个实参为直接写种子，返回Origin仍为空；其余规则不变 |
| 局部Closure | 参数按原规则遮蔽为空Origin，访问可见体、保留捕获的外部Origin；不假设闭包一定被调用 |
| Ascribed、转换、CompileTime、Try、Unary | 沿原规则转发子表达式Origin |
| Binary、聚合、RecordUpdate及其余叶节点 | 原先只访问子表达式或返回空Origin；不读取W |
| foreign声明 | 原先保守写全部Desc参数，加入直接种子 |

局部递归遍历的深度检查照旧。局部Origin循环是入口有限参数集合的单调并，
与函数调用图递归不同。这里“提取一次函数”允许其中的局部Origin循环按
原逻辑迭代；并不声称每个AST节点只访问一次。

## 3. 转移公式和精确关系

由第2节，对任意完整摘要赋值W，单函数转移恰为

`F_f(W) = D_f union union_{direct call c -> g} union_{j in W_g} O_(c,j)`。

这里仅保留签名中Desc位置；同一调用在局部Origin循环内多次被访问时，
O_(c,j)表示原访问序列中这些Origin的并。不同调用点可合并相同端口边，因为
输出运算是幂等并，不会丢失原扫描所保留的任何相关信息。

建立边`(g,j) -> (f,i)`当且仅当某次上述调用关系含i∈O_(c,j)，直接事实
种子为各D_f。布尔图上的从种子可达集合恰等于F的最小不动点：

1. 每条种子或已可达事实沿边产生的事实，分别对应一个直接写或一次合法
   参数替换，因此按路径长度归纳都包含于原最小不动点。
2. 任一满足原转移的闭集必须包含所有种子并沿全部边闭合，所以包含全部
   可达事实。可达集合本身沿边闭合，因此既是不动点，又小于每个不动点。

参数交换成为不同位置之间的边，别名成为一个端口的多个目标边；递归和
自递归只是图环。无种子且不受外部种子到达的环为空，不允许互相支持而
凭空产生写。每个事实从false变true至多一次；队列只在该转换时入队。
建图完成后的传播工作为O(V+E)，完整成本还包含输入扫描、局部Origin闭包、
图构造、摘要物化、分配和整条编译流水线，不把传播上界当编译器总复杂度。

## 4. 原扫描前缀与慢路径

前两轮完全沿当前扫描顺序，只有摘要严格增长才继续。任一轮不增长则已经
达到F的不动点；因为从空摘要按单调并迭代，得到的是最小不动点。

两轮仍增长时，已有摘要S满足S⊆lfp(F)，并含全部直接种子。以S与再次提取
的D作为事实图种子，传播仍得到lfp(F)：最小不动点包含S与D且沿图闭合，
所以不会超出；D的完整闭包已是lfp(F)，所以不会漏掉。重新提取D使慢路径
本身也可用空摘要做独立控制；正常生产调用中它不增加新假设。

慢路径明确outline，原Scan不增加跟踪集合/模式字段。这个源码约束不证明
整binary布局不变或运行成本恰好相等；静态反汇编、同binary负控制及无探针
完整成本测量分别回答机器布局、归因和生产准入问题。

## 5. 预算、失败及作用域

前缀与图共用剩余max_analysis_steps。节点容量、边记录、种子/队列容量和
每次传播在相应分配或操作之前扣费；不足返回Types ResourceLimit，临时图
按Rust所有权销毁，不发布部分Writes。每条实际可反复执行的循环都由输入
边界、局部Origin增长或工作配额约束。取消仍由既有driver的有界阶段检查
负责，不把此片说成支持任意点抢占。

早稳定路径应对所有较低额度保持旧诊断；进入慢路径时阈值可因真实工作量
改变，默认限额不提高。精确N/N−1、低预算后的恢复及取消后恢复必须在真实
源码和局部模型分别核对。方法不能用缓存的安全结论替代每次独立Verify。

## 6. 论文映射与已有方法

Deng/Hani/Ma的[主文献v3](https://arxiv.org/pdf/2408.07818v3)§2.2.2先用局部
因子表示消去长代入链，§2.3.1切口两端保留同一变量身份，§11.3的UP还要求
有方向的边界不变量。本片采用的是“先给局部关系、明确端口身份、再证明
组合等价”的研究步骤；没有套用UP的度数分类、物理小参数增益或范数估计。
FunctionId与参数位置是编译器端口，Origin是保留的参数关联，全部图闭包是
当前布尔观察的精确组合；这个对应是我们另行证明的有限应用。

有限事实与分配律转为图可达性已有[Reps/Horwitz/Sagiv的一手工作](https://research.cs.wisc.edu/wpis/abstracts/popl95.abs.html)。
本片不把该思想或普通队列称为新数学定理，也没有实现完整上下文敏感IFDS。
成果必须由当前生产转移的证明、真实对拍和完整成本决定。

逐项来源、端口示例、实现落点及不成立的外推见[PAPER-MAPPING.md](PAPER-MAPPING.md)。
