# 参数效果图的适用边界与推导

## 为什么可以提前建立边

检查实际`Scan`的状态：scopes只来自参数初始化、表达式来源、作用域绑定/别名并合、循环局部来源不动点。唯一读取callee summaries的位置是Call分支决定是否将参数来源加入writes；它不更改scopes、返回来源或分支遍历。record只更改writes。因此给定合法输入与足够预算，每个调用实参的Origins独立于callee summaries。循环可以重复访问源码，但其退出条件也不读writes。

逐语法结构归纳可得`F_f(S) = D_f ∪ { o | (g,p,o) ∈ P_f 且 p ∈ S[g] }`。空摘要下的writes是D，所有潜在实参来源投影组成P。字段快照、shadowing、imports、未知调用、foreign描述参数和局部闭包沿用现有Scan，不猜测更精细关系。

## 不动点

仅对实际Desc形式参数创建顶点(f,p)。D为初始真节点；每个投影生成(g,p)->(f,o)。从D遍历可达点。每个激活都是直接种子或一条已知规则的结果，因此不超出任何闭合解；最终集合包含种子且对全部已激活出边闭合，因此是最小解。无种子SCC不会因环而产生事实。输出是已有source receiver推断的同一个解，不是新的安全核。

## 成本与反例

图传播最多激活P个节点、访问E条边；建图仍需BTree索引/去重以及源码/局部循环来源分析，不冒称总成本为O(P+E)。记录的work是逻辑计费，不是时间。简单前向链的已有worklist只扫描一次，新图索引可能更贵；反向链已有worklist也通常近似线性，不能拿sweeps的平方退化当成相对生产实现的突破。需要使用多参数递归传播和完整编译请求与当前worklist比较。

## 失效与扩展

若未来返回来源、调用别名或作用域更新依赖callee效果，该证明前提将不成立，必须修改提取或退回旧算法。测试把每种当前Core语法的具体转移与投影解释器做对照，但不是未来所有语义的形式化证明。131的跨请求删除/撤销尚未接入本候选；本轮是每次类型分析的新建图，不能宣称跨版本增量删除已完成。
