## 2. 物理直觉可以落在三个明确对象上

资源身份可以对应带身份的粒子，变量、字段和环境位置可以对应容纳该身份的位置，move/drop/call则对应事件。在当前有限模型中，每一资源身份的清理责任必须有确定去向：仍由一个合法载体拥有、已按合同转交，或已清理。守恒约束可以排除复制和丢失责任，减少表示中的非法组合。

这还不足以证明内存安全。借用的可用时段、精确字段来源、别名写冲突、存储退出、错误路径、清理顺序和调用权限均是额外观察。abort应保留其原始责任状态，不能伪造成正常清理出口；循环重复创建也不能仅凭静态源码位置就当成同一动态资源。流体平均密度一类近似会丢失身份和相关性，不能直接作为接受安全程序的依据。

更有用的物理启发是局部相互作用：一次事件通常只读取或改变少量状态分量。问题应表述为“能否让计算与该事件的真实支持集成比例，同时保留全部故障和出口关系”，而非只缩短表示位数。076尚未做到这一点：整态共享仍通过现有direct内核构造完整后态。

## 3. 下一结构候选：按事件支持增量构造状态

设状态为资源位置、字段活性、描述来源与分支信息的有限元组。每个事件预先提取读取集合R、写入集合W及故障判定依赖F。候选只重建W涉及的持久化子树，读取R∪F并保留其他共享子树。恒等后缀和无关字段应既不复制，也不重新哈希整条向量。

这与已有模型检验文献的子向量共享、部分重建和增量更新有关。2011年的[Parallel Recursive State Compression for Free](https://research.utwente.nl/en/publications/parallel-recursive-state-compression-for-free-2/)研究树状子向量共享；2020/2021年的[Recursive Variable-Length State Compression](https://arxiv.org/abs/2007.12174)研究变长状态的部分重建及不完全具体化的增量更新。它们是可借鉴的已有工作，076的整态intern不是这些算法，也未移植其性能结果。

候选的必要比较是dense-direct、local-direct、当前整态intern及新子树方案；语料须同时包含稀疏写、稠密写、短态、长态、无共享和高共享。完整费用必须包含支持集提取、驻留表、更新、固定点集合、回收、最终展开及独立核验。若读取/哈希/指针追踪超过平坦数组的连续访问成本，应直接保留负结果或使用明确收费的回退，不能把预处理藏在计时之外。

## 4. 切割对象应是语义耦合关系

CFG边少不保证资源关系容易分解。一条分支条件可以同时耦合多个资源；跨区域的描述和后续使用也会扩大边界。应先建立事件—状态分量的依赖超图，再考虑带条件的边界摘要。若R为完整联合关系、S为共享分隔信息，只有在证明或完整核对R等于两个投影关系按S连接的结果时，才可把两侧独立求解后组合。

最小反例是R={(0,0),(1,1)}。分别保存两变量的边缘集合后做笛卡尔积，会额外产生(0,1)和(1,0)。两侧都只有两个值、资源总数也守恒，相关性依然丢失。切口必须携带足够的路径/守卫关联，或保留不可分解联合块。初始关系、错误和abort同样参与分解条件。

真正可能改变规模的收益来自低耦合宽度、重复边界关系或可证明的条件独立，而非每个资源位置编码少几个bit。若关系本身要求指数多的完整可观察行，精确算法不能靠改名消除输出下界；可研究紧凑关系供消费者直接使用，但必须把新观察合同作为独立实验，与旧完整展开合同分别核对。

## 5. 纵向共享：共享事实，分开建立信任

用户提出的全链条视角有实际落点。076四guard的dense-direct中，独立核验加完整物化占完整候选成本的比例中位数为60.3%。这是当前研究接口的测量，不是生产编译器60.3%的时间都可被删除。它提示：继续只优化转移内核可能越来越难改变总成本。

可研究一个请求内不可变的事件事实容器：稳定资源/字段身份、原始事件、精确读写支持、结构类型与请求摘要只构造一次。Types、Analyze、Verify和Lower可以引用这些原始事实，但Verify必须独立验证原始结构、权限及责任转移，不能把Analyze的“已证明安全”标记当成自身证明。格式、来源或生产者改变时，共享事实失效；预算还须覆盖验证、索引构造和长期保留的内存。

当前068已减少三类重复工作，但未证明普遍稳定的请求时间收益。下一纵向实验应同时测cold、相同请求复用、私有函数编辑、公开合同编辑和回退恢复，记录完整请求时间及内存，而不只记录缓存命中率。[Rust增量查询文档](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html)说明依赖追踪及红绿重验证；[Polonius](https://rust-lang.github.io/polonius/)提供关系规则与多算法实现背景。它们可帮助设计依赖和事实传播，但不自动解决ZIL的清理次序、环境字段责任和完整关系输出，也不构成当前ZIL提速证据。

## 6. 与语言主线的接点

077–079把多个资源字段保存在同一个拥有闭包环境中。数据、整包活性和字段责任标志始终位于真实环境，函数内Package视图直接引用这些位置；Bind/End只开启或结束词法访问，不搬出整包、重置责任或额外清理。可重复FnMut在所有普通及错误返回上恢复完整；FnOnce可以部分消费，调用结束后由caller按既定顺序清理剩余责任。Trap仍按abort合同处理。

这为后续研究提供更贴近应用的语义事件：字段替换、暂时移出再补回、环境跨调用保持状态、部分消费与失败退出。下一迁移应先在schema13上做完整影子抽取和独立对照，再判断事件支持/分隔关系能否减少真实核验成本。冻结schema10的076不能直接声称覆盖这些新增语义。

## 7. 本轮决策

保留076代码、原始完整关系、强基线、全部采样与负结果；当前生产替换仍NoGo。下一优先级是事件支持驱动的子态更新及可证分解，然后研究经独立验证的跨阶段不可变事实复用。每条路线都以强显式基线、完整成本、最近反例和现有产品门为准，不增加新的审批链，也不让研究成为语言施工的前置。当前一个对话内的隔离分支与独占计时窗口足以并行推进；另开对话不构成继承同一临时环境的保证。
