# draft18：图编译总成本与 ZUI 首窗边界

本轮以纯 ZIL 首窗为主线消费者，图研究独立在冻结的旧编译器上执行。两个分支互不把局部通过当作对方的证据。精确身份和正式状态以 `evidence/final-summary.json`、084–088 工单及各自独审为准；本文给出实际结论和下一步实施依据。

## 1. 对 ZUI 的实质推进

085–087 在 schema/wire15 接通普通 u16、不透明 `c_handle`、程序静态 UTF16 `c_wstr`、无环境静态 C callback、显式 `static_callbacks()` 重入合同、严格按地址 C record 布局，以及真实 Win64 LLVM→COFF→PE 目标链。独立 Verify 仍从不可信 raw/wire 重建检查，不能接受 Types/Analyze 的安全断言。

`examples/mainline/win32` 的窗口注册、真实 WndProc、消息循环、键盘/鼠标、状态更新、GDI Unicode 绘制、resize、退出与资源释放全部由 ZIL 源码完成。没有 C 窗口宿主。唯一 C oracle 属于测试，核对外部 ABI、record 偏移、窄返回及静态指针/代码地址留存。资源包装明确承担 DestroyWindow、UnregisterClassW 和 DeleteObject；Copy handle 本身不制造所有权。

作者完整 Win64 验证在 O0/O2 共执行 10 个 PE、66 项断言，实际截图与日志保留。独立审核另做 Linux/Win64、两优化级的多参数 ABI、静态值离开注册栈帧后反调、enum 混合布局、目标错配及 LIR 篡改检查。Wine 是兼容执行环境，不代表原生 Windows/驱动验收。字体来自显式安装的文泉驿字体，其他系统字体回退未测。

这已经足以开始抽出 ZUI 的 Win32 平台启动层，但尚不足以实现 GPUI 同等框架。当前窗口状态是 OS 提供的八字节整数槽，不能把它外推为任意 ZIL 对象的长期回调环境。

| 后续工作 | 实际依赖与目的 | 可并行范围 |
|---|---|---|
| 独立 ZUI 工程与最小平台 API | 复用已跑通首窗源，公开创建、事件、invalidate、退出边界 | 可以先抽取静态平台消费者；不宣称现有独立仓库已存在 |
| 长期状态、事件订阅与关闭 | 必须明确谁持有、何时停止回调、何时排空、何时释放，避免将借用转为不透明指针留存 | 语言/独立核规范先行，原静态首窗继续作为回归 |
| 字符串、动态容器与分配器 | 支撑组件树、可变文本、事件队列和布局数据；固定数组/静态字面量不能充当通用容器 | 拆成有限拥有容器与资源失败清理，再开放组合 |
| 布局、绘制后端和文本 | 平台层可先做纯 Copy 布局数值/事件类型；DirectWrite/DirectX 需要对应 COM/接口与资源生命周期 | 纯计算布局与 renderer API 可并行；GPU 实机能力单独验证 |
| 焦点、IME、可访问性、线程模型 | 依赖真实平台事件/对象与长期状态边界 | 保留未完成，不从首窗或测试数量推断完成 |

## 2. 084 的裁决：研究完成，生产 NoGo

084 比较数据库新 QueryKey 发布时的六行提前返回候选。理论依据是公开 API 的无悬空依赖不变量：不存在的 producer 不可能有存活消费者。原候选、强基线、功能控制、全部采样均保留；最终生产 DB 源码恢复为 f95 基线，主线只合入测试、研究工具和负结果。

冻结 schema14 的两版各有 66 个完整 API guard 请求，包含预算、取消、CT、目标、文件身份、公开合同和 ID 变化。正式窗口共 192 进程/768 请求，其中保留 168 进程/672 请求；没有删除不利样本或追加采样追求显著。root 独立重算 48 个请求单元和 12 个完整进程单元的配对中位数，并逐字节核对 4194 个归档文件。完整数据见 [084结果](084/RESULTS.md) 与 [全部表格](084/TABLES.md)。

64 模块冷 Verify 的配对时间比约 0.942，但完全没有执行新键 shortcut 的 unchanged 阴性控制也约 0.956。512 模块公开编辑约 1.041，真实 owned_component 私有编辑约 1.121。三个真实消费者的完整 Build 进程未建立一致收益。因此本轮没有新增可推广的编译提速补丁。已有 080 有限热点收益保留原 schema13 身份，不能挪作本轮或当前 Win64 编译器的性能结论。

## 3. 下一轮优先测实际重复工作

084 进一步核实：`load_sources` 每次为发现 import 仍真实解析源文件，后续 Parse query 的 reused 事件不能证明免解析；Parse key 又含逐模块剩余 token/node 额度，前面模块 token 数改变可令后面未改模块的 key 一起变化。两项机制必须拆开验证。

下一轮使用 B/K/L/KL 四控制：B 为当时强生产基线；K 只分开成功语法身份和请求预算；L 只复用发现阶段的已成功 syntax；KL 结合两者。每请求仍读当前字节、检查路径/import/身份并按原逻辑收费。命中不免除额度；资格不足或原本失败的输入回到原解析器，保持拒绝阶段、span、顺序和取消行为。计数版直接记录真实 lexer/parser 调用、摘要次数及字节，计时版不带这些插桩。

第二条独立路径是 RawSnapshot 的完整 Debug 格式化后摘要。先测其份额，再比较相同字节的流式 SHA 与现有一次性 String；只有再定义清楚结果身份与依赖边界，才研究单体 `no_hash` 配合精确投影。不能把 QueryKey 偷换成值相等摘要，也不能省掉独立 Verify 或 Typed/Candidate 身份核验。

Rust 的 [增量查询文档](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html)说明结果变化检测、稳定身份及 `no_hash`/projection 的成本关系；[新 trait solver 缓存文档](https://rustc-dev-guide.rust-lang.org/solve/caching.html)明确缓存资格与实际递归深度及循环上下文相关。这里借鉴的是可复用条件和成本分离，ZIL 的 ResourceLimit 仍是失败，不照搬 Rust 的 ambiguity 语义，也没有移用其性能数字。

## 4. 图、物理和关系算法的继续方向

位置唯一性有助于把资源责任描述为事件上的状态变化，但不能单独证明因子之间独立。保留同一条件或故障关联是必要的，否则把各资源的边缘集合相乘会制造从未可能同时发生的状态。图分解应沿实际读写支持和有证明的分量边界进行；粒子/流体类比只负责提出假设。

[Polonius](https://rust-lang.github.io/polonius/rules/loans.html)的显式关系传播、kill 和保守粗分析适合借鉴为缩小精确工作范围的方式，但 ZIL 的责任守恒、Drop 次序、部分 Package、错误出口仍必须另行满足。不能因一项借用预分析无错而跳过其余安全条件。

[差分数据流原始论文](https://www.cidrdb.org/cidr2013/Papers/CIDR13_Paper111.pdf)和[官方书](https://timelydataflow.github.io/differential-dataflow/)提供编辑版本与求解迭代分开维护的研究参照。ZIL 跨编辑删边必须撤销旧推导，菱形多重支持和 SCC 自支持是必需反例；单请求内只增不减的工作队列不能直接充当跨编辑维护算法。索引、支持计数、整合、释放和完整核验全部计入成本。

本轮没有证明原创复杂性定理，也没有把图切割研究换名为已完成的内存管理算法。优先 P/H 的原因是已经在真实编译路径上定位到具体重复操作；结构研究继续保留完整联合关系强基线，不阻塞语言主线。

## 5. 安全边界和当前工程价值

独审先后发现未使用泛型声明在擦除前漏检 callback 形式，以及公开 Source CT 在预算检查前复制深类型/UTF16/元数据的问题；088 进一步修复 materialize 的宽队列，独立固定预算观察从随宽度增长的 3072/12288/49152 字节改为均 940 字节，成功输出和拒绝诊断保持；这不是整体编译性能或 RSS 测量。所有原失败、修复与精确候选审核都保留。限额检查的先后顺序是实际 API 边界，不能靠“前端通常已经检查过”关闭。

继续施工的价值已具体到真实语言能完成窗口启动链，以及拥有资源在普通控制流和外部调用下的明确责任。尚未证明 Rust 同级完整安全、同语义运行/内存成本、维护更简单或编译总体更快。当前阶段应让 ZUI 的真实消费者决定下一项语言能力，避免把泛化求解器、平台清单或研究平台本身当作产品成果。完整语言 NotSatisfied、产品 NotRun、B0 Doing 均保持，原产品阈值未改变。
