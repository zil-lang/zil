# 055：真实 TypedIR 的倒序切割影子实验

## 本轮问题和边界

050 只处理人工有限关系。055 从真实 ZIL 源文件经生产 Parse → Expand → Types 得到 TypedModule，先用生产 Analyze/Verify 确认基线，再只读抽取每个函数的资源/闭包控制事件图。生产代码与接受集合不变。本轮具体消费者是 `verify/resources.rs` 的描述及借入闭包活跃性查询，不声称实现整个状态/权限/trait 求解器。

图节点身份为 `(FunctionId, BlockId, instruction ordinal)`；每块另外有终结节点。边来自实际 TypedCFG。资源创建/转移/描述/读写/清理、闭包环境/调用、所有调用、枚举标签、分支与所有 Return/Trap/Unreachable 都作为观察节点保留。没有删除或改写源 IR；标量定义仍在原 IR 中，分支保留条件 ValueId 和 true/false 边标签。被消去的节点只有对本次描述活跃性传递为恒等、且不属于上述观察事件的节点。

图回答的是实际 CFG 的路径抽象，不宣称每条 CFG 路径运行时可行。完整联合控制关系保存在同一有标签图中；不同资源没有各自复制分支节点，不把分支后态拆成边际表。保持观察事件图的下一观察节点关系（包括自环）即保持所有有限观察事件串，正常、错误/陷阱和不返回循环都不会因为切割而消失。未来错误 ABI 新增的终结类型必须显式加入，未知种类不得静默通过。

这里区分三层保证：①逐点 Desc/借入闭包 **may-liveness** 全集；②资源/捕获身份、原始分支条件、枚举 tag、清理顺序与出口的**同一有标签事件图**；③一般资源联合状态关系求解。055 验证前两层，没有实现第三层。交换两个资源对应的 true/false 出口会保持第一层不变，第二层检查能够发现；这不等于求出了各分支可行的完整联合状态。050 的精确有限关系算法仍是单列的人工模型。

schema7 的算术/索引/标签读取及调用可能隐含失败。抽取额外加入每操作一个 `conservative-failure` 终结观察点，独立计数；这是一种保守扩张，并非声称每个操作真能失败。它不修改 TypedIR，也不将未知调用当成必然正常返回。schema7 的 enum Err 普通返回与 schema8 的专门 error-return 不能混称；主计时冻结在 draft10/schema7，未来 schema8 只另交功能收据。

## 精确查询和倒序算法

活跃项是 Desc 局部/SSA 值，以及捕获 Desc 的闭包局部/SSA 值；身份带函数，绝不按类型或名字合并。每点传递为 `in = gen ∪ (union(successor.in) − kill)`，以空集开始求最小不动点。所有函数、所有 CFG 终止点和所有原始程序点的完整位关系都参加比较。不可达块在结果中保留不可达标志，不伪造可执行路径。

候选按确定的逆节点序处理透明点 v，把每条前驱边经 v 接到其后继，保留前驱分支标签；记录 v 当时的后继作为重建摘要。自环只表示恒等循环，其最小解仍是其余后继并集。填边超过锁定阈值则保留该点，继续原图精确求解；不是把超预算当作空关系。按消元记录逆序复原每个原点的行。生产候选仍必须由生产 Verify 核验，研究输出不能制造 Verified 权限。

图型基线不消去节点，使用与候选相同的位集、工作队列和完整结果表示，以分离消元与位集改写的收益。另保留按原始块处理的固定点算法，避免仅胜过逐指令图基线便宣称优于现有编译器。真正独立 oracle 直接解释 TypedIR 的 gen/kill 语义，使用 BTreeSet 和全块扫描，不调用候选的图抽取、消元、位集或队列；完整活跃关系逐点相等才算通过。

另一个 raw-TypedIR 审计独立重建所有原边和隐含失败出口，核对原指令身份、观察节点保留、所有槽位与可达性，并在空集/全集上核验每个 gen/kill 传递。两个映像足以确定这种传递，因而抽取错误不会被所有求解器共用的图掩盖。此审计也进入每次计时的 check 阶段。完整慢 oracle 仅在冻结时生成参照，构造该参照的成本不计入样本；样本包含逐点结果对参照的完整核对。此处冻结参照是实验裁判，不是未来生产的动态证明检查器。

## 范围与硬上限

不跨函数内联，不求 trait 特化，不合并动态身份，不改变清理次序。描述活跃性是现有资源核的一个 may 关系；它不替代责任、别名、顺序、状态与权限的其它检查。递归调用保留为调用观察节点；其内部 effects 仍由原生产核负责。

当前冻结查询不覆盖返回 Desc 或捕获 Desc 的闭包的函数，遇到该签名明确 Unsupported；19源语料不含此类返回。生产资源核对资源描述返回本来另有限制，且其历史表是指令后态，055记录指令前态/终结点；两者不能直接按相同数组下标比较。本文所谓生产对应点是相同的描述用途/kill子问题，不声称直接替换私有API已完成。

研究工具每函数最多 200000 点（包含保守失败出口）、8192 个活跃项、2000000 条边；单点带标签候选填边上限 64。**每个研究阶段调用**的计费上限 W=100000000，不是所有阶段共享的总预算。抽取、raw审计、计划、求解/复原、慢oracle、oracle行转换、边界审计、完整输出、形状普查、普查输出分别计费；块求解替换点图求解，不叠加为生产预算。

计费单位是显式元素/位字/编码字节访问或复制，含保守批量收费；不是CPU指令数或墙钟时间。大批clone、前驱扫描（包括fill>64的回退路径）、min-fill候选/团循环及完整行输出在执行前检查。集合内部树平衡、分配器和析构不是单独CPU计时模型；其对象规模由已收费的输入/分配量限制。超硬限明确ResourceLimit，不发布部分答案；不存在把预算失败当空关系成功的路径。

一次函数功能冻结最多19个阶段调用，因此**被计费的研究工作**总计不超过19W；一次flat/cut/block影子样本为6个阶段，不超过6W。该总界不涵盖前端/生产Analyze+Verify、整模块指纹/TypedIR文本输出、文件I/O或跨函数总和；这些仍受生产输入/预算边界或文件大小约束，不能宣传成进程总耗时上界。空资源函数返回空关系，但图、槽位与空行分配仍计费和统计。阈值不改变成功结果或生产接受性。

精确N−1/N/N+1测试分别穿过真实raw审计、资源形状普查和fill>64保留点的计划路径：N−1必须ResourceLimit，N与N+1必须完整成功且结果相同。

## 冻结、正反例和计时

源配方和来源文件清单在 `tests/perf/impl055/cases.tsv`。包含现有资源闭包样例、无资源小例、标量长段、分支、循环/continue/break、共同闭包描述、宽捕获、多出口。人工放大型由 ZIL 源码产生真实 TypedIR，明确与现有样例区分；不是直接手填数学图。

资源交互图取每个原指令直接使用/定义的 Managed、Desc、Address、非空捕获闭包身份组成同现团。边密度、最大连通分量及 min-fill 诱导宽度仅是这张图的形状普查：这是既有启发式给出的宽度上界，不是 CFG 的宽度，不是所有资源语义依赖都已抽取的证明；超过 256 个交互顶点明确不给宽度数值。宽捕获64源保留共同捕获团，使密图反例随真实前端而来。

普查分别记录 CFG 切口相邻节点数、消去点最大活跃槽位数、指令同现交互图宽度，三者单位不同，不相互代换。另记录全部关系事实数与行负载字节；后者只是位数组长度，不包括分配器、图、标签、审计及前端内存，不能称峰值RSS。

先提交研究代码/合同/配方，再 freeze 所有输入源码、研究实现及依赖生产源码的 SHA-256、实际 TypedIR 指纹、完整活跃关系及事件边界关系。正反测试包括漏条件臂、漏异常出口、复用其它函数的同号身份、删捕获用途、反转清理序、消元摘要篡改、错误活跃位、缺失完整行和填边回退。正确性冻结完成后才能计时。若修复实现，旧冻结失效，记录新身份，不能覆盖旧数字。

计时由集成方确认其它构建停止后执行；固定 CPU，6 轮 × 每轮 7 次，交错 flat/cut/block 顺序，预热每法一次。每样本包括源 Parse/Expand/Types、图抽取、计划、求解、全部原点恢复、完整结果/边界核对和销毁；分别记录各阶段。另记录相同源码的生产 Analyze+Verify 时间，但不将 shadow 追加开销当成生产核替换后的收益。文件读取、进程启动、写 JSON 在计时外。统计全部例的中位、p10/p90、IQR，不丢密图/小例退化；逻辑行/边字节不当作峰值 RSS。
