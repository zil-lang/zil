## 真实新增能力

拥有 State 可以携带两个独立声明的 F/G 回调。一个实际 State 参数只求值和转交一次，Core 的 State 绑定表记录实际参数位置及两个声明槽与字段之间的关系；它不把一个 State 伪装成两个直接 callback 参数。

| 能力 | 本片行为与边界 |
| --- | --- |
| 独立声明模式 | 即使 F/G 的两个实际值来自同一闭包类型 C，F:Fn 与 G:FnOnce 仍分别检查。实际 C 的更强能力不能替代声明的较弱接口 |
| 完整类型身份 | 模块、名义族、普通/phantom T、字段声明顺序及两个实际环境一并保留；函数 binder 顺序与字段顺序分别映射、同时替换 |
| 来源流动 | let、移动、字段取出、完整注解、普通完整T helper、Store、错误联合两侧及问号成功侧保留当前函数声明来源；跨函数使用被调用方自己的声明 |
| 双环境元素 | 有限 Store 元素可有一或两个直接 callback 字段、最多两个不同的具体自含环境；新异环境路径的结果为Copy，旧单根/同根 lending 保持 |
| 普通模板裸调用 | 静态普通 `T:StoreElement` 调用可从实际值的 T、Store<T> 和已有错误联合约束唯一推得完整T；实参仍只准备一次。无值或冲突推导继续拒绝 |
| 独立资格与布局 | Analyze/Verify 分别检查实际根、未用资源定义和完整元素，Verify 独立计算实际捕获、live flags、大小/对齐和有界内联依赖图 |
| CT与工具入口 | runtime CT正规化保留新元数据与正确标量上下文；CT执行新资源模板明确禁止。CLI/IDE使用同一生产阶段 |

字段、元素、实际拥有值的借用、移动与清理责任始终独立。复用同一类型布局不会合并两份运行时责任。源声明模式检查与raw TypedIR中的实际内存安全检查分开记账；raw输入没有源级较弱bound时，不能宣称独立安全核恢复了它。

首片仍只允许一个拥有 State 参数、两个声明槽及两个直接 callback 字段。State与替换F、两个State参数、一般异类型lending、dyn、来源擦除式capture/opaque返回/函数指针等未开放范围保持明确拒绝。新入口没有为Core表增加虚构的TypedIR opcode，也没有引入隐式Box、RC、锁或运行时元素权限表。

## 实际发现与修复

未调用的 State 定义必须按声明检查，不能等未来具体实例替它兜底。本轮原输入暴露了重复字段取走、借用别名丢失父位置、独占借用期间直接调用、循环补回后旧别名复活，以及循环条件使用被漏计的问题。Types 现在保留有界的真实位置、共享/独占种类、独立借用身份、祖先链与不可逆失效，并把条件和正文的循环使用共同检查。

对应的已使用非法程序原先已被 Verify 拒绝的情况，仍按这一实际边界报告，不称为已可执行的内存安全绕过。未调用定义漏检则保留原始失败和修复后同输入复验；两个公共 Types 入口均有raw覆盖。

静态审查还定位了祖先向量增长、投影临时向量、分支来源拼接和循环集合构造的四处新路径预收费缺口，修复后保留旧预算控制。CT的runtime标量提示曾在裸模板调用中丢失，导致 `#(4294967296)` 得不到合法i64上下文；原失败和修复后的独立CT组均保留。
