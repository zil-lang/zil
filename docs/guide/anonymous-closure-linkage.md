# 匿名闭包函数体的链接可见性

匿名闭包体没有可供其他源模块直接导入的函数名；闭包值通过既有环境与调用协议使用它。后端可以据此减少机器码中不必要的外部符号，但不能把“匿名”直接理解为“没有跨编译单元引用”。

先完成代码生成单元分区，再使用当前已验证闭包定义中的函数身份，收集其普通及大型 ABI 实现符号。只有该实现的全部实际引用都留在拥有它的单元内，才把其定义从 external 收紧为 internal。调用、函数地址、全局初始化及优化导入体中的引用均参与判断；真正跨单元使用的符号维持原链接方式。重复定义仍交由现有机器预检拒绝，不通过内部化掩盖。

这让 LLVM 可以在完成内联后删除不再需要独立保留的匿名函数体，而不是同时优化调用者中的副本和保留一个外部定义。规则不强制内联或禁止内联、不复制函数、不改变符号名称或被传出的函数地址身份。具名源函数和公开外部接口不因本规则改变；独立 Verify、当前机器预检、捕获布局、清理顺序及资源限额保持原规则。

LLVM API 和 Clang 参考后端消费相同的分区后模型。公开 `.ll` 诊断侧文件仍表示分区前模型，不能仅凭其中的链接标记断言该优化是否生效；原生符号和对象模型才是执行证据。对象缓存按实际分区后模型绑定。接受优化需要同时观察完整编译等待、原生行为和运行质量，不能把减少独立定义等同于所有程序都更快。
