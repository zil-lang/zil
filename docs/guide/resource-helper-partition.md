# 资源闭包的辅助代码分区

显式增量O2构建包含多个源文件和闭包时，先区分可复制的内部实现代码与必须保持唯一身份的局部状态。内部函数只有在其地址从未作为参数、数据或其他值被观察，且不依赖不可复制的局部身份时，才能随实际调用者复制。局部全局变量、被取址的函数及依赖它们的辅助函数继续按真实引用合组；外部调用的副作用不会因为复制代码而消失或提前执行。

辅助函数的不可复制性通过反向依赖传播；纯直接调用环可整体保留。源文件及必须共址的状态形成拥有组。可复制helper的实际实现依赖完整保留，供LLVM执行原有局部优化。跨单元源函数只在原机器指令和块成本不超过32时导入；更大的实现保留规范定义及调用声明，使未内联的大函数体修改不必使调用者对象失效。32是保守的编译成本策略，不是语言限制或LLVM内联成本的等价估计。大函数的跨单元优化可见性因此减少，必须另外验收运行质量；不能把这一取舍宣称为完全没有优化代价。

导入的源实现使用私有副本，但作为值使用的函数地址仍指向唯一规范定义。额外复制的指令和块成本不能超过一份原始机器图，规划另有有限工作量预算。无法保全依赖、身份或预算时，完整放弃该候选，交回原规划器，不能提交半份不一致的导入集合。单源文件不进入此路径。

在删除不可达辅助体或未使用声明前，检查完整原始机器模型；各输出单元仍通过当前机器预检。源码独立Verify、默认资源限额、内联属性、捕获布局和清理顺序不变。对象缓存绑定实际单元内容：已导入的函数体和helper变化使其实际副本失效，仅保留声明的大函数调用者仍依赖当前签名。本路径暂不持久化分区布局，也未实现跨声明插入的全局稳定身份。

验收应同时观察冷构建的总CPU工作量、真实编辑、无修改请求、命中对象大小及生成程序运行质量。新增多模块样本与已有固定频率协议分别统计；分区或缓存命中数量增加本身不等于总等待减少。
