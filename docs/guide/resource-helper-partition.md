# 资源闭包的辅助代码分区

显式增量O2构建包含多个源文件和闭包时，编译器先区分可复制的内部实现代码与必须保持唯一身份的局部状态。内部函数只有在其地址从未作为参数、数据或其他值被观察，且不依赖不可复制的局部身份时，才能随实际调用者复制。局部全局变量、被取址的函数及依赖它们的辅助函数继续按真实引用合组；外部调用的副作用不会因为复制代码而消失或提前执行。

辅助函数的不可复制性通过反向依赖传播；纯直接调用环可整体保留。源文件及必须共址的状态形成稳定拥有组。每个单元保留完整的直接调用实现闭包，供LLVM执行原有内联与过程间优化。跨单元源函数的调用可使用私有实现副本，但作为值使用的函数地址仍指向唯一规范定义，不随复制改写。

额外复制的指令和基本块成本不能超过一份原始机器图，规划另有有限工作量预算。无法保全依赖、身份或预算时，完整放弃该候选，交回原有规划器，不能提交半份导入集合。单源文件不进入此路径；分拆辅助代码不能让一个真正依赖全部闭包的巨大调用者免于重编。

在删除不可达辅助体或未使用声明前，检查完整原始机器模型，避免优化隐藏非法输入；各输出单元仍通过当前机器预检。源码的独立Verify、默认资源限额、内联属性、捕获布局和清理顺序不变。对象缓存绑定实际单元内容；辅助代码或其依赖变化会改变所有实际副本的键。本路径暂不持久化分区布局，不能因此声称零规划成本或完整函数级增量。

验收同时观察冷构建、真实编辑、无修改请求、实际命中对象大小及生成程序运行质量。新增多模块样本与已有固定频率协议分别统计；更多分区或更多缓存命中本身不等于更低的总等待时间。
