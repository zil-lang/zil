# 标量类型检查的增量依赖

函数级类型检查缓存保留未核的类型化函数体和完整工作量收据，不保存 Verify 授权。缓存命中后仍执行当前声明检查、Analyze 和独立 Verify；可信本地磁盘恢复遵循相同规则。

缓存键分为两层：共同上下文包含目标、全部限额、模块、导入以及完整名字和函数编号空间；函数键包含自身声明、相对源码位置、完整函数体，以及每个实际直接调用目标的声明签名。签名指纹保留可见性、参数、结果、调用种类和生命周期等声明内容。因此无关函数的签名改变不必使本函数失效，直接用户仍须重查；插入、删除、重编号和导入变化继续保守失效。

这一策略仅适用于现有标量缓存准入范围。一般泛型、trait、闭包环境、资源、存储生命周期及协议合同不因依赖拆分获得缓存资格；外部与间接调用保持原路径。缓存格式域随键语义更新，旧键不能冒充新语义。原缓存耗尽、取消、损坏和当前错误诊断行为必须保留。

收益按完整请求等待时间和实际使用频率评估，而非仅按复用函数数或类型检查局部百分比。生成程序正确性、清理责任和运行性能是独立约束；此机制不替代构建层的无修改跳过，也不代表完整的通用语义增量系统。
