# 拥有闭包的析构代码边界

拥有环境的字段析构辅助函数可以在多个调用位置展开。模块中至少有十六个拥有环境定义时，后端为这些内部析构函数保留 `noinline` 边界，避免重复展开同一组 live 标志、字段清理和分支状态。更小的模块以及不拥有资源的环境维持原策略；闭包调用体、缓冲区扩容和其他资源辅助函数不因本规则禁止内联。

策略只改变原有内部析构函数的优化属性，不改变其符号身份、参数、捕获布局、指令、清理顺序或 live 标志。`noinline` 不表示路径冷，也不产生无别名、非空、释放完成或生命周期权限。当前独立 Verify、机器预检、对象缓存绑定和默认限额保持不变。

十六个定义是控制代码扩张的静态策略阈值，不是语言能力边界，也不是运行性能保证。接受该策略需要同时测量完整编译等待时间、生成程序运行时间以及真实分配失败和清理顺序。未触发与阈值两侧都必须有测试；不能通过改变程序输入或丢弃不利场景来制造收益。
