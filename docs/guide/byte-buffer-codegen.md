# 字节缓冲区扩容的代码生成

字节缓冲区的容量检查与实际扩容事务分开优化。`zil.bytes.reserve` 保留可内联的负数检查和当前容量比较；容量足够时直接返回，只有确实需要扩容时才调用内部 `zil.bytes.grow`。后者带有 `noinline`，使相同的分配、失败判断及发布逻辑不因多个拥有闭包内联而重复展开。此边界不改变公开语言接口、对象布局或目标分配器。

扩容事务保持原始语义：请求为负数时失败；未超过容量时成功且不分配；分配失败保留原指针、长度、容量和字节；只有分配成功才发布新指针与容量。清理仍经过原有释放路径，不增加资源、借用或线程权限。两个辅助函数均为内部链接，不新增对外符号合同。

`noinline` 仅限制优化器的内联选择，不表示路径一定冷，也不产生分配成功、非空、无别名或可解引用假设。当前独立 Verify、机器预检、LLVM 前后结构核验和缓存身份规则保持不变。

验收同时检查完整编译等待时间和生成程序运行质量。容量已足够的热循环、零和负数请求、真实扩容失败的数据保留与清理，不能因编译加速而退化为未检查路径。拥有闭包的其他分区与失效问题不由此机制自动解决。
