# 资源初始化顺序的精确表示

资源分析中的关系 `a → b` 表示某条可达路径上，`a` 仍存活时 `b` 可能在其后初始化。清理必须保留全部实际关系；不能用编号、单一时间戳或传递约简替代分支、循环和重复初始化产生的边。

小关系保留原有有序边集合。超过阈值后，以实际源 LocalId 和目标的 64 位字编号索引非零位集；每一位仍对应原集合中恰好一条边，不构造按最大 ID 分配的矩阵。联合使用逐位并集，删除清除该资源所在行与目标位，后继查询只枚举相应行，结果顺序与原有集合相同。状态复制按实际存储量处理，不再复制每条重复的树节点。

这只是 Analyze 的私有表示，不保存或传递 Verify 授权，也不改变清理语义、默认资源限额、LLVM 内联策略或运行时布局。转换、查找、位操作和遍历按实际工作预付预算；超限终止当前请求。独立 Verify 继续从当前 CFG 重建责任与顺序。

回归以独立边集合为模型，覆盖全体四顶点关系、混合表示联合、重复初始化、跨字边界、稀疏最大 ID、清理后继及限额不足。编译优化验收另看频率加权的完整等待时间；未通过的规模样本不能从同一协议删除后重新归一化。保持机器代码不变的改动仍须核对实际生成结果。
