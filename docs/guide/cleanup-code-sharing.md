# 函数内退出清理的内容共享

多个返回路径可能以相同顺序清理同一批局部资源。代码生成在当前独立 Verify 和 LIR 核验之后，用“清理动作种类、实际 LocalId、下一节点”作为键，驻留相同后缀；每个返回点进入其准确后缀，不再重复发射整条相同清理链。它共享机器控制流，不合并运行时资源，也不改变析构或初始化顺序。

准入仅覆盖普通直接函数的标量或 Unit 返回，以及现有闭包和字节缓冲区的完整局部清理。资源 StorageDead 的 live 标志写入保留为独立动作；原本不发射机器代码的 ScopeExit 和标量 StorageDead 仍不产生代码。未知操作终止可共享后缀，原前缀不变；Task 及其拥有标记、非标量返回保持原路径。不同的清理顺序不能仅因资源集合相同而合并。

非 Unit 返回在进入清理前保存到本函数的私有、不逃逸栈槽，所有共享清理完成后返回该值。每个共享动作仍调用原指令发射器，沿用捕获布局、析构函数和当前 live 标志。闭包内联策略、对象缓存安全边界、公开 ABI 与默认限额不变，不添加 cold、noalias、nonnull 或分配成功假设。

驻留表和节点数受可选优化工作量上界约束；上界耗尽时放弃整个计划并发射原代码，而不是放宽核验。此机制仅减少当前请求内的重复工作，不是跨请求缓存授权或增量 Verify。

验收需分别检查完整请求等待时间、驻留内存、生成程序运行质量，以及真实分配失败、清理次数和顺序。只看到代码规模缩小不代表性能门通过；其他语言组合与任务清理不由这一有限准入自动开放。
