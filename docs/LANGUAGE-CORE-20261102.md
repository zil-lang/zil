## 为什么之前推进慢，这次如何调整

主要问题是单项功能已实现，但自然组合仍有缺口。直到把真实API连起来，才发现泛型包装身份丢失、整个拥有值返回后不能重新赋值、跨模块封装和捕获补回回退。按零散语法点收口，容易高估语言的可用程度。

后续以可运行的普通库API作为一批的验收单位：先固定源码、输出、清理及失败路径，再补通用规则。每次涉及拥有值，提前覆盖跨模块私有封装、普通/泛型调用、捕获、错误联合、部分移动和替换的既有组合。作者跑限定回归，非作者先审最近反例；稳定合并候选统一执行高风险全量。源码检查点先推送，避免把归档和研究实验排在必要语言开发之前。

并行实施使用`gpt-6.1-sol` high，复杂安全核与独立审核使用xhigh，作者与审核身份分开。root负责共同合同和集成；root自身模型/推理档位不能在会话内切换。并行不能代替共同候选回归，本批的真实漏测已纳入后续组合检查。
