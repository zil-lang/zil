## 实际开放的能力

模块声明和普通函数、闭包、控制块中的 `#if` 现在经过实际编译期选择。条件不仅接受字面布尔值，也可调用无条件、非泛型、无捕获、已封闭的 Unit/bool/u8/u16/i32/i64 普通纯标量函数及有限 helper 依赖。普通无条件 import 和 public 可见性继续生效；函数体、循环、递归、短路和整数语义沿现有 CTIR、独立 CT verifier、受配额 VM 执行。

```zil
fn slots(rows: i32, columns: i32) -> i32 { return rows * columns }
fn compact() -> bool { return slots(2, 3) <= 8 }

#if (compact()) {
    fn width() -> i32 { return 6 }
} else {
    fn width() -> i32 { return unavailable_branch() }
}

fn main() -> i32 {
    #if (slots(2, 3) == 6) {
        let value = width()
    } else {
        let value = unavailable_value
    }
    return value - 6
}
```

分支大括号仅定界生成列表。选中声明或语句按原顺序插入接收位置，不新增运行期词法作用域。局部可在后续使用，重复声明沿普通规则拒绝；return、break/continue 和拥有资源清理与同位置手写语句一致。当前普通语言尚未开放的构造不会因包在 `#if` 中获得权限。

两支都经过词法和语法检查，仅选中支进入名字、类型与安全检查。未选中的未知名字、未知类型和尚未执行属性不会提前进入这些语义检查；选中的属性保持原有执行/Unsupported 边界。选中代码仍完整经过 Types、Analyze、独立 Verify、Lower 和机器生成，没有新增 TypedIR 安全事实或 schema/Wire 指令。

## 阶段与真实依赖

选择先于完整项目/泛型正规化。所有条件读取同一不可变 ConfigReady 快照，保留真实无条件函数体；本批生成的声明不进入其条件函数集合。依赖条件生成声明或尚含生成指令的函数体时，`E-CT-PHASE-DEPENDENCY` 指向实际依赖位置。普通未知名字仍为普通名字错误；普通函数递归由 VM 步数和深度限制处理。

接收函数的参数、局部、循环/模式绑定及闭包形参不会成为编译期输入。运行期局部遮蔽同名全局函数时也明确拒绝，不能偷偷改查全局 helper。生成列表中的局部继续参与接收块的后续遮蔽检查。

普通调用和管道插入的调用均按实际静态 callee 建立传递依赖。静态模块对象的无括号、单层／多层括号及整个 callee 分组形式都解析为同一真实调用链；解开对象括号前先计费，仍检查实际 import、public 可见性与词法遮蔽。`selection.json` 记录条件 span、选中的分支、依赖函数原声明/module/source 身份以及实际 CT 用量；这些是原始事实记录，不是可注入的已核权限。原 source map 保持选中节点的源位置。

## 保留的失败和修复

首次源码测试错误地使用了语言不接受的 i64 字面后缀；现采用既有显式转换及真正的 i64 函数返回上下文。另一首次失败是 selection 产物未登记 ArtifactPlan，现通过同一预规划、冲突检查和原子发布流程写入。

`3563759` 的机器闭环及旧回归曾通过，但交付检查发现管道 helper 的传递依赖遗漏：程序仍被拒绝，却把实际生成依赖误报为普通未知名，且选择轨迹不完整。现将管道插入的实际 callee 纳入同一依赖遍历，并以原失败输入和轨迹正例关闭。该版本还有一个 Clippy 风格错误，已修复。原始源码、错误和收据保留，最终结果绑定修复后的 `4b4ac10`；两个提交重复执行的数量不相加。

独审 `4b4ac10` 又发现静态模块对象括号被 Expand 消去，但依赖扫描只识别直接 Name：`#if((cfg).choose(7))` 能执行实际 `choose → leaf`，轨迹却为空；若 leaf 来自条件生成，错误被报为普通未知名。`deb5824c` 只补对象 Group 的预付费解包。四种分组形状的回归同时检查完整依赖、生成 leaf 的实际 FileId(1)／源 span，以及运行期 cfg 遮蔽的实际 FileId(0)／源 span；没有据此开放 CT 权限或扩展 profile。新增回归先在原生产代码上复现失败，再在修复代码和固定提交上通过。非作者四个原字节探针的独立结果由 root 另行登记，不计入上述作者次数。

组合 all-target 检查还发现 `selection_cost` 位于测试模块之后，以及旧测试通过 path 引入文件时该新函数未被使用。函数原样移到测试模块前；既有 ct122 原始声明测试现在实际检查其节点与工作费用 N／N−1，没有 lint 抑制。固定提交的一次旧目录 Clippy 命令返回 0 却输出与当前源位置不符的旧错误文本，因此未采作质量 Pass；完整原日志保留，正式作者质量结果采用全新 target 下逐 crate 检查的成功收据。
