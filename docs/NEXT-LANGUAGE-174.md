# 174 起：把有限容器接入长期 UI 状态

这是接续建议，不是已派工或已实现的能力。实际开工须读取最后交付的 main、当前规范摘要及主树工单；不能从本页把未实现能力登记为通过。170–173 的最终结果见 [本阶段报告](LANGUAGE-173.md)，具体接受边界见 `spec/interfaces.json` 的三个20版有限合同。

## 本轮已有基础

- Package 能拥有一层完整固定 Package 数组字段，整取、补回、替换及失败清理已有源到机器实现。父壳内直接逐元素部分操作仍关闭。
- 有限 Copy payload 用户资源有真实共享头 `&Self`/`&R`。头窗口、Desc 写效果和责任转交独立核验；密封头、可变头、返回/捕获和含头模块的 Desc+Address 混合回调仍有明确边界。
- `Store<T>` 已有同质完整 Package 初始化前缀、显式容量、push完整失败返回、尾取、完整转交及逐项释放。它仍不能作为 Package 字段或捕获，不能外借元素地址，也不能直接存放带拥有数组字段的 Package、闭包或另一个 Store。
- 三入口组合消费者同时使用实际头地址、固定字段状态、运行时数量容器、跨模块 helper、保存回调及错误清理。它检验有限语言组合，不等于完整 ZUI、异步事件系统或全语言验收。

## 推荐顺序和三条并行线

| 优先工作 | 对 ZUI 的直接作用 | 第一个能独立验收的结果 |
|---|---|---|
| A：Store 成为普通拥有字段 | 让组件/窗口 State 真正持有可变数量的子项 | 一个 Package 中直接 `manages` Store，整字段 give/替换、完整 State 转交、错误准备和销毁 |
| B：动态前缀只读访问 | 布局、绘制、事件遍历可以读取现有子项，而不靠全部 pop 重建 | 有界运行时索引的只读访问协议，绑定实际容器来源和在场元素；窗口内阻挡扩容、尾取和销毁 |
| C：自含回调成为长期状态字段 | 将状态和订阅行为以普通语言结构组合 | 精确保留一个具体环境/opaque身份的回调字段，整取、调用、替换和递归清理 |

三线可先并行做最小原源码反例和接口提案。A/C 都涉及 Package 准入与递归清理，B 涉及来源、贷款和效果；共享分类、公共 Type/IR/Wire/预算入口仍由集成者单写。先固定有限合同再实现，不能通过一次扩大 `supported()` 打开尚无清理或来源证明的路径。最多三个施工代理；集成者负责冲突、消费者、整仓回归、非作者审核与交付。

### A：首先让 State 真正拥有 Store

当前 `Store` 的 `DropManaged` 有专用前缀清理，但 Package/closure 的旧通用 teardown 路径不能仅凭 `teardown=None` 静默略过。新的字段准入必须同步 Types、Analyze、独立 Verify、Lower、LLVM 和所有递归清理分类；本轮末端显式拒绝应变成精确的新处理，而不是删掉拒绝后依赖偶然布局。

首片只开放完整 Store 头作为直接 Managed 字段，元素保持当前完整 Item 形状。字段给出描述时，来源必须是父壳的实际字段位置；整字段提取撤销父字段责任，替换先准备新容器再清旧容器。父壳缺字段不得完整返回；任何未来仍使用的描述或元素窗口必须阻挡相应失效事件。先不同时开放递归 Store 元素、异构元素或用户自定义整壳 Drop。

最小消费者：`Item / State / update / main` 四模块。State 持有 Ticket 和 Store<Item>，运行时构建两个批次；更新失败保持未被显式消费的旧字段；成功替换清旧前缀一次；取出后早退只清剩余字段；补回后跨模块移动并最终清全部元素。每处真实分配失败都检查前缀内容、Drop顺序和分配/释放平衡。最近反例包括伪造字段Desc、缺字段整传、重复give、旧字段描述复活以及未实现的Store捕获。

### B：读窗口必须有完整的失效协议

当前六个 Store 原语没有任何元素地址入口，不能把它重解释为 ByteBuffer，也不能把动态索引塞进现有固定数组的 `u32` 静态槽。先确定是有限共享元素视图还是专用只读投影，明确类型、边界、调用效果和返回来源后由集成者登记公开格式；本页不发明一个已可调用的 `store_get` 名称。

运行时检查只处理索引是否在 `[0,len)`，独立静态核验还必须处理窗口来源和失效。reserve、pop、give、drop及未来替换均需与活动窗口冲突；两个参数名称不能证明两个容器不交。禁止经共享视图复制整个 Managed/Package 头。不能用隐藏RC、堆盒、全局表或未证 noalias 来稳定元素地址。首片可保持不逃逸、同步、只读；mut、任意孔洞、可保存切片和循环借出另立有限合同。

最小消费者要使用运行时输入决定索引，读跨模块 Item 的 Copy 字段，最后一次读后允许扩容；最近反例覆盖同源和未知来源别名、函数/闭包隐藏的写入、当前调用捕获地址、错误路径、越界trap及扩容后旧窗口。深/宽类型和每次实际展开工作必须先计费，不能按 cap 生成编译器槽。

### C：回调字段必须保留身份与责任

现有固定数组能保存一种自含具体回调，工厂返回 `impl Fn/FnMut` 也已有有限实现，但这不等于字段位置已经支持任意 `impl Fn`、异构回调或 dyn。先验证泛型 Package/别名正规化能逐层保存 source opaque identity、具体 ClosureId 与实际布局，避免机器环境相同就误认为两个工厂的源类型相同。

首片采用完整自含具体环境字段：其已有旗标必须与父字段责任一致，替换先保护新环境，旧环境只清一次。借入调用必须访问原环境位置，不通过值快照重置可变状态；正常/错误返回和 FnOnce 消费都要覆盖。捕获有活动外借、错误联合环境、递归工厂等现有限制不能顺带打开。

最小消费者：组件保存回调跨多次同步事件调用，中途替换回调；替换准备失败时旧回调仍可调用，成功后清旧捕获；最终整个组件释放。独立反例检查不同工厂opaque混赋、重复调用已消费FnOnce、部分环境整传和旧环境借片复活。

## 与三线一起保留的发布前置

| 缺口 | 下一次检查应回答的问题 |
|---|---|
| Win64 Store机器实现 | Linux x64证据不能外推。明确同一布局、分配ABI、错误及递归清理后跑目标代码；Wine只记兼容层证据，不能改称原生Windows |
| 共享头与混合捕获 | 本轮含头模块的Desc+Address混合回调明确Unsupported。进一步开放前，要跨具体环境/别名/helper重建每个捕获的读写和当前调用贷款，不能仅导出一个大写集合 |
| 可重赋值资源头 | 既有私有Package槽降低后的资源不能借为头；应在实际字段来源协议建立后处理，不能把临时副本伪装成原头 |
| 外部保留回调生命周期 | 同步保存回调不证明注销、重入、取消或drain。平台层开始保留外部回调前必须有明确的关闭及静止点合同 |
| 语言原始剩余探针 | 保留原159源码。直接资源数组与直接资源错误载荷涉及默认Desc/Managed模式，不能把Package包装器成功冒充原探针已经通过 |

完整 ZUI 的开发门不能由测试数量、一次组合程序成功或更短语法解除。下一轮仍应分别报告：新增有限能力、原样探针、真实消费者、未闭合前置，以及 Rust 四目标的实证/未测部分。编译提速研究继续单独推进，不与语言功能结果混计。
