# 046：把相关边界思想用于返回来源求解

本轮把附件中的“只传播相关边界”落实到现有 Rust 编译器的模块级返回来源求解。Analyze 与 Verify 各自建立调用依赖，并只重算摘要发生变化的直接使用者。最终独立核验、局部借用规则及语言接受语义保持原有合同。生产提交为 `a0532bdab298e4b0fac10f8ace311e77808d8691`，基线为 `493edcb0e2367ac7b8131a0c69893150356a0246`。

这修复了当前实现中的一处重复工作。它是通用的数据流调度方法；与论文的联系是分解复杂依赖的思路，尚不是 ZIL 对 Rust 的性能胜出证据。

## 论文出处与可移植的内容

截至 2026-10-23，[IMU 的 2026 Fields Medal 页面](https://www.mathunion.org/imu-awards/fields-medal/fields-medals-2026)列出 Yu Deng，获奖说明包含 Boltzmann 方程的严格推导、波动动理学与概率方法。与附件图切割最相符的原始论文是 Deng、Hani、Ma 的 [Long time derivation of the Boltzmann equation from hard sphere dynamics](https://arxiv.org/abs/2408.07818)：首次提交于 2024-08-14，本轮阅读 v3（2025-07-18）。获奖说明覆盖一系列研究，不应把这篇论文标为唯一的“2026 获奖论文”。

[论文 v3 PDF](https://arxiv.org/pdf/2408.07818) 的 §2.3（印刷页 19–22）解释如何把 molecule 切成子图，并保留跨界边的自由端/固定端，逐步化为可以局部估计的小块；§11（印刷页 99 起）用分层和简化模型组织切割。它处理特定碰撞历史图及相应积分估计，不提供任意编译器 CFG 的通用最小割或复杂度定理。

我们的工程推论是：先明确局部问题与边界摘要，再传播会实际改变使用方结论的边界变化。附件还包含相关切点、稀疏根索引、局部不动点和缓存的经验；本轮选择已有性能反例的模块返回来源传播。旧 gen/open/lease 与碰撞图专用分类没有进入当前编译器，也没有新建通用 ProofCutTree 框架。附件 SHA-256：`ac0817993630223fa1d215a1aa5d2433d5ecb6df63bf47aa279685c42ef4306b`。

## 具体改动及健全性

基线每次有函数返回来源增长，就重新求解整个模块。反向声明的单来源调用链要把参数来源逐层向前传递，全扫描产生二次重算，还会连带重算不相关函数。

新调度先检查每个函数一次，再按可达 CFG 中产生 Address 结果的调用建立反向依赖。调用者自己的返回类型可以是普通值：其内部地址事实仍消费被调用者摘要，因此仍必须入索引。摘要只保存返回值来自哪些输入参数，不携带被调用函数的栈位置。Analyze 使用集合与 FIFO；Verify 使用排序根向量与批次前沿，各自重建依赖与全部事实，不调用对方求证代码。

摘要有限且按并集单调增长。每次增长会安排所有相关消费者；已在队列中的消费者合并通知。队列清空时，每个函数的最终事实均已消费当前依赖摘要；这给出与全扫描相同的最小不动点。独立核验随后仍运行全部空来源、逃逸、候选事实、借用和 loan 检查。无根递归环依然拒绝；不可达的坏调用虽不进入来源依赖图，仍由结构核验拒绝。没有地址返回的模块保留一次扫描路径。

首候选 `1adccd0421336ed2e58c04eefa735d4261e1d3ca` 的 Verify 立即处理栈通知。交付前新增“一个调用者依赖 64 个叶函数”反例，实际观察到 129 次重证；改为处理完本批再消费下一批通知后为 66 次。该反例同时比较全部 Facts，旧全扫描为 195 次。反向 96 函数链在 Analyze/Verify 都是新调度 191 次、旧全扫描 9312 次。这里记录的是函数求解次数，不是墙钟加速比；多参数来源、稠密互递归图仍可能多次增长，不能把全部输入复杂度宣称为线性。

`max_analysis_steps` 限额没有提高。索引容量、边扫描、调度、根集合和实际函数求解仍扣预算，容量先检查再分配。Verify 两批前沿的额外表也先计费。减少工作可能使原来 ResourceLimit 的输入成功；某些极小限额也可能先支付新增索引成本而耗尽，资源限制并非语言接受语义。变更先记录于 [IMPLEMENTATION-0046](../changes/IMPLEMENTATION-0046.md)。

## 验证的范围

两个阶段分别保留仅供测试的旧全扫描参考，比较完整事实。它们复用各自原有局部传递，因此证明的是调度等价性；局部传递的正确性还由真实源程序、伪候选和跨函数借用回归检查。

实际限定检查包含 24 组确定性混合图、相互递归/参数置换、无根环、反向长链、汇聚、多个来源、非地址返回调用者、不可达坏调用、错误调用 ID、候选篡改和预算耗尽。`zil-driver/tests/impl046.rs` 从真实源码走到独立 Verify，并核对 wire 往返；现有跨函数借用和 loan 源码回归也执行。手填 IR 的图模型只标为调度事实证据。

最终生产提交的 `fmt`、Analyze 7 个单元与 11 个预算测试、Verify 42 个单元与 5 个编译失败文档测试、三个指定 driver 测试文件共 23 项，以及相关 crate 的 `clippy -D warnings` 均通过。没有运行正式全量门，也没有把作者测试当作独立审核。实际命令、退出码与日志摘要见 [作者检查收据](../evidence/impl/046/author-checks.json)。

## 基准合同

[固定输入合同](../tests/perf/impl046/contract.json)先于计时提交。基线为原始提交的独立源码快照，仅加入与候选逐字节相同的计时 example。两侧使用 Rust 1.99.1、相同 release 配置、相同默认限额；没有改变任何产品门。九个真实 ZIL 源样本在每次运行中都检查源哈希、函数数及完整 TypedModule+CandidatePlan wire 哈希，两版本全部相等。

Analyze/Verify 的输入准备放在计时外；Verify 的输入 clone 也在计时外。第三列重新执行普通源码→Verify 全链，包含语法、展开、闭包推导、类型、Analyze 和独立 Verify，不含 LLVM/原生链接或进程启动。它是预热进程内的完整 check 流水线，不是产品冷构建指标。每批交替两版本顺序，保留全部观察而不取最小值；首轮与最终候选分别保留身份。最终复测固定 CPU 8，但共享宿主不能视为独占受控机器。

所有样本的 median、p10、p90、IQR 与原始观察保存在 [配对测量收据](../evidence/impl/046/benchmarks.json)。p10/p90 为线性插值样本分位数，IQR 为 p75−p25；它们描述观察离散度，不是置信区间。

## 与 Rust 目标的本轮判断

| 目标 | 本轮证据与边界 |
|---|---|
| 同类安全 | 改动只调度既有传递，独立 Verify 保留；快慢事实、真实源码和伪候选反例通过。完整语言安全目标仍由主线资源/并发等工作决定 |
| 运行与内存同级 | 本轮不改生成代码；候选 wire 一致。没有测 ZIL 程序运行时间、峰值内存或编译器内存，不能增加优势结论 |
| 表达与演进更简单 | 无语法改动，不新增用户概念；整体维护优势未测 |
| 编译成本更低 | 相对 ZIL 自身旧实现，长链来源阶段有可重复收益；端到端收益较小，常见小例完整check仍退化且因果未确定。尚无同能力 Rust 编译器基线 |
| 至少一项实质突破 | 当前证明一处实现优化，不证明已经超过 Rust。Rust 本身已有成熟数据流不动点框架 |

Rust 的 [MIR dataflow 官方说明](https://rustc-dev-guide.rust-lang.org/mir/dataflow.html)明确描述格、合并和不动点框架。因此后续差异应由完整问题上更少的事实、更窄的依赖与可组合的核验边界形成，并以同合同净成本验证，而不把工作队列命名成新算法。

下一处优化应由主线真实程序的剖析决定：若单函数 CFG 重算或稠密 loan 索引成为主要成本，再处理局部前沿或稀疏根索引。长期缓存、通用区域树及并行求解目前没有足够收益证据，本轮不引入。
