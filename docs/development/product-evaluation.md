# 与 Rust 的同语义产品对照

本页定义如何解释证据；阈值和发布条件只读 [product-gates.json](../../validation/product-gates.json)，实际语言支持范围见[支持矩阵](../guide/supported-language.md)，排期在 goal。

| 维度 | 必须绑定的比较条件 | 不足以支持结论的材料 |
| --- | --- | --- |
| 安全与资源责任 | 同一成功/失败、别名、取消、清理合同；实际 Source、独立核及最近反例 | 单阶段接受、模拟器通过或仅 Analyze/Verify 相等 |
| 运行与内存 | 同布局、分配、地址稳定和错误行为；完整应用路径及尾延迟 | 单个 helper、排除封装成本、不同语义的 Rust 写法 |
| 编译 | 冷检查/构建、私有修改、传播修改；固定工具链/源码与依赖；完整请求成本 | 只报一个阶段加速，省略准备/缓存/恢复成本 |
| 表达与维护 | 同一真实程序从树到图、保存回调、独立删除、并发/取消的改动量 | 只数表面语法或把复杂性移入未计量的库合同 |

Rust 基线使用合理实践，包括索引、Arena 和适当安全封装；不能为了制造优势强迫额外开销。测量前固定候选、输入、方法与停止条件，保留不利结果和环境限制；循环压力通过不能替代并发协议的线性化与保活论证。

每次相关交付在同一精简验收里分别报告“实测支持、未测、仍未完成”，并指出是否满足既有量化门和可重复净突破。普通正确性增量不自动成为成本优势；有限能力验收不等于完整语言、B0 或 ZUI 达标。历史各批对照叙述通过[文档来源索引](../../validation/documentation-provenance.json)读取，不再累积一份按日期增长的当前报告。
