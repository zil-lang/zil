# 仓库组织与语义命名

## 目录按使用目的划分

```text
README.md                    项目入口：定位、构建示例、文档导航
AGENTS.md                    代理入口：接续顺序与必须遵守的规则
_zil_design.md               正式语言设计及稳定锚点
crates/  lib/                编译器、标准库；说明尽量贴近所属模块
spec/                       阶段接口、语法、诊断等稳定合同
policy/                     可执行的依赖和工程规则
validation/                 验收定义、固定输入、精简结果、来源索引
  inputs/<capability>/      真实验证输入
  results/<capability>/     固定源码的必要验收与独审
conformance/ tests/         按能力或不变量组织的正反例
examples/                   按用户场景组织的可运行示例
tools/                      按验证、研究、CI、交付等功能组织的工具
docs/
  README.md                 按读者问题索引
  guide/                    语言使用与实际支持范围
  development/              构建、施工、验证、交付方法
  decisions/                长期决定：问题、选择、理由、代价
  research/                 可复用研究：方法、适用边界、来源
```

根目录只承载项目入口、正式设计及构建/工具配置。示例使用说明留在示例旁，crate 内部不变量留在实现旁，避免另写一套中心文档。`spec` 是阶段合同，`policy` 是工程约束，`validation` 是如何判定及实际观察；这三者不存任务排期。

## 名称表达能力、场景或不变量

永久路径、模块、测试函数、工具子命令按行为命名。例如 `impl243_layout_tests` 应为 `owned_sum_layout_tests`，`G1.3.5-common-acceptance.json` 应位于相应能力组合的 `acceptance.json`，`examples/344/` 应使用示例实现的场景名。名字无法说明内容，通常意味着应先拆清职责，而非只去掉数字前缀。

任务号只用于 `goal:goal.md`、`task/<ID>`、任务分支 `.task/<ID>.md` 和历史来源字段；代码不能通过任务号决定行为、选择测试或推导类型资格。协议/ABI 版本、位宽、诊断码、已有稳定 case ID 与提交摘要有实际身份含义，继续保留。历史证据里的原路径、命令、失败与摘要保持原样，用明确的来源定位到原提交。

目录迁移同时处理真实消费者：Rust `mod`/`#[path]`/`include_str!`、Cargo target、fixture、测试筛选、脚本、CI、打包、Markdown。一组迁移按能力及其消费者闭包完成；不得靠漏选测试、放宽门或重复兼容文件通过。已有稳定 case ID 的改名属于接口迁移，必须单独核对外部消费者，不能全局替换施工号字符串。

## 文件的生命周期

| 产物 | 留在当前主树的条件 | 合入时处理 |
| --- | --- | --- |
| `.task` 过程合同、计划、进度 | 仅任务分支需要 | 合入前移除工作树文件，原提交保留可达；goal 只更新实时状态 |
| 规范与阶段合同 | 定义仍然有效的行为或义务 | 原位修改对应权威，不另复制一份“本轮规范” |
| 决定 | 存在长期选择、取舍或被否决的近邻方案 | 按语义主题写短决定；失效决定按 Git 追溯，不累积施工日记 |
| 验收和独审 | 精确绑定交付源码、范围及可定位证据 | 晋升必要精简结果；过程重试与原始日志走运行存储/历史 |
| 研究 | 有可复用方法、负结果或不可替代的冻结协议 | 用主题索引说明范围；旧测量不会因迁移成为当前性能结论 |
| 提案 | 尚有未裁决语义、接口或实验问题 | 任务分支先讨论；生效规则进设计/合同，理由进决定，过程留历史 |

不建立主树 `archive/` 来容纳所有旧过程，也不在每次交付另写一套 CURRENT、HANDOFF、NEXT 或批次报告。历史内容用固定 Git 提交和来源索引恢复。`changes/` 的旧提案包含具名规范附件和工具输入，必须逐项提取并修正消费者；目录仍存在不表示它是新的推荐写入位置。

## 防止回退与存量迁移

`python3 tools/check-repository-layout.py --base <本次基线> --delivery` 检查新增/重命名路径、新代码声明及主树过程文件；`--audit-all` 列出剩余旧编号。检查基线是实际 Git 提交，不是可以任意扩大豁免的名单。语义是否准确仍由独审判断。

存量源码、测试和工具按“拥有与借用”“泛型与编译期”“异步并发”“机器与ABI”“工具验证”这些实际能力分批迁移，保持原输入字节、测试选择/断言集合和受测源码身份。先提交机械迁名，再做功能修改，便于审查与回退。新目标优先并入现有语义测试集合，避免为每个任务增加 Cargo 测试目标。任务分解和完成状态只在 goal，本页不维护第二张进度表。
