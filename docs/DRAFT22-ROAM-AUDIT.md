# draft22：Roam 的实际作用与缺口

本轮的结论是：Roam 已能对新增的拥有字节组合执行独立语义差分，并把失败送入可重放、可缩减、可验证修复的同一队列；它仍未证明自己已经持续发现自然发生的生产编译器语义缺陷。质量通道的作用有实证，缺陷发现成效还不能评为充分。

## 现在到底检查什么

| 入口 | 实际对照 | 能回答的问题 | 不能据此推出的结论 |
|---|---|---|---|
| `session` | 真实热会话历史与独立冷会话 | 编辑、缓存、取消、预算和失败恢复是否一致；活动查询是否归零、Verify 是否实际执行 | 两边同源实现都接受时，不能单独证明程序语义正确 |
| `scalar-native` | 独立整数模型与真实 ZIL/LLVM 原生执行 | 有限整数、控制形状、CT、溢出和 trap 的结果 | 完整语言、全部优化级别或资源语义已覆盖 |
| `resource-closure-native` | 独立有限生命周期模型与原生程序 | 有限捕获、反复调用、消费及清理顺序 | 任意拥有对象、逃逸、并发或取消已覆盖 |
| `byte-buffer-native` | Rust 逻辑模型、独立 C 状态解释器、ZIL/C 各 O0/O2 | 同一字节动作序列在四类拥有载体中的状态、失败、保留与释放 | 存在通用 ZIL 降 C 后端，或这些程序已经完成性能对照 |

命令、协议和有界探索入口见 [Roam README](../tools/roam-rs/README.md)。这些入口共享原例、快照、队列和修复关闭流程；本轮没有另起一个不能接入旧队列的演示平台。

## 102 已补上的具体缺口

此前 `zil-byte-buffer-native/1` 只覆盖局部字节缓冲操作。本轮保留旧合同，新增明确版本 `/2`，把同一动作模型放入普通局部、Package 字段、保存的 FnMut 环境、保存的 FnOnce 环境四种载体。每个程序仍限两个缓冲槽、最多 16 个动作、容量最多 64；每 case 的 8 程序硬上限没有放大。

ZIL 一侧观察真实分配器返回的指针，并映射为本进程内的逻辑分配身份；跨进程比较逻辑身份及事件，不比较裸地址。失败扩容必须保留原内容和身份，成功替换必须按实际责任释放旧值，未知指针或重复释放不能成为正常事件。独立 C 解释器用有界数组解释动作，没有调用生产编译器的所有权实现。

固定矩阵执行 20 个程序、80 次原生观察，其中 6 个程序安排分配失败。另有无变异、无分配失败注入的 hunt：24 case、48 个唯一程序、192 次原生执行，结果为零自然 findings。为保留原成功动作的完整观测，随后按原确定输入分六组重放；这是原 48 程序的重放，不能再计作 48 个新覆盖程序。原 hunt 对成功尝试的临时产物清理策略也没有被隐瞒：作者收据逐项区分原始保留内容和后来补留的确定重放。

非作者另写了不调用作者模型生成的 literal 期望，覆盖四载体、负 reserve 不消耗失败序号、零容量替换、部分取走及重新填入、第三次增长失败、恢复后的新身份和错误清理。四个程序分别跑 ZIL/C 的 O0/O2，共 16 次实际原生观察。完整身份、命令和输出见 [作者收据](../evidence/impl/102/acceptance.json)及 [独立审核](../evidence/reviews/102/review.json)。

## 怎样评价“发现—修复”能力

本轮人工省略一次 push 后，故障经过 hunt、冻结快照重放、同性质缩减、错误修复候选拒绝、正确候选和七条固定回归后关闭。它证明这条通道会发现该类不一致，并且不能靠一个错误候选关闭问题。它是受控变异，不能记为自然编译器 bug。

103 的独立代码审核确实发现了两类泛型别名的名字捕获问题，原失败与修复均保留；这两个发现来自定向审核，不记入 Roam 的自然发现成绩。104 的 RSS 归因错误和研究采样控制器的完整性缺口也各记在实际发现渠道。不能把本轮所有质量工作统称为 Roam 的成果。

目前更准确的判断是：

1. 对会话状态，Roam 已是有实际作用的回归基础设施。
2. 对有限拥有字节，独立 C 差分与真实分配身份现在已经落地；覆盖比上一版更贴近新语言能力。
3. 对长期自然缺陷发现，当前证据仍不足。有限无注入运行零 findings 既不能证明没有 bug，也不能证明通道无效；需要继续扩大由真实语言能力驱动的输入域，并保留首次发现链。

## 仍然存在的覆盖边界

当前拥有字节域没有覆盖任意元素析构、拥有错误载荷、借入环境逃逸、任意分配器、通用图对象、外部长期回调、并发、挂起取消或 Windows。一般泛型别名和 CT 枚举目前由专项源/raw/wire/native 及独立审核覆盖，尚未自动变为 Roam 的随机生成域。

因此，不应以重复运行现有 48 程序代替新增能力覆盖，也不应把 C 参考解释器称为整个语言的第二编译后端。自然发现的可核对成绩仍须包含：原始非注入输入、原二进制和工具身份、同一失败性质、缩减过程、实际修复提交和非作者复核。未来对 Roam 成效的判断继续以这些产物为准。
