# 语言主线阶段进度与方向

本轮把优先级集中到能支撑 ZUI 的普通语言组合。环境已核对为 Rust/Cargo 1.99.1、LLVM/Clang 23.1.4，当前没有重装或升级工具链的必要。编译专项在本阶段只处理真实消费者遇到的默认预算阻塞；没有进行新的 Rust 编译速度比较。

## 已交付与正在验收

前一批 227/235/236/237/238 已通过源码、独立核验、O0/O2 和实际分配失败检查，随 PR16 合入 main。同步 defer、Product 中拥有 Store、泛型 Product 的完整身份和整值替换已经形成真实 Session API 闭环。

本批 239–244 接续普通拥有 Sum：非泛型枚举可以拥有多个资源或完整 Product，Product 可以拥有 Sum，错误载荷可以携带含 Store 的 Product。构造、移动、参数返回、消耗式 match、嵌套模式、整值替换、defer 和失败清理使用真实活动分支。普通 helper 的数据参数也承接这些值；callback 的拥有参数/结果仍是下一批能力。

本批仍在施工，当前已知阻断为泛型模板内 Desc 来源的失效与作用域闭合；尚未合入 main。最终共同候选和验收结果待收口后回填。原五模块消费者源码和预期冻结，开发验证已通过正常、错误、替换、早退及逐个分配失败路径。第一轮共同候选 P 的完整整仓结果为 3548 通过、12 失败，零忽略/过滤；原始产物已逐文件核回并归档。失败中包含需按已批准功能迁移的旧 Unsupported 断言，以及 helper 全链和 raw 类型资格的真实遗漏，均分别保留原输入后处理。

## 慢在哪里，如何调整

1. 之前的小切片能在各自阶段通过，却把真实组合的默认预算、跨模块调用和责任核门遗漏留到了集成。本批先固定一个五模块 API 和源码推导的预期，用它贯穿所有阶段；单独 Types 或 Verify 通过只计对应阶段。
2. 普通拥有资格与 capture、StoreElement、FFI 等资格曾共用分类入口，扩大普通 Sum 时容易误开其他位置。现在同时检查合法使用与结构完整的 raw/Wire 近邻，未用定义和不读取载荷的路径也必须核验。
3. 新语义会使旧负例变成合法程序。逐项依据规范迁移预期，保留原源码和 raw 构造；超出本批范围的负例继续拒绝。不能靠整体删掉旧测试消除红灯。
4. 完整消费者曾分别耗尽 Analyze、Verify 和 Codegen 默认预算。修复采用共享结构、收敛结果复用及按完整类型构建清理计划，实际工作继续计费，限额保持。两项必要的Copy资格检查以具名费用例外登记，保存旧/新精确额度及原样输入。性能结论只限于该消费者在默认预算内完成，不据此宣称整体提速。

实施继续使用 high，复杂责任核和非作者审核使用 xhigh。并行按互不相交的阶段源码划分，由 root 统一合同、候选与整仓验收；不把任务数量或重复执行次数当作进度。

## 下一项单一主目标

让同步拥有 Event/Reply 穿过具体闭包和公共泛型 dispatch，形成输入准备、调用、拥有结果与失败清理的完整责任闭环。实际原源码检查仍在 Types 拒绝拥有 callback 参数；裸 F 原样返回仍在 Expand 拒绝。现有 State<F> 完整转交后进入 Store 的对照已通过，避免重复开发已有能力。

之后推进 F 原样转交、Type/Syntax 声明式入口，以及外部 callback 注册、停止接收、排空与回收的完整生命周期。完整 1.4、全部 ZUI、挂起/并发和原生 Windows 验收仍未完成。

## 与 Rust 四目标的关系

| 目标 | 当前可以证明什么 |
| --- | --- |
| 安全 | 本批有限形状接受独立 Analyze/Verify、raw/Wire 和真实清理检查；不是全语言安全证明。 |
| 运行与内存 | O0/O2 行为、实际释放和失败回收可核，没有同语义 Rust 运行/RSS 比较。 |
| 表达与维护 | 自然 Session、状态分支和错误载荷可组合；完整框架维护优势尚未测量。 |
| 编译成本 | 默认额度保持，新路径真实收费，旧控制和新预算边界分别留证；没有 Rust 编译成本胜出结论。 |
| 实质突破 | 可用的语言组合范围扩大；产品级四目标合取和可重复净突破仍未建立。 |
