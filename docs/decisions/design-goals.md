# ZIL 设计目标、非目标与基线定位

> 说明：本文件为非规范性设计决策文档，记录 ZIL 立项动机、四项核心目标及与 Rust 基线的公平对比准则。规范性语言规则见 [`_zil_design.md`](../../_zil_design.md)，量化验收门槛见 [`validation/product-gates.json`](../../validation/product-gates.json)。

## 1. 四项核心目标

在相同可信计算基（TCB）边界下，ZIL 追求：

1. **内存与并发安全**：提供与 Rust 同等级别的内存安全（类型与初始化、范围与对齐、对象与子对象存活、防重复释放、防地址失效、防相交可变访问与非原子数据竞争），不得以任何“少量 safe UB”换取性能或便利。
2. **运行性能与内存占用**：与合理 Rust 基线保持同级；普通值保持内联布局，不默认引入 GC、RC、世代句柄、隐式锁、堆盒或全局对象表。
3. **源代码与全项目维护成本**：通过“复制描述不复制责任”与显式协议/资源模型降低图结构、回调、局部资源管理与演进重构时的样板与心智负担。
4. **编译效率**：在大项目冷编、温编、多点并发编辑与磁盘占用上具备实质性优势，同时始终坚持独立安全核验。

关键场景的结构性退步不得用全局平均数掩盖；所有产品数值门槛由 [`validation/product-gates.json`](../../validation/product-gates.json) 统一管理，不得在任务排期或工单中另定更宽标准。

## 2. 明确的非目标

ZIL 的静态安全保证**不承诺**：

- 任意图灵完备程序的必然终止；
- 运行期无死锁或无显式资源泄漏（但显式泄漏不得导致借入栈帧或短命 allocator 生命周期虚假延长）；
- 外部硬件设备的准时响应或高层业务事务逻辑正确性。

稳定图结构、独立可删身份、真实持续地址窗口与共享拥有均按各自显式协议提供，不为了统一抽象而强行退化为最大运行时成本表示。

## 3. 独立语言必要性与公平基线原则

独立语言必要性是立项与退出门，而非第五个最大化目标：任何语法或语义差异都必须影响真实语义、接口边界、编译边界或工程总成本，并能解释四项核心目标之一的净收益。仅更换关键字或表面词汇不构成新语言收益；反过来，某项能力可由库勉强模拟也不自动否定语言级抽象的长期价值。

与 Rust 对照时必须遵守公平基线原则：

- 允许 Rust 使用 `Cell`/`RefCell`/索引/Arena/安全封装与作用域执行等合理工程习惯用法；
- 普通拥有值与借入描述不得交叉错比；
- 编译器对照必须明确区分**同进程形态对比**（冷进程 CLI vs `rustc`）与**常驻会话响应延迟**（`--resident`），不得混用进程模型得出误导性结论。
