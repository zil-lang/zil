# 用语义组织永久资产

问题：任务编号与阶段汇报曾成为文件、模块和测试的主要身份；多份“当前”文档彼此冲突，迁出 `.task` 后仍没有解决查找、接续和重复权威。

决定：永久资产以能力、场景或不变量命名。文档按使用、开发、决定、研究分组，机器合同与结果归 `spec`/`policy`/`validation`；过程合同仅在任务分支，看板只在 goal。当前方法见[仓库组织](../development/repository-layout.md)，执行步骤见[工作流](../development/workflow.md)。入口只链接，不复制规则。

理由：代理可按当前任务读取最小相关上下文，用户能按问题查资料；合入物属于产品而非施工批次。只换目录而保留原任务命名、只删数字前缀或增建一个主树历史杂物目录都不能形成稳定身份。

代价与约束：迁移必须核完整消费者和选择集合。历史协议、失败和验收保留原源码/摘要，旧内容通过固定 Git 来源追溯；不能改写成当前通过。增量检查阻止新编号继续进入交付树，存量按能力闭包迁移并明确余项。正式接口/诊断/case 的稳定 ID 与来源字段中的旧任务号保留各自身份。
