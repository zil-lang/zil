# 仓库资产按语义归位

问题：施工号目录、过程报告和重复入口使实际规则、测试和状态难以定位；路径变动也可能使正式案例静默漏选。

决定：main 保留规范、源码、按功能命名的测试与示例、工具、当前有效决定、静态合同及必要的精简独审/验收收据。永久文件名按公开行为或不变量命名，不绑定任务/施工编号；已登记的稳定 case ID、诊断码、协议/ABI 版本仍可作为内容中的身份。`spec/` 放阶段接口，`policy/` 放依赖规则，`validation/` 放静态验收协议，`docs/decisions/` 放长期理由。实时状态只在 `goal:goal.md`，过程 `.task/` 只在任务分支。Git 保留历史及精确提交。`changes/` 提案逐件判定永久规则、决定、实验或历史价值，不整目录按名删除。

迁移条件：14 份旧正式合同的规则、产物、正反例、case、预算和完成判据先逐项迁到 `spec/`、`validation/` 等唯一位置，并让治理工具、CI 与干净克隆验证新结构。测试移动须给出旧新路径与内容哈希、执行/断言集合及引用闭环；漏选、缺字段、失败结果和零执行均不得 Pass。通过独审后最后清除 main `.task/` 和重复入口，不保留空转发文件。任务分支与审核对象在历史 bundle 中须可达。

代价：迁移期旧主树合同仍保留供比对，检查器必须说清当前读的是哪份静态源；布局收敛不改变语言接受性、性能阈值或产品门。本文只记录用户已定的长期边界；具体 14 项映射、分批顺序与过程证据在任务分支合同及审核收据中，不制造第二份主树施工计划。
