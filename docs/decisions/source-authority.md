# 计划、源码与决策的权威位置

问题：计划、任务说明和源码证据曾在主树留下多份状态，跨工作树接续会把旧快照当作实时结论。

决定：`goal:goal.md` 独占当前任务、分配、阻塞和状态；`main` 承载规范、源码、静态工程合同、当前有效决策和必要的独立验收收据。任务分支的 `.task/` 承载派工、写集、过程和交付。Git 提供可核查的源码与历史身份。`goal` 不合入 main，任务源码不合入 goal。原主树 `.task` 的生效义务已迁入静态合同，真实输入已迁到语义目录；过程记录退出当前文件树。`_zil_goal.md` 与重复任务索引同时退役，生成器和检查器直接引用当前权威。

理由与代价：一个实时看板避免并发覆盖；主树仍可在干净克隆检查正式合同。迁移期间有旧、新结构并存风险，检查器必须报告所读来源，不能把迁移后的缺件当通过。历史进度只按原提交解释，更新 goal 不会改变规范或验收结果。

分支生命周期：单次工作用 `task/<ID>` 和独立 worktree，验收合入且确认历史可达后退役；明确授权的长期研究可用 `research/<topic>` 保留自身历史。既有 `archive/<日期>/<来源>` 标签保持不可移动；新增源码备份统一进入固定 `archive/source-history` 分支，不再增加按任务或日期增长的备份引用。Bundle 导入先核真实 ref 与 SHA；已有远端分支只允许快进或确认已包含，分叉立即停止核对，不强推、不自动建兜底同步分支。Bundle 传输与代码集成分开，前者不代替独审或组合测试；`main` 的更新须由集成者完成真实验收。远端清理以提交可达、差异和审核收据为据，并按预期 SHA 操作。

历史来源：`.agent/goal-branch.md`、`.agent/workflow-handoff.md`、`.agent/git-branches.md`；实施细则见 `docs/WORKFLOW.md`，历史恢复见 `docs/DELIVERY.md`。
