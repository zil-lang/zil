200 的两个实参可不相邻；新双输入入口的其余参数限有限 Copy 或直接 Managed。结构 Copy FnMut 先形成各自真实临时副本，再分别转交；原值保持可调用。非 Copy 值的重复转交、活动 lending 与字段/父壳失效仍独立拒绝。双输入只保留其中一个字段时，未选环境也须实际清理。没有给这些拥有构造伪造空 helper 合同，Analyze 和 Verify 各自从实际类型及指令核验。

这里没有开放不同 F/G 的持久 State、含 callback 的 Store、两个 State 参数、State 加 replacement F、动态擦除、递归拥有或外部保留回调。原单输入路线的能力和精确 Expand 预算保持。

## 继续施工的优先顺序

1. **201：Store 元素拥有具体 callback State。** 原始输入仍被 StoreElement 前门拒绝。必须同时完成真实元素资格、闭包布局、前缀逐项析构、push 失败完整返还、pop 拥有转交及实际元素窗口调用，不能只放宽前门。提案见 [201-proposal](../changes/201-proposal.md)。
2. **不同 F/G 持久 State。** 类型绑定槽与真实参数角色不是一回事；同一个 State 参数只能被求值和转交一次。字段声明的调用模式必须独立于实际 ClosureId，完整名义身份和公共事实需要协同实施。
3. **完整抽象和拥有组合。** 一般 trait/关联项、life/HRTB、lending、固定 dyn 合同、一般 Product/Sum 及递归/异构存储仍须逐项闭合。
4. **声明式 UI 所需生成能力。** Type、卫生 Syntax、生成阶段闭合、源映射和格式化尚未完成；已有标量 CT 不等于 UI DSL 完成。
5. **保留、挂起与并发生命周期。** 外部 retained userdata、Active handler、Suspend/SABI、取消/关闭/no-future 及真实同步保留原义务。同步手写库入口与这些高级范围分别验收。

以上均不从完整 1.4 目标删除。ZUI 作为语言前置的消费者，本线继续实施语言，不将尚未运行的框架或产品宣称完成。

## Rust 四目标

当前有限范围有真实源码、独立 raw/Wire、O0/O2、故障清理和实际责任证据；全语言安全没有完成证明。实际行为、独立存储位置与分配平衡不等于同语义 Rust 运行时间或峰值内存同级。普通状态/回调 API 的组合能力增加，完整框架维护成本没有测量。编译成本属于独立支线，本轮没有相对 Rust 提速结论，产品门原字节保持。尚未建立同一冻结产品四目标合取或可重复产品级净突破。

## 离线交付

交付是标准完整 main bundle，入口 `refs/heads/main`，旁置 `.bundle.json` 绑定真实 source_commit/tree/SHA256。完整包无先决提交；所有可达祖先保留，不改写历史。新的机器产物、构建缓存和大证据不提交进 Git；新证据另附小于 50 MB 的附件。历史曾跟踪的证据随历史对象保留，不能在保留原提交身份的同时剥除。

具体导入、分支合并、冲突及验证命令见 [OFFLINE-BUNDLE](OFFLINE-BUNDLE.md)。本会话没有用户原一键脚本的内容，不猜测它的参数；标准 bundle 可作为其本地 fetch 来源。语言 main-only 包不冒充所有未合入研究分支的恢复包。
