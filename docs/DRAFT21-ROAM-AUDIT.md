# draft21：Roam实际作用与缺口

2026-10-25（Asia/Shanghai）。本记录区分实际执行、受控故障与自然缺陷发现，不以工具代码量或测试数代替有效性。

## 当前判断

Roam已经能稳定承载会话历史、有限语义差分、失败保留、冻结回放、同性质缩减及修复关闭，值得继续使用。但现有收据不能证明持续Roam已经首次发现自然发生的生产编译器语义缺陷。因此，“已是重要质量基础设施”有依据，“已经充分发挥缺陷发现价值、令人满意”仍缺依据。

此前用户强调的C差分在当前Rust编译器上并不是一个通用ZIL降C后端。098已补进真实字节领域的C参考，使这类差分进入现有hunt队列；范围必须按实际实现陈述。

| profile | 独立参照与实际执行 | 当前范围 |
|---|---|---|
| session | 同一真实CompilationSession的热历史与独立冷会话 | 编辑、缓存、取消、预算、失败恢复；不单独证明源语义 |
| scalar-native | 独立整数模型，对比真实ZIL→LLVM→native O0 | 有限整数、控制形状、CT/trap边界 |
| resource-closure-native | 独立有限生命周期模型，对比真实native O0 | 有限捕获、调用、消费和清理顺序 |
| byte-buffer-native | 独立Rust字节操作模型、独立C参考、ZIL和C分别O0/O2 | 有限reserve/push/fill/relay/reset、动态窗口和早返回 |

这些工具位于独立workspace，不改变语言语法、运行时权限或生产依赖。输入的完整动作序列是重放权威；seed不是失败原件的替代品。

## 098本轮实际完成

无注入hunt执行24个case、48个程序、192次原生执行，全部通过、0 findings。22项限定回归、格式和clippy通过。默认每case为2个程序，硬上限8个；每程序最多16操作。超限、零预算、invalid、error、unsupported与incomplete不能记Pass。详细身份见[作者结果](../evidence/impl/098/acceptance.json)与[独审](../evidence/reviews/098/final-review.json)。

root独审另写固定literal期望，核对16操作的完整状态、正常/早返回、非法第二步保留第一步、零时间和9程序超限。独立预期没有复用Rust模型或C预期计算。另检查仅破坏ZIL的push时C仍与模型一致，避免两个发射器一起错而对拍假通过。该组5case、12程序、48次native与作者运行分别计量。

人工省略push的失败完整经过记录、旧快照重现、同性质缩减、错误候选拒绝、干净候选与历史回归后关闭。这个实验验证检测与修复通道，不是自然编译器bug。先前host的profile硬编码问题属于工具基础设施缺陷，也不能计作生产编译器语义发现。

本轮没有启动无限后台任务；“具备持续入口”与“已经长期持续运行”不同。新编译器版本应创建新快照和新run，不能运行中悄悄换二进制。

## 最紧要的下一缺口

099刚新增的Package拥有字段、保存闭包、部分消费和错误清理尚未进入byte-buffer hunt。该域也未观察分配失败后的责任与每个真实指针的释放身份/顺序。现由099专项源/raw/wire/native和独审覆盖，不能把那些测试统称为Roam发现。

下一次扩展应直接复用已有字节动作模型，为同一操作序列增加普通局部、Package字段、保存环境三种载体，并接入明确的失败分配与释放观察；继续走原有队列，不另建测试平台。只有新run实际执行并保留可重放收据后才能登记完成。通用降C、任意资源对象、并发/取消、外部回调排空及跨平台长期运行仍不在当前覆盖内。

自然缺陷首次发现的记录至少需原始非注入输入、原二进制和工具身份、失败性质、最小化过程、修复提交与独立复核。未来用这条实际链衡量Roam收益，不用累计通过次数替代。
