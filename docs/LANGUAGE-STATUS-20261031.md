# ZIL 主线功能状态 2026年10月31日

当前源码核验基线是 `main=f2572502beb76eb86e9254dea855404e4998a64d`。对应[主线 CI 41198113948](https://github.com/zil-lang/zil/actions/runs/41198113948)已成功：25/25步骤，默认后端3027通过、0失败、0忽略，参考后端2983通过、0失败、0忽略。本报告核对该提交的规范、源码、测试和既有执行记录，**没有重新运行这轮CI，也不把两个配置的重叠测试相加为独立覆盖**。

## 剩余工作的推进顺序

1. **普通同步defer。** 先闭合注册成功后的履行义务，覆盖正常落出、return、`?`、break、continue，并明确借用保持、返回值准备及其与局部逆成功构造顺序的交织。FnOnce只保证至多调用一次，不能代替恰好履行一次。
2. **统一更一般的拥有组合。** 优先由真实公开API驱动Product内部Store、深层Store、拥有Sum/Option及variant切换，补齐来源、布局、初始化状态与失败清理；不只逐个放宽类型白名单。
3. **补足通用抽象。** 推进关联项、一般trait/lending、高阶参数与结果、需要运行时异构注册的dyn合同。已有静态trait和固定F/G家族不等价于开放组件系统。
4. **完成声明式生成链。** 从现有受限#if/#for推进Type/Syntax、生成trait/impl、卫生、源码映射与工具支持，形成真实ui!入口；手写程序成功不能替代这条链。
5. **闭合长期外部生命周期及异步并发。** 覆盖注册失败、停止接收、注销排空、重入、稳定帧、取消及最终清理，随后核验相应并发资格和平台行为。
6. **完成ZUI与产品验证。** 将语言前置用于实际框架，验证布局、文本、事件、渲染和关闭；用同语义Rust实现评估完整成本与演进。已有首窗和有限同步节点只是各自范围的证据。

这是按当前可施工前置排列的主线顺序；具备独立写集的工作可并行。编译效率研究继续独立，不以等待研究结果阻塞已具备前置的语言工作。

## 四个目标的当前状态

| 目标 | 已有证据 | 尚缺的结论 |
| --- | --- | --- |
| Rust同级安全 | 有限来源/权限、独立Verify、raw/Wire反例、真实资源清理及分配失败检查。 | 完整语言及全部组合的安全目标尚未建立，异步并发和外部生命周期仍有实质缺口。 |
| 运行与内存同级 | 内联环境与结构布局、真实原生行为及分配平衡；最近语言片没有新增隐式Box、RC、锁或世代表。 | 无法据此证明同语义Rust运行时间、RSS、尾延迟和全部目标场景同级。 |
| 语法与维护成本 | 多模块普通库能组合更多拥有状态、回调、容器和有限生成；一些原来误拒或无法表达的自然形式已打通。 | 有限表示仍需规避若干自然组合；完整ZUI、开放异构和实际演进成本尚未比较。 |
| 编译成本 | 直接LLVM Builder、显式对象缓存及既有工程优化在主线；新增语言片保留默认额度及具名预算检查。 | 预算未提高不等于编译更快；本轮没有Rust配对计时，独立研究结果不能提前算主线产品结论。 |

因此，**四目标同时满足及至少一项可重复的产品级实质突破尚未成立**。B0仍Doing，181继续施工；完整1.4/ZUI未完成，产品与原生Windows验收未完成。后续应以新增可表达的真实API、独立安全边界和同语义产品结果衡量进度，不按切片编号或测试数量计算完成百分比。目标条件保持在[Rust目标记录](RUST-GOALS.md)与[产品门](../validation/product-gates.json)。
