# 并行施工与交接计划

## 1. 分包原则

保留B0、T01–T09、W1–W4共14个顶层工单。按生产阶段和状态所有者分包，基础schema先统一；用W1–W3从源码贯通，防止各模块靠自制输入独立“通过”却无法组合。模块夹具允许提前开发，Ready/提验则必须满足实际前置。

## 3. 人手安排

本节描述正式移交后的顶层排程；当前B0内部准备切片的并行安排见第8节，不把内部切片当成正式T08开工。

四个代理槽位时，保留一个集成者，B0先独立；B0完成后先投T01/T02/T05三线，较早完成的槽接T04。之后按依赖投T03/T06/T07，全部资源模块验收后进入W1。若有更多施工槽，T04可以在第一波直接并行。

T08内部有CFG/协议、闭包环境、std图容器三个交付块，可由负责人在已有任务下按不相交文件分工；不新增另一套工单状态。共享注册文件和schema改动由集成者串行提交。T09在T08之后接管相交模块，不能以“任务名称不同”绕过文件所有权。

## 4. 第一波具体边界

| 任务 | 独占生产目录 | 必须交出的可用接口 | 最近错误样本 |
|---|---|---|---|
| T01 | zil-syntax | 未核CoreModule和源映射 | 歧义/错误接收者、非法#、重复求值转写 |
| T02 | zil-types | TypedCFG、类型与receiver/capture形状 | 函数指针丢环境、opaque多隐藏类型、trait候选自证 |
| T04 | zil-db/driver/cli/ide | 查询结果、失效闭包、native run入口 | 损坏缓存伪已核、CLI/IDE语义分叉、脚本隐式执行 |
| T05 | zil-verify | 私有Verified/VerifiedCTIR包装 | One/Many伪证据、缺清理边、未知操作、外部构造已核值 |

消费方不能为方便另写一个近似schema；B0的字段要求不够时由集成者更新正式接口和消费者清单。普通内存调用保持Rust函数与紧凑数据，不引入RPC/JSON热路径。

## 5. 贯通场景怎样消除隐藏依赖

W1只做两模块工厂、条件选择/管理route、完整包移动、关闭和失败清理；闭包保存属于T08/W2。这样W1可以先证明资源基本链可施工，再扩展高阶能力，不出现文字上的依赖环。

W2承接全部新语法与闭包：正文捕获、move/责任、调用能力与状态、匿名环境返回、`.field`词法绑定、记录更新、管道和native脚本；同义核心写法需保持求值与退出行为。W3承接真实OS完成根与取消；不以SC模型或设备模拟替代真实平台结果。

## 6. 案例和命令

每单JSON的`case_ids`指向已有规范源，`plan_case_ids`指向未来需实现的运行/协议夹具。后者共有明确required_fixture与可观察行为，B0建立runner后按本单命令执行；缺fixture不能跳过。当前所有这些状态均不表示已运行。

```sh
python3 tools/check-plan.py
python3 tools/check-plan.py --self-test
python3 tools/check-plan.py --print-hashes
```

这三条是本设计包可执行的计划工具命令。前两条验证结构/有意破坏的计划输入，第三条给派工摘要；它们不运行ZIL。

施工后按每单命令执行真实runner，例如：

```sh
python3 tools/run-cases.py --task T08 --manifest validation/task-test-plans.json --out-root evidence/T08
python3 tools/run-cases.py --task T08 --manifest conformance/index.json --out-root evidence/T08
```

第二条仅在该单拥有源样本时运行；若误选出零case必须失败，不能当“无需测试所以通过”。每次追加新的RunId，保留错误样本与实际计数。

## 7. 对完成的限制

不能仅凭目录、类型定义、接口名字或文档检查把模块标Done。T01需真实parser，T02需真实类型/CFG，T05需独立核验，T06/T07需实际候选/机器行为；W1–W3需真实源码贯通，W4需先冻结并实际测量同语义基线。所有任务必须保持本单写集和已验收输入，跨模块缺陷回到原模块返修或由集成者明确移交。

## 8. draft10 后的历史施工入口

当前已贯通：有限Copy数据与公共泛型模块、纯CT、一层共享/独占地址、标量C ABI和动态输入；047–049资源责任与正常清理；051–053资源闭包Fn/FnMut/FnOnce及环境转交；054有限原生生命周期hunt。不能继续把这些整块列为未开工。未完成的完整高阶、错误与资源合同仍按正式DAG推进，内部切片不擅自将B0/T08标Done。

四个槽位保留一个root；公共接口先用最小可跑提交发布，前置满足即并行。作者完成后立即交叉审，不让同一作者审核自身安全核。graph研究/标准库准备可占暂空槽，避免相交核心写集。若生产TypedIR抽取显示边界过宽或本来不是热点，保留反例并缩小入口，不用窄链模型收益强推通用替换。

拥有聚合、替换和部分构造明确后再扩环境参数/返回/保存与嵌套；动态容器、完整图、SABI、挂起/取消和并发继续服从正式依赖。现规范§18默认不支持impl specialization；该候选只作为trait求解研究问题，不因模型中有候选表变化而改动语言。

原生Roam的新profile复用既有持续发现和独立修复通道；可长期单独运行，但本轮只实际执行有界任务。源码/模型/原生执行/受控变异分别记账。每包一branch/worktree与独立target/out；作者限定测试、非作者精确审核、root统一正式门。历史失败保留原身份，包不携带target及成功临时bin。

语言保持1.3/A，问号、局部move、@等候选不变。每轮按[Rust四目标](RUST-GOALS.md)报告实证与缺口；完整语言NotSatisfied、产品门NotRun和B0 Doing保持到实际条件成立，不以速度或测试数量替代结论。
