# 设计迭代：以终态为目标

语言仍处施工阶段。以安全、表达、阅读一致性、运行成本和编译成本评价方案，不以旧源码兼容为保留机制的理由。能够吸收Rust、Zig及其他实现的成熟方法；每次采用必须说明解决的实际问题和成本，不能因新技术名称就扩大机制。

本文件说明迭代流程，不另设语言规则。当前主线是 ZIL-LANG-1.3/A；问号的三个候选见 `docs/OPTIONAL-REFERENCE-DISCUSSION.md`，018 实验未合入。某一候选已实现、已有测试或曾提出版本号，都不等于设计已经被选定。

## 一个修改的完整路径

1. 在`changes/`写短提案：问题、候选或选定规则、最近正反例、受影响阶段和仍不支持的边界。尚未裁决的候选并列使用同一用例矩阵，明确待决定的问题；无需为每个实现细节新建设计层。
2. 对仍待比较的方案，在独立分支做限定实验，记录精确源码身份与实际结果，不提前改写主线规则和完成状态。规则选定后，集成者更新唯一规范及其具名附件、实际接口版本和工单摘要；作者按固定写集直接修改当前实现。被替代方案撤出当前语法，不维持兼容双轨；历史提交仍可用于复查。
3. 让相同源码经过真实阶段和目标程序；独立oracle/核验与最近反例同时运行。缺实现准确报 Unsupported，基础设施失败单列。parser 接受、类型通过与原生运行是不同完成范围。
4. 未参与本片实现的审核者绑定精确提交复核，集成者合入并执行必要整合门。失败原件保留，不能覆盖为修复后的 Pass。未通过或退回的实验继续保留候选身份，不计入当前语言能力。
5. 更新一页当前状态、接续入口和可运行示例。长期探索由`zil qc`缺陷队列继续提供反例；修复流程消费同一 case，并在回放与回归通过后追加关闭记录。

规范、实现、受测提交是不同身份。终态修复可以修改现有源码和接口，不以兼容旧输入为目标；也不因“无需兼容”就跳过规则选择或独立验证。新规则影响并行任务时只迁移受影响者；未相交任务继续施工。先完成一个可执行纵切片，再扩宽能力范围，不为追求一次设计完全部细节阻塞实际闭环。

## 求解器采用原则

优先有限、可计费的数据流和显式状态边界；固定点在预分配节点上增长。类型约束先收集再默认，避免遍历顺序决定接受性。来源传播、活跃性和独立核验分别承担职责，不能用一个启发式结果制造安全权限。引入新求解算法前提供当前反例或可测成本；算法替换保持公开合同与独立复核义务。

长期测试工具是一等开发工具；语言保留字仅在普通工具/库协议确实无法表达所需语义时讨论。持续runner不自动改源码，修复消费者领取缺陷、修改代码、回放和回归，通过后追加关闭记录。发现、修复和证据保存因此能够独立并行；该机制是否已经可运行，以对应提交与验收记录为准。
