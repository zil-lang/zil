## Remaining findings

1. **Qualified constructor query still deep-clones before payment.**
   `zil-types/src/enums.rs:735`, `enum_constructor(&self)`, returns `ty.clone()`.
   The actual ordinary Builder call at `lib.rs:1961` reaches this before
   `make_variant:780` reserves its two output copies. The member constructor path
   at `lib.rs:1817–1818` calls the query twice, and `known_type:2254/2258` also
   reaches it. `expr_raw` has no preceding per-query full-Type reservation.
   Namespace installation and helper-context snapshots pay for their own copies
   once; they do not cover an arbitrary number of later query clones. Borrow
   the installed Type or meter every actual new qualified clone before it occurs;
   do not hide ResourceLimit in an Option-returning query. Root and the assigned
   Types author were notified.

2. **SourceFact rejects actual Unit-variant construction.**
   `generic_source_life.rs:1184` accepts only `VariantFields::Tuple` and returns
   Unsupported for `Unit`. Thus the source chain for
   `enum E<life a>{Empty}` / `E::<'a>.Empty()` cannot produce the complete enum
   Fact, although the producer/Types support zero payloads. A bare member follows
   the generic member/field path and also does not establish its Enum Fact.
   Unit construction needs the same genuine declaration and full actual vector,
   with zero payload evidence. Producer notified.

3. **SourceFact does not project enum patterns.**
   `generic_source_life.rs:549–583`, `bind_inner`, handles Name/Tuple/Reference
   only. Matching `E.V(v)` therefore never binds `v`'s declaration/payload Fact.
   For `E<life a>{V(Leaf<'a>)}`, returning `v` as `Leaf<'a>` or passing it to a
   qualified consumer reaches Unknown and is rejected by `compatible`.
   Engine's later `enum_pattern` update does not repair this earlier source
   pass. Reconstruct each actual variant's payload facts from the original
   declaration and full actual vector; accepting Unknown would lose the source
   class proof. Producer notified.

4. **Type-only Enum with qualified Type actual is absent from SourceFact inventory.**
   The Enum inventory at `generic_source_life.rs:1728–1733` includes only enums
   with their own lifetime formal. For `E<T:Copy>` carrying `Leaf<'a>`, `head(E)`
   is `Head::Plain`. Comparing actual `E<Leaf<'a>>` with that same annotated type
   misses the Plain branch because it requires `!expected.has_class()`, then
   reaches Unsupported. `variant_call_result` also cannot select its declaration.
   This is the explicitly required old type-only Enum → new qualified wrapper
   path. Preserve genuine declaration/actual identity without inferring classes
   from a generated name. Producer notified.
