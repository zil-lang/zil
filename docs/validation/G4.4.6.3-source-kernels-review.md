## Blocking findings

1. **Enum signature publication still searches only Records.**
   `generic_stored_nominal.rs:498–505`, inside `storage_header`, pays only Record
   names and selects only `BorrowedStorage<Record>` from produced instances.
   A real `Choice<'a>` parameter or result first produces its Enum instance and
   then fails with `stored nominal instance output absent`. The new Enum
   constructor path cannot close the promised Source signature chain. Select
   either nominal storage kind and retain the same complete instance/class
   checks. Author notified; an uncommitted fix was reported during review.

2. **Payload hint substitution captures caller life labels.**
   `generic_enum.rs:94–99`, `source_field_actuals`, inserts Type actuals and then
   applies the nominal's life substitution throughout the result. For declaration
   `E<life a,T:Copy>{V(T)}` and caller actuals `E<'b,Leaf<'a>>`, field `T` becomes
   `Leaf<'a>` and is then incorrectly rewritten to `Leaf<'b>`. Caller `'a` has
   become the declaration's `'a`. This affects tuple constructors and the new
   `source_record_field` helper. The checker at `generic_check.rs:551` correctly
   applies declaration life substitution before inserting caller Type actuals;
   the producer needs the same separation. Author notified and reported a local
   ordering fix.

   The same capture mechanism also needs closing in compound physical fields:
   `generic_stored_nominal.rs:118–149` inserts original caller Type syntax, then
   recursively resolves it while `nominal_life_bindings` contains the enclosing
   declaration's formals (`:818`); `source_life` gives those formals precedence
   (`:582`). A field `Wrap<T>` with caller `T=Leaf<'a>` under enclosing formal
   `'a → 'b` therefore resolves the inserted caller label through the wrong
   frame. Direct `T` selection already has a full-ordinal qualified-actual path;
   compound applications need equally explicit source class ownership.

3. **New allocation work is not consistently prepaid, and ordinary Enum fees
   change.** `zil-types/src/enums.rs:214–225` deep-clones every enum payload before
   calculating and subtracting snapshot work. Even a request without any new
   qualified instance incurs this new constructor-inventory fee; the previous
   implementation did not debit it. `:751` also adds an unconditional complete
   output type clone before the existing constructor branches. On the producer,
   `stored_types.rs:1312–1320` collects both payload reference vectors before a
   field-count reservation, and `generic_stored_nominal.rs:156–163` reserves the
   map tuple but clones a variable-depth path without reserving that path.
   Reserve complete work before growth, and isolate old all-Type paths or record
   an explicit approved fee migration with original-source N/N−1/fresh evidence.
   `_zil_design.md`'s aggregate budget contract requires prepayment and preserves
   old profiles except its named exceptions; these new unconditional Types fees
   are not one of those exceptions. Root notified.
