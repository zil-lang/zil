  producer classifications. Different supplied roles join to mixed; equal
  ClosureId does not identify runtime instances. Ordered complete bindings,
  joint event traces and child substitutions retain the real parameter ordinal.
  Type keys use inline two-slot storage or a paid immutable extended vector;
  runtime storage never gains Rc/Box/locking from this compiler metadata.

  cannot retry. The cyclic fallback independently requires a real cycle and
  complete reachable graph. Analyze keeps a paid deduplicated queue bounded by

  conditional cleanup settles only the actual local position. Return requires

  user teardown must be the exact actual Direct Desc-to-Unit entry, with real
  nominal resource identity. Ordinary calls/function references cannot invoke
  teardown. Analyze invokes its existing resource ledger after stored-flow
  derivation; Verify invokes its separate resource ledger at module end.
- The single-role environment lender's parameter/captured-target life contract
  does not invent a result row. Both stored-flow kernels independently recover
  complete returned BorrowCapture field sets, compare lending_captures exactly,
  and project those fields through the current actual receiver. Result loans
  retain that receiver and parent chains; live receiver replacement or another
  exclusive call rejects. FnOnce environment lending stays closed. Lower and
  LLVM consume the checked module and preserve the existing pointer ABI.
- Analyze authenticates scalar C declarations, canonical immutable parameters,
  empty foreign body, unique symbol, absent noescape/callback claims, exact
  actual argument/result types and lexical unsafe stacks. Ordinary Call cannot
  impersonate ForeignCall. Verify retains its separate general foreign
  declaration/call/region checks. These scalar leaves provide no pointer,
  owner or retained callback permission.
- New tables, role scans, snapshots, keys/COW and cyclic revisits are charged
  before growth. The independent helper-origin record changes from u8 to a
  16-byte role/flags record on this host. For the legacy tail's 16 actual slots,
  each kernel's table costs 240 additional units. This is a recorded physical

## Concrete remaining boundary

Design profile196 explicitly permits several actual runtime positions from the
same callable generic. The captured-Fixed frontend still counts callable
receivers against generic declaration count in
`generic_stored_nominal.rs:223`, selects only one matching generic role and rejects
a second in `generic_callable_context.rs:202–216`, and Types independently rejects
two contexts for one Type ordinal in `helpers/source_life.rs:356–381`.
Thus `dispatch<life s,F:Fn(&Tag<'s>)->i32>(f:&F,g:&F,h:&F,x:&Tag<'s>)`
cannot use the new context lane even when the same shared closure is legally
supplied three times. Existing three-same-F non-Fixed tests do not prove this
qualified case. The author acknowledged the source consumer gap; this is an
acceptance gap, not an unsafe acceptance. A successor must bind context selection
to both original generic ordinal and actual parameter position, retain independent
runtime class namespaces, accept lawful shared alias and retain mutable-alias
rejection. Merely deleting the ambiguity check is insufficient.

Ordinary Value `give F` remains rejected by the original language rule. New
capture kinds, multi-role lending, general storage/dyn/async combinations and
persistent environments are not authorized by this finite consumer review.
Actual safety/source composition and accounting improve; Rust-equivalent
runtime/RSS, compilation/maintenance cost and a product-level net breakthrough
were not measured. Parent completion and formal root acceptance remain open.
