# G4.4.6.2 production review — source authentication

Reviewer: `/root/ct_source_auth`. Reviewed production commit `4d38c5db16757171c0cf9dbb3a5bd2b71f58173f` in isolated branch `review/g4.4.6.2-source-auth-4d38`. Author-tree untracked tests and later commits were excluded. Static review only; no builds, Source executions or heavy tests were run.

## Blocking findings

1. **P1: successful request is substituted for a successfully executed host call.** `execute.rs` retains every static `source_bindings.calls` entry after the whole VM invocation succeeds. `invocation_context_static_host.rs` proves a corresponding IR Call exists, but has no VM execution/normal-return evidence. `compiler_cfg.rs::expr_if` emits both successors even for a constant false condition. Thus a CT request equivalent to `if false { Host::<...>.make() } else { 7 }` retains the host call although the VM never executes it; an otherwise type-correct `make` containing a division-by-zero operation distinguishes this case from a successful host call. The new namespace eligibility contract requires the actual host call to succeed. Keep the ordinary runtime rejection gates; add an internal VM normal-return occurrence receipt tied to exact caller/block/instruction/callee and the independently reconstructed original call. Author acknowledged the finding and is implementing this; that WIP is outside this reviewed commit.

2. **P2: new AST traversal work is charged after traversal, including failure paths.** `execute_static_host.rs` first calls `ct_selection::item_cost` for source and actual host, then reserves the sum; `modules.rs::NormalizedRuntimeCt::check_static_host` likewise computes `item_cost` before charging. Two trees each costing S can both be traversed with a remaining balance between S and 2S before the later reserve fails, leaving that visited work uncharged. Counter failures do not propagate spent work to the shared meter. Generated-span remapping also returns its work only after traversing, then the caller charges. Replace these with a prepaid/shared-meter visitor, or reserve a valid known upper bound before traversal and settle afterward, preserving failure spending.

## Examined safeguards

- Actual host/member AST pointers are recovered through immutable original/generated inventories, complete original Call arguments and lexical parent IDs; generated catalog/emitter validation is invoked again.
- Driver checks the retained complete source Item after the required generated-span remap; the normalization bridge replays the normalizer and compares the entire resulting Item. Unsupported additional transforms and retained-member deletion correspondence fail closed.
- The namespace checker registers all retained sibling functions before independently checking their universal bodies; receiver, unsupported attributes/contracts, declaration bodies and non-function members are explicitly rejected.
- Both runtime instantiation paths retain rejection gates: `instantiate_inner` and `stored_nominal` reject aggregates with methods. These observations do not remove finding 1 and are not execution evidence.

Conclusion: **not ready at this exact commit**. Resolve the actual-call success binding and prepaid failure accounting, then bind independent Source/nearest-negative/native/quota evidence to a fresh clean commit.
