# G2.4.1.2 · Life and Option type path

Base `56e19764654de9428eaf52f991200b87973cb50e`; parent contract `.task/G2.4.1.md` and `changes/G2.4.1-trait-lending-iterator.md`. This slice owns Expand `lifetimes.rs` and Types life/Option/call consumers. Shared public schema and standard library Source belong to integration; trait method definition checking belongs to G2.4.1.1.

The existing G3.4.1 source producer in `generic_stored_nominal.rs` retains `Option<&'a T>` as a qualified Option with a `Result` class tied to the input outer address. `stored_types::Catalog::publish` installs the existing `StorageLifeContract` and clears the flat `CoreLifeContract`; this requires no public schema change. The sealed Option nominal instance carries the actual `Some` variant shared address slot. Both kernels must still prove a real source root and receiver loan.

Implementation opens the life declaration gate for ordinary trait methods with method-local life binders, and for generated life-only or Copy/life method providers whose original trait obligation remains in the `where` clause. The generated provider name is an internal spelling unavailable to Source. G2.4.1.1 remains responsible for the finite trait shape, associated Item:Copy, alpha-equivalent impl relation, and body source check.

The canonical Source first exposed a narrower class-production gap at `Option::<&'p T>.Some(&self.values[i])`: the Source checker preserved a declared class when indexing an Address(List), but discarded it when a mutable receiver Address selected an inline array field before indexing. The new `generic_source_life.rs` branch recovers that class only from the actual receiver address and its actual nominal field declaration, and only when the field is a List. It does not obtain a class from the desired result type or establish a runtime target; generic definition checking and both kernels retain those obligations.

The first fix still saw `Self` as an unresolved plain source name because source-class validation runs before trait-method lifting. The follow-up retains the actual impl target in a sparsely populated private function inventory and resolves `Self` through that target when checking its source fact. The resolved target must lead to an actual nominal declaration before a field can contribute the array shape. Source fact cloning and impl-target map insertion are charged; old non-impl rows keep their earlier budget fee.

Symbolic generic `next_copy` exposed a second Source origin gap. The checked trait method has a declared invocation-local result life and the actual call holds its receiver address loan, but the existing alias lane discarded all loans for an Option result. The new alias path keys the selected method to its actual Call callee, filters held actual inputs by that method's declared result-life input set, and creates a shared child loan with the receiver's parent chain. Only a canonical `Some(name)` payload binds that child; `None` does not. Match, if-let and while-let use the same payload hook. An Option local's own storage position remains distinct from its tracked payload referent, so borrowing the Option container cannot masquerade as borrowing the cursor.

Types now checks the sealed Option in two phases: initial Core inventory may carry a nonempty unresolved nominal pointee, while resolved inventory repeats the complete shape/Copy proof on the actual structural type. During enum resolution, the compiler Option actual is compared with its original declaration field before imported nominal names are expanded. A generated provider in another module may resolve a physical Option enum only when the producing module has a matching compiler-tagged stored instance and its complete inventory authenticates that declaration. The project constructor index separately matches the resolved physical Enum with that sealed stored instance before treating it as an imported constructor; a `$stored_` spelling is only a work prefilter. No Option annotation supplies a source loan. An unknown symbolic `Some(name)` payload fails closed; transparent alias patterns use the same real Option check; nested `Some(ref slot)` remains explicitly Unsupported because its extra address layer has no borrowing consumer.
