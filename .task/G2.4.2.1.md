# G2.4.2.1 · Symbolic static trait host and definition checking

Parent: G2.4.2. Frozen base: `18d481e16db77d38144ca575bb9843b679cd6a7c`. Contract: `changes/G2.4.2-draft-foundations.md`. This branch owns `generic_check.rs` and the private `generic_trait_static_host.rs` classifier. The G2.4.2 author wires `generics.rs` and implements provider selection/rewrite; root owns public and native consumers. This slice is implementation pending joint validation and independent review.

The classifier recognizes a current lexical type binder with an exact declared method bound and returns its origin-backed trait reference, selected method signature, and symbolic host type. A local value with the same spelling takes precedence. Nominal hosts retain the existing constant host parser and fee path. Unbounded symbolic hosts, ambiguous declared methods, and type arguments on a type parameter fail during definition checking.

`generic_check.rs` uses the classifier before evaluating a member-call object as a value. Its existing bound method rule then checks ordered method-local type and value arguments, substitutions for `Self`, declared method bounds and where clauses, result shape, and source-order argument evaluation. A static call has no receiver, records the exact trait call target even with zero method-local type binders, and cannot use a receiver method through a type host. The original receiver method path continues through the same rule. A concrete nominal type host in a generic definition obtains a unique committed static method or supported recipe through `Index::definition_static_method`; the ordinary static function argument/where/result checker receives the real trait origin for visibility.
