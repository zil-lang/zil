# 闭包编译差距复核与匿名函数链接改进

基线 main `947063a63880b375889ff30b3beba6151abf55f3`，精确受测源码 `1e4ff8229275463f318975b07fa9fabf509728c2`；生产候选 PR79 / `9cf0e95d8108c82f0cb3ebf91075a60c6707332e`，源码树 `65a48d418a7165ef7b15cfa05b6d66388bfadb09`。本报告记录有限阶段证据，不把全部闭包性能目标标为完成。合入状态以 PR 和 goal 收据为准。

## 具体差距，不归因于抽象的“图算法不够快”

旧直接常驻运行42818577639的owned32函数体编辑均值447.199ms，LLVM优化202.347ms、发射181.542ms；二者约占86%。只改前端调度，即使完全消除其余开销也不足以达到同组Rust194.490ms。请求8单元实际2单元，命中的对象仅480字节，主体46736字节对象重编。

当前实现的边界逐项可定位：

1. `crates/zil-types/src/incremental.rs::keys` 对聚合类型、枚举、模板、非标量签名、callable return等返回None；旧标量函数Types依赖复用没有覆盖目标拥有闭包链路。不能把顶层Types=executed解释成全语言都无缓存，也不能把标量成绩外推到闭包。
2. `machine_object_patch.rs::signature` 和Snapshot保守限制整数参数、外部函数及无一般类型/全局的机器模型，闭包指针/结构环境不符合。删除限制而不绑定环境布局、清理/effect/ABI和符号依赖是不安全的，当前没有这样做。
3. `machine_cgu.rs::partition_view_once` 将内部辅助函数与其所有引用者强制合组，之后才按源文件/256函数块分桶。对真实owned32机器IR回放这条规则，109个定义中的99个已在同一局部链接连通分量；仅调小分桶数字不能分开它们。共有内部helper不一定代表必须共享的可变数据，但当前算法不作区别。
4. 匿名闭包体按external输出，调用者内联后仍保留独立定义，重复消耗优化/机器码发射。诊断42826582815独立单模块O2输出中，ZIL保留71定义，Rust6定义；这只是形状诊断，不是实际Rust增量CGU数，也不能用定义数估计耗时比例。

因此zit式点对点依赖/早停有用，但前提是节点粒度和依赖合同确实覆盖闭包，且后端没有再把它们合成一个巨大失效单元。现有成果没有形成完整的端到端闭包增量链路。

## 本轮实际改动

借鉴Rust `rustc_monomorphize::partitioning::internalize_symbols` 在分区之后检查跨单元实际使用的方式，只对已验证ClosureDefinition指定的匿名普通/大型ABI体收紧链接可见性。具名源函数不动；跨单元调用、函数地址、全局初始化和优化导入体引用均参与判断。传出的地址仍指向唯一原实现，不复制函数；重复定义保持给原机器预检拒绝。

只有linkage改变，不添加noinline、cold、noalias或生命周期假设，不改捕获布局、清理顺序、默认限额及独立Verify。API和Clang都消费转换后模型；Clang单单元路径同步修正为使用实际转换结果而非分区前诊断侧文件。对象缓存已有测试确认链接属性参与机器模型指纹。生产只含三个源码/测试文件与一份长期说明，不含本报告或研究工作流。

## Rust失败合同对照更正

原Rust语料使用Vec::push，分配失败不能像ZIL的append一样返回false并让闭包返回-1。因此此前将它们笼统称为全失败路径同语义不准确。旧结果保留；另开独立补充轨道，在同一Rust输入上用可恢复try_reserve_exact、容量至少8/按倍数增长和溢出检查后push，再与同组两版ZIL对照。正常输出逐项验证，但不宣称标准库、分配器和所有故障行为完全相同。此轨不计入原八样本加权成绩。

## 运行质量的有限通过与父目标未通过

原活跃长循环30格全部不超过相对原版10%的新增退化，候选/原版延迟比0.9666–1.0478；原主矩阵覆盖的8/32闭包及扩展16/24闭包共24格也达到Rust90%吞吐。新增空/少活跃邻近16格的相对延迟比0.9947–1.0078，没有此前noinline候选的明显新增退化。

但两个原始完整报告的runtime_gate_pass仍为false，绝不改成true：64闭包的6格及空/少活跃10格，在原版和候选都不满足Rust90%目标；本次没有新增跨过该90%线的失败格。64闭包候选吞吐约为Rust64%–89%，仍是严重的既有产品缺口。阶段可依据正确性、原冻结主矩阵净收益和新增退化界限单独裁决；整个闭包运行质量及G10.5父任务不能通过或关闭。本报告不是用局部通过替代全目标。
