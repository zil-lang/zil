## 输入与前置

B0 的阶段接口、结果状态与工具链 profile；当前实现的 bootstrap 阶段用于真实基本贯通，后续阶段按冻结接口接入。

## 实现与交付

实际查询依赖与各类指纹、缓存损坏重建、取消；CLI/IDE 共用语义入口。native run 仅生成普通入口包装，不开启隐式 GC。

driver 组合已完成阶段快照，不维护第二套安全判断。native run 的顶层语句与模块、导入和错误边界按规范包装；宿主GC/桥接不成为首发隐式依赖。缺阶段输出必须 Unsupported，不以缓存命中或空结果冒充完成。

## 接口交接

输入产物：`schema.v1`、`runner.v1`、`bootstrap.v1`。输出产物：`query-driver.v1`、`native-run.v1`。字段与可信访问方式见 `spec/interfaces.json`。产物名存在不等于已完成，交接须附实际版本、源码提交与构建证据。

## 验收命令与样本

B0 建立统一 runner 后执行：

```sh
python3 tools/run-cases.py --task T04 --manifest validation/task-test-plans.json --out-root evidence/T04
```

已有规范源样本由 `case_ids` 指向 `conformance/index.json`；仅当本单列表非空时再运行：

```sh
python3 tools/run-cases.py --task T04 --manifest conformance/index.json --out-root evidence/T04
```

`plan_case_ids` 是本单必须补齐的运行、故障注入或协议样本，完整要求在 `validation/task-test-plans.json`；夹具实现状态以 manifest 为准，实际执行证据见 evidence；不能把已写 fixture 直接计作通过。已有 `.zil` 文件继续保留规范预期，实际成绩另记。runner 必须实际选择并执行所有登记样本，零命中、缺 fixture、零断言、Unsupported、ResourceLimit、超时和基础设施失败均非 Pass；预期拒绝必须核对阶段与理由，不接受任意失败。每次生成新的 RunId，不覆盖旧证据。

## 完成条件

- 各指纹实际控制查询重算；私有编辑、公开合同编辑与源位置变动有可见差异。
- 缓存损坏、版本不匹配与取消不产生伪已核值或半写成功记录。
- native run 与显式入口代码语义一致；CLI/IDE 对同一输入返回同一语义诊断。

## 本单边界

不改所引用规则和profile。不把 IR 夹具、手工 lowering 或依赖策略检查冒充真实源码贯通；不恢复旧世代方案、不隐式加入 GC/RC/锁/堆盒。共享 schema、根 Cargo/工具链、其他写集变更须由集成者记录关联变更，不能以实现便利暗改接口。正式状态以本文件 JSON 为准；已有独立准备实现不解除依赖或全包验收条件。
