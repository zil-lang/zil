# Borrowed Package ByteBuffer metadata queries — proposed finite contract

Read-only design for G3.4.15. No implementation is accepted by this document. The next implementation baseline must be the root's shared integration candidate, not the old Package-return worktree. Source inspection: Package667; independent reviewer also checked the current 5aa implementation. No Cargo was run for these probes.

## Existing proof and missing consumers

Types resolves bytes_len/bytes_capacity through an actual Desc<ByteBuffer> argument and produces i64. A managed Package field accessed through an address becomes the actual AddressField(index) followed by DescribeAddress; the owner is not copied. Verify independently authenticates the sealed ByteBuffer resource, descriptor operand and result type. Existing resource ledgers propagate actual PackageField(index) descriptions and check owner/field liveness. Package667's helper bridge copies the selected argument's existing live description.

Both stored instruction profiles and transfers currently omit ByteBufferLen/ByteBufferCapacity. LLVM's stored comparison prepayment table also omits them, though its existing emitter implements the two actual header i64 loads. Analyze's pure-stored return skips the ordinary pipeline; merely enabling the opcodes and adding scalar no-ops would omit both the independent resource ledger and the actual read-versus-exclusive-window check.

## Private weak origins, not active loans

Use Byte-specific private origin alternatives, held in a private field or sparse flow only under a dedicated byte-query profile and exact ByteBuffer description checks. Each alternative preserves one complete Permission (targets plus its own parent-loan IDs). It remains weak, is excluded from active-loan collection and public Hold projection, and creates no fresh loan or responsibility. Do not derive physical paths from coarse resource-ledger roots or candidate Hold rows. Do not alter the existing Option store_description lane or the global Permission merge rules.

| Actual producer | Weak query origin |
| --- | --- |
| DescribeLocal of a real Managed<ByteBuffer> local | Actual Local root, no loan |
| DescribePackageField of an actual Managed<ByteBuffer> field | Actual Local plus the authenticated physical Field(index), no loan |
| DescribeAddress of an actual Address<Managed<ByteBuffer>> | Copy complete actual pointer targets and parent-loan ancestry |
| Actual Desc<ByteBuffer> formal parameter | Its real Parameter index, no loan |
| Store / Load / snapshot | Carry complete Byte alternatives, with paid full target/path/parent copies |
| CFG join | Concatenate alternatives with full exact deduplication; never union parent IDs between alternatives, even if their physical targets are equal |

No fallback from an empty pointer to any available weak origin is allowed. Missing or unsupported producers must not acquire authority. Capture, foreign/indirect execution and descriptor-return transport remain outside this first slice unless their complete actual substitution is supplied.

The new Byte alternatives do not participate in either kernel's active-loan collection or public Hold projection. Both kernels retain their full existing claim checks; no Byte-specific claim bypass is needed. Option and other descriptor behavior remains unchanged.

Construct alternatives from the completed actual pointer solution, not an intermediate growing parent set that could be mistaken for stable delegation. Preserve them in every relevant local/value state, snapshot, merge, solution comparison and paid fixed-point inventory. Missing origins must fail at final completeness. At a query, check every alternative independently with only its own ancestry exemptions. Do not flatten them before cross-function instantiation. A loan-ID intersection alone is also insufficient to preserve common indirect ancestors precisely.

## Actual read at the query and across helpers

Each query requires nonempty actual alternatives and invokes the existing stored use_permission(write=false) / independent Verify access(write=false) separately for each alternative against the current active windows. Parent ancestry must authorize a description derived from the current exclusive parent. An older shared description must conflict with a subsequently established overlapping exclusive parent. Separately, the resource ledger must reject moved, dropped, cleared or invalidated owner/field descriptions.

Record an extremely narrow private actual-query read set in each kernel's fixed-point summaries. Only actual Len/Capacity operations and actual Direct calls propagate it; local owner reads are checked locally, and only Parameter-origin effects are exported. At a Direct call, instantiate each effect from the callee's actual parameter category: Desc<ByteBuffer> selects the actual weak description lane; Address selects the actual pointer/address and then appends authenticated inline projections. Preserve every actual origin and each alternative's correlated parent ancestors; do not export callee-local loan IDs as effects. Check each instantiated alternative against the caller's current windows, and propagate remaining Parameter effects upward. Do not pretend that every descriptor argument is read: ignore(desc) has an empty actual-query effect and remains legal beside an exclusive window.

Also propagate a scheduling-only reachable-query marker, since a function may query only local owners and export no Parameter reads. Read-effect and query-marker state must distinguish fully covered/final-empty from omitted, masked-out or not-yet-converged. A default empty summary is not proof that a callee ignores its descriptor. If a query-bearing edge crosses into an ordinary/Task/closure domain without an independent read substitution in this slice, reject explicitly; do not manufacture coverage or enable Task/Option. Unrelated mixed paths proven to contain no reachable new query keep their existing behavior. All actual incoming execution edges to a query-bearing or query-relaying function must be covered. Unsupported FunctionRef / closure / indirect escapes must reject explicitly instead of bypassing the Direct-call read substitution. Existing unrelated closures and Task/Map paths keep their original admission rules.

## Scheduling and fees

Analyze inventories only the two query opcodes during its existing paid instruction pass, validates their exact operand/result and canonical resource, and schedules its existing resource ledger once after successful actual derivation in the pure-stored path. Existing mixed outer-ledger execution must not be duplicated. Existing head_descriptions and actual BorrowLocal seeds suffice; do not globally invent new roots or enable a Task/Option feature.

Verify keeps its independent byte-buffer instruction checker and unconditional resource ledger, adding only the two stored consumers plus its own private weak-source/read-effect proof. LLVM adds exactly the two scalar query variants to its existing comparison prepayment table before consumption. Existing ByteBuffer mutation/relocation, Copy, class, parent and ownership rules stay in force. Prepay new origin construction, target/path clones, set search/comparison/publication, fixed-point read effects, call instantiation and incoming-edge inventory. Existing full-payload snapshot work covers the old weak permissions; the new Byte-specific alternative storage and comparison need their own prepaid inventory, without charging the old work twice. Measure new N/N-1/fresh/warm boundaries without raising Limits or rewriting unrelated old budgets.

## Required controls

- Direct &job and Package identity/pick_second windows: real len and capacity metadata, refs value 7, selected manager only, both backends at O0/O2; nonempty backing gives observable query values.
- Old shared Desc -> new overlapping &mut Job kept live after query: precise actual-read conflict. A description derived from that current exclusive parent: legal via ancestry. Different owner/field and a finished exclusive window: legal.
- CFG mixed old/shared and current/exclusive-derived alternatives (both runtime flags): reject the unsafe possible source without laundering delegation. Both branches derived from the same current exclusive parent (both flags): legal through each alternative's own ancestry.
- ignore(desc) beside exclusive: legal even with another actual query enabling the new profile. read(desc) and two-level relay(desc) beside exclusive: reject at the caller using actual read effects. Same helpers without conflict: legal.
- A two-descriptor helper reading only parameter1 must permit an exclusive window on the ignored parameter0 owner and reject a conflicting selected parameter1 origin.
- Owner/field drop, take, clearing or retirement after descriptor creation: reject on actual liveness; unrelated owner cleanup remains legal. Independent raw/Wire mutations preserve candidate metadata and change only a real spare cleanup/target to the held owner, then refresh only the fingerprint.
- Raw wrong descriptor type, result type and sealed resource identity/definition: reject independently. Shared head metadata queries never grant mutation authority. Existing external stored-leaf writes, mutable upgrades, slot/class, parent, Task/Map and constructor/spent controls remain.
