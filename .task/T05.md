## 输入与前置

B0 固定原始数据/证书 schema 与阶段ID；候选可先用标注为模型夹具的输入，完整真实来源由 W1 对接。

## 实现与交付

有限证据核验、VerifiedModule/VerifiedCTIR 私有构造接口、反序列化重检与变异拒绝；不依赖 types/analyze 求证函数。

crate 必须 forbid(unsafe_code)。只共享原始 schema、格式和算术定义；核验安全结论必须有独立实现。新节点尚未支持时 fail closed，不通过未知字段或默认分支授信。CT 验证是 T03 的生产前置。

## 接口交接

输入产物：`schema.v1`、`runner.v1`。输出产物：`verified-ir.v1`、`verified-ctir.v1`。字段与可信访问方式见 `spec/interfaces.json`。产物名存在不等于已完成，交接须附实际版本、源码提交与构建证据。

## 验收命令与样本

B0 建立统一 runner 后执行：

```sh
python3 tools/run-cases.py --task T05 --manifest validation/task-test-plans.json --out-root evidence/T05
```


`plan_case_ids` 是本单必须补齐的运行、故障注入或协议样本，完整要求在 `validation/task-test-plans.json`；夹具实现状态以 manifest 为准，实际执行证据见 evidence；不能把已写 fixture 直接计作通过。已有 `.zil` 文件继续保留规范预期，实际成绩另记。runner 必须实际选择并执行所有登记样本，零命中、缺 fixture、零断言、Unsupported、ResourceLimit、超时和基础设施失败均非 Pass；预期拒绝必须核对阶段与理由，不接受任意失败。每次生成新的 RunId，不覆盖旧证据。

## 完成条件

- 依赖门与实际 Rust 构建证明未导入 types/analyze 求证实现。
- 全部控制边、窗口/责任事实和 CT 允许操作有核验路径；变异夹具能触发具体拒绝。
- Verified 构造权、只读访问和缓存解码路线符合 interfaces.json。

## 本单边界

不改所引用规则和profile。不把 IR 夹具、手工 lowering 或依赖策略检查冒充真实源码贯通；不恢复旧世代方案、不隐式加入 GC/RC/锁/堆盒。共享 schema、根 Cargo/工具链、其他写集变更须由集成者记录关联变更，不能以实现便利暗改接口。正式状态以本文件 JSON 为准；已有独立准备实现不解除依赖或全包验收条件。
