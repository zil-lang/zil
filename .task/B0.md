## 输入与前置

本包规范及附件；实际仓库和目标环境。由施工入场记录精确 commit、Rust/LLVM 版本、target、依赖锁和工作区状态，不继承旧 Zig 项目的完成标记。

## 实现与交付

在新 Rust 实现仓的正式 crate 流水线上，从一个真实算术源文件经过语法、类型、候选、核验和 LIR 生成可运行原生产物；同时建立错误链、公共 schema、精确工具链和统一 runner。未实施能力显式 Unsupported。

B0 是唯一串行引导任务，暂持最小正式链的生产目录写权。只实现该链实际需要的节点和行为，其他接口给有类型的 Unsupported；不另建一次性编译器。schema 全形状先冻结，语义能力按阶段实现。runner分别处理main进程退出码和具名函数的完整类型返回值，超过255的结果须由原生harness读取，不能截为shell状态。B0 完成后各生产目录移交对应模块；公共 schema、根 Cargo 和工具链后续由集成变更单串行处理。

## 接口交接

输入产物：实际环境与规范输入。输出产物：`schema.v1`、`runner.v1`、`bootstrap.v1`、`target-profile.v1`。字段与可信访问方式见 `spec/interfaces.json`。产物名存在不等于已完成，交接须附实际版本、源码提交与构建证据。

## 验收命令与样本

B0 建立统一 runner 后执行：

```sh
python3 tools/run-cases.py --task B0 --manifest validation/task-test-plans.json --out-root evidence/B0
```

已有规范源样本由 `case_ids` 指向 `conformance/index.json`；仅当本单列表非空时再运行：

```sh
python3 tools/run-cases.py --task B0 --manifest conformance/index.json --out-root evidence/B0
```

`plan_case_ids` 是本单必须补齐的运行、故障注入或协议样本，完整要求在 `validation/task-test-plans.json`；夹具实现状态以 manifest 为准，实际执行证据见 evidence；不能把已写 fixture 直接计作通过。已有 `.zil` 文件继续保留规范预期，实际成绩另记。runner 必须实际选择并执行所有登记样本，零命中、缺 fixture、零断言、Unsupported、ResourceLimit、超时和基础设施失败均非 Pass；预期拒绝必须核对阶段与理由，不接受任意失败。每次生成新的 RunId，不覆盖旧证据。

## 完成条件

- 精确工具链与目标 profile 已记录，真实算术源经过全部正式阶段并返回预期结果；类型/语法错误不产生可运行产物。
- Verified wrapper 构造权封装于 zil-verify；解析/反序列化只能产生候选，编译测试证明下游不能直接构造已核值。
- runner 支持两个已登记 manifest，零选择、缺 fixture、未执行和 Unsupported 均非 Pass；提交所有 PLAN-B0 用例的实际结果。
- 公共 schema 与产物协议已供 T01/T02/T04/T05 复核，原始阶段产物和产物哈希进入证据。

## 本单边界

不改所引用规则和profile。不把 IR 夹具、手工 lowering 或依赖策略检查冒充真实源码贯通；不恢复旧世代方案、不隐式加入 GC/RC/锁/堆盒。共享 schema、根 Cargo/工具链、其他写集变更须由集成者记录关联变更，不能以实现便利暗改接口。正式状态以本文件 JSON 为准；已有独立准备实现不解除依赖或全包验收条件。
