# 221 作者交付的 Rust 四目标反思

本记录只总结 221 的有限作者实现和实际运行，不替代非作者审核、root 的最终组合回归或既有 `validation/product-gates.json`。完整 1.4、全部 ZUI 前置及产品门没有由本片完成。

| 目标 | 本轮实证 | 实际限制 |
|---|---|---|
| Rust 同类安全 | 单 F 拥有工厂从真实源码到独立 raw/Wire 和机器清理闭合；同型不同值、重复责任、伪造合同和未调用 FnOnce 定义有对抗控制。发现 direct Store 伴随参数隐藏额外 callback 的真实误接受，保留原输入及修复前后记录。 | 只覆盖冻结同步 profile。Verify 不调用 Types/Analyze 求证；有限测试也不证明完整语言安全、长期保留、挂起或并发。非作者组合审核待 root 安排。 |
| 运行与内存同级 | 两轮不重叠的 20 次普通 LLVM API 产物运行，以及另 22 次 allocator 观察产物运行；O0/O2、6 个实际分配失败均按预定顺序清理，最终 live 为 0。四种模式的额外观察没有新分配；callback Store 的内联元素步长为 40 字节。 | Store 的 80/160 字节是请求 payload 峰值，不是 RSS。没有同语义 Rust 的运行时间、峰值内存或尾延迟配对，不能宣称同级或更快。 |
| 表达与维护更简单 | 一个普通公共泛型工厂可以把按值 F 变成新的 opaque 环境；跨模块两层组合、三种调用能力、输入即时清理/消费、State/Store 保存和同步地址参数都有源码与运行证据。 | 只增加可组合的有限语言能力，没有测量完整框架演进和维护成本；一般 F 原样返回、开放异构、一般 trait/lending 和声明式 Syntax 不随本片完成。 |
| 编译成本更低 | 新手填和源派生 raw/Wire 分别实测精确 N=2919、N=16559，N−1 仅 ResourceLimit，fresh N 身份一致。三个固定旧源的 Analyze/raw/Wire 基线完整保留，root 的初次组合对照相同。默认限额不变。 | 精确费用控制不是运行耗时或 Rust 编译速度比较，也不证明所有旧输入零费用回退。最终候选旧源重放及正式全量由 root 执行；编译速度研究支线独立。 |
| 至少一项实质突破 | 普通公共 F→新 opaque 的拥有组合已成为可运行、独立核验、可在错误路径准确清理的工程增量。 | 本轮没有建立产品级四目标合取或可重复的产品净突破；没有降低既有产品门。 |

精确证据入口为 `DELIVERY.json`、`raw-boundary/RESULT.json`、`legacy-budget-baseline/RESULT.json` 和 `source-native/{RESULT.json,ROUND2.json}`。手填 IR、真实源码、普通产物和额外观测产物分别记账；两轮源码测试的重放不与根集成或独审次数相加。旧规范摘要、实际测试编译器身份及一次编译过程中生产文件更新导致的无效收据均按原身份保留。
