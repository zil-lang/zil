## 新增的实际能力

`store_at(store, index)` 从真实初始化前缀取得共享 `&Item`。LLVM 先用 `index < len`
的无符号比较同时排除负数、空前缀和末端越界，再计算真实元素地址。跨模块
helper 可读公共 Copy 元数据，Managed 字段不暴露，Package 整头不被复制。

实际 Store local 或 Package 的 `Local + Field` 是窗口来源。175 的组合正例在
读取 `State.left` 时替换 `State.right`，最后一次读取后再替换 left 并移动完整
父壳；同字段修改、整字段取出、父壳移动/消费及提前 Drop 均拒绝。helper 的
两个参数名不证明分离：实际 left/right 可通过，left/left 被拒绝。原始候选把
right 描述改指 left 时，即使公共 Hold 粗根相同，独立核验仍重建字段并拒绝。

旧字段描述不能在替换或父壳移动后恢复窗口；作者同时提交源码拒绝和绕过
Analyze 的 raw/Wire 反例。Copy 子字段地址捕获继续受实际 loan 保护，错误参数
准备会正确结束临时窗口并只清理前缀一次。

本片没有可变视图、任意孔洞、直接视图捕获或视图派生地址返回。含共享 Package
地址的函数若返回 Address，仍保守 Unsupported；同模块无关的合法地址返回函数
有原生对照。没有扩大一般 `is_address_pointee`，没有 RC、堆盒、全局表或未证 noalias。

## 证据与真实失败

`commands/focused05` 是最后 66 项限定运行；`commands/cli-build02` 与
`commands/consumer-command02` 绑定同一个干净源码提交。`consumer/` 保存实际
CLI 构建、优化等级、每次 stdin/stdout/stderr/退出码和分配记录。其 O0/O2 阶段
IR、接口、候选、已核结果、LIR 与 LLVM 实际输出一起保留。`field-stage-example/`
另保存真实不同 Store 字段组合的阶段输出。可执行文件仅记哈希，不存入本证据。

失败记录没有覆盖或删除：

- focused01 为 5/14，暴露 LLVM 三处地址表示准入漏接，以及作者可见性夹具分号
  和消费者重复 foreign 声明；修复后的 focused02 为 14/14。
- focused03 在 rustc 编译阶段遇到 `StableCrateId` 碰撞，执行测试为 0；只清理
  本树 target 缓存后恢复。该次是基础设施失败，不能记成语言拒绝。
- focused04 为 19/20。raw 提前父壳 Drop 的夹具后面还描述父字段，所以先被普通
  初始化核验拒绝。保留该候选与真实诊断，并改用仅剩元素窗口读取的更近反例；
  最终仍要求 `E-BORROW-CONFLICT`，没有将预期放宽为任意拒绝。

`artifact-manifest.json` 是保留文件的字节哈希；`all-case-stage-hashes.json`
记录未重复存档的全部 175 阶段输出。历史命令里的绝对路径只标识原运行位置。
源码交付压缩包应按 Git 收录源码、测试与工具；本目录及其他证据单独归档。

## Rust 四目标与未闭合条件

安全目标增加了有限 Store 元素窗口、实际字段分离、别名约束、错误清理及
独立 raw/Wire 核验的实证，未建立完整语言安全结论。实际指针布局、真实
分配/释放与失败保持得到验证；没有进行与 Rust 等价程序的运行时间、峰值内存
或尾延迟比较。多模块运行时遍历与 State 持有容器的组合能力已落地，维护成本
优势没有测量。编译成本支线独立进行，本片没有性能比较或产品净突破结论。

动态前缀可以在不消费元素的情况下遍历，是本片明确的工程进展。Linux x64
之外的 Store 机器实现、一般可变/逃逸窗口、混合捕获和外部回调关闭协议仍未
完成。完整语言 `NotSatisfied`、产品 `NotRun`、父 B0 `Doing` 保持。
