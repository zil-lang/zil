## Source-derived consumer oracle

For input n in 0..3, let old be the sequence D onward with n Items and fresh be M onward with n+1 Items. Each callback owns its real Tag: original H, replacement K; State owns Z. On main success, prepared replacement storage is complete before old storage is replaced, then H is replaced by K, so stdout is `old + H + Z + fresh + K`, exit 0. Failed initial allocation(n>0) gives ZH, exit 1. Failed replacement allocation gives `Z + old + H`, exit 1: old data and the original callback survive and are used again. Failed growth retains new children and produces the normal success output, exit 0. In field_exit, taken children and callback locals drop before the remaining State Tag, giving `old + H + Z`, exit 1. Invalid input 9 gives empty output, exit 9.

The main normal allocation-call count is `int(n>0)+2`: optional initial Store allocation, replacement Store allocation, and growth realloc. Logical block creation is `int(n>0)+1`. Failure injection stops at its selected call and leaves no live allocation. field_exit makes `int(n>0)` Store allocations. Items' ByteBuffers are empty and allocate nothing in this consumer; callback environments remain inline. Therefore the consumer allocation count does not cover allocated byte payloads. The independent BytePanel test supplies that narrow check separately. These are behavioral checks, not Rust runtime/RSS or compilation-cost comparisons.
