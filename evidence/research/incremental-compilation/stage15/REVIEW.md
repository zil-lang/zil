## Compiler changes

- [Work-aware lowering](../../../../changes/research-work-aware-parallel-lowering.md): the existing compact-leaf qualification is unchanged and remains pure. Private prepared records come from the current immutable LIR, are sliced by the scheduler's original batch start, and are consumed in the same function order. A serial decision also consumes the prepared results, including known misses. Remaining work is counted by the actual fixed 64-function batches; thresholds only select workers and cannot reject source. Intrinsics, ordinary diagnostic order, joining and current verification remain unchanged. The revised real-source jobs control contains enough non-summary, non-leaf work to exercise the new parallel gate.
- [Partition layout reuse](../../../../changes/research-partition-layout-cache.md): the key includes the current machine items and order, target, compiler identity, entry/count/policies and the exact LIR fields read by planning. The old planner and receipt replay share final construction; index ordering, canonical ownership, prototypes, imported clone naming and direct-call-only rewriting retain their old behavior. Decode is bounded and validates indices, kinds, ordering, ownership, named types and import cost. Current declaration-prelude validation and complete native-unit preflight remain. The receipt is trusted local producer data, not an independently checked graph proof or a defense against a writer replacing both payload and checksum.
- [Filesystem discovery reuse](../../../../changes/research-project-discovery-cache.md): every source is read currently and every recorded import edge is resolved currently, including repeated aliases. Added ambiguous files, missing paths, canonicalization and confinement still reach the original resolver. BFS order and cumulative source/token/node accounting are preserved. A mismatch returns to ordinary parsing using successfully prefetched immutable bytes; cancellation does not retry. The complete exact semantic candidate still runs current independent Verify. Pending receipts require successful downstream processing and a fresh full source/output/receipt artifact plan.
- [Function-scoped Types work products](../../../../changes/research-function-semantic-incremental.md): inference and shape resolution follow the previous prepared-input path, including its complete Limits check. Global declarations, signatures, resource effects and visibility are recomputed. Keys bind the current declaration/import/visibility/FunctionId universe, target, every Limits field, parameter names/types/modes, foreign ABI promises and each eligible body's structure with relative spans. Foreign/unsafe or otherwise unsupported bodies execute normally without disabling unrelated eligible helpers. Unsupported declaration domains still conservatively disable the slice.

For Types reuse, successful entries contain raw scalar CFGs, not Verified values. Function, local and instruction spans are rebound to the current origin; malformed or out-of-range spans miss. The six shared accounting counters are monotone in the eligible domain. Replay checks every addition against the current remaining allowances before changing any counter; otherwise the original builder executes and produces its original first limit diagnostic. Per-function limits are bound by the complete key. Closures, templates, resources and other shared-state-producing body forms remain excluded. A failed request restores the preceding in-memory epoch; successful Analyze/Verify rejection handling retries once with the same immutable sources and disk semantic reuse disabled. Cancellation, I/O and resource-limit failures do not trigger that retry. This is bounded scalar CFG reuse, not complete cross-edit language-semantic incrementality.

The optional layout destination is registered through the existing physical artifact-overlap checks before publication, then checked again after observer callbacks and output publication. A conflict discards only the pending layout. Semantic/function/discovery cache publication retains current source/output protection and cancellation checks. Failed requests do not publish new work products. No cached result replaces current ZIL Verify or native-unit preflight.

Two material findings were resolved before freezing: the original all-project fallback on a foreign declaration/unsupported body would have disabled Types reuse in the actual I/O fixtures; and Types success followed by downstream cancellation needed restoration of the preceding epoch. The extra layout metadata destination also received explicit source/output alias protection rather than relying only on directory permissions.

## CI recovery and delivery

The reviewed recovery code rejects unsafe/duplicate paths, file/directory conflicts, unexpected/missing/duplicate blobs, inconsistent sizes and SHA mismatches. Restoration requires a new directory. Log recovery requires exact ordered chunks, compressed size/hash and an END marker matching the archive index. Main and PR triggers preserve distinct official/research LLVM workflow identities and concurrency groups; evidence recovery does not suppress compiler-test failures.

A successful fallback step establishes **local archive verification and emission only**. Before merge, the integrator must retrieve the exact run's logs, reconstruct the archive and verify it against the expected run and checkout. Evidence from successfully uploaded earlier phases that were subsequently cleaned is still part of the required evidence set; the fallback contains remaining files and cannot replace those earlier artifacts. The revised [CI evidence documentation](../../../../docs/CI-EVIDENCE.md) states this distinction. Log truncation or missing retrieval therefore remains a delivery blocker even if local emission succeeded.

The runner's optional `edit-warm` request extends the existing history and records that request list; it does not change wait4 timing or create an additional independent cold history. No Stage15 speedup, universal Rust advantage, general runtime equivalence or completed product gate is inferred from this source review. Final measurements and exact-head CI must be reported separately, including adverse observations and the distinction between official LLVM and the research LLVM build.
