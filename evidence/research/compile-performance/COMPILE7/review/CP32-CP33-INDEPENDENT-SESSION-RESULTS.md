# CP32 / CP33 完整会话窗口独立复算

审核：cp25_evidence。两窗的完整性、身份和统计复算均 **Pass**。性能判断分开：**CP32 不采用；CP33 在有限公开编辑和完整七请求序列上出现正向收益，但预先冻结的四请求主混合指标仍有不确定性，尚不默认采用。** 五区块 bootstrap 仍为探索性统计，不是正式 product-gates 的变更或替代。

## 完整性与固定口径

CP32 精确提交 `3ba131efdeffe85ba5fccd1c177745d812a6ce61`，窗口 `/tmp/zil-compile7-cp32-session`；CP33 为 `83854ae83f7fec4fc8f9c22d0751a1fd2725671f`，窗口 `/tmp/zil-compile7-cp33-session`。二者分别与 ee72fd6 基线配对，互不叠加，也不是两候选之间的直接竞赛。

每窗均完整 200 个序列 × 7 请求 = 1,400 次受测 compile_path 调用；控制阶段另有 20 序列，即 140 次持久会话与 140 次 fresh 对照，均未计分。审核重新读取全部原始 stdout/stderr、严格命令与顺序、数值类型、快照、Success、Verify=1、active=0、fresh 控制观察量和摘要；非空 stderr 为 0。每窗 110 个生产汇总格均重新计算相符，共 220 格。59 个构建文件的现时摘要也再次相符。

固定 case 权重为 tree4x2/tree32x8/tree256x8/tree1024x8/retained = **5%/15%/30%/30%/20%**；预先冻结的主混合请求权重 cold/unchanged/private/public = **10%/35%/40%/15%**。每格每 arm 在每个区块内取两次观测平均，再对五个区块取绝对成本中位数；按固定绝对权重相加后最后才计算 B/A。default 与 8192 分开计算。

区间枚举全部 5^5=3,125 个配对整区块重采样，同一抽样同时用于 A/B 和所有 case/请求，重算相同统计量后取线性 2.5%/97.5% 分位。只有五个共享主机区块，因此称为探索性 95% 区间。所有比值 B/A 小于 1 表示候选成本更低。

## 边界与可复核证据

本窗是实际 compile_path 至 Verify 的会话成本，不包含 LLVM 发射、链接及 native 程序运行。fresh 控制比较报告/接口观察量，不把这批性能样本冒称完整 TypedIR 或 native oracle。CP32 有另列的全量 Typed 正确性控制和作者 6 次 Clang O0 native 控制；后者经非作者静读核查，非作者 native 执行数仍为 0。CP33 不叠加 CP32，也没有在这里建立联合候选的行为或收益。

Parse query 事件不能直接当作 lexer 调用次数：容量清退后，loader 借到的已检查 Arc 可能被重新发布为 Executed。速度结论取实际完整计时和进程资源，不由命中计数推算。

原始记录 SHA256：CP32 `04c82cc144412e45acb5986fff6767275f7c979aa1b242be763b4004c212d903`；CP33 `96a8686c09fd8985a6a545130b98396f4e46fb29e3bc375685d878701c82ccb0`。

完整复算：`review/followup-session-independent-recompute-r1/RESULT.json`。全七请求及恢复请求补充：同目录 `RECOVERY-REQUESTS.json`，它重新绑定完整复算结果和原始 records 摘要，原 RESULT 未修改。首跑日志：`review/FOLLOWUP-SESSION-INDEPENDENT-RECOMPUTE-R1.log`。复算入口：`review/compile7_followup_session_recompute.py`；请求补充脚本：`review/compile7_recovery_request_supplement.py`。原 CP29/CP30 的脚本、报告和机器收据保持不变。

本审核没有新跑编译器或增加计时样本。Pass 只指证据和计算一致；语言完成度、正式产品门禁与默认采用仍保留其独立状态。
