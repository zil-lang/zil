## 计算方法

JSON 小数从解析开始使用 40 位 Decimal。每个语料、请求、臂先在每个配对区块内取两次观测的算术平均，再取五个区块均值的中位数。先按语料/请求权重求两臂的绝对成本，再计算 ZIL/Rust；没有平均比值，也没有挑选最快样本。CPU 为记录的 user+system（包含已回收子进程），单进程最大 RSS 不解释为同时进程树峰值。

五语料固定权重为 5% / 15% / 30% / 30% / 20%；四请求为 cold / unchanged / private / public，权重 10% / 35% / 40% / 15%。块内使用 ABBA/BAAB，语料顺序与 seed=20261030 的冻结计划完全一致。

独立复现了作者的 2,000 次整体配对区块 bootstrap：共同重采样区块索引，保留臂、语料和请求间的关联，按最近秩选择 2.5% 与 97.5%（索引 49、1949）。另穷举全部 5^5=3,125 个有序重采样（索引 78、3046）。本次八个总体区间及所列敏感性区间在两种方法下相同。区间仅描述五区块共享宿主数据，不是产品或全语言置信结论。

原摘要中 346 个数值字段均与独立结果一致（容差 1e−12×max(1,|值|)），实际最大绝对误差 1.02e−15。JSON 保留每个语料×请求×臂的五个块均值、墙钟/CPU 绝对成本及所有分组的描述区间。

## 原始数据与审计边界

每条记录核对了序号、块/语料/臂/请求顺序、冻结计划和预检哈希、精确 argv、原始 stdout/stderr、输入/oracle 哈希、退出状态、超时、产物身份前后一致、完整成功收据。ZIL 原始报告另外核对 LLVM API/版本/目标/优化流水线、实际 closed 模式、分区数量/工作线程钳位、直接 Clang/LLD 链接命令、独立 Verify 事件、前端执行/复用事件、query 键和 CT 使用量。

`8/4` 是请求的上限配置。实际 tree4x2 为 7 CGU，retained 为 3 CGU/3 jobs，其它三个树为 8 CGU/4 jobs；这与后端按实际分区数钳位 jobs 的实现一致。默认关闭的前端缓存与 closed 模式没有暗启用。

可信对象缓存命中报告明确写入 `llvm_verification_this_request=false`、`producer_verified_before_after=true`，并执行本次机器 preflight。它复用已生成的本地对象，并不声称再次运行 LLVM 优化/机器发射；当前请求的语言 Verify 仍恰好 1 次。

冻结 runner 在每个序列后删除临时 build 工作目录，因此正式 build 的机器文件现在只有其记录的 SHA 与当次原生输出校验；不能声称这些已删除文件又被重新读取。所有正式 runtime 使用的预检可执行文件仍存在，已实际重新核对内容与元数据。

二进制来源依靠 cargo 前的 `start.json` 源提交/crates 树、成功 release 构建日志和实际冻结 SHA；本审计没有独立可重现构建。`release-binding-check.json` 还单独核对了最终构建收据、原 start/log、实际二进制，以及 Cargo.toml、Cargo.lock、rust-toolchain.toml、toolchain-profile 的源提交 Git 对象，共 13 项通过。Rust 预编译 std 与宿主 libc、语料中 Rust Vec 与 ZIL ByteBuffer 的差异均保持原比较范围，未提升为全语言同义性或产品门。
