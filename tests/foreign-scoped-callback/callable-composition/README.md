# Concrete callback composition inputs

`frozen/` preserves exact Source bytes and foreign symbol names; `SOURCE_HASHES.json` binds each input. Handler sources place an Event→Reply closure inside the generic With body or capture it in the outer wrapper. Concrete controls move F into a nongeneric run. Factory sources move an Event into a concrete FnOnce body; the dispatch factory carries the full Event→dispatch→Reply→render pipeline. `handler-without-with.zil` checks that ordinary handler admission does not depend on the presence of With. These are legal positive obligations: an early Unsupported or callable-contract rejection is a gap, not a passing negative.

`observed/` variants add C observation, Mark Drop and a remaining Mark in the body environment. On success the Event Mark and ByteBuffer pass through Reply/render, and the still-live body Mark drops before close. Null registration skips body entry and cleans both; reserve failure creates no Event or second Mark and drops the initialized first Mark. The caller checks its retained F after success, null and preparation failure, plus cleared C roots and live=0. Success checks the full returned i32 value rather than its exit-code byte. The independent source-operation oracle has success/null crossed with disabled injection, actual reserve failure and beyond-request control; it does not use compiler output.

`nested-helper-propagate.zil` is a legal result-propagation control; the separate generic `return Fault.NoMemory` spelling has its own context gap. `frozen/factory-only.zil` is a separate plain Copy-signature factory control without With or foreign declarations; expected arithmetic is make()(2)=5 plus supplied F(1)=2, so run returns 7 and main exits 0 with empty output. It has no allocator/live-zero claim.
