# Local preparation in scoped helpers

`frozen/` retains three exact Source inputs, with digests in the baseline [Git document](https://github.com/zil-lang/zil/blob/28b3e37bb4d8a1fe8b146c72cf891fc99de32440/tests/foreign-scoped-callback/local-preparation/README.md). The generic-local source gives a real Mark, ByteBuffer and Event into a concrete body; the concrete-local and generic-owned-parameter variants control the admission boundary. A separate `return Fault.NoMemory` generic spelling is not exercised by these files; they use the existing `no_memory()` expression. The frozen mains ignore the returned result, so native checks must inspect actual allocator failures and live=0 rather than infer success from exit 0.

`observed/generic-local.zil` adds C observations, Mark Drop, consume observation and an explicit f(4)==5 check after run returns. It preserves the same preparation and failure operation, and makes body entry, exactly-once Mark cleanup and restored caller access observable on success, registration-null and preparation failure. `driver.c` keeps the actual reg/close C protocol; registration byte 0 succeeds and byte 1 returns null after a synchronous callback. Close requires the ByteBuffer allocation already freed, rejects Closing reentry and clears both roots.

Independent `local_preparation_oracle.py` models Source without reading compiler/native reports. Frozen and observed matrices each cross success/null with no injection, actual first reserve failure and beyond-request control. All returning paths require zero live allocations. Use the existing `foreign_scoped_callbacks` target with `scoped_local_preparation_` selectors; for the API backend add `--features llvm-api`. Bind each run to compiler, source bytes, actual backend/O0/O2, no fallback, full return/cleanup and allocator counters. The original callback oracle and separate native groups are not combined into a larger acceptance claim.
