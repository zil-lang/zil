# Closure receiver borrows

`StorageBase::Receiver` names the actual borrowed invocation head of a concrete closure entry. It is a contract position, never a physical field, address operand, or persistent class directory. Its only binding has the empty path and an Invocation binder. Canonical order is parameters, captures, Receiver, result. Contracts without Receiver retain their original order. Receiver has no semantic-class rows: persistent classes remain on the complete actual capture types.

Only an actual non-consuming Fn or FnMut entry, or a role bound to that independently checked entry, can use Receiver. Ordinary functions, factories, thin function pointers, foreign functions and suspension contracts cannot introduce it. A genuinely consuming FnOnce entry cannot return an escaping receiver view. Adaptation to a consuming call cannot preserve a receiver-bounded escaping result.

An entry returning a short view must independently prove actual target provenance, full leaf type, access mode, initialization and all parent loans. An Invocation result binding may refer to Receiver only when its actual returned permission retains that head. `lending_captures` bounds the environment sources; it does not introduce an implicit input binder or supply the proof. A Fixed external pointer copied from a genuinely shared capture can retain its original parents without the invocation head only when the actual return derivation proves that weakening.

Reading a captured exclusive address in Fn or FnMut creates a fresh child reborrow for that instruction within the actual invocation region. The child's pointee class map is unchanged. Its parents include the original captured loan and the actual invocation head. Read-only Fn grants only shared reborrowing; FnMut may reborrow exclusively when the actual operand permits it. Sibling child loans share ancestry, not identity or permission. A shared result obtained by weakening an exclusive capture still retains its invocation dependency.

An exclusive capture makes the closure environment affine even when it owns no external data. Cleanup consumes the environment ticket without dropping the borrowed pointee. FnOnce can transfer the original captured permission only through a unique actual Take from its environment slot, removing that slot and transferring its complete parents. ReadCapture, casts and lifetime labels cannot replace that transfer.

A live returned receiver view prevents conflicting calls, movement or cleanup of the actual receiver. Its last future use ends that dependency; cleanup that never reads the external data does not add a fictional read. Capture updates apply to the actual original holder selected by the call-before receiver: a unique target permits replacement, while multiple possible targets retain a conservative join. Already extracted SSA pointers keep their old targets, epochs and parents.
