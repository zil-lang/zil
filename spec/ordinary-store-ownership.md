# Ordinary Store ownership

A scalar or POD `Store<T>` may occupy existing finite ordinary owning positions: Package, Tuple, Enum, ErrorUnion, concrete calls/results and self-contained Fn/FnMut/FnOnce environments, subject to the same structural responsibility rules as other admitted Store owners. Preserve exact canonical element identity, Copy protocol, actual initialized prefix and allocation debt. This ordinary ownership does not independently grant `StoreElement`, array, borrowed storage, dynamic dispatch, asynchronous qualification, shared address or capture permission.

Construction, initialization, movement, transfer, field take/refill/replace, branch selection, return and cleanup must account for every real owner once. Prepare a replacement RHS before retiring the old value; preparation failure leaves old obligations intact. A scalar/POD element has no per-element destructor debt, while the Store allocation is released exactly once by its actual owner. Unused capacity has no cleanup debt. Borrowed views block conflicting move, replace or structural mutation through their last use.

Types qualifies all admitted positions; Analyze tracks responsibility and roots; Verify independently checks real raw/Wire metadata, origins and flow; Lower/LLVM consume verified active branches and emit actual cleanup. A finite composition must reject forged Store definitions, duplicate transfer, incomplete parents and stale views. Governing rule: `_zil_design.md` §8.1.3.2.

## Managed Store replacement through a borrowed Package

An ordinary direct helper may replace a direct `manages items:Store<T>` field through its actual exclusive `&mut Holder<T>` input, with the same complete incoming owned Store type and the existing `StoreElement` constraints. Named and explicit-dereference field syntax select the same real address endpoint. The reference does not become the owner of the Package, and field replacement does not grant permission to give a field out of a borrowed Package. Shared receivers, ownerless descriptions, mismatched complete Store types, repeated input transfer and live old element loans remain invalid, including in unused generic definitions. Field resolution retains declaring-module privacy.

Resolve the destination without evaluating the RHS; evaluate and prepare the new Store exactly once before committing. Successful commit retires the old allocation responsibility and its descriptors, then publishes the complete new Store. Preparation failure preserves the old field and cleans only acquired temporary responsibilities. A caller's old descriptor or element view cannot become valid again after a helper replacement; a later view must derive from the current field. Source alias origins track the actual referent and field, including reborrows, rather than treating the pointer local as its owner.

Analyze and Verify independently recover mutable parent permission, exact canonical Store identity, consumed input responsibility and descriptor retirement from the current IR. Verify's matching Store-input exception applies only to this actual direct mutable Package field endpoint; it does not admit whole-Package replacement, environments, foreign calls or general capture updates. Existing reservation/commit instructions, Wire, layout and cleanup ABI remain unchanged. New alias-set, field-map and origin-invalidation work is charged before growth or mutation, without raising limits or changing the fee schedule of existing local-owner paths.

The source, raw/Wire attacks, exact fresh/warm budget controls and native scalar/Record/RHS-once consumers are in `tests/language-readiness/borrowed-store-field-replacement/`. The native observer checks both Store allocations are freed once and the replacement RHS emits its marker once; this finite path does not establish general collection or arbitrary helper acceptance.
