# Mutable stored holder

A finite nominal `Record` or ordinary owning `Package` may carry direct `&T` and `&mut T` borrowed slots. Each slot has a matching `SharedAddress` or `ExclusiveAddress` mode and an actual field path in `StorageLifeShape`; `T` must satisfy the finite address pointee rule. A `Package` may combine these slots with supported `Managed` ownership fields, and a qualified owning `Package` may contain another independently qualified owning `Package` as a complete inline child. The parent flattens each child slot's physical field path and maps its lifetime class through an actual retained boundary; the parent owns one complete child field debt while the child's managed leaves retain their actual sources and teardown routes. The field path, declared lifetime class, and actual source all matter: a nominal name or lifetime label alone grants no target or permission. Complete nominal instance and signature relation checks apply across modules.

Constructing the holder transfers each actual address into its slot. A mutable borrow of the holder may reborrow an initialized exclusive slot through `LoadStoredBorrow(Reborrow { mutable: true })`. Assigning a new address to a direct shared or exclusive slot uses `StoreStoredBorrow` after the right-hand side succeeds. Analyze and Verify independently recover the target, carrier ancestry, and a separate retained loan for each write site, preserving the declared shared or exclusive mode. A live child prevents a conflicting replacement, access to the stored target through an older SSA address, or early retirement of the carrier. Direct helper calls instantiate each returned child and each external slot poststate from the caller's actual arguments. The poststate cannot extend a target beyond the slot's declared lifetime binder.

`move_out(holder.field)` destructively extracts the original shared or exclusive address from an actual declared slot of a mutable holder place. The physical pointer remains just an inline field; a private CFG state marks its path vacant. Reads, reborrows, another extraction, whole-carrier moves, and helper calls require an initialized slot on every incoming path. A later ordinary assignment may refill the exact hole, and every normal or error exit of a helper holding `&mut holder` must leave all slots initialized. A local holder may instead be dropped while a borrowed slot is empty; its actual owning fields retain their independent cleanup debt. Branch joins union possible holes, while target sources still union separately. This capability does not grant whole-holder Copy, mutable capture, or arbitrary holder shapes. Ordinary stored shared reads retain their detached `CopyShared` behavior.

The machine loads and replaces pointers in verified inline fields; owning `Package` fields keep their separate resource debts and cleanup, including normal and error exits through qualified child Packages.

Stored-holder functions may coexist with ordinary owning callbacks, borrowed Tasks and registration protocol helpers in one linked program. The finite bridge is an ordinary direct `fn(i32) -> i32` call with no environment, foreign declaration, retained relation, reference-return bound, callable contract or protocol contract on the target. The holder and every child loan remain entirely within the stored component. Each kernel independently classifies actual functions, checks every cross-component edge and proves each complete function using its own applicable solver. Candidate Hold rows do not determine component membership or supply missing loan facts.

This bridge does not permit a holder, address, owning value, captured environment, task worker or indirect function edge to cross components. A qualified owning `Package` containing both resource fields and direct borrowed slots is checked by the stored and resource kernels on the same instructions. Other asynchronous and owning combinations still require their own actual source, lifetime, and cleanup proofs.
