# Finite borrowed dynamic dispatch

A borrowed shared `dyn` value contains the actual receiver address and an immutable static table address. A real trait interface with fixed scalar, recursively closed Tuple/Array value slots may select among distinct concrete finite Copy providers at runtime. Preserve original trait, implementation, member, module and provider identities. The pair must never point at a temporary carrier; each derived borrow remains tied to its actual owner.

Each table entry and call has a complete executable provider contract: prerequisites, access, guarantees, hold, result source, cleanup, effects, resume and thread requirements are proven where needed. Empty effects must be established, not inferred from missing fields. A provider's reads fit the erased shared receiver contract; shared access gains no mutable or owning authority. A plain value result adds no borrow or management right. A shared scalar address result requires the explicit `Borrow { sources: [Parameter(0)], mutable: false }` result bound and the same Invocation binder at receiver and Result. Each actual entry must return the real address of its concrete receiver field; arbitrary addresses and receiver-independent temporaries do not satisfy this bound. Call results retain the receiver’s actual roots and parent loans through ordinary helpers, including an `OwnedDyn` receiver.

Types checks used and unused tables and Source coercions. Analyze and Verify independently reconstruct roots, entry/slot conformance, body facts and lifetime, including raw/Wire inputs. Lower emits the real pair, table and indirect call signature through both supported native backends. Governing rule: `_zil_design.md` §9.4. The executable profile is finite: fixed plain value slots, concrete Copy record providers and shared borrowed receivers. Large Tuple/Array arguments and results use the same caller snapshot, callee copy-in and out-pointer convention as direct language calls; the out pointer precedes the erased receiver. A vtable always stores the actual function with that complete physical signature.

The finite exclusive extension admits `&mut dyn Trait` for fixed Unit or scalar slots on the same concrete Copy record providers. A mutable slot contract covers the receiver read and write; its entry must prove an actual scalar field write, including through a checked direct helper or default wrapper. Shared dyn cannot call a mutable slot or create an exclusive dyn loan. Mutable slots return plain values. A shared call may reborrow an exclusive dyn pair while preserving both payload and table. Scalar unary/binary expressions and compound field updates retain a `Panic` upper bound rather than disabling checked arithmetic. All actual entries are independently checked against that bound; an empty or Unknown effect set cannot admit potentially trapping arithmetic. Unknown calls and effects remain rejected. The receiver loan stays tied to the concrete owner across the indirect call.
