# Finite borrowed dynamic dispatch

A borrowed shared `dyn` value contains the actual receiver address and an immutable static table address. A real trait interface with fixed scalar method slots may select among distinct concrete finite Copy providers at runtime. Preserve original trait, implementation, member, module and provider identities. The pair must never point at a temporary carrier; each derived borrow remains tied to its actual owner.

Each table entry and call has a complete executable provider contract: prerequisites, access, guarantees, hold, result source, cleanup, effects, resume and thread requirements are proven where needed. Empty effects must be established, not inferred from missing fields. A provider's reads fit the erased shared receiver contract; shared access gains no mutable or owning authority. A scalar result adds no borrow or management right.

Types checks used and unused tables and Source coercions. Analyze and Verify independently reconstruct roots, entry/slot conformance, body facts and lifetime, including raw/Wire inputs. Lower emits the real pair, table and indirect call signature through both supported native backends. Governing rule: `_zil_design.md` §9.4. The initial profile is finite: fixed scalar slots, concrete Copy providers and shared borrowed receivers.

The finite exclusive extension admits `&mut dyn Trait` for fixed Unit or scalar slots on the same concrete Copy record providers. A mutable slot contract covers the receiver read and write; its entry must prove an actual scalar field write, including through a checked direct helper or default wrapper. Shared dyn cannot call a mutable slot or create an exclusive dyn loan. The result remains a plain value, with no borrowed or owning result source. Unproved arithmetic or calls cannot be assigned empty effects; a body with potential Panic must retain that effect in an independently verified contract before admission. The receiver loan stays tied to the concrete owner across the indirect call.
