# 分析库存、共享表示与独立核验

固定点分析反复复制、合流相同形状的状态。降低这部分成本，应改变实际表示和重复工作，保留完整逻辑库存、独立核验与预算约束。不能让仍然执行树搜索或深复制的实现，只按直接索引或共享引用收费。

本文约束 Analyze、Verify 内部的状态表示和请求内复用。[主设计 §19.2](../_zil_design.md) 允许共享不可变原始输入，但每次完整请求仍须独立 Verify；共享 TypedCFG、类型或原始计划，不等于共享安全结论，更不能从序列化结果或指纹直接构造 `Verified`。

## 库存完整，事实独立

库存回答“有哪些槽位、字段和坐标”；状态回答“这个位置现在有什么来源、初始化状态、借用或责任”。两者必须分开。类型形状和索引可以不可变共享，当前控制流事实不能由这些形状推导出来。

| 表示 | 必须保留的逻辑内容 | 可以共享或压缩的部分 |
| --- | --- | --- |
| SSA 值表 | 每个实际值的槽位、完整页形状及内容 | 固定页布局、不可变页与内容引用 |
| Local 与 Observation 索引 | 实际声明坐标、稀疏项存在性、缺项行为 | 规范直接索引；不能凭缺项补造事实 |
| 资源 cell 表 | 完整资源身份集合及所有状态字段 | 相同有序库存上的逐项线性合流 |
| 初始化表 | 每个 local 的 `0..3` 状态及按位 OR 合流 | 小库存保留字节，大库存采用两位编码 |
| SSA 消费状态 | 每个实际 SSA 值在各块的已消费状态，按位 OR 合流 | 小域保留布尔行，大域采用完整机器字位表 |
| Package 字段表 | 所有 SSA 行，包括空行，以及每个字段字节 | 不可变行偏移；动态字节由各状态分别拥有 |
| 描述活跃历史 | 完整描述域、每块每指令对应的活跃位 | 大库存采用机器字快照；小库存保留布尔行 |
| 资源槽位布局 | 实际函数的全部责任、描述、字段、捕获与 Product 坐标 | 封闭请求内唯一持有完整 Slots，按构造模式守卫后借用 |

Analyze 与 Verify 各自依据当前模块构造、检查自己的库存与事实。一个阶段的“已经检查”不能替另一个阶段提供许可。来源、代际、父借用、捕获、返回及跨调用合同仍由实际语义路径核查。

## 共享前先检查完整形状

共享只改变存储和访问成本。SSA 页的逻辑长度、页数、末页宽度及各槽位必须先满足当前接口的完整形状要求。资源表的线性合流必须对应同一实际身份库存；不完整库存、额外身份或不适用的形状仍走完整路径或返回原有错误。

同一 `Arc` 的身份比较，只能用于本核、本请求内已经绑定的不可变内容。异指针但共享的页，需要只读证明：接收方已经包含来向的全部相关信息。这一证明必须覆盖完整元数据、来源及状态，不能以相同标签、相同行数或相同哈希替代。

探查证明不了“无新增事实”时，恢复完整合流。探查遇到语义错误，也不能抢先改变原合流的错误位置和已完成修改前缀。原操作允许先完成若干槽位再失败的地方，不能为了快捷路径改成全局回滚；原操作要求预付后才改动的地方，也不能先改再付。所有探查工作本身仍计费。

后续写入按真实共享程度执行写时复制。保留一份引用可能令下一次写入发生复制，因此不能只比较当前合流省下的工作，还应覆盖后续写入和最终释放。

## 静态资格与动态事实分开复用

Copy 资格与“内容已处于完整未知标签形状”是两个问题。资格检查必须包含原有类型、布局与元数据条件；动态形状检查仍要区分实际 Copy 与 Leaf 终端，保留 fresh、moved、missing 和路径信息。

Verify 的请求内 Copy 缓存绑定当前 `Flow` 借用的函数及实际 local 类型地址。只有确实属于该声明的类型，才能使用该 local 已完整计算的静态资格；相同结构的临时类型或不匹配的地址仍完整检查。静态 `copy = true` 不能代替动态未知形状证明。正向形状记录保留强引用，只有同一不可变根才可命中；换了根就重新检查。新建 `Flow` 使用新的空缓存。

POD carrier 的请求内缓存同样只接受当前不可变模块中预登记的实际类型节点。登记发生在完整原始形状约束检查之后，`false` 仅表示“在库存中”，不表示任何许可。只有完整冷资格检查成功、发布费用也已预付，才将该实际节点标为成功。临时类型、外来模块或未登记节点保留完整冷路径；一次失败不能被缓存为成功。

这些缓存保存有限静态资格或正向不可变形状证明，不保存可跨请求复用的 `Verified`，也不缓存路径上的动态写权限。缓存所持强引用的深层释放、表槽实际宽度、初始化、查询和发布均属于真实成本。

## 紧凑表示的边界

### 初始化状态

初始化表的完整状态域是 `0..3`，不是一个布尔值。两位编码按位 OR 必须与原字节表一致，末字的无效高位保持为零，索引和布局错误不能被掩盖。合流沿用原有重叠前缀语义，保留接收方未重叠的后缀。

当库存不超过一个机器字所占的字节数时，保留直接字节表示，避免为很小的表额外支付移位和掩码。更大的表每个机器字存放 `usize::BITS / 2` 个状态。复制、验证、读取和写入分别按实际工作收费；容量减少不意味着访问免费。

### SSA 消费状态

所有权分析的 move 状态记录某个 SSA 值在来向路径上是否已被消费。固定点反复建立、复制和合流完整布尔矩阵，大域可以改用真实机器字位表；这是一位的 OR 状态，不是初始化表的两位状态，也不替代借用活跃分析。

每行仍覆盖函数的全部 SSA 值，位坐标保持原 `ValueId` 序号，包括当前未被消费的值；不能只为 affine 值或已观察到的候选建立缩小索引。很小的域保留 Dense 布尔行，阈值按一个 `u64` 所占的布尔字节数确定；较大域保存逻辑宽度和完整 `u64` 数组。零构造与有界写入保持末字无效高位为零，机器字行在复制、比较和合流前检查双方宽度及实际字数。所有生产行由同一函数的固定 SSA 域构造，原逻辑矩阵大小的溢出检查仍在新增存储计算之前。

收费对应真实表示，不能把仍在复制的布尔行按位表收费。Dense 也增加了枚举行头、构造和释放分派，因此须支付相对于旧 `Vec<bool>` 的实际头部差额；空域和小域不因旧预算较小而免除这些工作。机器字行支付实际字数、完整行头和外层容器、分配及释放；读取、写入、比较、复制和 OR 同时支付枚举分派、边界与字操作。构造或修改前先付相应费用，已完成的付费前缀仍按原语义保留，不能宣称整个分析失败都会回滚。

表示替换保持分类、消费者和控制流顺序。affine 与 view 分类仍扫描全部声明及块；固定点和最终验证才跳过不可达块，完整矩阵保留其零行。入口块即使有回边也保持全零输入，其他块只合流可达前驱。推导仍先清除指令结果再标记消费者；最终验证仍先检查全部操作数，再清除结果，随后按原消费者顺序检查已转移、拒绝 view 消费并标记转移。返回检查保持已转移优先于 view 返回的错误次序，Copy 值保留原有短路，不新增不必要的状态读取。原固定扫描、轮次边界及后续 live carrier 借用检查均不改变。

独立对照保留完整旧布尔矩阵算法、原消费者分类和合流函数。测试以明确成功的新旧结果比较完整 view、每轮所有块与所有 SSA 槽位，覆盖字边界、多前驱、回边、不可达块、消费类别和错误先后；只读观测不能改变被测状态。预算失败后重新以足量预算执行，仍须显式成功并核完整矩阵及已付修改前缀，不能用两个失败结果相等替代成功证据。

### Package 字段

字段坐标来自实际 SSA 槽位库存。行数较大时，一份不可变前缀偏移描述全部行，包含宽度为零的行；各状态单独持有连续的字段字节。行数很小时保留原有嵌套行表示。

合流保留原 `flatten().zip()` 的语义：比较和更新共同的字节前缀，接收方其余字节不变，不新增“双方行形状必须完全相等”的条件。Flat 来源合入 Dense 接收方时，遍历接收方空行和行头的成本仍须预付。字段布局只描述坐标，不授予 Store 替换、借用或 owner 转移权限；这些规则见[普通 Store 所有权](ordinary-store-ownership.md)。

### 描述活跃历史

历史压缩发生在完整 CFG 活跃分析之后，不省略冷路径的出入块计算，也不缩小描述域。压缩后的每条历史仍对应实际块与指令；逆序转移读取所有真实操作数，再按原程序顺序保存历史。

机器字快照的构造、输出位扫描、逆序更新、快照复制、重排和容器释放均需计费。消费端读取压缩位还要支付边界、字索引、移位与掩码工作。原来的短路顺序必须保持，例如已由结果身份决定无需读取活跃位时，不提前触发新增读取或错误。

同一请求内，较大描述库存的活跃历史可以绑定实际不可变函数和已经选定的 CFG，供后续推导及最终验证借用。描述数不超过一个 `usize` 所占字节数时，每次仍执行完整冷活跃分析并返回独占结果，不建立复用记录。完整键包括描述总数、每个 local 和 SSA 值的描述坐标；每个 `None`、`Some` 及其序号都参与比较，不能只比较函数编号、长度或摘要。换了函数、CFG 或任一描述坐标，就重新执行完整冷活跃分析。

记录保存完整坐标键，并唯一持有只读 History。完整冷分析和发布费用均成功后，才将历史移动到记录并复制完整键；后续命中返回只读借用，不做 History 深复制，也不引入 Arc 共享所有权或引用计数操作。失败不能发布部分历史，也不能覆盖原有完整记录。函数绑定表、包装表示、每次完整键比较、发布、替换和最终释放均按实际宽度与操作收费，小函数也承担真实的设置开销。

复用历史不会复用责任或写权限。Slots 可以由下述封闭请求保存，但历史仍检查完整描述坐标。每次仍重建初始 State 和 replacement 写集合，并使用当前调用效果重新求解资源状态；最终逐块 Transfer、返回责任和 `close_pairs` 检查照常执行。独立旧实现对照覆盖完整历史、全部键及状态，另核实际对象隔离、键变化、冷构造和发布失败、命中后的预算失败与重新执行。

## 资源槽位布局只在封闭请求内复用

资源推导和最终检查会反复建立同一函数的责任、描述、字段与捕获坐标。布局决定状态中有哪些位置，不决定这些位置当前是否存活、来自哪里或可以被谁消费。因此可以保留完整不可变 Slots，让每次状态求解继续使用原来的全部动态检查。

封闭的 Request 借用实际模块、函数、选定 CFG 及其完整 CaptureViews、replacement Plan，并独占本次资源阶段的 Budget。每个函数记录整份 Slots，包含全部 local/SSA 坐标、捕获映射、Product 区间及字段布局，不用摘要或一部分坐标替代。函数、图和 Plan 不能在请求中途换入；另一请求从空表开始。完整 inline Store 根库存按实际类型地址登记，在进入封闭资源阶段前已固定；该阶段的生产调用不修改它，接口也不向外暴露 Budget。这个不变条件允许避免逐记录复制或逐命中扫描根集合，不能简化成只比较集合长度或指针摘要。

布局记录同时保存构造时的六项模式：全局 Sum、当前函数的 Sum 标记、head descriptions、inline Store addresses、POD Stores 和最大调用深度。每次借用前付费读取并比较这些值。实际 replacement 端点检查可能调用 `mark_sum`，所以前一次构造成功不保证下一次模式相同；任一项变化都重新执行完整 `Slots::new` 和 Plan 扩展。两步成功且发布费用已付，才将新完整布局移动到记录。构造、扩展或发布失败不能覆盖旧完整记录；保存静态布局也不表示随后执行的动态检查已经成功。

布局以唯一所有权移动和只读借用保留，不新增 Slots 深复制或 Arc 共享所有权。表槽、Request、Slots、Mode、Layout 及其可选包装均按实际类型宽度收费，另计初始化、查找、六项比较、发布移动、替换和最终分派；外层容器不因小函数而免费，也不重复计算同一容器头。唯一移动没有增加原有深层内容的释放次数，但这不能用来宣称旧构造的全部释放成本已经统一计过。

每次运行仍建立完整初始 State 和 written 集合，使用当前 effects 与 Sum bridges，按原顺序执行固定点求解。最终阶段仍对每个有输入的块执行完整 `Transfer(validate=true)`，实际捕获归还、返回责任、Task 行为与 `close_pairs` 均不能因布局命中而省略。Plan 的动态调用和退休配对表保持本次真实操作产生的内容；不把状态、摘要效果、桥或权限放进布局记录。

独立对照保留完整旧构造器、资源运行器及调度器。测试比较整份布局、所有块输入、written 和实际动态元数据，覆盖真实对象与图隔离、模式改变、端点触发的 Sum 标记、原有错误次序，以及冷构造、发布和命中后的预算失败。失败后的 fresh 请求必须明确成功并匹配完整旧结果；一个布局快照相同不能代替完整资源验证。

## 摘要调度只跳过没有变动依赖的重算

函数摘要调度记录的是实际发生的摘要读取。空效果、条件分支中的读取、公共回调、捕获和历史调用来源也可能影响结果，不能只登记产生了非空新事实的调用。

调度保持原函数顺序和轮次边界。一次摘要发布变化，按原顺序唤醒当前轮尚未经过的消费者，或下一轮的既有消费者；历史读取依赖继续保留。反向索引、去重搜索、脏位表及轮次扫描都要付费。

跳过无变化的重复求解，不等于跳过最终检查。完整 final 仍执行实际操作、捕获、返回及责任核验；不能把“摘要稳定”当作最终核验已经完成，也不能复用前一请求的结论。

## 稳定输入只替代重复求解

Sum 分析在同一次检查中，可以为重复求解过的函数保留完整成功输入，供最终验证使用。记录包含每个 CFG 块的完整输入状态、不可达边、实际写入历史及不可变函数计划；不只保留摘要结果或状态哈希。首轮不建立这份保留，避免没有重复求解的函数承担整份状态复制。

复用前检查实际模块、函数和 CFG 对象身份、全部相关模式，以及本次求解读过的每个摘要发布版本。读取自身的函数不保存；版本溢出禁用复用。每次发布都推进版本，值恰好相等也不绕过守卫。任何条件不满足时，仍执行完整新求解。

命中只省去再次求固定点。最终阶段用当前摘要重建上下文和空的动态形状缓存，对每个有输入的块重新执行完整操作验证与记录；实际捕获归还、返回来源、bridges 和 Store 历史照常核验。保存了状态并不表示最终安全检查已经通过。

保留完整状态会增加引用数，并可能使后续写入发生复制。保存、实际容器宽度、所有输入与路径、深层清理、版本表和命中守卫都先支付相应费用；判断收益时还要计入未命中的保留、后续写时复制与释放。复用记录只属于当前检查，不能成为跨请求的 `Verified` 或动态写权限。

## 预算与差分验证

预算应覆盖真实发生的库存扫描、索引搜索、分配初始化、引用复制、写时复制、深层释放及缓存发布。先支付相应工作，再分配或修改；取消和超预算不能发布半成品许可。

表示优化的差分基线应保存完整旧算法，包括旧 BTree 查找、平铺状态复制、完整合流以及所有附属状态。把旧基线改成调用新表示的合流，会失去独立对照。比较对象应覆盖完整事实、错误和可观察的修改前缀，不能只比较长度、单个布尔结果或同一共享对象的两个别名。

边界测试先找到成功所需预算 `N`，要求 `N` 成功、`N−1` 拒绝，并在失败之后以新的预算再次执行 `N`，显式检查成功结果和完整状态。只比较两个 `Result` 相等，可能让两个失败被误记为成功；输入隔离还需与独立旧表示生成的期望值比较。

组件成本改善与完整请求成本改善分开判断。截断请求只能比较共同已经完成的范围；整请求收益还需包含冷登记、调度、后续复制、最终检查和释放，不能把不同截止位置的剩余预算相减。
