# Retained dynamic contracts

A dynamic dependency envelope is a complete qualified Context type. Its full nominal identities, ordered actuals, retained class maps and phantom lifetime occurrences remain part of interface identity. Context is compile-time metadata; it adds neither a runtime Context value nor another allocation to the owning pair. The original one-argument owner has the empty closed envelope.

Public ports are typed target uppers, not physical fields. Normalize a Context's complete actual borrowed leaves by full leaf type, stored access mode and fixed class in first-occurrence order. A vtable supplies exactly one `DynRetainedPortBinding` per public port. Its sources are complete actual Self selectors rooted at `Result`; an explicit empty vector proves an unused upper, while an omitted row is unknown. Every actual external leaf must be covered, with its real type, mode and class. A port may cover several actual targets. Equal fixed classes provide neither target identity nor apartness.

`DynVtable.self_classes` maps the complete canonical persistent Self-class domain into Context Fixed classes, including phantom classes. Empty is valid only for a Self with no persistent classes. A constructor independently equates its actual SSA Self classes with the selected Context result classes and transports every actual target and parent loan. A registered Source constructor selects a concrete table explicitly; same Self layout or type alone cannot select between different joint maps.

`DynDeclaration.self_pattern` retains the original impl's nominal declaration and complete ordered actual recipe. `LifeParameter`, type `Parameter`, and const `Parameter` refer to the full original formal ordinal and must match its declared kind. Interpret every occurrence through the actual nominal declaration and full semantic instance. Repeated life actuals remain separate occurrences even when their instantiated classes merge. For example, the pattern of `impl<life a, life b> Read for P<'b, 'a>` contains formal positions `1, 0`; it is not the vector of canonical Self-class numbers. Nested nominal arguments retain their occurrence paths. Concrete type recipes must be complete closed types; unresolved Named placeholders confer no meaning. All actual methods must have the corresponding complete receiver type and class relation. A missing generic borrowing pattern is unknown.

`DynDeclaration.implemented_trait` uses the same application-recipe shape for the real implemented Trait declaration. Every used provider has this complete relation, including a nongeneric trait's empty actual vector. Substituting the impl's complete ordered table actuals must yield exactly the interface application, including phantom life actuals. Matching Self or method layout cannot establish trait membership. None is unknown for an unused declaration; it never licenses a provider table.

A borrowed method result may name the receiver and compatible receiver ports. An inline field view retains the actual owner address and loan. A saved external pointer returns its actual pointee targets and external parent loans. A receiver-bounded shared view retains the receiver loan as well; it does not narrow or freshen the saved Fixed class. Scalar and plain value results add no loan.

`retained_return_sources` is an untrusted function result-source upper. Each result port has a complete `StorageSourceBinding` from its actual input selectors. None is unknown. Explicit empty source rows require actual empty dependencies; missing rows cannot create that proof. A whole empty proposal is valid only when every actual returned port is independently known empty. Definitions prove each actual Return is within the declared upper; calls substitute actual operand permissions and all parent loans. Capture and retained selectors are metadata, never GEPs into pointer slots. Existing holder and Task contracts retain their own proof obligations.

`DynGuarantee::StorageSources` is a receiver **after-state upper**, not an assignment or an equality assertion. Its position selects the receiver port after the call. Sources naming `Parameter(0)` select the call-before snapshot; other sources select actual evaluated arguments. Every receiver port requires a complete row. Definitions independently prove their actual external-after facts are within this upper. Calls establish the new row and all of its parents before replacing the old row and releasing any retired dependency. The owner/head location and its loan ancestry remain present throughout.

A declaration-level conservative mutable upper may include the old port plus compatible arguments in the same actual Fixed class. It is independent of the currently available provider set. Such an upper can prolong an old target's borrow until owner cleanup; it does not promise precise retirement. Only an explicit narrower guarantee, proved for every actual provider CFG, permits that precision. Shared receivers acquire no exclusive access by listing a source.

Whole-owner cleanup consumes the carrier responsibility, not ownership of its external port targets. It accesses external targets only through the declared port bounds. Reconstruct actual user teardown, fields, Store live prefixes, captured remainder and heap release independently, including allocation failure. Release external parent loans after actual synchronous cleanup. Unknown effects, missing responsibility, incomplete source rows and unproved asynchronous cleanup never become empty contracts. Budget every recipe, path, type, source vector and absent/present discriminant before recursive cloning, hashing or expansion. Wire transport and fingerprints grant no authority.
