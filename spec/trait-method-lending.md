# Trait method lending

Ordinary static nominal traits may declare method-local life binders on shared or mutable receivers. The finite profile returns an existing shared thin address directly or inside the canonical built-in `Option`; its referent is an existing Copy type or declared Copy associated `Item`. The method life variables identify actual input positions, including lowered receiver position 0. Each invocation substitutes its actual inputs. An implementation may alpha-rename local binders but must preserve the complete relation, receiver mode, nominal trait/provider identity, associated substitution, coherence and visibility.

Definitions, implementations and generic consumers, including unused definitions, retain bounds, scope and loan checks. The implementation body must prove returned roots lie within the declared relation. A shared result borrowed through a mutable receiver retains its parent loan through last use. While live, it prevents an overlapping call, movement or overwrite. Distinct receivers and use after last use remain valid; local, wrong-parameter and retired-root returns are rejected. Analyze and Verify reconstruct actual CFG and call provenance independently.

This profile includes ordinary nongeneric traits with `Item:Copy`, concrete nominal implementations, existing type-only nominal generic implementations and generic functions consuming the trait bound. Method generics in this profile are life-only. It does not grant GAT, trait/impl life parameters, default body, mutable or fat Option payload, blanket selection, dyn, async, owning, capture or storage capabilities. The existing generic, default and inherent cases follow their own established contracts.

A type-only generic implementation may write bounds on its associated type equation, including bounds beyond the trait declaration. Every such bound is proved from the complete symbolic equation and the implementation's own declared premises when the implementation is defined, even if no instance is called. The trait's declared bounds are proved independently and remain the only associated bounds exposed to a generic consumer. The trait parameters and implementation parameters retain their separate binders, and module paths in both the implementation premises and associated bounds resolve to their actual nominal providers. An equation cannot establish its own premise; active equation cycles and overlapping implementation heads remain errors. This does not admit generic associated type members, implementation life/const binders or projected implementation heads.

The `std.iter` interface and cross-module consumers preserve provider/Item identity and the per-call lending relation. Raw/Wire mutations must be rejected by independent checks of actual provenance, not producer annotations. Scans, maps, substitutions and queues consume the current request budget.
