# Explicit owned dyn storage

The joint runtime schema, Wire envelope, Typed, Type and LifeInventory identity domains are version 48. Older envelopes, including versions 46 and 47, and unknown future versions are rejected; the frozen version-40 fixture adapter remains test-only. Transport records never grant semantic authority.

`OwnedDyn<dyn Trait>` owns one complete, self-contained concrete provider. Source constructs it only with `owned_dyn::<dyn Trait>(package)`, moving a complete owning Package as an ordinary value. The result is `DynCreateError!OwnedDyn<dyn Trait>` with the single error case `Allocation`. Construction consumes its source on both outcomes: a failed allocation synchronously performs the source's exact concrete cleanup once; success transfers its whole obligation into the erased owner. All argument evaluation and failure preparation obey ordinary source order and cleanup.

The immutable table holds method function pointers in slot order followed by one compiler-generated payload cleanup pointer for owning tables. The cleanup function has internal ABI `void(ptr concrete_payload)` and is derived from the exact canonical Self and its concrete resource definitions; it does not acquire an ordinary `&mut Self` method loan or invent an owning value. The owner pair remains `{ptr, ptr}` in function parameters, returns and local storage. The compiler owns allocation/deallocation; no table entry may replace its deallocator. `Heap` requires the checked target allocator ABI, and failure does not publish a pair. Cleanup has already assumed the single obligation before calling user teardown, and never reads the payload after deallocation. Each static constructor reserves one entry-block concrete cleanup scratch before loop execution; every allocation-failure activation reuses it after completing the preceding cleanup. A module accepting only an `OwnedDyn` parameter still runs the affine obligation solver and emits the interface's drop helper even when it declares no local resource or concrete vtable.

Full self-contained ordinary Packages must contain at least one actual managed leaf. Eligible leaves are the sealed ByteBuffer, a canonical ordinary resource with a closed Copy payload and independently checked synchronous user teardown, or a canonical Store whose complete element cleanup recursively satisfies this rule. Companion fields may be closed Copy scalars, Records, Tuples, Enums or fixed Arrays, or qualifying nested Packages. Resource identity includes the actual nominal payload and teardown target; equal layout never substitutes for identity. Store cleanup traverses its real live prefix in the ordinary element order. Desc, Address, qualified borrowed fields, opaque cleanup, retained ports, async close, guards and unverified thread capabilities still reject in this closed profile.

`DynInterface.owning_cleanup: Option<DynCleanupContract>` is the independent whole-owner bound. `None` means Unknown and prohibits every `OwnedDyn` use, including a parameter-only module. The current closed bound requires `environment = true`, empty external positions/read/write sets, and an explicit finite synchronous effect upper bound. `environment` consumes the carrier obligation and grants no ownership of an external borrowed leaf. Slot `DynContract.cleanup` describes an ordinary method call and cannot replace this bound. Types checks actual Core teardown targets and bodies; Analyze and Verify independently reconstruct concrete resource identities, exact descriptor signatures, Store element cleanup and reachable direct code. Foreign cleanup conservatively requires Alloc, Ffi, Io, Block, Reenter and Panic bounds; it is never inferred pure from a missing foreign contract. Unrecognized operations, indirect or recursive unknown cleanup, asynchronous code and unproved effects reject. The ByteBuffer route retains its independently proved empty user effects. Metadata lists, positions, projections and effect types are charged and bounded before fingerprinting, including an absent bound’s discriminant.

Fixed method value/receiver contracts and shared field-address results retain proof from every real provider body. Unknown contract components remain Unknown. Types and Analyze reconstruct actual source, concrete type, route and obligations; Verify reconstructs the same independently from raw/Wire; Lower consumes verified bindings. Every new type, table, glue and operation is charged before allocation or expansion. Same-named or same-sized providers never share cleanup identity.

A complete `OwnedDyn` may move into a self-contained environment. Creation transfers the actual owner once. A consuming FnOnce entry may use `TakeCapture` to transfer that field into one activation-local owner; ordinary local cleanup then discharges it. Shared Fn and exclusive FnMut entries instead use `BorrowCapture` to address the actual still-live owning field, retain its responsibility in the environment, and may repeatedly call through borrowed `OwnedDyn` parameters or its actual methods. Fn never grants an exclusive owner address. Dropping an uninvoked or repeatedly invoked environment clears the capture flag before calling the same erased-owner cleanup. `ReadCapture`, ordinary `ReadAddress`, `WriteAddress` and copying `Load` may never copy or replace the pair. Internal owner addresses do not satisfy the foreign C payload profile. Nonmoving captures, shared/repeated consumption and error unions carrying an unselected owner remain rejected. Both kernels independently track the capture debt, actual source and parent loans and verify all normal exits. Factory and generic forwarding preserve the same complete environment obligation.

A concrete ByteBuffer view cannot remain live across whole-provider erasure. Borrowed method results likewise prevent conflicting moves, replacement or owner cleanup until their last actual use; raw/Wire instruction reordering receives the same independent checks.
