# Explicit owned dyn storage

`OwnedDyn<dyn Trait>` owns one complete, self-contained concrete provider. Source constructs it only with `owned_dyn::<dyn Trait>(provider)`, where a resource input is explicitly `give` and an owning Package input moves as an ordinary value. The result is `DynCreateError!OwnedDyn<dyn Trait>` with the single error case `Allocation`. Construction consumes its source on both outcomes: a failed allocation synchronously performs the source's exact concrete cleanup once; success transfers its whole obligation into the erased owner. All argument evaluation and failure preparation obey ordinary source order and cleanup.

| Public item | Tag / physical ABI | Obligation |
| --- | --- | --- |
| `Type::OwnedDyn { interface }` | Type tag 40; two native pointers `{payload, table}` | Affine owner, no Copy, no implicit coercion or thread capability. |
| `CoreExprKind::MakeDynOwned`, `InstructionKind::MakeDynOwned { interface, vtable, source, route: Heap }` | Typed opcode 148; `DynCreateError!OwnedDyn` | Source is one complete actual Self. Allocate checked Self size/alignment; on failure clear the transferred source responsibility only after concrete cleanup. |
| `InstructionKind::BorrowDynOwned { local, mutable }` | Typed opcode 149; `Address<Dyn>` pair | Actual live owner local, shared/exclusive loan tied to that local. No move/drop while a conflicting loan is live. |
| `InstructionKind::DropDynOwned { local }` | Typed opcode 150; no value | Conditionally clear live flag, invoke table's compiler-derived concrete payload glue, then deallocate payload once using the same Heap route. |
| `CoreDynVtable.owned_storage`, `DynVtable.owned_storage` | `None=0`, `Some(Heap)=1`; appended after ordinary `cleanup` in Wire45/fingerprint45 | An owning constructor requires `Some(Heap)` and exact actual Self, impl, complete slots and structured cleanup eligibility. Borrow-only tables retain `None`. Ordinary `cleanup: Option<DynEntry>` is unrelated to owning drop glue. |

The immutable table holds method function pointers in slot order followed by one compiler-generated payload cleanup pointer for owning tables. The cleanup function has internal ABI `void(ptr concrete_payload)` and is derived from the exact canonical Self and actual `ResourceDefinition`/Drop binding; it does not acquire an ordinary `&mut Self` method loan or invent an owning value. The owner pair remains `{ptr, ptr}` in function parameters, returns and local storage. The compiler owns allocation/deallocation; no table entry may replace its deallocator. `Heap` requires the checked target allocator ABI, and failure does not publish a pair. Cleanup has already assumed the single obligation before calling user teardown, and never reads the payload after deallocation.

Only full self-contained ordinary Packages and synchronous registered Managed resource heads are eligible in this first profile. Retained borrowed fields/ports, async close, guards and unverified thread capabilities reject. Existing fixed Unit/scalar method contracts continue to require proof from each real provider body, including arithmetic Panic and actual receiver accesses. `None` contract components remain Unknown. Types and Analyze reconstruct actual source, concrete type, route and obligations; Verify independently reconstructs the same from raw/Wire; Lower consumes only verified bindings. Every new type, table, glue and operation is charged before its allocation or expansion. Same-named or same-sized providers never share cleanup identity.
