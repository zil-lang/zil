# Explicit owned dyn storage

`OwnedDyn<dyn Trait>` owns one complete, self-contained concrete provider. Source constructs it only with `owned_dyn::<dyn Trait>(package)`, moving a complete owning Package as an ordinary value. The result is `DynCreateError!OwnedDyn<dyn Trait>` with the single error case `Allocation`. Construction consumes its source on both outcomes: a failed allocation synchronously performs the source's exact concrete cleanup once; success transfers its whole obligation into the erased owner. All argument evaluation and failure preparation obey ordinary source order and cleanup.

| Public item | Tag / physical ABI | Obligation |
| --- | --- | --- |
| `Type::OwnedDyn { interface }` | Type tag 40; two native pointers `{payload, table}` | Affine owner, no Copy, no implicit coercion or thread capability. |
| `CoreExprKind::MakeDynOwned`, `InstructionKind::MakeDynOwned { interface, vtable, source, route: Heap }` | Typed opcode 148; `DynCreateError!OwnedDyn` | Source is one complete actual Self. Allocate checked Self size/alignment; on failure clear the transferred source responsibility only after concrete cleanup. |
| `InstructionKind::BorrowDynOwned { local, mutable }` | Typed opcode 149; `Address<Dyn>` pair | Actual live owner local, shared/exclusive loan tied to that local. No move/drop while a conflicting loan is live. |
| `InstructionKind::DropDynOwned { local }` | Typed opcode 150; no value | Conditionally clear live flag, invoke table's compiler-derived concrete payload glue, then deallocate payload once using the same Heap route. |
| `CoreDynVtable.owned_storage`, `DynVtable.owned_storage` | `None=0`, `Some(Heap)=1`; appended after ordinary `cleanup` in Wire45/fingerprint45 | An owning constructor requires `Some(Heap)` and exact actual Self, impl, complete slots and structured cleanup eligibility. Borrow-only tables retain `None`. Ordinary `cleanup: Option<DynEntry>` is unrelated to owning drop glue. |

The immutable table holds method function pointers in slot order followed by one compiler-generated payload cleanup pointer for owning tables. The cleanup function has internal ABI `void(ptr concrete_payload)` and is derived from the exact canonical Self and sealed ByteBuffer resource definition; it does not acquire an ordinary `&mut Self` method loan or invent an owning value. The owner pair remains `{ptr, ptr}` in function parameters, returns and local storage. The compiler owns allocation/deallocation; no table entry may replace its deallocator. `Heap` requires the checked target allocator ABI, and failure does not publish a pair. Cleanup has already assumed the single obligation before calling user teardown, and never reads the payload after deallocation. Each static constructor reserves one entry-block concrete cleanup scratch before loop execution; every allocation-failure activation reuses it after completing the preceding cleanup. A module accepting only an `OwnedDyn` parameter still runs the affine obligation solver and emits the interface's drop helper even when it declares no local resource or concrete vtable.

Only full self-contained ordinary Packages with at least one actual `Managed<ByteBuffer>` leaf; other fields may recursively be closed Copy scalar, Record, Tuple, Enum or fixed Array, or another qualifying nested Package are eligible in this first profile. The ByteBuffer resource definition must be the unique sealed builtin with no user teardown. All other Managed heads, user Drop bindings, Store, Desc, Address, borrowed-qualified fields and unknown cleanup reject. Slot `DynContract.cleanup` describes an ordinary method call, not the erasing owner's destructor. Supporting user Drop requires a separate whole-owner cleanup bound on the interface or owning carrier, with explicit effects, accessed positions and source upper bounds, proved independently for every concrete provider; `None` there would mean Unknown. The sealed ByteBuffer route has compiler-proved empty user cleanup effects. Retained borrowed fields/ports, async close, guards and unverified thread capabilities reject. Existing fixed Unit/scalar method contracts continue to require proof from each real provider body, including arithmetic Panic and actual receiver accesses. `None` contract components remain Unknown. Types and Analyze reconstruct actual source, concrete type, route and obligations; Verify independently reconstructs the same from raw/Wire; Lower consumes only verified bindings. Every new type, table, glue and operation is charged before its allocation or expansion. Same-named or same-sized providers never share cleanup identity.

An `OwnedDyn` value or an error union carrying it cannot be captured by a closure in this profile. Analyze and Verify independently reject this raw shape because closure capture debt is not part of the owner carrier rule. A concrete ByteBuffer view cannot remain live across whole-provider erasure: both kernels check the actual future view use against the provider root, including raw/Wire instruction reordering.
