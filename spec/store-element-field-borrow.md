# Store element and field borrowing

The governing rules are in `_zil_design.md`; this attachment records the finite admission and borrowing conditions.

- Compiler-reserved `StoreElement` constrains the admitted element shape. It does not grant Copy, Managed, address, or cleanup authority; users cannot implement or shadow it. An unconstrained type parameter or user empty trait does not establish eligibility.
- Local and field projections retain both the parent shell lifetime and the precise field access range. A disjoint sibling field is usable, while moving or cleaning up the complete parent and replacing an overlapping field remain prohibited while dependencies live.
- `store_at_mut(store, index)` forms a synchronous, nonescaping exclusive window into one complete element. Check the actual length before forming its address. The window may read or update Copy fields, but cannot take Managed responsibility, copy an entire Package, or create a hole. Unknown indices do not establish disjointness; structural mutation waits until the last use.
- Analyze and Verify must independently reconstruct source, layout, control flow, and real obligations. Neither a shared schema field nor producer metadata grants safety authority.

A shared `store_at` view may return a shared complete eligible element or a Copy field through an ordinary helper, including an explicit lifetime and one or more actual StoreElement binders. The result source is the actual manager and element domain, not the temporary pointer variable or an inline field of the manager. Whole-manager structural pinning is conservative: reserve, push, pop, replacement and owner movement wait until the last relevant use. Matching pointee types or lifetime class labels do not identify a source.

For the admitted `Option<&V>` route, a saved Some and a helper call result retain their actual manager loan before any payload projection. An `inspect` or identity helper accepts the exact input payload selector and substitutes the caller's real leaf; None creates no target. The address is only a thin pointer in the payload: resource flow creates no V owner debt and uses no Store-head retirement exemption for an element. Stored target permissions, ordinary manager ownership and lifetime flow are each proved on the same CFG. The shared qualified Enum resource skeleton has zero owning leaves; it is not a language Copy grant. Mutable address updates to such Enum carriers remain outside this route.
