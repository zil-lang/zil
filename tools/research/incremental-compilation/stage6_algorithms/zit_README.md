# zit 同步查询适配实验

这次把原内核实际改造后再运行，不把 Web/JS 内核的高度策略视为其原应用的错误。源文件保持原字节，SHA256 为 `719a914356a24ac1edbeb1ffe6637d22311c9299e6be9ddbcdf3f7fdddf1474f`。`zit_adapter.mjs` 按唯一源码片段做可审查替换，Node 只擦除 TypeScript 与补充未提供的工具函数。

适配保留原 `bond` 游标、稳定边对象、直接 dirty 通知、等值屏障和高度队列，增加：

- 活动求值栈判断真正的递归读取；提交候选依赖时用当前消费者闭包的 Kahn 检查准确判环，秩可以升降，不使用固定高度上限。
- 依赖未变且所需秩未变时不重排。秩降低时同步重分已排队节点；只计算受影响消费者闭包。
- 按实际反向边标记可能失效者；拉取只核对其祖先。不能在活动查询中任意 flush 无关队列，否则动态 DAG 的调度重入会被误认成依赖环。
- 单次查询失败恢复上一成功值、边对象和边顺序，失败查询不能标绿。嵌套查询成功提交不属于同一全局原子事务，因此这仍不是编译器完整事务实现。

`zit_probe.mjs` 包含 5000 次无环方向切换、真实递归与经缓存节点成环、菱形批处理/相等屏障、稳定边重用/剪除、失败恢复、1200 层链、40 节点 500 次随机 DAG 修改。随机控制逐次比较 20000 个新值及 20000 个拓扑秩，不依赖适配器给出的结果作 oracle。

可选调用图来自当前保存的真实 LLVM 诊断产物，携带产物 SHA/生产提交。图的节点计算替换成简单数值函数，因此它验证真实拓扑上的调度行为，而不是原编译器查询语义或完整编译时间。旧内核与适配内核都跑同一图、同一编辑；旧内核的高度换向负控不计入可比性能。

```sh
node tools/research/incremental-compilation/stage6_algorithms/zit_probe.mjs \
  evidence/research/incremental-compilation/stage5/validation/zit.ts \
  /tmp/zit-probe.json /path/to/callgraph-large-8192.json
```

适配后的 8192 函数图有 8195 个节点、8194 条直接调用边。一次叶修改重新求值 4 个节点，两内核相同；适配版只标记 4 个潜在失效者，0 次重排。与此同时，它仍读取/快照 8198 条边并做 24594 次依赖形状边检查。大聚合函数的线性成本没有消失，不能把 4 对 8195 的求值数称为 2048 倍编译加速。具体计数由每份 JSON 中的 `editStats` 留存，独立结果核对的读取单列在累计 `stats`。

性能脚本须在协调的独占窗口运行：

```sh
taskset -c 0,1 python3 tools/research/incremental-compilation/stage6_algorithms/zit_bench.py \
  evidence/research/incremental-compilation/stage5/validation/zit.ts \
  /workspace/.zil-env/research/stage6-algorithms \
  /tmp/zit-benchmark.json 6 100
```

默认七种实际拓扑，每种六区组 AB/BA，每臂一个新 Node 进程，分别记录图初始化、100 次编辑、失败恢复绝对成本和外层进程墙钟。初始化内部时间不含 TS 擦除/导入，但外层墙钟包含。失败恢复时两内核的依赖提交合同不同，故不计算其速度比。完整行、操作计数、脚本及输入身份都保留。它没有同时给出置信区间、编译器总时间或内存产品结论。

## 已完成的独占窗口

`stage6-ee786-graph-zit-01` 完成七图、六区组、84 个独立 Node worker。原 Node 父 runner 调用 `spawnSync` 时被当前沙箱以 `EPERM` 拒绝，失败记录保留；改为 `zit_bench.py` 父进程调用同一份、未改字节的 `zit_bench.mjs --worker` 后完成整个窗口，未把启动失败当作快慢样本。实际结果为 `/workspace/.zil-env/research/stage6-algorithms/zit-benchmark-python.json`，逐臂命令、标准错误和结果另在同名 `.jsonl`。

| 真实调用拓扑 | 适配/原内核冷初始化配对比 | 适配/原内核编辑配对比 |
|---|---:|---:|
| large-128 | 1.748 | 4.346 |
| large-512 | 3.330 | 2.454 |
| large-2048 | 2.405 | 2.678 |
| large-8192 | 2.280 | 3.404 |
| large-skew-8 | 1.851 | 2.445 |
| even-64x64 | 2.595 | 3.452 |
| body-16x16 | 1.776 | 1.993 |

这里是六个区组内比值的中位数，不能用两臂中位时间相除替代。所有七图都出现成本增加，没有建立适配后的速度优势。8192 拓扑每次编辑的两臂中位时间约 0.278→1.000 ms，完整依赖快照、形状比较、准确环/秩维护及失败策略确有费用。原内核与适配内核的稳定图重算节点数相同；修复提供的是面向编译查询的正确性条件，不能把新增条件免费化，也不能据此宣称生产编译器慢了这些倍数。

原高度换向负控不在这张表里。适配内核已通过该动态负控，但静态调用图上的回退说明：直接移植一套完整 JS 调度内核不会自动加速编译。稳定逻辑身份、实际读取依赖、等值停止传播仍可通过生产缓存与查询粒度改造单独实施，并由实际编译测量判断。

范围是固定生命周期、同步、纯数值查询节点；DOM、异步、求值中创建/销毁子 owner、并发、完整 SCC 固定点以及跨进程存储均不在这个适配实验中。生产接入应由实际 Session/语义查询实现及其真实源码正反例单独验证。
