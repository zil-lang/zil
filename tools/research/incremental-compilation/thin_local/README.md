# ThinLocal private compiler experiment

This tool prepares an exact compiler snapshot and records a single full source request. It does not change the production backend. Read changes/research-thin-local-lto.md before interpreting measurements.

1. Run prepare.py --repo /workspace/zil --out <new-snapshot>. Default revision is ee786e7fd7162cfd76d5f532fe5c80d9e175ad57. It records original source identities, exact patch, patched hash, and injects current machine preflight/capture for both Clang arms. It performs no compilation.
2. In an authorized functional/build window, activate the existing environment and build the snapshot with a separate CARGO_TARGET_DIR: cargo build --offline --locked --release -p zil-cli.
3. Run run_request.py --zil <snapshot-binary> --snapshot-receipt <snapshot>/RESEARCH.json --clang <pinned-clang> --lld <pinned-ld.lld> --source <main.zil> --out <new-request-dir> --cache <trusted-private-sequence-cache> --mode baseline|thin. Use --imports off (default) to isolate ThinLTO from manual AvailableExternally imports; --imports on tests composition. Use --closed only for the explicit closed-executable contract. Both modes use O2 and lld. Requests use current language Verify and actual machine preflight before captured IR enters the wrapper.

The wrapper requires byte equality with the actual transformed unit-N.ll capture. It never consumes public program.ll as a partition. Single-unit builds are routed through actual unit-0.ll by the private snapshot. Original and substituted commands, actual raw/normalized unit text, compiler/clang/lld identities, every pre-LTO bitcode or native object, export roots, LLD cache file keys and final output identities are recorded.

The pre-stage key retains full machine inputs and tool/options identity. Only the documented verified-fingerprint diagnostic comment is normalized; current authority is recorded separately. Pre-stage cache damage is a miss. Existing post-LTO files must match the previous manifest before being staged; actual post-LTO reuse decisions belong to lld, never to our source hash. New pre/post entries are committed only after driver Success. Every request still invokes the linker; no complete final-link action cache is claimed.

The default contract supplies actual External-definition export roots to both link arms. Closed mode omits only the exact current nonforeign LIR function identities from that root set. LLVM internalization may then remove them after global analysis while preserving references and unique function addresses. This policy still requires nm/readelf, behavior and resource/closure/address controls; flag equality alone is not proof of ABI equivalence.

Both arms now compile with -ffunction-sections/-fdata-sections and link with --gc-sections. This is an explicit matched link policy, not a production change. The first functional epoch omitted section GC; ThinLTO optimized the caller but retained 512 otherwise-unused canonical functions in the 600-helper closed case. Re-linking those exact bitcode inputs with GC removed them. Default export roots retain all 602 ZIL definitions with GC. Do not attribute changing this link policy to ThinLTO alone; only compare the matched second epoch.

result.json elapsed_ns measures the current driver plus wrapper invocations. compile_service_elapsed_ns additionally includes setup/tool hashing, staged cache copy, audit inventories and transactional publication, excluding native execution. Use full-service time or an external timer when comparing overall compilation. This instrumentation-heavy prototype must first be compared against its same-snapshot Clang baseline; API-vs-Clang differences are not ThinLTO gains. All caches are trusted private local research inputs, not untrusted remote objects. Concurrent writers to the same sequence cache are unsupported.

controls.py --evidence-root <stage6> --out <new-dir> reproduces the 52 functional controls, including 40 scalar source requests across baseline/Thin × default/closed × DSO-local on/off, eight current-body rejection/cache-preservation cases and four resource/owned-closure/Drop/function-pointer cases. Activate the same LLVM runtime environment used to build the snapshot before running. These are functional controls, not formal performance measurements.

extended_controls.py --evidence-root <stage6> --controls <completed-controls-dir> --out <new-dir> performs 18 additional builds: pre/post-cache corruption recovery, four explicit manual-import composition cases, and 512-helper opaque-input arithmetic/branch/large-body cases across baseline/Thin and default/closed. The latter execute five independently checked runtime inputs per binary. This command deliberately corrupts disposable research cache entries in the named controls directory and checks recovery; use a research copy, never a production cache.

screen.py --zil <snapshot-binary> --clang <clang> --lld <ld.lld> --snapshot-receipt <snapshot>/RESEARCH.json --out <new-dir> --blocks 2 --dso-local runs nine source families: single-module 128/512/2048/4096/8192, even 4×2048, skewed 8192, branch and 64-statement body. Each block reverses baseline/Thin order, with independent cold/unchanged/early-edit/late-edit/restore sequences and private caches. This is 180 requests. Run again with --closed into a different directory; never merge the two export contracts. --case limits families and --imports on separately tests composition. Schedule this command only in an exclusive performance window.

The primary screen time includes the entire compile service, including hashing the compiler/Clang/LLD executables on every request, current validation and cache publication. This research audit overhead is significant for small/warm requests; driver-only timing is reported separately for diagnosis, never substituted silently. Text/executable bytes, preserved export roots, current preflight, actual pre keys and LLVM-generated post keys are retained per request. Key-presence deltas are not claimed as precise backend CPU attribution. The screen checks functional output, not representative runtime throughput; use opaque runtime controls and separate run-time measurements before promoting a policy.

Optional --dso-local changes only actual External function definitions named by the structured snapshot capture; declarations and AvailableExternally bodies are untouched. Raw and transformed text are retained, and the flag plus transformed text enter pre-stage keys. LLVM23 exposes no LLVMSetDSOLocal C API in the pinned library, so this is explicitly a Clang/text-only experiment, not an implemented native API property. Export roots stay unchanged; DSO-local does not imply hidden visibility or removal of an exported definition.
