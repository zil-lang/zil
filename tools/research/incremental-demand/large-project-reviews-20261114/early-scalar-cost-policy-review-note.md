# 早期标量优化成本策略：只读附注

附于既有 early-scalar / scalar-admission 审查；本页是策略判断，不构成对 stock30c 精确源码或尚未完成测量的接受。未施工、构建或测量。

**判断：按当前函数实际 LIR 成本选择早期优化是合理的通用策略，但不应仅因千函数 ELF 不等就立即设阈值。** 优先完成 directSSA stock30c 的统一 QA 与匹配 host 重测。native capture 是下游捕获策略；关闭它不保证消除上游 leaf IR 经 inline 放大的差异。

若受控测量确认短函数的 producer/prepass 成本高于收益，可以让短函数走原 main `scalar_locals`，大函数走完整新 producer/早期优化链。该策略只选择代码生成方式；完整 O2、当前类型/Verify、LIR binding、机器 preflight 和发布事务都保持。两条代码生成路径都必须独立满足完整语义，阈值不得承担安全证明作用。

**安全落点**是普通函数生产器分流之前、任何新 directSSA/facts 驱动改写尚未改变该函数输出时。依据当前 LIR 的指令、block/边、local 等廉价长度信息做有界决定；计数溢出或不支持模式保守走原路径。若 directSSA 已在更早处改变表示，仅在末尾关闭 cleanup 或 native capture，不能称为恢复原 main 路径。还应核实全局 facts/摘要不会继续改写被选为原路径的短函数；所有影响输出的策略要进入相关缓存配置/失效条件。

**最少测量原则：**同 host/profile/features/LLVM、稳定磁盘余量与无竞争构建，保留原失败窗。用同一完整请求矩阵比较 main、全开、按成本选择；至少包含同总指令量的“多短函数/少大函数”、阈值邻近点和短长混合调用链，避免把项目总函数数当作函数成本。阈值由实际 producer/LLVM/链接分项和端到端冷、unchanged、private、broad 代价支持，不以哪一数值恰好让现有 fixture ELF 相等来选。样本不足时保留阈值为待验证策略，不声称通用优势。

**质量原则：**完整原输入、default limits、实际 Verify、运行结果/极值/首 trap/副作用顺序及 fresh 对照仍必需；阈值两侧和同一会话跨阈值编辑/恢复都要成立。既定全 ELF 门继续如实报告；ELF 不等本身不能证明语义错误，但 oracle 通过也不能把该门改记通过。局部名字/分配差异必须由实际 IR、符号/段/指令差异解释，不能预先认定只是不相关噪声。原 2500 simple 和 425 branchy 相等，不代表千函数已经覆盖。

只有质量与受控端到端结果共同支持，才值得落地该策略；即使启用后 ELF 相等，也不能单独证明策略正确或划算。若退化主要来自宿主/前端等非该 producer 阶段，则没有证据据此增加早期优化阈值。
