# 面向显著领先 Rust 的设计方向

本文件是理论方案，不是已实现功能或新性能结果。测量编译器仍为900293cfd，完整结果及恢复收据见8581aafc9。此次仅阅读源码和已有证据，没有新构建或测量。

## 用户目标与设计空间

用户明确要求显著超越 Rust 的编译速度并拉开差距，而不只是逼近。允许从语言设计、所有编译器架构层、验证架构、持久化、原生工作粒度到 LLVM 本身重构或重新设计；现有架构不是不可突破的边界。当前先理论分析，再实施。

保持有意义的安全保证和生成代码质量。语言/构建合同如需改变，必须明确描述和验证，不能暗中跳过验证、降低优化或预算、更换简单样例来制造领先。此前“不合main、不默认启用研究开关、保留失败和负结果、单一重窗口、远端保存证据”的约束继续有效。

Rust query 的 pull 是从结果需求出发递归索取/核验依赖；这里所说 Zit 的 push 是从具体变化点出发，逐层通知实际消费者，结果不变即停止。响应式读取为一致性进行的 pull 是另一个问题。当前 ZIL 是外层整项目阶段流水线加内部细粒度复用，主测 ProducerMemo 路径不执行 ReactiveGraph，不能把已有收益称作全局 push 的收益。

## 新核对的事实

- r7 单处编辑的对象处理423.304ms；唯一 LLVM miss409.943ms，其中 preflight26.939、builder21.951、O2优化142.324、机器码发射215.758ms。这不是理论下界，也不是正式903ms中位数的拆解。
- 正式矩阵 block0 私有编辑：ZIL 改变的对象定义42个符号（函数ID5–25、341–361）；Rust 对应对象定义一个优化后的 m0::value 符号。两边均复用15/16对象。一个优化后符号不等于一个源函数，42比1不等于42倍工作；这里只证明实际工作内容不同。
- 当前 ordinary 分区按源归属分组，再用 `(file % count + chunk % count) % count` 分配，可能把无关源组绑进同一重编单元。不能只移动样例中被编辑的 m0 来改善成绩。
- `machine_cgu::internalize_closed_executable` 已存在，受默认关闭的 closed Linux executable 路径控制。打开它不属于新实现；内部化还必须正确处理导出、ABI、外部使用、函数地址及实际跨单元引用。符号减少也不自动证明运行质量或编译时间更好。
- `_zil_design.md` §5.3 已要求公共合同投影与内联/CT/特化的实现依赖分离，私有实现满足既定上界时不应重查无关调用者。当前整项目 PrivateImplementation 依赖尚未贯彻这一设计。

## 核心架构：让变化成为被拥有和记录的事实

常驻保存稳定语义项、结果及精确反向依赖，以事务安装变化。边按 body、公共合同、ABI/layout、位置、构建环境区分。结果版本应表达实际值变化，不能因输入key或构造历史改变而自动变更。

```text
安装本批输入变化 → 只通知读取了已变投影的直接消费者
工作队列稳定化：处理当前依赖、动态边与递归分量
    重算受影响结果；只有值变化才继续通知
独立 Verify 维护并核验自己的当前输入/证明依赖
全部成功后原子发布本轮产物
```

不能把原来完整的 Expand/Types/Analyze 函数塞进图节点就称作完成。阶段结果改成持久化逐项集合，计数、标志、索引与指纹采用可精确增量更新的汇总；删除、负名字查询、依赖变化也必须入图。函数语义位置相对化，当前诊断位置单独映射。预算收费与首错顺序必须保持；简单相加不足以代替所有检查。

证明复用始终由独立 verifier 掌握，绑定当前不可变raw输入、实际依赖、完整规则/限额。Analyze的dirty标记不授予旧证明权限。外部文件/环境变化也是输入，漏事件或watcher溢出必须保守恢复。冷编译采用融合构图与函数/合同级节点，不无依据建立庞大的逐指令响应图；push只流向当前实际需要的产物消费者。

## 后端突破：分离优化范围与机器码复用范围

前端push不会自动消除 LLVM 对受影响CGU的整体工作。先查明私有实体为何保留外部可见性、无关函数为何共同重编，独立评估已有内部化能力，检查优化决策、运行时间和代码体积，不靠改CGU数制造收益。

更深的候选方案是 **ordinary O2之后的逐函数原生work product**：先完成必要优化区域，再在完整当前codegen上下文下比较优化后函数，只发射变化的机器函数，复用未变的机器码/重定位贡献。第一步针对发射成本，不声称已让LLVM优化本身增量化。

这需要处理模块级后端pass、全局/常量身份、linkage/COMDAT、地址逃逸、展开/debug数据、目标选项和符号引用；LLVM现在不自动提供这个完整复用边界。未证明域维持原完整发射。后续才研究按真实inline/global-summary依赖增量优化区域，源代码调用边不足以证明优化器依赖。

不能把很多隐藏的原生单元重新打包成16个对象就声称CGU粒度相同。应分别报告源项、优化区域、发射单元和最终对象；新后端按明确的代码质量保证比较。

## 删除没有实际消费者的工作

可重新设计构建产物合同：默认原生构建只需要可执行文件时，LLVM诊断文本成为显式请求的产物，而非每次完整生成/写出。目前sidecar合同不能被静默取消。消费者的启用不要求稳态更新重新变成自顶向下的缓存遍历。

链接/工具解析形成完整可复用的构建输入描述，覆盖配置、loader、搜索目录的不存在项及库/script内容；可以研究冻结工具链快照，但不能仅把当前发现成本挪出计时。两套持久化可共享已证明相同的raw body片段，分别保留不同格式及完整限额。

## 下一轮优先级与验收

1. **全流程push骨架**：替换外层整项目失效和重新组装，复用现有逐函数产物/独立证明作为节点值；以实际遍历、重算、分配和写出验收，不能只看命中率。
2. **后端原生粒度**：先界定真实可见性/优化边界，再建立安全的O2后发射复用；这是拉开原生编译差距的必要研发方向。
3. **产物/输入合同**：消除无消费者的文本发布、重复解析与重复函数体编码，不能继续把几十毫秒的局部优化当整体终点。

可将代表性单处/多处/恢复编辑端到端至少2倍领先Rust作为初始工程设计目标；这是建议目标，不是已有结果、性能预测或用户指定倍数。保留原425函数对照，新增复杂资源/CT/泛型真实场景而非换简单输入，保留冷/广与运行质量负结果。继续明确新Cargo与resident ZIL、LLVM版本和检查保证差别。高风险LLVM方案在实现、独审及测量前只是待证假设。
