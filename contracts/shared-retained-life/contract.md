# Shared retained-life model handoff

This is an external data-model patch for root publication, not a production edit or acceptance claim. Apply `retained-life-model.patch` to b377, then `retained-life-inventory.patch`; `dyn-retained-model.patch` targets341's external draft. The CT companion targets344's separate CT3 WIP and must be composed only with that actual schema. Root owns version/domain changes and consumers.

## One fixed domain, three distinct kinds of information

`StorageLifeShape.slots` contains only actual physical Address/Desc leaves. Its path remains PlaceProjection and is the only path accepted by129/130. `retained` maps every class of a nested qualified carrier into the enclosing fixed domain once. Several ports sharing that class use that same mapping. `nominal_arguments` binds actual nominal lifetime argument positions, including phantom positions with no physical field. All three contribute to the one canonical binder domain. None is an actual target or permission.

A nested map stops at its carrier: BorrowedStorage, Address<Dyn>, or later qualified Task/owning head. Do not flatten that child's classes into independently fresh physical rows. Metadata TypeArgument/Pointee/Element/Parameter/Result selectors must match the actual semantic constructor and complete argument/signature inventory; they never create a byte path or permission to dereference. Physical storage traversal does not cross pointer slots. For lookup through an entry Address, the existing single entry-address unwrap rule remains.

Canonical numbering scans the actual semantic type in deterministic declaration/argument order. At a nominal node, visit its complete ordered lifetime actual occurrences; at an actual physical borrow leaf, visit its slot; at a nested qualified carrier, visit its canonical classes in child-class order. Keep the explicit child map and stop its physical flattening there. Stored vector order must agree with this traversal, not caller-supplied sorting by lexical names. Every child class and every nominal lifetime occurrence is accounted for exactly once; duplicate/conflicting/missing mappings and unused numeric tails reject. A class is allowed to have only a phantom nominal occurrence. A phantom-only wrapper is meaningful and MUST NOT erase. Phantom occurrences create no owner, target, read/write effect or returnable loan.

Example `Pair<life a,life b>{d:&'a dyn Reader<'b>,p:&'b i32}`: outer classes a=0,b=1; physical slots d->0,p->1; d's interface class0 maps to outer1. Two interface ports with binder0 both map via that single class row. Swapping d's class to outer0 changes semantic type identity. An actual value still needs independently reconstructed roots for both the outer receiver address and each hidden port.

Example phantom `Phantom<Tag<'b>>` with no fields: the real full-argument inventory identifies TypeArgument0 as Tag's type, and its lifetime actual at its full generic ordinal maps to b. The relation is retained even though slots is empty. Empty erasure is valid only when slots, retained and nominal_arguments are all empty and no enclosing actual/nominal relation is discarded.

## Declaration and instance inventory is required

Existing CoreAggregateTemplate/Application covers only the old finite Package recipe. TypedModule has no general nominal binder-kind/full-actual inventory. The new `life_declarations` and `life_instances` rows fill that representational gap; names or compiler/module/NodeId bits alone are insufficient.

Source production resolves the actual original declaration through341's Origins/SourceIndex, reads its full ordered generic kinds, and records each complete actual instance after ordinary formation/obligation checks. CT production uses FrozenReadView.index + actual frozen syntax and its complete application snapshot. Both preserve original declaration identity through aliases, imports, generated scopes and nominal shadowing; no Span identity or parsing generated names.

Runtime/raw verification checks unique declaration keys and stable identities, exact full kind/arity, const domain/target bits, instance type constructor/complete fields, and a unique complete instance for every selected qualified nominal Type. Every NominalLifeArgument must name that actual instance's declaration and a real Lifetime slot. TypeArgument traversal comes from the full actual vector in that same instance, never field layout or a name hash. A Lifetime actual refers to the instance's own local fixed scope; nested/outer uses compose through retained maps. Two identical qualified types cannot select different declaration/actual vectors. All ordinary shape/ownership/loan/call validation still runs. These raw inventory rows do not prove trait premises, Copy, Share, Transfer, visibility or builtin identity. Compiler-reserved declarations must additionally match the actual registered canonical builtin definition; a compiler flag cannot create one.

Stable semantic fingerprints include the resolved declaration identity and full ordered actuals/relations, not raw module/NodeId numbers. Cross-request source/interface consumers must use the same context-aware traversal required for Dyn. The original structural `Type::fingerprint` of a raw table reference is not an adequate export/cache identity. Table relocation changes references consistently; changing actual argument kind, phantom relation or selected declaration changes identity. Frozen CT visibility services remain the authority for private-definition queries.

## Ports and class maps stay separate

`RetainedLifeShape` is the common opaque-carrier fixed domain plus typed ports. DynInterface stores it; each vtable maps each port once to actual concrete Self storage/capture. The map must check the complete actual Address/Desc leaf, mode and declared fixed class. Multiple ports may share a class without proving target equality or apart.

`ContractProjection::RetainedClass` selects a class only for binding. It is illegal in Read/Write/Manage/Call or physical operations. `RetainedPort` selects one actual typed port for effect/result substitution; it does not imply a class mapping or actual permission. A readonly stored Desc remains readonly even when the interface upper is WritableDescription. Resolve a nested contract path through checked carriers/classes, never through raw GEPs. RetainedClass and RetainedPort are terminal selectors. No independent Dyn-only permission engine is introduced.

A fixed class must be grounded in the actual retained/nominal class of the real value; an Invocation binder meeting it binds that existing upper without narrowing or freshening it. A phantom class can preserve type identity but supplies no target roots. Flat invocation relations and stored relations must have one authority: reject contradictory dual metadata, or independently require an exact projection.

## Task integration

Current Task<T>38 has no retained shape and remains the no-external-frame-dependency profile. Independently inspect entry PC0 as well as all suspended/closing PCs: inputs are retained immediately between Create and first poll even without Yield. T, an empty result relation or ClosedEnvironment(T) says nothing about hidden inputs/captures/children.

When the borrowed Task lane is published, its semantic type becomes `Task { result, retained_life: RetainedLifeShape }`; no runtime layout change is implied. A zero-class/zero-port shape retains the closed current lane. TaskCreate's actual worker/ordered arguments and all live/possibly initialized frame states independently determine the port-source mapping. Use the same complete typed borrowed leaves, canonical classes and concrete root/loan/epoch engine as stored carriers and dyn. A private Verify-derived mapping is sufficient where it is reconstructed from actual worker CFG; if any mapping crosses raw/module boundaries, serialize it as untrusted port->StoragePosition data and independently recheck it. Do not accept a proof flag or derive captures from result T.

An input port is rooted in a real worker parameter/capture borrowed position. A child may borrow the parent frame's actual owned storage: that is an internal parent/frame loan, not an invented external port. Parent cleanup waits for child close/drain. Every success/error/partial preparation and saved PC is covered. Failed allocation/creation cleans transferred input obligations once and publishes no live Task.

RequestCancel and computation Ready do not release retention. Close/drain/destroy discharges actual remaining users and responsibilities. A moved Ready T keeps its actual target/owner/parent roots. A result borrowing frame-owned storage cannot survive Destroy: retain the actual frame loan (blocking destruction) through the common lending/storage mechanism, or reject until that mechanism exists. Do not add RC or merely label the result with a life.

Task moves, stores, returned factories and exported interfaces must preserve the complete retained shape/class map in semantic identity. Source Task<'s,T> and inferred exports require the real full stored/retained contract; omitted hidden relations cannot default to closed. A raw C/SABI export with borrowed inputs/results remains unsupported until its explicit retained contract and actual caller boundary are represented and checked. The existing closed scalar public ABI remains unchanged.

## CT numeric scope companion

CtLifetimeArgument contains a real numeric owner-node and Fixed/Invocation binder. Owner links are semantic backreferences and are excluded from physical type children/cycle/layout walks. Independently check physical DAG validity and lexical scope validity. A Fixed owner must be an actual retained binder owner; Invocation must be an actual invocation binder owner such as BFP. Count/range/domain must match. The referenced owner must actually enclose the occurrence in the checked complete graph, not merely be some reachable same-shaped node. A schema arg resolves in its schema's one joint life_context. Missing, dangling, wrong-domain, sibling-owner or escaped references reject.

Renumber/copy/remap physical nodes and owner references together, including forward owner references. Canonical keys encode the validated relative binder scope/domain/ordinal, not incidental node IDs. Sharing a DAG node may not change lexical scope; a shared life-bearing node must validate in every actual occurrence context. Numeric source IDs are never assumed globally stable.

One schema life_context is the complete closed qualified nominal application, including all ordered type/const/life actuals and nested maps. Its nominal root must match the schema's actual symbol. When life_context is present, every type actual MUST be CtSchemaArgument::TypeInContext(CtTypeNodeId), selecting its exact corresponding argument node in that SAME graph. Standalone Type(CtTypeRef) is forbidden in this contextual form. Context-free schemas retain Type(CtTypeRef) for genuinely closed argument graphs; an intrinsic closed BFP FunctionLifeContract alone does not require an application-fixed context. Lifetime refs within a Type graph are local to that graph; Lifetime schema refs are local to the explicit joint context. Do not alpha-freshen each argument separately and then discard the joint equality relation. Missing context, independently freshened phantom relations and context/argument mismatches reject. Context identity participates in full record/enum/Sum keys.

A query extracting a contextual type argument must keep a real scoped context handle; if its current return representation cannot do that, it rejects Unsupported rather than returning an independently fresh graph. Generated Type/Syntax materialization must preserve this one numeric scope and argument kinds. Fresh lexical names may be produced only for binders actually created by the materializer and with all corresponding uses rebound consistently; a free lifetime spelling or empty-wrapper erasure is forbidden. Until the source/generated representation can express the complete scoped relation, that materialization path must explicitly reject Unsupported; the data model alone is not a language completion claim.

## Opaque shape recursion (final model supplement)

RetainedLifeShape has its own retained and nominal_arguments rows as well as ports. This is necessary for a port `&'a Stored<'b>`, a fixed associated type containing another carrier, or a Task result `Stored<'b>`: the outer port lifetime alone cannot describe the nested class. Metadata Port(i) selects the full declared port leaf; AssociatedType(i) selects the real fixed associated type; Result selects the actual Task result. Child-class maps have the same exactly-once rule as physical storage. Dyn slot invocation classes remain owned by that slot's storage_life and must never be promoted into the interface's fixed domain. RetainedPortBinding is a shared untrusted port-to-actual-StoragePosition record; vtable and task owners each independently constrain its allowed actual bases.
