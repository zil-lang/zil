# 文件参考

同级目录存在如下文件时使用，冲突就近优先：

- _skill.md：所属目录规范。
- `_<仓>-goal.md` / `_goal.md`：终态、不变量、验收规则、排期、当前提纲与已达提纲。
- `.task/<号>.md`、`.task/done/`：在途与已达工单，含施工文与往来记录。
- .agent/<功能点>.md：当前决策，只留当前态;

# 本skill术语说明

- **稳定性描述**：包括但不限于决策实施与Git提交等文档与标题描述
  - 优先描述公开行为、状态、因果、不变量、边界。
  - 优先使用业界术语，避免私有标识、路径、步骤、函数、类等易改名、易变性内容，引用使用仓库#号、禁止裸#号。
- **功能点**：稳定的功能或责任域，全局名为“顶层文件夹/独立包-逻辑功能”，如flow-路由、ed-blr等等。
- **改动点**：≤20字，一次实施的原子变化，提炼动因和变化；改动必有改动点，但可不产生新决策，影响多决策点的须拆条。
- **决策点**：≤20字，功能点内可独立选择的长期规则，共享同一核心不变量的风险与机制，可独立替换则拆点。一核心不变量加其备选为一点：太细重复约束且连续修补信号失效，太粗混不相关不变量。

# 单对话子代理调用

- **机械性任务定义**：跑测/搜证/复现/shell/浏览器等执行性明显高于分析性的任务;
- **强代理**：继承父模型，或旗舰高档推理(opus、sol、k3、grok high)，取最新版；
- **弱代理**：快速档(grok low/medium、haiku、sonnet)，取最新版；只做机械性任务、不判结论，回传结果/证据路径/失败项 ≤500 字。
- **分工**：强模型负责架构/分析/方案/结论/切片/派工，机械性任务优先派弱代理，指令明确;
  - **冷启动**：只读当前 skill、Goal 与状态；旧 transcript、大文档和历史范围交一只提取弱代理，回传 ≤8 行，父模型禁重复搜史。
  - **搜证**：`rg/grep` 默认只返文件；内容搜索无上下文且 `head_limit≤20`，`Read` 单窗 ≤40 行；一次裁决最多读取 6 个定点引用。
  - **顺序**：同主题按“提取→主模型切片→实施→审核/验收”进行;
  - **审核输入**：只给范围 diff、实施钉表、架构不变量和 ≤6 个定点引用；发现新疑点再定点追加，禁止自行重读历史或全库。
  - **父模型复判**：禁读完整 diff、终端和测试日志，只读实施/审核给出的定点窗，不足时 resume 原代理补证。
- **代理复用**：同片补证、返工续接原代理；跨片或续接不上开新代理，凭工单接续，不空等原代理。
- **任务状态**：等待阶段明确展示；长任务挂可见终端，禁隐藏窗口，通知只订阅结论行。
- **强制超时**：后台默认2×预估超时，疑似卡死先取证，确认挂起后按PID终止，终止后走「命令收口」；可降级重试或上报(与子代理协调);

# 工作流程(派工、施工、验收)

goal 为主仓唯一详细开发任务与派工安排，分支复用。

- **角色**：一个boss对话管全仓任务，任务状态只在工单与看板。
  - boss(主管)：排期、派工、改工单正文、裁例外、合入、归档；
  - 施工代理：强代理，一单一树一代理，复用。
  - 验收代理：强代理，一单一树一代理，复用，不由施工代理兼任。
- **工单/任务单**：主树 `.task/<号>.md` 为唯一记录，分树副本不读不改。
  - 状态：首行，记录 `施工|待验|退回|已合入|卡住`，最后动作方改；
  - 标题： <号> <中文名>`(≤12字)。
  - 正文：前置、目标、范围、接口约定、拒绝、退出、切片，只 boss 改，
  - 钉单：具体钉单号或写无。
  - 往来：末节追加开工、交付、验收记录，列表格式，一条一行、多条可多级列表，不写过程：
     - 交付记录：片号、基线、交付提交、检查命令、结果与证据路径。
     - 验收结果：合入提交、退回证据、返工要点等等。
  - 交片只认工单行，聊天与未跟踪文件不计。
- **编号**：开工取号、分配不改；分支、worktree、工单只用号，多仓前缀互不重叠。
- **一枝一树**：一任务一分支加一分树 worktree，同基线，验收合并后删除。
- **派工**：
    - 流程：从goal排期派工、放入task、修改当前任务提纲
    - 限流：每仓在建 ≤8；待验积压不停不占锁的施工，全机待验 ≥3 先合必须先合的单。
- **施工**：
  - 范围：只改本单范围，退回任务优先，一事一提，工单往来处提请求。
  - 测试：可跑单点钉、单树测试、本树构建，不跑全量(以全量本身为任务除外)。
  - 缺陷：本单问题本单修，同一缺陷失败三次上报卡住；外部缺陷只登记，不挡合入。
  - 交片：交片后续作下一片，前片退回同步修正。
- **验收**：机械门与验收都过才合入。
  - 机械门：验收脚本攒批、按档表定档、试合、红归因、快进合入，每批一行总判；常驻于可见终端、boss 只订阅总判，无常驻时 boss 按看板触发。无总判视为未验。
  - 验收：常规及以上档的代码片派审查代理，输入正文与交片范围 diff，查改裁判、写死测试、越出范围、退出数据不符，回传通过或 ≤3 条问题；锁被占时与机械门并行。
  - 集成：相交枝串行，独立枝并行，后合收前合；只合交片提交不合枝尖，合入改回施工，退出那片合入才写已合入。
  - 分级：文档不构建；产物与主干逐字相同为搬移，构建加钉；常规跑钉和受影响测试；高风险或核心产物变化跑全量。档表机械定档，施工不自定。
  - 全量：全量与速度门只由验收跑；全机一把锁，持锁进程不在即放，构建到剔除连续占锁，不并行构建、不杀施工。全量档无名单外红记全绿点，此后未经全量的合入满三次或超一天且锁空闲时补跑，红了先回退它们。
  - 红：按测试名复跑，过了记偶发、不挡合入；仍红按测试名归因，剔掉引入枝并退回；归不了因派分析代理，boss 不翻日志。
  - 提交：主树只暂存本次路径，不卷入他人未提交改动。
- **合并决策**：或有，实施过程中提交在本枝，合入后进集成枝，有冲突的修订原决策，试验过程只记往来。
- **等待期限**：每种等待都有机器期限，到期必醒，不靠 boss 巡检。验收持锁按档或钉数定预算，超预算由看门进程出「总判: 超时」、放锁、终止验收；主干自身大面积红直接不可合，不逐枝剔除。看板对卡住、待工、锁超时、可验每 30 分钟重复唤醒，同单两次唤醒工单未动标空转。
- **裁决阶梯**：被唤醒的卡住、待工、超时，boss 当次必走一步并在往来留一行：取证 → 续接原代理一次 → 新代理凭单接续 → 拆单或停住（末行写「停住」与等待条件）→ 上报用户；禁止无期限不改派。主干自身红时先停受害验收，二分归因，修正单置顶。

# 分析与思考

- **回应身份**：回答首句提供模型简称。Always respond in 中文。
- **解决思路**：第一性原理，找问题与目标的最短路径。
- **问题分析**：客观中性，先读事实及引用链，并理论推导逻辑/完成度，禁止附和、无效重测。
- **场景驱动**：决策按真实场景加权(不限于目前代码覆盖)，实现按理论最优，不受修改量和老代码兼容性限制。
- **反馈风格**：简约精准，按功能点陈述；禁过程叙事、禁大段贴码

# 任务约束

- **最小边界**：只改用户要求范围，顺路死代码/类型/注释一律不动、不询问。
- **跨层禁改**：顶层文件夹分属不同项目，改前须征得同意。
- **文档更新**：除更新goal/.task/.agent外，如无要求、不更新其他md文档;
- **注释与总结**：不动原注释，注释单行模式，言简意赅，优先代码目的、不写详细逻辑。
- **临时脚本**：用完删除，结束临时服务器/任务。

# 风格与实现

- **代码设计**：极度精简高效，逻辑直达、少抽象，确保代码少、效率高、功能够。
- **ui/dom写法**：强制使用zit语法(含zss)，不使用vue/react等语法，zit语法以api见 `docs/base/*.md`、以及相关源码。
- **脚本执行**：优先 pnpm、bun、pwsh、esm，禁npm、cjs，编码UTF-8。
- **文档风格**：技术博客风格，简约，有逻辑，对于源码设计要讲清楚：为什么、是什么、怎么做。
- **源码引用**：完整URL或本地用相对路径、确保能点，避免大段源码复制、可用startLine:endLine:filepath格式。

# 决策实施记录

权威见git和源码，决策=就近 `.agent`。

- **.agent/<功能点>.md决策文档**：一功能点一文件一决策点，格式如下：
  - **问题**：动因、影响、目标，不含方案
  - **约束**：决定方案的事实和不变量，只写结论。
  - **决策**：当前方案、闭环逻辑链、理由、代价、边界。
  - **备选**：若存在，记录逻辑链、优缺点、否决理由，可编号，禁虚构。
  - **验证钉**：稳定编号+标题，或无需/无法验证。
  - **依据文件**：决策若依赖会过期的测量，同名可复跑脚本放 `.agent/<决策点>.`*（纯 JS 优先；`%DebugPrint` 用 `.js`/`.mjs` 以免进 tsc）。头三行写清量什么、怎么跑、支撑哪一条。关键数字连环境与日期落 `.md`，文档可独立阅读。只放能重跑出数字的脚本，不放测试（测试在套件，文档用钉 ID 引用）。每点一两只。
- **连续修补**：同一决策点连续修补 ≥3 次，须写备选并评估底座，不得继续补丁。
- **自检**：不外查仍能说明动因、约束、规则和边界，前问题和决策逐项对应，重新生成。

# Git 提交

- **一事一提**：判据=独立逻辑+独立回滚；同提交，禁攒批。
  - 整理类改动(format/rename/cleanup等)，无独立回滚价值则fixup到所属提交，有价值可独立提交。
  - 琐碎类改动(纯改名/注释/规范等)可并入同一提交，首行写总意图，必要时正文一句带过细节。
- **首行**：`+|-|~ 功能点 改动点：动因，变化，预期`，+增-减~改，单行，稳定性描述。
  - 禁编号词/批次词/$斜杠等符号、禁写行为变化/所涉文件名/函数名等易变性内容。
- **正文**。首行看不出动机时补一句因果、或者补充验证钉说明，不写审核者、轮次、涉及文件，。
- **自检**：不外查仍能说明行为变化的核心、核心词改名后仍成立、能独立回滚

# 测试约束

- **明确风险点**：只测明确风险，能复现时合入，可做变异校验，禁对非风险点堆覆盖率。
  - **覆盖对齐风险**：对于明确的风险点，如核心路径、并发协议等，测试密度不得低于表面语法。
  - **门禁落盘**：性能与规模门禁，使用可追溯数字产物落盘(如json等)。
- **冲突处理**：一般冲突禁改spec迁就错误、逻辑变更导致测试必须变更可修改spec，契约场景消失删测退号。。
- **真实入口优先**：ui相关须从真实入口（鼠标键盘等）出发，禁产品API直调替代，模拟构造仅限前置状态与最终断言。
- **场景来源**：竞品公开issues、常见坑、roam;，并用bfs穷举生成。
- **roam流程**：定义状态和操作集、测试使用seed、操作原子化、失败bfs剪裁复现。
- **测试类型与文件组织**：(ts文件类型可视代码环境而定)
- **状态规范**：确定性状态规范（数据结构/API/工作流/DSL等）依据spec状态契约建模
  - scene场景测试：并入`xxx.test.ts`
  - roam随机带断言测试：并入`xxx.test.ts`
  - fuzz随机耗时测试：单列`xxx.fuzz.ts`
  - pf性能测试：单列`xxx.pf.ts`
  - dom环境测试：单列`xxx.pw.ts`(playwright)
  - ui演示：单列`xxx.demo.ts`
- **命名规范**：<@>[功能点]-[连续编号](或者旧版是[功能点][-或@][连续编号])
  - 带`@` 为roam测试，同一功能点共用连续编号，已分配不改号。
  - 标题≤20字，自解释，避免易变路径和函数名。
- **共享功能**：通用底座 `zit/__`，测试底座 `zit/zst`，单元底座放入单元同级文件；
- **文件数量**：默认 ≤2/单元、必要时放宽 3~4；

# 看板监视(仅对cursor适用)

- **看板监视**：boss 挂且仅挂一个，消失重挂。照下面原文发，命令、主树、唤醒标记取 goal，`block_until_ms` 必须是数字 0；首次打印无唤醒标记属正常，不重挂。

```json
{
  "command": "<goal 看板监视命令>",
  "working_directory": "<主树>",
  "description": "Watch board for signal changes",
  "block_until_ms": 0,
  "notify_on_output": { "pattern": "<唤醒标记>", "reason": "看板信号变化" }
}
```
