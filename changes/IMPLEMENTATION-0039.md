# 039 条件模式中的泛型实例与透明类型别名

先修035/037交汇：if let与while let的scrutinee只求值一次，按推导的具体enum实例改写模式路径并将payload类型放入成功分支局部环境。失败分支与外层不能获得成功分支绑定；复用普通match的预算与路径处理。

随后实现既有type alias语法的同模块透明语义，先借用预检，再规范化别名。类型签名、字段、构造及模式统一使用原类型身份；未用别名、前向引用、循环、重复名称和属性同样检查。函数泛型形参和局部值名称保持各自遮蔽规则。产物仍进入既有泛型、types、analyze和独立verify，不增加公共IR、权限或运行时成本。泛型别名和跨模块导出别名不属于本片。

实现范围：别名目标为当前已接通的标量、Unit、tuple、定长array、fn指针、引用以及同模块record/enum具体实例；方法接收者先展开别名再沿既有Self规则检查。别名不是新的名义类型。具体泛型enum的别名模式保留完整类型参数约束，并由模板定义检查与实例展开分别核对；私有合成路径只传递该约束，不以源码Span作身份，也不进入公共IR。借用预检覆盖源树、缓存展开类型、使用位置合并深度和最终展开树，循环、错误arity和未知目标在未使用定义上同样报错。带属性、bound或泛型形参的别名仍明确Unsupported。

原始组合程序在irrefutable tuple if-let之后还有return 0。条件实例修复后，该程序仍遇到既有“unreachable-statement type checking”Unsupported；依据_zil_design.md的不可达源码检查规则，它不是非法语言程序。本片用没有冗余尾句的同义程序证明条件实例修复，不声称完成该独立缺口。
