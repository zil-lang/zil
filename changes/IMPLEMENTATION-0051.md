# 051 本地资源闭包前端

施工基线为 draft09 `5e9826583929a5beadc3a3a5baec1efe1afb5a0c`。本片落实设计第9章已经确定的本地具体环境：资源与不相关 Copy 闭包共存；普通资源使用捕获 Desc；`move` Managed 或正文 `give` 在创建时转入环境。Desc 指向目标，字段在每次调用时读取，不能在创建时拍快照。

调用种类由环境操作决定：读取拥有资源为 Shared，修改拥有资源头为 Exclusive，正文移出拥有资源为 Consume。复制的 Desc 对目标写入不等于修改环境；拥有捕获也不自动等于 Consume。未调用的拥有环境仍有清理责任。捕获顺序保持源码首次使用顺序。

前置类型约束使用私有资源项，将有限 Copy payload 的投影推导与 Managed/Desc 模式分开。公共具体环境与清理指令由053冻结；本片不修改独立 Verify 或后端，也不把 Analyze 结果当安全许可。

首片聚焦本地闭包，闭包逃逸、闭包参数/结果中的资源模式、嵌套拥有环境和异步取消仍不由此片承诺。同步错误清理由053独立纵切实现与验收。本片仅运行限定真实源回归；最终证据记录精确受测提交，不以旧收据替代新验证。

## 已接通的路径

`DescribeCapture` 将拥有字段投影为本次激活的 Desc；正文 `give` 使用 `TakeCapture`，不会在每次 Shared 调用时搬走载体。拥有环境通过 `CallClosureShared` 或现有实际局部 `CallClosureMut` 调用；Consume 使用 `TakeLocal` 与 `CallClosureOnce`。局部、未调用和完整表达式临时环境通过 `DropClosure` 进入后端清理，沿用正常 return、break、continue 的出口顺序。闭包移动不会复制载体。

具名函数的 Desc 参数写效果由独立的前端源码摘要推导。摘要沿别名、直接调用、模块导入和递归迭代，受工作与深度预算控制；未识别的调用保守计写。只读辅助函数不会迫使拥有环境成为 Exclusive。闭包内部局部函数体中的可见目标写保守纳入外层摘要，即使该局部闭包未被调用；这可能增加限制，但不会给出额外许可。Verify 在052从实际 Typed CFG 重新推导，不读取这些私有摘要。

051 的限定回归包含16组：12组真实源码各执行 O0/O2，覆盖共享描述每次重读、描述目标写、拥有 Shared 重复调用、别名与递归辅助函数写、条件 Consume 与残留清理、未调用环境、环境转交、早退/循环出口/临时清理、地址与 Managed 混合捕获，以及每次调用新建的资源。Copy payload 读到局部后修改快照仍是 Shared；新增反例先复现错误 FnMut 误拒，再区分写目标路径与字段值读取后通过。另含 i64 数组上下文与最近拒例；8个错误源在 Types 通过后由安全阶段拒绝，包括重复调用已消费环境、旧描述跨转移、环境已转交后再用，以及同一环境同时捕获旧描述与其已搬走载体。精确受测提交与结果见本片证据，不把施工 checkpoint 的旧计数改写为新计数。

旧047仅迁移两条已获授权的阶段合同：删除已实现 Desc 捕获的 Unsupported 断言；旧描述/伪装 create 的相同错误源码仍要求 Types 成功、之后明确 SafeReject，允许新的独立 Analyze 提前报 `E-ANALYZE-IR`，或独立 Verify 报原 `E-VERIFY-RESOURCE`。独立 Verify 的不调用 Analyze 反例继续由052保留。
