## 真实消费者及首个失败

`owned-enum-saved.zil` 将已拥有 Token 转入普通非泛型 `Packet.Item(manages Token)`，保存在局部，真正 `task_yield()` 后消耗式 match，再通过已有 `Task<i32>` 结果返回。驱动先观察 Pending，再继续至完成；近邻删除第二次 poll 后执行取消/close/destroy，另有 PC0 未首次 poll 的取消近邻。这里没有借入 frame port、外部登记、child、defer 或一般拥有结果。

该原源到 Types Success，worker 确为 Suspend、结果 I32；实际 TypedIR 含完整 Managed payload 的 Packet、MakeVariant、TaskYield、VariantTagLocal、UnpackVariant 和 DropEnum。默认 check 在 Analyze 首报 `E-TASK-ABI: task owner needs a complete canonical inline resource frame slot`，Verify 尚未运行。完成、Pending 后取消和 PC0 取消同报该第一个静态准入断点；这不是机器清理失败证据。

将同一 Packet 改为 Copy i32 载荷（Token 作为独立旧拥有局部保留）后，同样的 Task/yield/match 路径到 Verify Success。原完整拥有 Packet 去掉 yield 并普通 Direct 调用的 `owned-enum-direct.zil` 也到 Verify Success。既有 G8.2 的 Task<Managed<Token>>、Copy ErrorUnion Task 及 G8.4 queued-cancel 源均原样到 Verify Success。故不能把普通 Sum 支持或有限 Static Task 支持当作交集已成立。

更宽的 `owned-enum-task.zil` 尝试让 Packet 作为 Task 结果；首报 Expand `E-GENERIC-ARGUMENT: Copy enum field cannot own resources`。`owned-result-task.zil` 尝试 `Failure!Managed<Token>` 结果；首报 Expand `StoreElement fields require finite Copy or explicit direct manages resources`。去掉两者的完整结果 Poll 消费者，只做 create/cancel/close/destroy 后，Enum 结果到 Analyze 的普通 Sum 载体资格拒绝，ErrorUnion 结果到 Analyze 明确 Unsupported `general owning task result lowering is not yet admitted by this frame profile`。因此完整结果还包含独立的 ordinary Poll<T>/外层 ErrorUnion 准入和结果责任问题，不能用只放开一个 gate 概括。

## 建议首片：封闭帧内完整普通 Enum，保持已有 i32 结果

先只接实际完整、无递归的普通非泛型 Enum，拥有叶限现有同步 inline-resource 资格；已有 Copy 伴随值和 Unit variant 保持真实 tag。只在已封闭的静态 Task 中把整个 Enum 作为规范 local/SSA 责任槽，不开放投影后部分 Sum、借入结果/输入、拥有 Task 结果、child 返回拥有 Sum、pollable 根嵌在 Sum、拥有泛型 Enum 或 user defer/ticket。普通完整值进入帧并不推导 Transfer/Share/Closed。

两核分别核实际构造及 TagLocal/Unpack/Drop 的控制边和责任转移，不能拿前端计划或最终 Type 当证明。Move 到 Sum 后原 Token 不再拥有清理节点；Sum 活动分支只拥有真实载荷；Unpack 原子把完整根责任转交到全部真实目的 local，来源/清理顺序沿普通 Sum 合同，暂停点覆盖实际仍活债务。取消在真实保存 PC 上清活动分支一次，Unit/空责任不生成虚假 Token；PC0 输入、构造中失败、完成后的清理、重复 close/destroy 与一次 Ready 均保持原 Task 合同。

预计写集与接口审查入口：

- `zil-analyze/src/tasks/owned.rs` 与 `zil-verify/src/tasks/owned.rs`：各自将新 profile 的完整 Sum 类型、真实资源/teardown 及实际 owning instructions 纳入准入；当前 storage 分类和指令名单都不覆盖该路径，不能仅改递归 classifier。
- `zil-verify/src/resources/task_frames.rs` 及两核普通 Sum 责任消费者：现有 `TaskOwnerSlot::{Local,Value}` 携完整 Type、真实 debt 与 Link/Unlink，可能足以表示完整 Enum 根；先证明所有 live debt 都有唯一规范槽、Unpack 不重复 link，再考虑复用。当前 start 明确拒绝非 Managed/Tuple/Closure 的完整 local 和非旧集合的 SSA debt；不能关闭 coverage 检查。
- `zil-backend-llvm/src/emit/tasks.rs`、`emit/tasks/owners.rs`、`emit/drop_plan.rs`：当前 task_leaf 只接受 Empty/Leaf 清理结果，完整 Sum helper 需要按真实 tag 的普通 DropPlan 接入稳定帧节点。已有普通 Sum helper 符号及 whole-slot payload 指针可供复用；不能把所有 variant 叶同时登记，或以释放帧替代活动载荷清理。机器实现须同时覆盖两后端及 Direct adapter 保真。
- 不建议先增加公开字段/证明位。当前原始 opcode 和完整 Type 已包含首片需要的构造/解构事实，是否足以由两核和后端实际消费须在实施时证明；若确有缺失再将精确公共签名交 root。完整 Poll<owned Sum/result> 属后续独立切片，预计还涉及 Expand 泛型 family/普通资源闭包与结果槽。

后续验收必须原源到两核/native，分别观察完成、Pending 取消、PC0 取消、Unit variant、同型多叶与两侧/嵌套 tag。构造后项失败只清成功 prepared 部分；外层/内层清理序、重复移动、陈旧 tag/绕过成功边和遗漏 frame debt 必须有 raw/Wire 近邻。实际 frame/owner/helper 图、遍历、clone、比较与布局在当前四预算预付，交 N/N−1/cold/warm/fresh 及旧 profile 控制；默认额度不升。现阶段这些都是后续义务，0 个新原生执行、0 个新 raw/Wire 实验，不宣称实现通过。
