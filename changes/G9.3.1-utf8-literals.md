# G9.3.1 · Runtime UTF8 string literal contract proposal

Ordinary source string literals currently reach Core but have no Types consumer. This change gives every runtime literal the same ordinary value meaning, independently of the consumer name.

1. Decode the existing scalar escape grammar exactly once; encode the decoded scalars as UTF8 without normalization. Embedded NUL is an ordinary byte. No trailing terminator is added. Invalid escape/scalar input remains rejected, including caller-built Core inputs.
2. Runtime value type is the existing immutable `&[u8]` (`Address { mutable:false, inner:Slice<U8> }`). The bytes have immutable program-static storage. A zero-length string has length zero and a valid static backing address; it is not a null special case. Runtime representation is the existing pointer/length slice ABI. There is no runtime allocation and no owner to destroy.
3. Literals may flow through ordinary immutable slice bindings, helper calls, returns, indexing and slicing. They cannot grant mutable access. Static origin must be reconstructed independently from the actual dedicated instruction; names/spans/type fields alone grant no origin.
4. Owning String construction remains the ordinary `std.string.from_utf8(literal, byte_limit)` library function, with existing validation/capacity/allocation/failure cleanup order. Literal evaluation never constructs a String implicitly and does not bypass the ordinary module body.
5. Proposed minimal stage extension: `InstructionKind::StaticUtf8 { bytes:Vec<u8> }`, exact output type above. Analyze and Verify independently validate encoding, shape and immutable origin; backend emits private constant data and existing fat slice. Wire/fingerprint/new tag and schema version are integration-owned changes. No new public Type, loan class or hidden global runtime table.
6. Encoding traversal, output byte storage, static-data inventory and serialization must charge actual work/backing growth to the current request before materialization. Default limits and product gates remain unchanged. Focused N/N-1/fresh controls and previous unaffected controls must be recorded.

This proposal changes source acceptance and IR, so implementation starts only after the integration owner resolves the schema/text contract. It does not establish general escaped borrowed-storage combinations, source-level UTF8 nominal text, graphemes, platform text or product cost superiority.
