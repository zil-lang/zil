# G1.3.8: complete Package replacement with a finite Copy result

Baseline main is 917971a13a1590ee912db73be7474d0cceef2b2c; the task is a
bounded extension of the accepted G1.3.7 Direct Unit consumer. The preserved
`g137_review_failure.zil` is an actual `F!i32` helper: a Reserve precedes RHS
argument preparation, the failing `?` arm aborts the ticket and cleans prepared
R66, while the caller retains P65 and reborrows it on `.err`. The accepted
G1.3.7.3 release CLI first rejects this Source in Analyze with
`E-UNSUPPORTED` / `complete Package replacement requires this body's exact
whole local owner`. This is a real producer admission gap; no native result is
inferred from the preflight.

Proposed Analyze admission retains Direct/no-environment/no-callable-envelope,
exactly one mutable whole-P parameter, one Managed<CopyRecord> leaf with scalar
companions, and the existing scalar/owning-RHS companion parameters. Besides
Unit, allow a finite ordinary Copy result tree whose leaves are B0 scalars and
whose constructors are Tuple, Array, Record, Enum and ErrorUnion. Error and
success payloads both meet that qualification. Address, Desc, Managed, Package,
callable/function-pointer, foreign carrier, storage and task results remain
outside the slice; Copy classification alone does not admit those carriers.

Result formation transfers no destination-shell responsibility. Existing
independent actual endpoint/init/loan checks and affine Reserve/Commit/Abort
activation checking remain mandatory on every executable return edge. Preparing
or aborting a ticket changes no destination provenance or retirement effect;
only an executed Commit consumes its fully prepared exact-type RHS and retires
the old leaf. Both normal and error returns must pay all actual prepared-value
responsibilities. An error returned after a Commit still has a may-retire effect;
`.err` is not proof that the old instance survived.

All non-Unit helpers retain conservative may-write provenance, including the old
origin alternatives. They grant no must-Commit or Fresh result privilege, even
when a successful path commits fresh. G1.3.7's Unit postcondition machinery and
its accepted precision boundary are unchanged. Resource retirement and actual
separation remain independent of Copy result admission. No exit-sensitive
interprocedural freshness guarantee is introduced.

The new qualification traversal is charged before work; Unit retains the old
constant-time path. No public IR, schema/Wire, runtime layout, default budget,
Cargo target or product-gate change is proposed. Verify independently authors
and checks the same shape; no Analyze/Types proof call is shared with it.
