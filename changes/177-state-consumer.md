# 177：完整 State 的三线组合消费者

## 目的与真实行为

单个 `State<F>` 同时拥有 Ticket、`Store<Item>` 和自含具体 FnMut 字段。工厂和更新 helper 以普通参数/结果跨模块转交完整 State；实际运行时数量与索引决定动态前缀的创建和只读遍历。回调在原位置连续调用，替换为同一源 opaque 工厂的新实例后重新计数。准备新容器失败时继续使用原 State 和原回调；成功才清理旧 Store 并发布新值。

第二入口取走回调字段和 Store 字段后提前退出，确认父壳只清剩余 Ticket，两个已取出的完整值独立清理。不会以整体 State 捕获、外部保存回调或未实现 GUI 行为替代这些语言能力。

## 独立预期

Ticket 的 Drop 只输出其 ASCII 标签。旧元素为 D 开始，替换元素为 M 开始，State Ticket 为 Z，旧/新回调持有 H/K。正常主程序的输出为旧前缀 + H + Z + 新前缀 + K；这由字段声明序和替换提交时点独立推导。初次 Store 分配失败输出 ZH；第二批准备失败保留旧 State，继续一次回调并检查旧前缀后输出 Z + 旧前缀 + H；最后扩容失败仍保留新前缀并走正常输出。各处失败都由真实 realloc 包装器逐次注入。

第二入口正常输出为已取出旧前缀 + H + Z；初次分配失败仍输出 ZH。空前缀也执行，测试探针在 main 前注册真实退出计数，不把缺报告解释为零分配。

源码在 `examples/mainline/zui_language177`，运行器在 `tools/language/177`；原173样例与结果原样保留。所有结果以实际运行收据为准，本提案不预填通过。该消费者检查通用语言状态组合，不宣称完整 ZUI、并发取消、OS 回调注销或产品目标完成。
