# 033 普通函数值与间接调用

本切片依据 `_zil_design.md` 的无环境 `fn(A, B) -> R` 类型，贯通具名函数取值、参数与返回、分支选择、局部重绑、模块函数取值和聚合存储。类型继续使用既有 `Type::FunctionPointer`；新增 `FunctionRef`（wire tag 25）与 `CallIndirect`（tag 26）。公共 schema 版本由集成者统一处理。

当前准入限于闭合、有限的纯 Copy 参数与结果，可递归包含 tuple、record、array 和相同约束的函数指针。函数指针签名不含地址、资源或闭包环境；普通直接调用现有共享借入合同不受影响。间接借入来源与资源效果合同尚未实现时不得把它们当作空合同接受。捕获闭包不转换为薄指针。

verify 独立核验 `FunctionRef` 的真实目标存在、无环境、参数与返回精确一致，以及 `CallIndirect` 的 callee SSA 支配、签名、参数、结果和 Unit 约定。原始类型在 fingerprint/clone 前按调用者预算逐层检查。分析方只提供候选，不授予权限。

原生表示为 LLVM `ptr`，间接调用保留完整结构参数和结果；Unit 参数与结果沿用直接调用 ABI 消去。没有隐式堆分配、RC、全局函数表或环境擦除。当前 CT 仍保持独立标量白名单，原始函数指针 CT 程序按既有 `E-CT-FORBIDDEN` 能力边界拒绝。

验收使用真实源码多函数程序在 O0/O2 执行，覆盖函数工厂、参数传递、聚合存储、Unit 和模块身份；反例包括错误签名、原始 IR 伪造、非支配 callee、地址合同越界及闭包入口冒充。仅运行限定测试；完整门和 Rust 产品成本比较由集成者管理。

## 已贯通与交接

`examples/impl033/main.zil` 的多函数处理程序执行为 8320；`examples/impl033/modules/main.zil` 在两个模块含同名函数时执行为 8016，公开工厂也可返回本模块私有函数的已核指针。函数指针可放在 record/tuple/array、按字段或索引改写，原生 ABI 保留 aggregate 参数和返回；Unit 及直接共享借入函数指针槽位均有执行覆盖。使用真实 SSA 间接 callee，非支配指针在 Verify 拒绝。

030 正在重写闭包推导 Graph。本切片基线在含闭包的源码中仍由旧 Graph 拒绝具名函数作为值；合并后应接入 Pointer(Signature) 推导并增补闭包/函数指针组合，不把该组合记为本单已完成。`call_closure` 中先求 callee 值再按 FunctionPointer 分派的分支必须在 030 合并时保留。无捕获闭包转换及含地址的间接签名合同属于后续工作。

## Rust 目标复核

| 目标 | 判断、证据与差距 |
|---|---|
| 同类安全 | 本切片独立核验实际目标、完整签名、SSA 支配、非法环境与来源合同边界；完整资源/独占/并发安全目标仍未达成。 |
| 运行与内存同级 | 原生薄指针与结构值，无隐式堆分配或 RC；没有同能力 Rust 配对测量，成本同级仍未证明。 |
| 表达与维护更简单 | 普通函数以既有表达式/函数类型进入高阶数据处理；完整语言和惯用 Rust 的任务级维护优势尚未证明。 |
| 编译成本更低 | 新类型形状与调用操作沿用有限预算，并有预算反例；未测配对冷编译和增量成本。 |
| 至少一项实质突破 | 尚未证明；本轮增加可运行的高阶主线能力，不以语法或测试数量代替产品结论。 |
