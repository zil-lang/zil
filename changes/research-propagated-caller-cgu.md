# Isolate small callers affected by propagated results from stable leaf owners

Stage10 baseline6dd46bcf59f74c0def15b3db8c3bf2ac49d0bf87 (production70615ae1). Existing retained-symbol O2 edit changes three of eight native units. Two small caller result changes are grouped with roughly1,024 unrelated leaf definitions each; every missed unit repeats about80ms optimization and85ms emission. All original source symbols must remain.

Under the existing explicit incremental O2 multi-unit policy, evaluate a bounded partition-only candidate: identify current LIR ordinary direct callers, including the entry component, whose resulting machine group is small after current fact substitution. Co-locate these small callers in the original entry owner's bucket, keeping other source groups and their original ordinals/buckets. Never split a component that must share local state. Keep complete imported call implementations, canonical addresses, declaration dependencies, current preflight, exact object keys and original fallback behavior. The source-call classification comes from current LIR because relevant calls have disappeared from the machine model. Bound caller count and generated cost to avoid concentrating a large call-heavy graph, and reject the policy if remaining direct source calls require ordinary leaf imports. Foreign calls and canonical address references retain their original dependencies.

Before implementation measurement, read-only parallel-balance analysis rejected the initial dedicated extra lane idea: seven large units plus one tiny unit with two workers can add about12–14% cold tail time. Packing small propagated callers into the existing entry bucket instead preserves eight balanced large units. The target then changes two large units concurrently rather than three in two waves. This avoids redistributing unchanged helper owners; no timing or success is attributed to the unimplemented dedicated-lane proposal.

This borrows Rust's separation of stable and volatile generated items, but is not a Rust partitioner port or persistent semantic query implementation. Changing grouping may affect parallel balance, code placement, cross-unit merging and edit granularity; measure cold as well as edit, preserve unfavorable results and inspect runtime/object quality. Do not weaken optimization, change default flags, hide definitions/diagnostics, alter language budgets or public Wire. Root handles actual-source controls and all builds; scoped author owns only machine_cgu.rs. Existing unit-count assertions may be updated only to the concrete new partition contract while preserving exact hit/miss and current-verification checks; opaque and closed paths should retain their behavior where qualification fails or closed collection already selected a unit.

First verify activation and changed-owner attribution on one representative source before a paired screen. If it only moves cost or loses cold/runtime quality, revise or withdraw before the final bounded confirmation. Do not rerun historical full matrices to summarize existing data.
