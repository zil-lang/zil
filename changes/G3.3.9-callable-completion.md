Acceptance proposal, baseline fd261b22c8a05c5cd1e7bc9cc05d91eeb0f12c95. This proposes implementation acceptance additions under existing language rules; it neither changes public representation nor relaxes missing-proof rejection. No parent completion follows from one matrix row.

The old `fnonce-helper-next/give-f.zil` gives an ordinary Value F. §86–92 explicitly disallow give for ordinary Values; it must remain a nearest rejection. F is transferred by ordinary Value movement. Actual Managed give inside F or a declared Managed companion is the legitimate scope.

For cycles, retain accepted DAG proof as the exact old path. Only non-limit graph/profile rejection may attempt the cyclic consumer, and that consumer first proves an actual graph cycle; ResourceLimit is never retried and rejected DAGs gain no alternate activation discipline. Analyze uses a forward input-state worklist; Verify independently recomputes predecessor states in bounded fixed-point sweeps. Both preserve actual parameter provenance, local activation, SSA transfer and per-role settled debt; equal types grant no identity. Reachability, actual blocks and SSA definitions checked, unsupported effects remain closed. Cyclic StorageLive is valid only at a definitely inactive empty nonparameter slot, and resets activation for that dynamic iteration; a consumed original owner cannot be resurrected. No unbounded path enumeration.

Source acceptance includes loops before/after consumption, nested branches/loop transfers, multiple different and same-type runtime environments, selected invocation versus unused destruction, actual Drop side effects and lending final-use controls. Hostile neighbors cover duplicate consumption/backedge, activation omissions, parameter/SSA substitution, wrong resource teardown identity and environment escape. Existing raw/Wire, N/N−1/fresh/retry and old exact fees remain mandatory. Machine observations require real Clang/API O0/O2 and actual cleanup counters; stage-only results cannot stand in for those. No runtime Box/RC/lock/global registry is added.

Rust four goals: safety and ordinary expression composition are targets, not yet evidence; inline layout is retained, comparative runtime/RSS/compile/maintenance and a product-level net breakthrough remain unmeasured. Existing product conditions are unchanged.

First limited run: three new loop Sources/raw/Wire succeed and old G338 driver 5/0 (including ten actual Clang O0/O2 runs) pass. The old private G338 self-loop assertion fails because that synthetic neighbor is a legitimate nonterminating owner-holding side branch with a separate legal normal exit; this is an explicit accepted-source/control-flow boundary promotion. Its new positive expectation does not bless a cycle through consumption, reactivation or an unavailable owner. The initial failed log is retained; repeated-consumption backedges remain negative.

The multi-role implementation forms one actual helper header from each original selected bound. It maps authentic data input classes to the same original Source binder; other environment classes are namespaced by actual runtime parameter position. The merged consumer uses dynamically sized role identities and bindings. Owning CFG debt keeps the first role inline and pays for an additional byte per role; it has no fixed bit-mask role limit. Per-role origin/debt checks use the real parameter ordinal and every call/drop settles only that parameter; equal ClosureId does not combine instances. Existing one-role profile fees remain on the original successful fast path.

User Drop is admitted only with independently authenticated actual Direct Desc-to-Unit entry, exact registered nominal payload, unique teardown registration and no use of the teardown entry as ordinary Call/function value/closure entry. The existing phase-local resource ledger already runs after stored derivation in Analyze, and Verify runs its independent ledger at module end; no extra lib dispatcher pass or duplicate ledger charge is introduced. Direct Managed companions remain actual owning carriers and use that same mandatory transfer ledger. Desc parameters remain limited to an actual teardown entry in the new owned Fixed lane.

Observable teardown fixtures require a scalar-only foreign leaf such as putchar(i32)->i32. The stored permission consumer can accept such a real foreign declaration only with no Address/Desc/Closure/qualified parameter/result, no environment/storage/callable/reference contract, no executable CFG/SSA body and a Direct scalar ordinary ABI. Analyze independently authenticates the actual C ABI, identifier, unique symbol, canonical immutable C-number parameters, empty body and absent callback/noescape claims; Verify retains its separate general foreign declaration checker. These leaves introduce no retained pointer or callback permission and obtain an empty permission summary; no address-bearing FFI is admitted by this change. All new signature/teardown scans are prepaid; old nonforeign/teardownNone fast paths do no new charge.

Root static review requested bounded pending-queue residency and precise fallback scope. The cyclic Analyze queue now tracks paid queued bits, with at most one pending entry per block. Both independent cyclic fallbacks must first find an actual graph cycle; a failed acyclic proof cannot retry with a different activation discipline. This retains DAG behavior while allowing legitimate loop-local dynamic activation only on an actual cyclic graph.

### Qualified environment lending completion (under implementation)

A single shared or mutable callable role may return a shared scalar address into
its actual inline environment. The helper must spell the receiver/result life
relation explicitly (`f: &'env F -> &'env i32`). Its existing signature relation
continues to describe that parameter/result borrow. The closure's existing
`storage_life` describes qualified parameter and captured external targets;
its inline environment result has no parameter lifetime row. Existing
`lending_captures` identifies only the actual inline fields reconstructed from
`BorrowCapture` and returned CFG values. Analyze and Verify must separately
recover those sources and compare the complete field set, then substitute the
current runtime receiver environment on each call. Matching closure IDs, binder
numbers, or equal capture types cannot identify two runtime environments.
The result loan keeps that receiver alive until its final use; a later mutable
invocation conflicts with it. FnOnce environment lending remains rejected.
No public IR fields or result-source authority are added. Actual shared/mutable
Source/raw/Wire lending and the nearest live-receiver and same-type field-claim
counterexamples have passed; native and complete merged composition evidence is
still pending.

Observable user Drop uses the existing dedicated scalar `ForeignCall` instruction
and explicit `UnsafeEnter`/`UnsafeExit` regions. Ordinary `Call` to a foreign
entry stays rejected. Scalar-only FFI has no address result, borrow, owner,
callback, or retained environment capability. Analyze independently checks the
actual declaration and arguments, unique lexical region declarations, actual
region stacks across CFG edges, and source spans; Verify retains its existing
independent `foreign::check_call` and `foreign::check_regions` checks. The stored
permission solvers only admit these already authenticated scalar operations and
create no target or loan from them. Analyze's extra lexical work is triggered
only after the paid instruction inventory discovers actual FFI/unsafe syntax,
so old modules receive no new whole-module scan.


### Existing owning capture, nonconsuming qualified consumers

Per §9.3 and the G10.1.11 consumer contract, an existing finite scalar Managed
capture does not force FnOnce. A qualified Fn may repeatedly describe/read that
actual capture; a qualified FnMut may also update its separate inline Copy
state. The capture remains in that runtime environment across calls and is
cleaned once at the environment's final destruction. A single-role qualified
lender may borrow its inline Copy state while retaining that same capture.
The existing resource ledgers still independently prove actual capture epochs,
description use and cleanup; admitting DescribeCapture never grants TakeCapture.
Both kernels require the actual environment's FnOnce kind for TakeCapture.
This adds no new capture type, dynamic container or multi-role lending profile.
Actual repeat/Drop/lending sources and forged nonconsuming capture transfers are
prepared; the combined candidate is pending its first root-managed test window.
