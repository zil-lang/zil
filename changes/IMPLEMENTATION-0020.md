# 020：局部共享地址与显式混合捕获

## 接受性变更

复用 schema3 的 `Address`、`BorrowLocal`、`ReadAddress` 与稀疏 Hold 证明，
接受标量局部绑定的 `&x`、共享地址的 `*p`、局部地址复制和赋值。
地址与闭包副本持有原始 `FunctionId + LocalId` 来源，最后使用前的冲突写入、
存储结束或越域仍由独立 verify 拒绝。默认借入闭包体对捕获标量取地址时复用
捕获的地址，不能创建指向环境指针的伪地址。

`let borrowed = &x; let f = move () => *borrowed + snapshot;` 的环境同时保存
共享指针与标量快照。复制指针不复制目标，也不改变来源寿命；无堆盒、RC、
宿主 Rust 借用检查或新增捕获语法。

本片仅支持一层共享地址且目标为 Unit/Bool/i32/i64。地址参数/返回、默认捕获
地址绑定、嵌套地址、投影、独占引用和间接写入继续准确返回 Unsupported。
这些是本片边界，不是终态语言限制。普通函数和闭包调用合同保持标量。

## 实施与核验

前端两道私有约束保留标量 Graph，以共享地址包装关联内层变量；CT 前约束与
CT 的执行/核验顺序不变。公共 IR、wire、分析器和独立核验算法无需改变。
限定源码正反例覆盖复制、覆盖、遮蔽、分支/循环、最后使用、越域、混合捕获，
并检查真实 LLVM 指针布局和原生结果；错误 Hold 以未核 IR 变异验证。
保留原门槛，作者只跑限定检查，由非作者审核后交集成正式门。

## Rust 四目标

| 目标 | 本片预期与证据边界 |
|---|---|
| 同类安全 | 扩展可执行共享子集，沿用独立来源/活跃期核验；完整资源与并发尚未完成 |
| 运行/内存 | 地址是栈指针，环境内联；没有增加强制堆分配，尚无配对性能结论 |
| 表达/维护 | 显式引用绑定加 move 对齐 Rust 的惯用混合捕获能力，不宣称完整闭包能力或语言整体优势 |
| 编译成本 | 两个有限私有类型包装，来源分析不扩展；尚未做同规模 Rust 配对测量 |

至少一项实质突破仍未证明；本轮能力和限定测试不能代替产品门。
