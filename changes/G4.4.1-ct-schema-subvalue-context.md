# Keep source binding consistency with its actual CT schema

An existing source control returns a Tuple of Phantom<a> and Phantom<b>. CT5
retains both authentic full source ordinals. During reification, however,
ValueContext::type_with_scopes checks every private SourceLifeBinding from the
whole artifact against EACH current subgraph. The Tuple contains both mappings;
its Phantom<a> child correctly does not contain Phantom<b>, so the unrelated
binding causes a false schema-absent rejection.

Validate the private producer's retained binding once at ValueContext capture,
using its exact record/enum schema ID, that schema's own root Fixed mapping, and
the genuine frozen invocation. Keep the complete ordinal/owner/class check and
prepay all new traversal/comparison work. Returned child graphs still validate
every ambient reference against the retained frozen context; this does not
freshen classes, drop metadata, grant permission or widen a runtime profile.
The original failing source and test remain unchanged. Add real source joint
values plus nearest wrong-lifetime controls and private wrong-schema/ordinal
binding controls, and retain cumulative budget boundaries. No public schema,
ABI, language rule, default limit or product gate changes.
