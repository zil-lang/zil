## 缺口与实现范围

183 已让具体 `E!Store<Item>` 的显式 create/give 成功载荷进入普通
Types、Analyze、独立 Verify 和原生清理。178 的符号正文检查只识别直接
Store 结果，不能据这两片单独通过就宣布泛型组合可用。

在 Expand 私有泛型检查中识别 `E!Store<T>` 的成功 Store，要求 `T` 的
真实 `StoreElement` 义务，以及 E 的已支持有限 Copy 形状。显式
`result(create/give)` 和 `give x:E!Store<T>` 仅选择成功侧拥有类别。
外层仍是普通非 Copy Value，按普通值移动；`give union` 不成为另一种
移动语法。无模式声明和默认 Desc 别名不能获得拥有成功载荷。

符号状态分别记录联合载体、直接 Store 载体和创建来源。新建 Store、
声明 create 的结果以及它们经局部移动和 `?` 的成功路径保留创建事实；
give 入参、give 结果和取出旧资源不能通过包装、取出、再包装或普通转发
制造 create 证明。错误侧返回不产生成功资源，不能因为缺少成功来源误拒。
分支汇合保留所有存活路径都满足的事实，循环继续要求外部责任不变量。
同一联合只能被消费一次；整个联合替换和默认类型注解推导拥有模式不开放。

实例化过程中只在已确定的 Store 成功形状内传递构造期望类型，不把任意
泛型结果变量错误地约束成整个 `E!T`。全部实际实例仍走普通类型检查、
独立责任核验和现有机器表示；本片不生成安全证书，不修改公共 IR、wire、
默认预算、Analyze/Verify 或 LLVM 生产代码。

## 限定验收

真实源码覆盖至少两种名义 Item，共用泛型 fallible factory、显式联合
参数转发、直接成功注入、错误返回、`?`、局部移动、清理与跨模块调用。
既检查实际实例，也检查完全未实例化定义。最近反例包括缺失形状约束、
默认 Desc 升级、重复联合移动、give union、原入参重包装为 create、
分支混入旧来源、give 转发伪装 create、资源错误侧和借入/嵌套形状。

以源码派生的 raw/Wire 变异继续检验独立核对；不以符号检查代替核验器。
真实消费者保留 O0/O2 输出、分配失败、唯一清理与实际命令/源码哈希。
先冻结有限源码，再限定复跑；正式全量和非作者审核由 root 执行。

## 边界与目标

不开放任意拥有嵌套 Sum、资源错误载荷、联合捕获、借出环境、异步或通用
trait 求解器；不把 StoreElement 当作 Copy、Managed 或可见字段权限。
泛型定义检查的既有限制继续明示，不从某个实例成功推导普遍能力。

该片的实质增量是同一普通泛型库可以返回一个可能失败的拥有容器，并且
在定义期拒绝来源伪装。运行/内存与 Rust 的量化比较、维护成本、编译成本
和产品净突破仍未测；有限安全反例不是完整语言证明。B0 Doing、完整语言
NotSatisfied、产品 NotRun 均不由本片更改。
