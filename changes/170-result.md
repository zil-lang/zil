# 170 施工交付：完整拥有数组字段

## 已贯通

`package State { manages tag: Ticket; items: [Item;2] }` 中，Item 是直接 Managed+Copy 字段组成的完整 Package。State 的普通字段表达式将整个数组移出；普通数组局部可静态逐项取出、补回、替换，完整数组可补回父壳。父壳只维护完整/缺失字段责任；函数值、普通参数/返回和完整父包移动均要求补齐。替换先完成 RHS 准备，失败保持旧字段；成功清旧数组再发布新数组，父壳清理位置不变。

普通 State、`[State;N]` 元素、`E!State` 成功载荷及 `State!T` 错误载荷共享完整字段清理路径。清理按父字段声明序，再按数组下标递增、元素字段声明序。每个实际责任位先退役，再调用用户 Drop 或释放 ByteBuffer。字段数组不增加隐式堆分配，也没有内嵌的部分初始化子旗标。

有限 fields 操作复用现有 IR 指令；公共编码与版本由173统一管理。Verify 不消费 Types/Analyze 责任证明；独立重建字段完整状态与源活动性，ReadPackageField 对拥有字段明确 SafeReject。布局计费核算外层数组长度与内层数组长度的实际乘积，默认预算不改。

## 当前边界

父包内不支持 `state.items[0]` 的嵌套部分位置，先整取字段到数组局部。字段元素限直接Managed+Copy的Package；不开放更深的数组字段组合、直接嵌套Package、Closure字段语法和动态容器。含拥有数组字段的父Package捕获在Types与Verify明确关闭，不能沿旧环境视图协议漏核嵌套责任。源程序必须显式普通值移动，`give` 仍仅适用于Managed字段/载体。

没有运行完整仓验收、原生Windows或产品对照；父B0状态、完整语言与产品门保持。
