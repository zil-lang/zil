# 162：有限名义泛型 trait 约束

生产基线：`e9a604c80d56027a5fb6c28bcb8b58f9c9e84a7b`。依据 `ZIL-TRAIT` / `ZIL-COMPTIME`，本单实现现有终态规则的一个有限切片，未改变语言规范、公共 IR、机器 ABI、默认预算或安全核信任关系。

## 问题与拟改变的接受范围

现有局部非泛型 trait 已核验实现签名并生成普通直接方法，但普通 `fn apply<T: Measure>(value: &T)` 在展开阶段统一拒绝。仅在实例化后根据真实类型是否恰有同名方法来接通会违反定义处符号检查，并错误接受只有 inherent 方法、没有名义 impl 的类型。

本单对无泛型参数、无关联项/默认体/父约束的普通具名 trait 建立冻结声明与具体 impl 索引；普通函数的直接类型参数约束可引用该索引中的 trait。模板正文只获得其声明 bound 的签名；静态调用/单态化必须满足对应真实名义实现。泛型转发的约束必须由调用方已有的独立 bound 或具体 impl 满足，不能从候选自身生成证据。

共享、可变及普通按值接收者保留原权限/移动规则；bound 不授予 Copy、Transfer 或 Share。相同方法由多个 bound 提供时拒绝歧义。符号检查和索引遍历使用现有展开预算，实例输出仍是未核语法，完整 Types→Analyze→独立 Verify→机器执行链保持。

## 最近反例与限定

- 未声明 bound 的模板即使恰好只用 Point 实例也不能调用 `value.measure()`。
- 只有同名 inherent 方法、没有 `impl Measure for Point` 时不能满足 `T: Measure`。
- `&T` 不能调用要求 `&mut Self` 的 trait 方法；按值 Self 不得从借用对象移出未知非 Copy 的 T。
- 模板转发到更强约束函数时，未使用模板也须拒绝缺少的 bound。
- 私有 trait、不同模块同名 trait/类型、重复实现与签名不一致继续拒绝。

本切片不实现 trait 自身的泛型、where 约束、父 trait、关联类型、动态派发、特化选择或独立跨模块 foreign-trait impl。本轮会记录实际支持边界，不把有限功能宣称为完整 trait 求解器。

真实源码正例覆盖多具体类型、泛型转发、多约束、共享/可变/按值接收者和跨模块公开 bound；最近反例覆盖未使用的坏模板、无 impl、错误权限、错误参数/结果、歧义与可见性。O0/O2 原生执行核对结果；输出仍通过独立 Verify，保留实际命令及失败日志。旧147中已过时的统一拒绝断言只迁移这一条，保留其他不支持边界。
