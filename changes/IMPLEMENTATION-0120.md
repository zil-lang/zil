# 0120 — 独立拥有字段的可用借片组合

本次从恢复的 draft22 源码重新实施。受测源码为 `04ed0b8be05e67f16a6403c8c594ddaef42e6ed0`；原113文件没有恢复，不继承它的通过记录。

## 实际变化

对于已核固定 Package 的独立 `manages ByteBuffer` 字段，`p.b` 的活跃窗口现在允许合法取走、补回、替换、扩容或写入 `p.c`。两个不同字段的独占窗口、普通 helper 的 apart 前提、返回视图与拥有 FnMut/FnOnce 也能组合。四模块消费者真实编译执行。

Analyze 以私有 BTreeSet 根保留字段来源，Verify 从实际 CFG/type 以自己的排序向量重新计算。核验器按整个局部/精确字段的包含关系检查 shared Hold 失效与 exclusive loan；helper 所需 apart 仍代入真实来源，参数名字不产生分离。

公共 schema/wire17 和粗 `HoldRoot` 完全不变，逐值导出为去重的 `Local` 投影，Verify 独立投影后比对。候选能重算 fingerprint 也不能制造权限。Package capture 的已有唯一绑定约束继续检查；两个字段必须有真实独立责任，重复 Managed SSA 装进不同字段仍拒绝。

字段位置不是永久 backing 身份：同字段 take/replace/扩容、整个载体移动/销毁、未知资源 Drop 和可能重合的合流来源继续保守拒绝。没有实现稳定 payload 跨整体移动的运输，也没有扩展借入 slice/Desc 逃逸捕获、一般嵌套拥有字段或未知外部副作用。

## 实测

最终限定运行 `final002`：Analyze/Verify 合计375个实际测试/文档测试通过；七个 Driver target 共72个测试通过，其中本单8个源/raw/预算测试、4个原生测试。fmt 和限定 clippy 全部通过。这些是受影响范围验证，不替代root正式35门。

- 本单源面26次编译：14次 Success、12次在 Verify 精确拒绝 `E-BORROW-CONFLICT`。
- 5份 raw/wire 候选各走两条入口，共10次观察：原候选通过；缺 Hold、假 Parameter、取走活跃字段、把来源改到被取走字段均拒绝。
- 8个实际原生程序各 O0/O2，共16次编译和执行。观察输出、失败扩容保持、部分错误出口和实际 malloc/free 债务；4模块程序两次均输出14。
- 新的实际逻辑预算边界：Analyze 在6873通过、6872 ResourceLimit；Verify 在5185通过、5184 ResourceLimit。默认配额未改；字段来源数及投影工作实收费，不声称与旧粗根的预算边界等价。

原始错误全部保留：基线兄弟字段误拒；开发 raw 测试未重绑 fingerprint 导致先到身份门；final001 的旧“兄弟字段活跃期也拒绝”期待与 clippy。前者是预期修复目标，后两者是测试/检查迁移，不记作新发现的生产语义 bug。旧099期待经root明确授权改成同字段/兄弟字段 × 活跃/末次使用后四格；同字段及重复拥有反例保持。

原始记录、源码、实际阶段/机器产物与 stderr 统一保留在 `evidence/impl/120/raw.tar.gz`，有逐文件 SHA/mode/size 清单。开发过程的脏工作树运行明确标识，最终成绩只绑定04ed0b8b；重复运行不累计为不同能力。

## 四目标与边界

| 目标 | 本单证据 | 当前判断 |
|---|---|---|
| Rust级安全 | 独立 Verify、最近源码反例、raw/wire伪造及实际清理 | 完成有限直接拥有字段切片；没有全语言安全结论 |
| 运行/内存同级 | 无新运行时结构，16次实际结果和分配债务检查 | 行为成立，未做相对Rust运行时间或峰值内存测量 |

| 编译成本 | 新精度仍受默认逻辑预算约束，N/N−1实测 | 没有本单编译速度净收益或Rust胜出结论 |
