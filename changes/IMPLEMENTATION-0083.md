# 083：字节与同步借入 C 缓冲区

2026-10-25（Asia/Shanghai）。本提案先于实现提交。父任务 B0 不因本切片完成；产品门与限额不修改。081 负责源面/Types/Analyze，082 独立 Verify，083 单写公共表示、CT、机器链与真实消费者。

## 为什么

draft16 已有固定 Copy 数组和真实地址窗口，但仅 i32/i64 标量 C 调用；无法调用常见 read/write/pipe 缓冲区接口。下一步先贯通可复用的字节和同步借入地址，而不再只扩拥有闭包边角。这是字符串、动态容器和平台后端的前置，不等同它们已经完成。

## 语义和表示

新增 `Type::U8`、`Constant::U8(u8)`，值域 0..255，内联大小/对齐 1 字节，全部位模式有效。无上下文整数仍为 i32；明确 u8 上下文和 u8 后缀支持十进制/二进制/八进制/十六进制，超范围静态拒绝。当前其它源码整数后缀拒绝策略不随本片扩张。既有整数 match 的保守通配要求保持。

u8 的加减乘和取负采用 checked 语义（取负为 0-x），溢出 trap；显式 wrapping 算术模 256。除/余零 trap，比较无符号，右移为逻辑移位；移位计数必须小于 8，左移仅截断高位，与既有位运算合同一致。普通赋值、实参与运算不隐式宽化。

`u8(expr)`、`i32(expr)`、`i64(expr)`为预留的直接整数转换原语，恰一参数，不是可遮蔽的普通函数。仅三种整数互转，保留数学值；超范围在运行时 trap、CT 求值失败，不隐式截断，不允许 bool/地址转换。Core 新增 `IntegerConvert { value, target }`，Typed/CT 新增 `ConvertInteger { value, target }`；每条输出类型必须精确等于目标整数类型，来源必须整数。所有 raw 遍历、预算、指纹和 wire 同批消费；CT 仍仅执行独立核验后的程序。

## 外部合同与安全边界

`ForeignDeclaration` 新增 `noescape_parameters: Vec<u32>`。旧纯标量声明使用空表。地址声明在源码显式写 `contract { provides(noescape(buffer)); effects(ffi); }`，每个地址参数恰一次，表按参数位置规范化；遗漏、重复、额外标量/未知项、其它未实现合同均拒绝。普通参数和返回继续 i32/i64 与 Unit 返回，不在本片扩展窄整数 C 值 ABI。

地址只允许一层 `&T` / `&mut T`，T 为 u8/i32/i64 或递归非空固定数组。禁止 bool/Unit/Record/Enum/FunctionPointer/Package/Managed/Desc、嵌套 Address、零长数组和地址返回。实际 ABI 为 ptr；数组地址不复制为新临时，不增加 noalias/nocapture/dereferenceable 属性。

本有限 profile 的外部承诺是同步、不保留地址、无回调/重入、无跨边界异常/longjmp/挂起，遵守声明可变权限、有效宽度及平台 C ABI。`effects(ffi)`不宣称无 IO、无阻塞或纯性。外部实现和长度实参的正确关系仍由显式 unsafe wrapper 承担；语言不验证 libc 实现。noescape 表是未核输入声明，不自动制造有效地址或独占许可。

ForeignCall 必须经过既有词法 unsafe 检查，并将全部地址参数作为同期访问核对活性、来源、重借、读写权限及相交关系。传入缓冲区必须完全初始化；C 失败后部分写入仍为有效 u8/i32/i64 比特，不能由声明把未初始化存储转为已初始化。共享只读和独占写入按现有保守整个根的借用精度检查。无 raw 整数指针伪造、异步保存或 OS callback 生命周期扩张。

真实源码反例 `#(1 + 2u8)` 暴露旧标量 CT 快路径先默认左值 i32 的局限。083 在修正前保存失败。增加一次受模块累计 `max_nodes` 与 `max_call_depth` 约束的后序提示构建，按实际入栈/归约访问收费，只传播显式标量类型；无后缀常量仍可受两侧约束。转换的目标不流回其操作数。提示只决定未核 CtModule 的类型，独立 Verify 和执行时保值检查不省略。不按每个二元节点反复扫描完整子树。无 driver 的公开标量 CT API 与完整 driver 使用同一规则；新增分析访问可能提高原精确节点预算，不更改执行步数、默认上限或产品门。

## 独审发现的 move Copy 捕获回写遗漏

ffce7dc5 的独立原生审查发现 `move ()=>{bump(&mut b);return b}` 连续调用会从旧环境重新装入 b；b=128 时应得 129、130，实际为 129、129。C 与普通函数均复现。类型分类 FnMut 正确，但只生成局部内存修改，缺 WriteCapture，因而是源码语义遗漏而非原始 Verify 权限绕过。原候选与失败完整保留。

修复在已有受限的捕获扫描中记录私有 `address_written`，仅按值 Copy 捕获的可变地址根设置；在物化前已扫描完整函数，避免循环后访节点影响早生成退出的回写。此类捕获在每条正常、提前、Unit fallthrough 与同步 Error 退出的 StorageDead 前生成 Load+WriteCapture，新增节点/指令/核验工作按原额度实收。已有直接 Store 的即时回写保持，未借出可变地址的捕获不新增退出写；共享捕获、普通局部 Copy 快照与借入地址不被改成拥有环境写。原始 Fn 如伪造相同环境写仍由 Verify 拒绝。Trap 仍中止而非承诺回滚/展开。无公共 schema、ABI 或 unsafe 合同扩张。
