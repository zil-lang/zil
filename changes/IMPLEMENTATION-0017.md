# 017：持续探索与独立修复流水线

## 为什么

既有 campaign 是有限验收，发现错误即收口；它没有供长期探索者与独立修复者协作的持久缺陷通道。新增工具流程保持 `roam/1` case、`roam-worker/1`、六态、逐步持久化 ACK、同性质回放及原 campaign 判据不变。

## 行为与边界

- `hunt` 对本次固定的内容寻址 worker 快照运行有限或可停止的持续路径；失败原子发布到独立队列后继续。缺陷存原始 case、完整结果、journal/stderr、种子、性质、Git 来源与二进制摘要。成功路径删除原始尝试，仅累积计数。队列容量与运行期限有界，容量不足保留当前原件并返回未完成。
- `issue list/claim/replay/verify/release` 组成独立消费者。claim 采用原子文件和 token；本地协作锁不提供安全认证。原件不改写；每次验证写新目录。关闭要求旧快照重现同一失败身份、当前候选回放通过以及固定回归/已关闭反例通过。错误 token、变更的原件、缺少结果、Unsupported、配额/超时和错误候选不能关闭问题。
- 测试专用 `stale-after-edit` 明确标识 controlled mutation，不能记为生产缺陷。其他非 pass 状态分类保存；测试系统故障不冒充语言语义错误。
- 新版本构建后启动新 run 并复用队列，运行中不偷偷替换被测快照。claim 不自动过期，失去消费者的任务可用原 token 显式 release；程序崩溃时的临时操作锁需要确认没有存活持有者后人工清理。本片不引入跨机器租约、分布式调度、任意命令执行或通用插件系统。
- 默认通道 `out/qc/issues`；大型产物留 out，只有小收据晋升 evidence。语言语法、生产依赖、公共 IR 和产品门不变；根 CLI 的 `zil qc` 薄入口由集成者单独实现。

## 最近反例与验收

真实 worker 下检查：失败后继续；原件与快照去重；并发 claim 只有一方成功；错误 token 与路径穿越拒绝；坏候选不能关闭；修复验证与回归全部成功才能关闭且原件不变；原件/快照篡改不能成为 Pass；持续运行响应停止文件；零执行不标 Pass；队列满保留未发布原件。旧 13 项协议测试保持。

二进制摘要证明实际运行字节，运行时 Git commit 仅是来源记录，不能独自证明构建关系；正式集成先构建再运行并记录命令与源码身份。

## 独立审核修订

暂停边界复现：`--max-ms=50 --pause-ms=700` 在一例后仍等待完整暂停，循环报告 727ms；有限例数完成后也会多等一次暂停。修订让最后一例完成即收口，暂停期间继续检查总运行时限；单次 worker 的时限与已声明的快照准备边界不变。原持续/零执行测试同时覆盖这两个边界，不扩大测试计数。

目录操作锁依赖正常析构时删除目录，而且旧 Drop 忽略删除错误；进程终止可留下永久忙标记。改用 Rust 1.89 起稳定的 `File::try_lock` 独占锁：固定锁文件保持原 inode，文件句柄关闭时由系统释放锁，不能通过删除/重建锁文件“解锁”。实际业务 claim 仍是显式 token 协议，不自动过期。本次只替换内部操作锁，不改 case/worker/缺陷格式。旧版本遗留的目录锁拒绝打开，停止旧进程后显式清理旧目录或另建通道；不能混用两种锁实现的活跃进程。

独审在工作区发现过“删除的 claim 原字节及空锁目录随后重新出现”，同一独审程序在独占 `/tmp` 中 33 命令、54 断言通过，诊断拦截亦观察到成功的 rmdir。这个未知外部状态变化保留原始 Fail，不能以本次文件锁修订宣称已定位或修复。新回归直接验证活跃持有者互斥、终止持有者后可再次取得锁、锁文件 inode 不换，以及未完成业务 claim 继续保留。

关闭事务另有可证明的中断点：有效 closed 收据已经发布，claim 尚未删除时进程可能退出。有效 closed 是终态权威；list 必须显示 `state=closed, owner=null`，不再读取残留 claim 内容，同时用 `cleanupPending=true` 明示残留文件，不自动清理。无效 closed 仍拒绝。原真实流程保留正常完成后 claim 缺席断言，另受控还原旧 claim 模拟该中断点；这不改变未知工作区复活异常的 Fail 判据，也不宣称找到了它的原因。
