# G4.4.6 generated source ledger 接口提案

本提案提交 root 协调；公共 Rust sidecar 的接受性变化先于实现记录，
不改变 CT/runtime wire、原语言权限、机器 ABI 或默认额度。

每个实际 ItemList 生成事件在 parse 和 hygiene 完成后、remap_generated_spans
之前冻结独立 AST。冻结树保留原始 binder 完整顺序；声明身份不读取卫生名字
中的 Span，不把生成子树伪装为 Original，也不共享 emitter 的声明身份。
`SourceTreeIdentity::Original(ModuleId)` 与
`Generated { module: ModuleId, event_path: Vec<u32> }` 分域。
事件路径由实际声明/成员结构遍历和生成事件组成，emitter 另记录其真实源树、
声明 NodeId 和树内结构位置。树内声明按原 SourceIndex 的 top-first、
field/member 递归顺序编号；完整身份包含树身份与 NodeId。

拟增加只读 `GeneratedSourceTree` / `GeneratedSourceCatalog` 接口。
CT SourceSite 使用 Copy 的请求内 `SourceTreeId::{Original,Generated(u32)}`
只索引 catalog 行；行号不成为跨请求语义身份。编译器与独立冻结上下文
读取同一 Arc 树，消费者重新遍历真实树和 emitter 链核验。

输出 `DeclarationOrigin` 拟增加生成 root sidecar，绑定实际冻结树和 root
结构序号。Aligned reader 核验树身份、唯一完整声明 ID、实际输出 root/member
对应、声明 kind 与完整 binder 顺序，之后才允许 generation_path。
生成 declaration_path 使用 kind 和结构序号；生成名字只用于绑定一致性检查。
原成员删除记录与生成成员删除记录分别由相应冻结源树的实际事件验证。

所有新增头部、路径向量、树副本、遍历、比较及 Arc/copy 接口在增长前从
同一当前请求余额预付。无生成事件的旧路径不创建 generated catalog。
失败不发布部分 AST、来源行或可运行产物。raw 行/形状检查不声称认证真实历史；
真实历史在持有冻结树及当前事件的生产边界和独立 CT 来源核中分别检查。
