# G8.4.1.2 source and independent registration consumers

This slice implements Design §12.3.1 against public42 commit
20d40f57580265788915f48f35ba567fe286b301. It does not publish schema or a
new automatic-drop permission. Dedicated source operations retain the frozen
three actual provider IDs, actual concrete consumed callback and unsafe region.
The result of poll_close is the actual ordinary std.task Poll<Unit> enum; a
same-shaped user enum does not match the canonical name or confer Closed.

Analyze and Verify independently reconstruct canonical sealed definitions,
provider roles and exact ABI, actual FnMut capability, complete self-contained
capture graph, callback and environment teardown Direct dependency graphs,
exclusive complete head windows and ordinary ownership transfer. No kernel calls
the other's proof functions. Early explicit finish remains a runtime CLOSED guard
obligation for the native consumer. It grants no static refinement.

First-slice restrictions are explicit: borrowed/Transfer/Share environments,
AsyncRegistration retained inside a callback environment or ordinary Store/Package,
and live pollable owners transferred into TaskCreate are rejected. Creating the
registration inside a Suspend worker avoids a TaskCreate allocation failure having
to clean an already live pollable input. Direct default Drop of a still-live
AsyncRegistration is rejected. Pending cannot be translated to automatic-cleanup
abort. Pending Task/frame drain and native event-queue semantics belong to the
separate G8.4.1.3 consumer and require a combined-source validation.

Task automatic Drop must reconstruct its actual worker and source head, including
TaskCreate ErrorUnion result projection and owner moves. The independent Task
consumer provides this private obligation; an unrelated unused async worker must
not change the cleanup eligibility of a known synchronous Task. Unknown or
actually pollable Direct Task cleanup needs an advancing continuation.

Actual new traversal work uses the existing selected request budget. Default
limits, schema, normative contracts and product gates are unchanged. Source/raw/
Wire checks and exact N/N−1 thresholds belong to the limited slice validation;
BackendUnsupported is never native success.
