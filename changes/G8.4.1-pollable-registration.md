# G8.4.1: same-thread sealed external registration consumer

This is a proposed successor on an isolated branch, not a public schema or main
admission. Normative obligations are ZIL-ASYNC §12.1.3, §12.2 and §12.3,
ZIL-CAPTURE ClosedEnvironment, ZIL-CLEANUP and ZIL-LOWERING. G7.3/G8.4 remain
larger tasks. Existing synchronous Registration and scalar SABI1 do not change.

## Reuse and actual current boundary

Reuse existing concrete Registration environment ownership, stable allocated
record/trampoline, explicit unsafe provider roles and allocation/install failure
cleanup. Reuse real Task init/poll/request_cancel/poll_close/finish_destroy,
saved SSA/local slots, result-live responsibility and canonical cleanup age.
Current child notification precedes draining, but sequential Await admits at
most one active direct child. Existing kernels prove synchronous close from the
actual closed worker/teardown graph; they do not admit retained external users.
The existing false close branch is active-poll protection or recursive child
drain, not an external event source. Await Ready currently traps on unexpected
child-close Pending under that checked synchronous premise. It cannot be reused
as an asynchronous-close implementation.

Current TaskFinishDestroy kernel admission checks the real owning type and
consumption; the native frame has a state==Closed guard before free. It does
not already provide a static Poll.Ready-to-same-owner Closed refinement. Reuse
the ordinary Poll representation and that final machine guard, not an imaginary
existing refinement. This distinction is part of the new consumer work below.

The attached `task-registration-current-boundary.zil` uses current syntax and
current synchronous Registration inside a real suspending worker. It must remain
rejected before admission until its external roots and frame cleanup have actual
consumers. It is a boundary reproduction, not the new pollable API or a claim
that synchronous registration close may report fake Pending.

## Minimal public successor for root publication

Use a distinct sealed payload `AsyncRegistration { environment: Box<Type> }`,
wrapped in Managed/Desc as with Registration. Distinction prevents the old
synchronous drop recipe from silently freeing a pollable root. No borrow, dyn,
Transfer/Share or cross-thread callback is admitted in this first slice.

Proposed source operations and dedicated raw instructions (tags/version assigned
only by root):

| Source | Raw candidate | Actual operand/result |
| --- | --- | --- |
| `unsafe c_register_async(register, request_close, poll_drain, f)` | `AsyncRegistrationStart { register, request_close, poll_drain: FunctionId, callback: ValueId, region: u32 }` | Consumes actual concrete FnMut(i32)->i32 + ClosedEnvironment F; nullable owning AsyncRegistration<F>, preserving existing registration constructor failure convention |
| `async_registration_valid(owner)` | `AsyncRegistrationValid { registration }` | Desc of the same sealed payload -> Bool |
| `async_registration_request_close(&mut owner)` | `AsyncRegistrationRequestClose { registration }` | Actual exclusive complete owning head address -> Unit; persistent/idempotent |
| `async_registration_poll_close(&mut owner)` | `AsyncRegistrationPollClose { registration }` | Same exclusive head -> ordinary actual std.task.Poll<Unit>; Pending preserves ownership |
| `async_registration_finish_destroy(give owner)` | `AsyncRegistrationFinishDestroy { registration }` | Consumes actual Closed owner; nullable head is a no-op |

New FFI roles must be distinct from existing synchronous Register/Close:
`AsyncRegister(extern C fn(c_handle,i32)->i64, c_handle)->c_handle`,
`AsyncRequestClose(c_handle)->Unit`, `AsyncPollDrain(c_handle)->i32`.
The drain C ABI is exactly0 Pending /1 no-future; any other value is a provider
violation and must never grant reclamation (fixed fault/abort policy). There is
no new Bool C ABI. All three providers are actual Direct `effects(ffi)` entries,
cannot unwind/longjmp or suspend across the boundary, and promise same-thread
callback delivery. F's actual callback and cleanup graph must also be Direct;
the target's existing fixed-abort panic policy applies to callback/cleanup panic.
The exact actual foreign declaration/role/signature/unsafe region is checked by
both kernels. Merely matching these names or receiving tag1 does not prove
quiescence. The explicit unsafe provider promise is:

- Registration failure returns null only after all accesses and future raw
  callback entries using userdata have been synchronously withdrawn.
- RequestClose closes backend admission for new work; already queued, currently
  entering and already entered raw callbacks may remain. It does not authorize
  environment destruction or record reclamation.
- PollDrain0 means unresolved users/no-future;1 attests that every raw
  entry and backend access to userdata has ended and can never start again.
  This includes raw entries rejected by the language trampoline and entries
  that have not reached it. Same-thread delivery is an explicit initial bound.

This role contract is an unsafe external assumption, not a generated proof bit.
A real host event-queue fixture must enqueue late raw callbacks and retain its
raw callback/userdata until the queue is drained; no wrapper returning false
around an already synchronous close is an adequate positive consumer.

## Stable record, events and ABI

Keep callback userdata pointing at the independently allocated registration
record; never at a movable helper stack or a freed Task frame. Reuse existing
callback return ABI: high32 rejection tag, low32 i32 value. Retain provider token,
request/poll function addresses, environment/drop entry and explicit env-live,
OPEN/CLOSING/CLOSED, callback-active and polling/reentry state in the record.
These are machine storage, not trusted raw IR claims.

1. Allocate and fully initialize record/environment before calling register;
   synchronous callback entry during register sees the actual live environment.
2. RequestClose in the same-thread admission protocol writes OPEN to CLOSING
   before calling the provider; this promises no cross-thread atomic guarantee.
   Later raw entries still reach a live
   record but reject before invoking F. Reentrant FnMut calls also reject.
3. PollClose also requests close when necessary. Repeated request/close never
   repeats the one-time backend request. Recursive poll_close cannot finalize
   an outer poll; the poll guard and active-callback guard preserve the root.
4. While provider PollDrain is0 or active/reentrant users remain, return
   real Pending and retain the complete record, environment and owner.
5. Only provider no-future plus zero active entries permits environment cleanup.
   First-slice environment teardown must itself be independently synchronous.
   Clear env-live once, mark CLOSED, return Ready(Unit). Repeated close returns
   Ready without reentering the provider or repeating cleanup.
6. FinishDestroy requires CLOSED, then frees the stable record exactly once.
   Closed is not permission for the host to keep dereferencing userdata: its
   no-future promise must already cover those host accesses.

The explicit nullable head follows all four existing empty-head conventions:
Valid(null)=false, RequestClose(null)=no-op, PollClose(null)=Ready(Unit), and
FinishDestroy(null)=no-op. These do not manufacture a live registration. A
non-null unclosed head cannot use the empty-head path. No implicit busy loop or
external event pump runs inside PollClose; the caller remains its advancing root.

Explicit FinishDestroy uses the actual runtime CLOSED guard, consistent with
the existing task contract: early explicit destroy traps without freeing.
An ordinary user-created Poll.Ready, a callback count, a copy of a descriptor
or a request-close bit cannot override that state guard. The first slice does
not claim a new owner/Poll-origin static refinement. Direct automatic Drop of
an unknown pollable root must instead be statically rejected; Pending-to-abort
is never its cleanup implementation. This first slice requires explicit
advancing close and explicit finish. A future permission for automatic Drop of
a statically Closed pollable root requires a separate two-kernel relation.

## Task producer/consumer obligations

The real consumer transfers one concrete self-contained registration into a
stable Task frame, yields, receives a cancellation request, and returns Pending
from Task poll_close while the host queue still owns late raw entries. A driver
turn delivers those entries to the still-live rejecting trampoline. Later
poll_close observes actual no-future, cleans environment/parent debts and closes;
finish_destroy then releases storage. Also cover normal return and ordinary
error: a prepared return value remains owned in the parent's PendingExit slot
while external users drain; final failure cleans any displaced success value.
Once a body error exists, later cancellation cannot replace it. Preserve the
body error first, then select any unobserved child error by actual creation order
after draining. Source return/error RHS must already be legal before this state
is formed. The first slice does not add a new recoverable panic/unwind ABI.

Required production consumers after public publication:

- Expand/Types: concrete type recipes, reserved source operations, real standard
  Poll<Unit>, actual foreign roles and source unsafe region, independent input
  source-order evaluation and allocation/install failure responsibility.
- Analyze and Verify separately: exact canonical resource, F ClosedEnvironment
  and actual environment teardown; unique live roots and head windows; request,
  Pending and Closed transitions; body return RHS access at its source location;
  actual provider identities and callback signature; task worker/cleanup graph.
  Existing empty retained shape proves no borrowed ports, not NoExternal.
- Verify private TaskOwnership: pollable registration owner recipe distinct from
  synchronous DropPlan leaf, actual cleanup age, retained result/partial-input
  responsibility and close-mode provenance. No transported bit grants proof.
- LLVM: reuse stable Registration allocation/trampoline and real Task frame;
  private PendingExit reason/result-live/closing-PC; notify all live children and
  pollable roots before draining in real creation/cleanup order; preserve each
  root across Pending; re-poll closing child instead of treating Complete as a
  second Ready. No implicit busy loop or Pending-to-abort fallback.
- Direct default Drop: retain only independently reconstructed synchronous-close
  instances. Unknown pollable roots require an explicit advancing root or parent
  frame and explicit finish; first-slice pollable roots have no automatic Drop
  permission. Result type alone cannot establish a synchronous-close instance.
- Wire/fingerprint/operand visitors/CGU/cache/metadata fees: all actual function
  IDs, callback and head operands and complete environment types. Root publishes
  public schema/version; existing defaults and formal gates remain unchanged.

The source exposure of constructor failure can later become a nominal error
union separately; this slice deliberately freezes the existing nullable
Registration convention and does not silently change old constructors.

## Split and mandatory nearest cases

Public slice: root owns Type/opcode/foreign-role fields, source role vocabulary,
normative ABI and raw transport. Consumer slice A: source/Types and independent
registration kernels/owner-state rules. Consumer slice B: private Task/LLVM
draining and source-to-native host event-queue controls. They join on the actual
public commit, never on hand-written substitute IR as source admission evidence.

Nearest cases: allocation failure before host register; register failure with
callback attempts; callback reentry; request/close reentry; a late raw entry
before trampoline; raw entry rejected after CLOSING; drain0 retaining
environment/root; complete no-future before final free; repeated request/close;
early finish_destroy/default Drop; wrong provider role/signature/drain tag; mutable or
borrowed callback environment; normal/error/cancel result ownership; child or
prepared input still borrowing parent. Unsafe provider violating no-future is
not a safe-language success case.
