# 181 组合验证

在178–180候选分别建立实际能力后，用一个真实四模块消费者联合验证：同一泛型Store库用于两种名义元素、完整State拥有Store与回调、独占元素窗口内原地更新Copy字段、与独立回调/Copy字段同时使用，之后才增长容量。所有输入由运行时stdin决定，不手写替代状态机或宿主容器。

保留两个层级的核验：每个源文件走正式编译链；未经插桩CLI产物与单独分配观察产物分开。每个分配失败点在运行前列出精确Drop/退出/存活分配预期，增长失败后检查旧内容、len和capacity。Linux与Win64/Wine按相同源码和预期执行。

最近反例包括活窗口期间同Store结构写、完整State移动/替换、共享窗口升级为独占。构造函数的create/give鲜度缺陷由178作者修复并独审，当前准备分支不因此提前获准合入。本文不改变接受性规则或产品门。
