# 008 模块路径与目录入口修订

## 来源与裁决边界

用户要求重新核对指定 ZIL 设计对话，指出后期讨论使用 import a.b。个人上下文可检索到点路径等候选，但没有检索到其后明确批准原话；直接网页访问进入登录页，不能据此声称读完原对话。现有1.1正文、EBNF、嵌入HTML与实现都停留在斜杠版，未发现这几份文件互相采用不同分隔符。

用户已授权确定设计并实施。本修订明确采纳点分隔逻辑路径，记录为新的集成裁决，不伪称历史对话已经最终批准。泛型 ::<...>、返回 -> 保持现有唯一写法；闭包正文自动捕获、move、组接收者与.name已在当前规范，不恢复强制capture表。@与后置转换留作提案，不进入1.2文法。

## 行为

- import a.b / syntax use a.b as x 使用标识符逻辑路径；a.zil 是两个逻辑段，不剥扩展名。
- a.b 解析到项目根下 a/b.zil 或 a/b/mod.zil，恰有一个入口才接受；同时存在精确拒绝歧义。
- 目录仅靠mod.zil显式入口成为模块，内部文件不扫描、不合并、不自动导出；仍文件即模块、默认私有、别名默认最后段。
- 旧斜杠或混合路径拒绝并提示点拼写；字符串、相对段、glob继续拒绝。
- canonical路径不得逃逸项目根，同物理模块保持唯一身份，入口缓存不得绕过双入口歧义；模块图与预算策略保持。

## 迁移与最近反例

同步规范、EBNF、parser、resolver、正例与CL21–CL26拼写，预期语义不变；测试file/dir双入口、无mod、别名复用、symlink逃逸、a.zil路径、停点与热冷失效。新增三模块整数程序真实native执行。历史工单保留原规范hash，由独立切片009核验其精确历史规范；在途工单明确迁移到1.2，不追改旧审核事实。

## 施工中发现的既有预算缺陷

真实边界例根文件53字节、依赖26字节、总额79字节会被文件适配器拒绝：已读取文件的解析上限误用了扣除后的剩余读取预算。008同时修正这两个预算用途：全图读取仍累计扣费；已获准读取的当前文件按其自身长度解析。钉住总额等于上限通过、少1字节拒绝，不改正式预算数值。原始26/27失败运行保留到独立原始归档，源码包保留精简复现。
