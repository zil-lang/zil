# draft08 公共表示与应用集成

042、043、044 分别在独立树提出独占操作、字段可见性及外部声明/unsafe 区域。集成者统一将 compiler schema 与 raw wire 升到 5，Typed 指纹域改为 V5；旧版本 1–4 明确拒绝，不把旧缓存解释成含新操作的新候选。新操作 wire tags 为 27–30（独占借用、重借、间接写、转交）及 31–33（unsafe 进入/退出、外部调用）。CoreField.public 只记录前端字段可见性；foreign 元数据进入 Typed 指纹和 wire。

这些是既有语言规范能力的分批实现，仍是 partial schema。接口附件和诊断登记只记录实际实现；资源/清理、一般 trait 约束、闭包逃逸和异步/并发不因 schema 升级而成为已完成。

根集成同时机械补齐独立 wire 边界夹具的 foreign:None，保持原有拒绝断言；035 之前示例和主应用的跨模块数据字段必须显式 pub。045 用独立 Rust 行为对照验证五模块动态输入，并检查普通和 JSON CLI 的 stdin。各生产包保留精确独审记录；集成应用与版本调整交由非作者审核后进入主干。

首次完整应用构建发现：泛型预展开对 `Result.Err(state.error)` 无法推导 payload，因为 state 是共享地址，Member/Index 的预推导遗漏了普通 Types 已支持的一层自动解引用。此处补齐记录/tuple/数组的一层投影形状，仍由正式 Types 与独立 Verify 检查访问资格和存储；不增加嵌套地址、能力界限或泛型模板体新操作。原失败日志保留在045证据中。

随后的组合核验发现混合外部捕获误拒：可变 Stats 与只读 callbacks 的 loan 合集被整体要求拥有同一个父 loan，导致无关来源破坏本来有效的父子授权。修复仅在存在访问冲突时，要求所有与该窗口相交的自身 loan 都有已重建的父子关系，且至少有一个相关 loan；不将 `all` 简化成可能放过同源兄弟 loan 的 `any`。原042生产候选的独审结论保留此接受性缺口，根差量另由非作者检查。

最终合并后的 Rust 格式由根统一执行 cargo fmt；相关额外文件仅是机械格式化，不改变已独审的生产逻辑。
