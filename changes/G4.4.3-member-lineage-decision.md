# G4.4.3 retained member identity interface decision

Integrator /root approves `DeclarationOrigin.retained_members` with the proposed
`RetainedMemberOrigins { original_count, positions }` representation after the
read-only Astra architecture review. Implementation remains assigned to sol high.
This is a Rust source identity sidecar; Typed/Wire, native ABI and default limits
are unchanged. The public field alone does not complete a language capability.

Only deletion of original direct methods of a nongeneric struct is covered.
The Materializer must bind the row to the same original module/host and reconcile
its count and retained ordinals against the immutable original AST and actual
skip events before moving output. Length, strict order and range checks cannot
detect an in-range wrong ordinal or a fabricated original count. Test those at
the producer event boundary; do not claim arbitrary public Aligned data has
authenticated source history. Names, spans and Some do not grant authority.

Some(empty) preserves an all-methods-deleted host. None denotes no member-vector
change; unknown/generated lineage stays Unavailable. Reject Some for unsupported
host kinds, generic hosts and trait/impl. Every actual aggregate member identity
consumer uses the retained original ordinal, never a renumbered output position.

Producer, Aligned validation, aggregate consumers, top-row filtering, project
redistribution, capture/copy identities, source.clone in generic_closure_context,
Driver origins_cost and execute bind_source_origins must be updated together.
Charge actual new header and vector footprint and each copy/traversal from the
current budget; no artificial zero-cost promise for a physically larger header.
Record changed old boundaries honestly, preserve unchanged ones, and keep limits
fixed. Source, raw structural/event neighbors, cache, native full values and
independent review remain required before integration.
