# G3.4.1：普通泛型 inherent impl 的真实方法消费者

基线 c63001c8e。依 `_zil_design.md` §18.1、§3.4、§20 V10 接通原 `342/slice_iter.zil` 的 `impl<life s,T:Copy> SliceIter<'s,T>`；不修改原输入字节。普通 bound/完整名义实例/实际 life 与权限独立。

本片将完整、名义的泛型 inherent impl 的非泛型显式 receiver 方法正规化为普通函数模板：继承 impl 全序 life/type 形参，Self 只替换为该 impl 的真实 target，原声明及 member 来源保留。全部方法，包括未使用方法，进入已有 parametric 定义检查；不靠某次 i64 实例补证。调用按实际 receiver 的完整名义实例匹配唯一方法，保留一次求值和参数顺序，按 receiver 声明形成显式共享/独占重借，再进入普通实例化、Types、Analyze 与独立 Verify。

首片 target 必须为当前模块实际 struct 声明的一对一完整 type/life 参数应用；impl 额外 where、const、泛型方法、隐式 receiver/default 与特化模式显式 Unsupported，不能以擦除其义务放行。拥有、dyn、trait lending、async 权限不由此新增。原非泛型 inherent/trait 路径不改；无此特征不新增遍历费用。新克隆/替换、查找、向量增长与源身份扫描先付费，沿同请求预算，无默认限额上调或公共 schema 修改。

最近反例包含未使用模板中的未约束 T 数值/字段使用、重复可变借用、错名义/phantom实例、错life来源及方法歧义；原 SliceIter 与连续多个 Option<&T> 返回/失效由 G3.4.1 合流验证。实证报告精确提交及限定运行；本提案不宣告完整 lending、产品门或 Rust 性能优势。

实施澄清：mixed life/type沿既有单Copy-T定义期profile，life-only成员保持普通retained函数；调用方不以TypeApply传递life名字，实际receiver/result存储合同保留callee自身全序life并按真实输入实例化。方法/字段同名在移除impl前检查，跨模块公开资格要求host nominal与member均公开，真实module来源必须在既有项目预费遍历中、flatten之前捕获。原SliceIter完整责任仍由父G3.4.1合流验收。
