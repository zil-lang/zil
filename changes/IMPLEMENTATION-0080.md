# 080：沿资源效果依赖传播，而非每轮重扫全模块

状态：实施前提案。生产基线 `c4c307648087f2f9d23fb5d611638140751e61ed`，执行 schema13；
并行语言施工的新 schema 不重标本研究。父任务 B0 和原产品门不变。

## 原因与实际目标

076 的 dense-direct 相对研究 BDD 的改善不是生产可替换热点。当前生产 Analyze 和 Verify
各自使用分量数据流。新发现是两个 `resources.rs` 的资源写效果固定点仍逐轮运行全部函数；
每次运行又包含函数内状态求解、类型位置和 future-Desc 准备。调用链逆声明序传播一个新
写效果，会使未受影响函数被反复执行。本片只改变函数间调度，不改变这些函数内算法。

## 候选与不变量

每个函数的摘要是有限的输入/借入捕获写效果集合。各阶段独立读取本阶段使用的实际调用
和闭包入口，构造 `callee -> consumers`。所有函数先执行一次；摘要严格增长时，仅安排
已消费该摘要的函数重新执行；队列为空表示完整有限单调方程组达到原有最小固定点。
之后仍依原有顺序执行所有函数的最终 validate，不把中间空摘要当成安全许可。

Analyze 与 Verify 分别构图、求解和验证，不共享摘要或“已安全”标记。普通 Call 的公开
helper 合同与私有效果消费沿各自现有实现判断；五种具体闭包调用解析其实际 ClosureId
及入口。允许保守多边，禁止漏掉任何可被读取的摘要。不可达块不引入必需依赖，但保留
所有原函数结构检查。递归、自边、重复调用及不连通分量均合法。

无 schema、接受性、ABI、机器布局、错误/清理次序变更。先保留旧全轮扫描为仅测试参考，
在足额预算下核对完整摘要及最终诊断；拒绝信息不因跳过最终验证而消失。正式语言新增
能力与本算法后续集成由 root 再验证，不偷偷加入冻结计时。

## 预算变化

默认 `max_analysis_steps` 不变。新依赖表的建立/释放、块和指令访问、边、队列与通知均
按实际确定性规模收费；取消的整函数重算不再收费。不同算法的 ResourceLimit 阈值可以
不同，须分别报告，不把受限结果记为语义通过。每阶段另测完整请求 N/N−1，并在独立
进程重放。已有精确预算测试若失效，保留失败、报告真实新 N，交集成者处理相应夹具。

## 最近反例与证据

- 反向普通调用链末端写入，前端 Fn 拥有环境不得因空旧摘要被接受。
- 借入闭包调用的写效果，覆盖 local、SSA、借入 Address 三种入口及 Fn/FnMut/FnOnce。
- 互递归和参数交换，直到全部传播完成；星形和重复边不漏通知；不相关分量不被重算。
- 公开 helper 的合同是消费边界，不反向读取私有实现；错误/Trap、Package Bind/End
  保持原责任和 future-Desc 检查。
- 两个请求之间修改私有函数或公开接口，不残留本请求队列/图；没有跨请求缓存。

## 性能实验预注册

固定同工具链 release，基线与候选相同 runner、源字节、预算与输出合同。准备阶段仅作
功能核对，正式采样由 root 提供独占窗口。语料包括 scalar、真实 owned_component 的
main/lifecycle/fd，以及短/长正反链、星形、不连通、递归分量和闭包/公开 helper。全部
Complete/拒绝/限额及失败尝试保留。候选费用包括构图、队列、固定点、最终检查和释放。

测完整 compile_path 的冷空会话、原样复用、私有编辑及公开编辑；阶段微测量只作诊断，
不能替代完整请求结果。保留进程 wall、Linux VmHWM、实际 Verify 次数、产物/接口/输入
身份和原生行为。OS 页缓存不清除；单机有限语料不代表 Rust 产品编译速度。固定一轮
预热和七轮配对采样，交替先后次序，确定性配对 bootstrap 仅描述本组小样本不确定性。
若小例/真实组件无净收益或内存成本恶化，完整保留，不用长链倍数掩盖。

## 归因与后续

这把图思想落在语义依赖边和局部传播上，属于已有单调数据流工作队列技术，非原创数学
定理。Rust 查询系统的纯查询与显式依赖、重验证成本提供工程参照；本片没有实现 Rust
跨会话 red-green，也没有从论文中移用提速数字。物理启发的子态树和条件分量切割仍可
在强 dense-direct 控制下继续研究；076 的生产 NoGo 不由本片自动解除。
