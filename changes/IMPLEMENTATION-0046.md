# 046：返回来源只沿相关调用边界传播

父任务 B0；基线 `493edcb0e2367ac7b8131a0c69893150356a0246`；语言 1.3/A 与 schema 5 不变。

## 问题与变更

当前 Analyze/Verify 在任一函数的返回来源增长后重新求解所有函数。反向声明的长调用链因此产生二次函数求解工作，与无关函数也被反复访问。附件 `compiler-proof-cut.md` 的可移植原则是按真实依赖边界隔离工作；旧世代/租约机制和碰撞图专用切割定理不进入本实现。

两个阶段各自从可执行 CFG 建立地址返回调用的反向依赖，首次检查所有函数，随后只在被调用者的参数来源集合增长时重新求解直接调用者。每次函数求解仍完整执行既有局部传递，不缓存已核权限，不共享生成端与核验端的求解状态/实现。无地址返回的模块不建立调用索引。局部来源、loan、初始化和最终逃逸/空来源检查不变。

## 健全性与预算

返回摘要只包含有限参数位置，按并集单调增长；首次全体入队，之后摘要变化会调度每个真实消费者。因此队列为空时，每个函数事实已消费当前依赖摘要，结果等于原全扫描最小不动点。无根递归环仍由独立核验拒绝。不可达调用不形成依赖；不借由可达性删除任何原本接受检查的语句。

`max_analysis_steps` 数值、产品性能门与 ResourceLimit 类别不变。计费改为实际反向索引分配/边扫描、队列调度、函数重证与根集合操作；不再支付未执行的全模块重扫。容量计算先检查/扣费再分配，预算耗尽不给出任何已核结果。因此相同限额下程序可能由 ResourceLimit 变为成功，这是工作减少，非修改语言规则或抬高预算。旧固定预算误触发不能继续作为性能优化的强制结果。

首个候选的 Verify 使用立即处理通知的栈；多叶函数同时更新时会反复唤醒同一个调用者。交付前改为当前/下一批两个私有前沿，合并同批通知；额外一张最多 F 项的索引表在分配前计费。Analyze 保持 FIFO，两个实现不共享调度器。65 函数的汇聚反例由 129 次重证降为 66 次，完整 Facts 与旧全扫描相同。

## 验证范围

测试专用旧全扫描参考与新调度比较全部来源事实；真实源码覆盖长链、相互递归、多个参数来源、无根递归、无关函数、不可达调用、伪候选和预算。Release 基准冻结源码、基线提交、工具链与参数，交错重复，核对候选序列化逐字节身份；分别报告 Analyze、Verify 与端到端，不将本机加速当作超过 Rust 的证据。
