# 102：拥有字节差分的冻结工具合同

本片从 `24ca9583d8789cfdfe3ccdbfe3eeff614bf56429` 的099既有语言能力出发，
只改变Roam工具。语言、schema17、独立Verify、生产分配器和预算不变。

## 输入与兼容

保留同一个 `byte-buffer-native` profile；新生成输入明确标为
`zil-byte-buffer-native/2`，模型性质为 `byte-buffer.owned-c-model/1`。
旧 `/1` 的模型、源发射、C参考、期望输出及冻结worker身份保持；新worker继续
解释旧合同。旧worker必须把 `/2` 拒绝为unsupported，不向旧输入偷偷加入新含义。

新程序有两个逻辑ByteBuffer槽，初始为空。`carrier`明确为 `local`、`package`、
`fnmut` 或 `fnonce`：后两者由普通工厂返回真正保存的拥有Package环境。
同一有界操作数组驱动独立Rust模型、独立C有界数组解释器及相应ZIL载体。
载体的局部逆序/Package字段序清理按各自规则建模，不假定所有载体有相同析构顺序。

每程序最多16动作、容量0..64、字节0..255；每case默认2程序、最多8程序，
沿用既有时间、输出、证据和监督配额。输入包含明确的 `model`、`carrier`、
`failAt`、`finish`、`early` 和 `operations`；未知形式和越界不得当作通过。
`failAt=0`表示无计划分配失败，正值表示第n次真正增长请求失败；未发生的失败
位置不制造一次分配。negative reserve和容量已足够不消耗分配序号。

## 动作、错误和观察

- `reserve`、`push`、`fill` 指定槽0或1，沿用098的容量/初始化含义。
- `relay`转交既有槽责任后补回，不产生新分配身份；`reset`替换为空头。
- `replace`先准备新槽并尝试指定容量，成功后才释放旧值并提交；分配失败保留旧值。
- `take_refill`先取走旧字段，再补入新值；取走值由独立局部责任结清。
- `prepare_error`准备临时ByteBuffer后从普通错误出口退出该步骤；保存FnMut真实
  错误返回后仍可再次调用，原槽不变，临时责任结清。
- `finish`区分正常、普通错误，以及取走槽0/1后的正常/错误退出；FnOnce允许
  部分消费后由调用方清理剩余字段。FnMut不在不完整状态下返回。

每步比较成功/失败、两个槽的len/cap/全部已初始化字节，以及真实分配事件和
释放顺序；最后检查零遗留。独立C参考不读取Rust期望，也不嵌入ZIL执行结果。
它是有限语义参照，不是通用降C后端。

工具内置C观察器只拦截测试可执行文件的malloc/realloc/free。它以实际指针查找
当前责任，给成功的新分配单调编号；成功realloc更新指针映射并保留该编号；
失败不改映射，free退役该编号。未知/重复free明确失败；不比较跨进程裸地址。
观察器本身不实现ByteBuffer操作或拥有语义，不进入生产运行时。

分配失败计划是明确的测试环境条件，与 `bytes-omit-push` 语义变异分别记录。
无注入hunt只统计failAt=0且mutation=false的运行；计划OOM实验单列，不能将其
或受控变异登记为自然生产缺陷首次发现。非计划宿主分配失败保留为环境失败。

## 固定最小回归与完成路径

固定序列覆盖：双槽真实分配；填充后增长失败且旧字节保持；relay无新增责任；
replace的新分配在旧释放之前；take/refill的独立责任；FnMut准备错误后继续写入；
FnOnce取走第二字段后正常/错误退出；正常局部逆序与Package字段序清理。
无预算、非法第二步保留第一步、未知合同、超限和旧 `/1` 重放继续拒绝假Pass。

四个实际变体仍为ZIL/C各O0/O2，每次成功ZIL编译恰好一次Verify。观察器源码/hash、
实际clang完整argv、LLVM/二进制hash和输出进入既有native evidence；clang proxy
只允许其本worker内置观察器，并沿用原监督和配额，不能接受输入提供的任意链接参数。

实施后先运行限定回归，再以冻结源码/二进制运行有界无注入hunt、单列计划OOM
案例，并使受控省略push完整经过同性质回放、缩减、坏候选拒绝、回归和关闭。
失败原件不得覆盖。发现生产问题立即给root准确阶段/原件，本片不改生产编译器。
最终精确提交交非作者独审；作者不合入、不运行正式全量。
