# 0067：守恒启发的精确责任位置编码

2026-10-24（Asia/Shanghai），生产基线400a082，研究冻结schema10。仅独立研究，不修改生产安全核或语义。

## 问题与机制

063在正常传播态用carrier×token布尔矩阵表示每个责任token的位置。借鉴守恒网络/粒子身份和因子图消元，候选将每个token的关联列改为一个二进制位置（0表示无当前carrier），保留全部其他坐标。多个不同token可处于同一个闭包。

不是预先假定程序合法：原始有序实参的重复转交、重复清理、重叠incarnation、Desc和退出fault，仍由原有限query解释；全部fault/abort记录原始完整前态。候选还构造正常转移后的多位置谓词，在实际无fault输入上若非空则返回内部不变量错误，不过滤这些输入。初态编码也检查每个关联列至多一处。

## 等价合同

输出与063相同的完整字段、事件标签、逐点/正常出口/fault/abort/unsupported联合关系。独立oracle直接解释raw TypedIR，不调用候选抽取、BDD、编码器或转移。位坐标编解码及只读TypedIR类型为共同数据格式。解码需要与初态、正常迁移和每种观察交换；正常态唯一性必须从初态和无fault迁移保持推导，而非删掉反例。两个拥有字段捕获同一个token是必测反例。

## 支持域与成本

沿用063有限域：schema10但只接纳旧模型已定义的操作；Package、Address、新helper环境与其他未知操作仍Unsupported。单活跃site incarnation的限制不放宽，不恢复语言已弃用的世代机制。沿用100M工作、30万物理BDD槽、10万结果行等预算；编码/解码、保持检查、状态查询、GC和完整输出费用全部计入候选工作。oracle独立计费；ResourceLimit、Unsupported和Mismatch均非成功。生产接受性仍是不同合同。

稀疏关联位数约T×ceil(log2(C+1))，它不直接证明BDD节点或总耗时减少；编码等值测试和保持检查可能增加成本。对照包含相同当前TypedIR的dense:mono/fused:owner:gc强基线；正式wall只在root批准的独占窗口采集。提前冻结源码、工具链、输入、输出与预算。
