# G3.4.1 · Qualified carrier parameter mode

The original SliceIter reaches Types with an exclusive outer address to a Resolver-authenticated borrowed record. The ordinary parameter type gate already admits this address, as do address-place consumers. The BorrowMut mode check alone omits the existing `stored::shared_address` classifier.

Admit the existing qualified-carrier classifier only inside the existing `Address { mutable:true, .. }` BorrowMut branch. This dispatch consumes the already independently authenticated nominal inventory; it neither marks the carrier Copy nor permits mutable reference Type actuals in Option. The outer exclusive borrow and shared stored leaves remain distinct. Ordinary writes cannot replace qualified carriers or stored borrow leaves outside the existing protocol, and both kernels continue reconstructing actual targets and active loans.

No schema, ABI, allocation, cleanup ordering or default budget change. The classifier is the same constant-time private discriminator already used by parameter admission and place consumers. Validation must include the original unmodified SliceIter (successive mutable next calls retaining earlier shared results) and its underlying-array-write invalidation counterexample through the safety kernels and native consumer.
