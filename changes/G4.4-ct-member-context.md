# G4.4 authentic member CT context

The existing SourceIndex freezes top-level declaration rows followed by actual
member rows, but CT source life attribution, frozen invocation scope and result
reification only index the top-level item vector. A method's own lifetime binder
therefore cannot traverse the existing CT5 Definition path.

Resolve a member function through the same original traversal order, paying each
visited row and bounding depth. The original top-level Origins row and authentic
member symbol jointly name the owner; spans only reject containment mismatches.
The first slice admits a member's own generic binder in a nongeneric host and
retains the complete original generic ordinal. A generic enclosing host remains
unsupported until its actual enclosing scope relation is carried. No raw symbol,
name, source span, inferred specialization or generated function name establishes
a new scope. Existing CT5 scope authentication, independent verification, ordinary
kernels and machine checks continue to apply without a public layout change.

Controls must include actual source, a free sibling life, wrong ambient member
selection through raw/Wire, source/module relocation, and paid request boundaries.
This implements current ZIL-COMPTIME context obligations; it changes no language,
ABI, budget default or product gate. Generated lineage and full specialization
actual-vector construction remain separate unfinished consumers.

The private expression entry now separates its naming `definition` from an
optional authentic original `lexical_owner`. Generated item subtrees retain
naming provenance but pass no original binder witness, including their nested
members and nested emits. The frozen view and compiler both honor that absence.
This is a conservative boundary correction, not a claim that the earlier source
proved unsafe: ordinary generated-life input already encounters the missing
transformed declaration ledger. Its scalar no-life neighbor still executes.
A hypothetical private entry with the same real naming owner but no lexical
witness cannot create an ambient scope or materialize its lifetime. Statement
splices in an actual original function retain that function's lexical context;
this change concerns generated declarations, which need their own ledger.
