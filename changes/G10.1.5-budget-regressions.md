# G10.1.5 budget regression repair

Root authorized this budget-consumer repair from `8477e08c1d8e124f6b9b920295cc461332213c49` in `.task/G10.1.5.md`. This proposal retains source semantics and default limits. Exact ResourceLimit boundaries change only for the measured occurrences below. Root's original full-run failures remain failures of that frozen candidate; this is a subsequent, independently reviewable fix.

## Work removed

- Alias lookup borrows the AST name for a single-component key. A joined owned spelling is needed only for a qualified path. A bare lexical binder/non-alias namespace returns before constructing two unused owned names; qualified aliases and shadowing still use the existing resolver.
- A declaration with no callable role does not scan its generic list for a role-local class scope. Template registration asks its extra Copy/life profile question only on encountering an actual life formal; the outer parameter loop still checks every formal.
- Flat callable bounds do not search the source generic list for invocation binders. `generic_hrtb::relation` yields a relation only for a `ForLifetime` header with actual input life bindings. Qualified role frames, including independent nested storage classes, retain the original checks.
- Literal/Binary RHS skip the owning-address planner. Their language result cannot be Managed: literal types are scalar constants; normal binary expressions yield numeric/Bool results (or Bool for ForeignHandle equality), and logical operators yield Bool. Their operands may have effects. The existing `assign_address` path still prepares the actual address, checks permission, checks/evaluates RHS and emits the write; no expression evaluation or ordinary check is skipped. The gate uses Core variants, not source names. Constructor, Call, Give, Sequence and every other possible owning RHS retain the planner.

The no-callable scope shortcut only concerns `generic_role_check::Scope`. `generics::specialize_products_prepared` still runs full-AST `lifetimes::validate` first, and `generic_check::validate_parametric_with_bounds` still checks signatures and unused bodies. Its independent `lifetimes::copy_life`/`lifetimes::contract` path remains active for no-F life functions. Replayed negatives include undeclared signature lives, unused invalid operations/control flow and an unused no-F function applying a same-class Code to independent life classes.

Direct Expand/Types APIs have no shared compilation cache: their repeated N calls create fresh ledgers over the same input. Existing impl229 shared-cache test separately retains fresh/warm N and exhausted N-1 retries. Owning replacement's existing wide/long-name source test also checks fresh/warm failure/retry behavior. They do not falsely label direct API calls as cache hits.

Source-level malformed-expression, lifetime, alias shadowing, qualified-class and owning-replacement tests are controls for the optimizations, rather than claims that all parent feature goals are complete.

Rust-goal reflection: measured compiler work/allocation is reduced on these real controls; budget accounting stays bounded and explicit. Runtime/memory relative to Rust, compile-time comparison with Rust, maintenance-cost comparison and a product net breakthrough are unmeasured. This patch does not establish a new product gate or complete the owning/generic parent goals.
