# 198：语言分支离线同步

用户要求提供 Git bundle，交给已有的线下一键同步流程使用。当前会话没有该脚本的内容，因此不猜测其参数，不更改现有 remote，也不将编译支线当成语言主线覆盖。

新增 `tools/language/198/bundle.py` 只负责两个明确动作：从干净、精确冻结的分支导出普通 Git bundle；核对 SHA256、真实 bundle header 和本机前置对象之后，把交付提交导入 `refs/remotes/zil-language/<完整提交>`。导入不 checkout、merge、reset、修改 index 或工作文件；已有同名正确 ref 幂等成功，已有不同对象不覆盖。所有 Git 调用使用参数数组，不通过 shell 拼接。

完整 bundle 只承诺指定分支及其可达祖先；增量明确排除指定祖先并记录 Git 实际先决提交。保留真实 Git 历史意味着历史已提交 evidence 仍可能存在；不能删除这些对象同时声称提交身份和祖先未变。无关未合入分支、未提交材料、新执行产物不因本工具进入 bundle。原 all-ref 审计恢复工具保持原职责。

默认交付上限 50,000,000 字节，超限拒绝发布；输出与 manifest 已存在时拒绝覆盖。完整包优先，只有接收方具备声明的祖先历史时才用增量。导入和语言合并分开；快进、分叉、冲突和缺少共同祖先的具体命令见 `docs/OFFLINE-BUNDLE.md`。

本片不改变语言接受性、公共 schema、ABI、求证或逻辑预算，也不构成 Rust 性能或完整语言终态证据。验证仅为隔离真实 Git 仓库的离线文件/分支操作；最终交付 HEAD 和实际 bundle 大小由集成冻结及包装收据记录，不预填成功。
