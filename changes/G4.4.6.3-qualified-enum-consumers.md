# Qualified pure Enum life consumers

Baseline `aabc9a331ee542e4c040ea976f4513ebc0451e28`. Extend the existing private storage-life inventory to real `LifeNominalKind::Enum` instances with `BorrowedStorage{storage: Enum, life}`. The complete declaration identity, ordered Type/Const/Life formal and actual vector, direct life positions, recursive TypeArgument rows, class mapping and unique semantic key remain independently checked by Types, Analyze and Verify. Types compares actual Enum variant names, order and payload types against the Core source declaration. Analyze and Verify have no source declaration table in TypedModule (the same boundary applies to Record); each independently checks the complete actual Enum Type, ordered variant payload, qualified instance identity, formal/actual vector, physical payload and retained classes against actual operations. Nominal metadata never grants roots or loans.

The physical profile accepts pure Copy scalar/tuple/array payloads and pure qualified nominal children at actual Variant/Field paths. Array elements contribute one homogeneous `LifeTypeProjection::Element` class path, including nested qualified children, but no physical slot or target. It rejects Address, Desc, Managed, owning leaves and mixed physical borrow/retained relations. Real address and ownership profiles require separate consumers. Existing Record acceptance and its budget stay unchanged. Enum/variant/array walks, child identity lookups, row construction, clones and comparisons debit the same request before growth. No public IR or Wire schema change is proposed; the public `Enum`, `VariantProjection`, `LifeNominalKind::Enum` and `LifeTypeProjection` variants already exist.

The Expand producer publishes the same complete instance interface through `products.storage.instances`; this consumer change does not reconstruct source identity from a generated physical name. Source, raw and Wire tests must include a real Enum Type actual and nearest wrong kind, wrong variant/payload, omitted/duplicate class and physical Address/Managed counterexamples. Native/link work uses the integration window.
