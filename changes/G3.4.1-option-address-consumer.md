# G3.4.1 sealed Option address actual consumers

Root approved this acceptance expansion on 2026-11-06 before implementation.
The common fixed domain may include the exact direct shared Address Type actual
of sealed builtin Option: retained path `[TypeArgument(0)]`, local class 0,
outer binder 0. Its physical slot remains `[Variant(1,0)]`, SharedAddress, binder
0. One fixed class, no nominal lifetime rows. No runtime representation changes.

Authentic builtin declaration is independently reconstructed by each consumer:
compiler id `(module=u32::MAX, declaration=0)`, stable identity
`@zil.builtin / [option] / [enum,Option] / []`, kind Enum, formals `[Type]`.
Only exact `None()` / `Some(actual shared Address)` layout is admitted. A
compiler flag, a matching type name, or a fabricated nominal lifetime row does
not grant authority. Ordinary user nominal Address Type actuals remain closed:
the current declaration metadata does not establish which original Type formal
produced a physical field when several formals share the same layout.

Types checks complete declaration, instance actual, exact payload and shape.
Analyze and Verify each independently check those facts and transport the actual
Some input permission to its physical slot and back through ReadVariant. None
creates no permission; the retained row itself creates no root. Existing runtime
tag checking on ReadVariant remains mandatory. Storage contracts, invalidation,
actual source checks and loans continue through the existing independent flow.

No schema, ABI, implicit allocation, cleanup ordering, default limit, new test
target, formal gate or product-gate change is proposed. Source/raw/Wire nearest
counterexamples and full original SliceIter remain required for parent completion.
