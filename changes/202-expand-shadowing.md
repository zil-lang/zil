# 202 Expand：回调泛型遮蔽同名名义类型

生产及测试冻结为 `504141f1c7de54d401c94554432485cb5eafe033`。独立复核发现：没有 type alias 的单模块输入中，全局 `struct T` 与函数自己的回调泛型 `T` 可以在生成的 Package 字段中共用 `Named("T")`。Types 按全局聚合定义解析时，无法再恢复已擦去的词法来源，因而拒绝本应有效的调用。

本修复在原有已计费的泛型参数遍历中检查实际 callable binder 与已有 nominal 索引是否碰撞。只有发生碰撞时，才在仍保有作用域的原始 AST 上使用已有名义卫生改名，再重建专门化索引。重建沿用同一个剩余 Budget，保护、复制和重新扫描都计费；普通无碰撞路径保持原样。局部 `T` 保持其函数绑定，实际全局类型及其引用获得卫生名。没有给 Types 新增全局名字优先规则，也没有在生成后的聚合字段上猜测来源。

干净提交的 `shadow03` 实际通过 15 项 Expand 检查，包括五模块消费者的六个公开普通模板。新碰撞用例保留真正的全局 `T`、具体函数参数以及局部 `T: FnMut`，检查真实 Core 中两类身份仍不同，来源映射有效。精确边界为 12755；12754 返回 ResourceLimit，新的 12755 预算重新成功。原 197 对照 1731、普通 Store eager 对照 2255、原 deferred factory 8399 均未改变，默认额度未提高。
