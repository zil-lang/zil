# G9.3.3 proposal · Mutable windows into ordinary POD Store elements

Status: implementation contract frozen 2026-11-07. Base 812d4659f56f7d4734e17d9b6444fda3e220aacf. Not an acceptance record. Start from the accepted G9.3.2 POD Store profile (`148014641f9244d5814373e5adaacd4a013676fe`) and the existing restricted exclusive Store window rules in `_zil_design.md` §4.4. The exact branch base and goal assignment are to be fixed by integration before work starts.

## Finite behavior

Admit `store_at_mut(store, index:i64) -> &mut Record` for the same complete, nonzero, finite ordinary POD Record family accepted by G9.3.2. The backing value remains the actual `Desc<OwnedStore<Record>>` of a unique managed Store head; no new permission follows from `StoreElement`, `Copy`, a resource name, a source lifetime, or a candidate plan. The existing `OwnedStoreBorrowMut` opcode is only a transport shape until Types, Analyze and Verify independently validate its complete element type, result mutability, actual head and executable operation. Do not add owning fields, nested borrowed fields, callback elements, capture, escaping return, mutable Option payloads, contiguous slices, new public ABI or per-index separation.

Evaluate store then index once, left to right. Check `0 <= index < len` against the initialized prefix before forming the address; negative and out-of-range indices take the existing checked trap. Capacity alone does not authorize an element. The exclusive address may synchronously read and write supported Copy fields and their Copy projections, and may be reborrowed to an ordinary synchronous helper under the existing explicit address relation. A live exclusive window conflicts with another shared or exclusive window from the same actual Store, regardless of index, and with reserve, push, pop, give, drop, head movement or parent overwrite. These structural operations remain may-effects even if a particular reserve does not reallocate or a push fails. Last use ends the window; a distinct actual Store remains independent. No index inequality, same type, or name spelling establishes disjointness.

The existing rejected Source in `tests/language-readiness/G9.3.2/consumers.rs` (`g932_pod_store_mutable_view_is_rejected_without_banning_record_mutability`) is the unchanged positive candidate: create `Store<Cell>`, reserve and push `Cell{value:41}`, take `store_at_mut(items,0)`, write `view.value=42`. Preserve that exact source as the before/after control and retain its old rejection log. Also use the existing `std.store` `new`/`reserve`/`push` helpers to prepare an actual Store, then call the built-in `store_at_mut` directly. `std.store` currently has no `at` or `at_mut` returning wrapper; a new wrapper would require a separate source-class return proof and is outside this minimum. Keep the adjacent ordinary `&mut Cell` positive and all G9.3.2 shared-view positives/negatives unchanged.

## Independent consumers and nearest controls

Types checks the complete POD resource/element/result identity and the exact mutable borrow instruction in used and unused definitions. Its current explicit gate is `crates/zil-types/src/dynamic_store.rs:687-693`. It must not infer field/owning permission from the generic StoreElement bound. Inspect source lowering for `store_at_mut` and direct field writes, then validate raw TypedIR and Wire with rebinding of fingerprints where appropriate. Check whether the present opcode and machine result shape suffice before considering public metadata.

Analyze changes the explicit POD `OwnedStoreBorrowMut` rejection in `crates/zil-analyze/src/pod_store.rs` to exact `Desc<OwnedStore<Record>>`, i64 index and `&mut` same complete Record admission. Independently inspect the already present mutable paths: `dynamic_store::access` labels this opcode a write; `holds` preserves its actual Store root and published may-effect; `head_loans` makes the result loan a child of the actual Store carrier; `head_access` transports actual head requirements. Confirm that a derived field address and ordinary helper call keep this parent loan until the result's last use. Do not rely on coarse exported Holds for private window precision. Any new comparison, clone, scan or map is charged before work from the same request, while no-new-path legacy fees remain exact.

Verify independently rebuilds the type, actual root, mutable loan and call/CFG windows from TypedIR and rejects a forged plan, raw module or Wire input on its own path. Its current explicit POD mutable gate is `crates/zil-verify/src/dynamic_store.rs:935-947`. No Analyze helper, proof or candidate permission may be used as verifier authority. Raw/Wire nearest controls start from successful Source: change a shared borrow to mutable with coherent result type, or substitute a distinct Store operand with the live Store operand; refresh only transport fingerprints, then require the relevant kernel's actual alias rejection. Include an unused malformed producer and a wrong complete element/result type.

Focused Source pairs: (1) mutate one POD field through `store_at_mut`, read full value and release the Store once; (2) hold the mutable view across a same-Store shared view, another mutable view at index 1, reserve, push, pop, give, drop, head move or parent overwrite, and reject each; (3) consume the view's final use before those operations, and use two distinct Stores while one view is live, and accept each. Reborrow through a synchronous helper must retain the parent, including a call whose last argument use occurs inside the call. Different runtime indices do not weaken the same-Store rejection.

Failure and machine evidence: inject reserve allocation failure and verify pointer/length/capacity/complete values remain; attempt a full push and verify the uninserted POD error payload, existing initialized prefix and single final Store release; pop must shorten the prefix before returning its complete last value. Legacy mutable Store emission already exists in `crates/zil-backend-llvm/src/emit/dynamic_store.rs`; its POD behavior remains to be validated. Run the original positive and these failure/alias controls through native Clang and LLVM API at O0 and O2, including a nested POD Record and a large element near the existing 4096-byte protocol threshold. Confirm the checked negative/out-of-range index trap and unchanged default stack. Treat these as checks, not assumed LLVM or Types outcomes. No hidden heap, RC, lock, global alias table or runtime generation is introduced.

Budget evidence uses the existing targets and one coordinated build window: default N, N−1 and fresh request for each newly charged path, plus old exact Package and G9.3.2 shared controls. Do not raise default work, stack or ABI limits, and do not replace the current shared-window contract. Source, raw/Wire, machine values, failure cleanup and independent two-kernel review are required before parent acceptance.
