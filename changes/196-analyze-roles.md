# 196 Analyze：按实际参数重建联合调用顺序

Analyze 保持自有的 helper 依赖次序、来源传播、图拼接和 BFS 编号实现。来源位只标记实际签名中的最多两个环境参数，普通实参位置不因 F/G 类型声明顺序而改变；工厂结果与未知来源另有位。相同 ClosureId 不合并角色，混合来源不能猜成其中一个角色。公共角色表必须精确覆盖真实参数、严格按位置排序；环境、能力、Hold/Call/write 与清理模式逐角色重建。

旧单角色私有 `Row.calls` 的计数改为有序 `CallEvent`。有限前缀集合保存完整序列，不使用逐角色集合的笛卡尔积；每次静态 child 调用分别建立 child 参数到实际 caller 角色的映射，再拼接该次调用的事件和出口。Flow 的每个事件、边与 Return/Trap 同实际图逐项比较。有限 FnOnce 按每个实际角色最多消费一次；存在可达回边且含任何 FnOnce 角色仍关闭，即使该角色在循环中未被调用。

资源效果逐角色检查联合轨迹中的实际调用存在性，再按那个角色的实参来源投影写上界。第一角色没有事件不会抹掉第二角色的写；Flow 中无返回的可达前缀也参加扫描。Analyze 不调用 Types 或 Verify 的求证函数，也不把传入合同本身作为来源证明。

新角色表、事件复制、child 映射、完整前缀拼接和集合比较均先收费，序列比较按长度和集合查找层数收费，默认 Limits 不增加。首次限定回归发现候选对没有环境参数的普通函数也收取新表费用，导致三个原有精确预算断言失败；已改为这些函数不建立角色表，原断言逐字保持并通过。首次失败与修复分开记录。

测试分为手工 raw TypedIR 的独立 Analyze 检查，以及真实 ZIL source 经 Types、Analyze、raw Verify 和 Wire Verify 的组合检查。原始 source、阶段 IR、合同篡改和实际诊断依命令目录保存；raw 构造不冒充源面能力，当前调用/原生清理和非作者审核仍由 196 整片验收负责。本组件不改变 schema25、公开 ABI、默认额度或 Rust 产品门，也不声明完整 1.4 完成。
