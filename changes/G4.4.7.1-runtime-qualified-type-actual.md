# Runtime qualified Type actual instance keys

The real runtime call `leaf::<Phantom<'s,T,N>>()` fails in Expand before its
CT callback: the generic function instance key sends the complete qualified
Type actual to the ordinary structural renderer, which deliberately rejects
life arguments. The source call itself remains a qualified nominal application;
erasing `'s` or using a generated name as its authority would lose the
caller's lexical class.

For a direct nominal Type actual in a function with an actual source life
scope, first use the existing stored nominal application path. It validates
the original declaration, full ordered Type/Const/Life arguments and bounds,
publishes the joint nominal instance, and returns the physical type name with
the caller's lexical classes. Build the runtime function key from that physical
name plus a length-delimited joint class vector for all qualified Type actuals.
Pass the physical type to ordinary substitution and Copy qualification. Retain
the pre-normalization actual for the runtime CT recipe, whose independent
consumer replays the original Call and parent substitution. This preserves the
actual call anchor and full source identity.

The ordinary closed Type path and its key fees stay unchanged. Compound
qualified Type actuals and unsupported physical borrowed storage continue to
fail closed at their existing checks; this proposal covers direct nominal
Type arguments only. It does not add a public schema, recover life from a
physical name, or grant source borrow/capture qualification.
