# G3.3.1 ambient source annotations

C40 canonicalizes Phantom<'a> and Phantom<'b> separately to the same local
class0 shape, which is correct for transport layout but insufficient to check
`let x:Phantom<'a>=Phantom::<'b>{...}`. The current generic statement/record
rewrite discards the real lexical-class vectors before comparing these two
positions. This is an actual earlier ordinary-source acceptance defect;
M37 did not parse the source, and CT subvalue correction d1b7867 did not cause it.

Check source class constraints while the actual declaration and original full
binder positions are still available, before header/body stored-type erasure.
Private scoped facts carry those classes through source bindings, annotations,
construction, ascription, projections and relevant boundaries. Static result
substitution must use actual formal/argument relationships; a callee's binder
with the same spelling is not the caller's binder. This validation grants no
borrow/Copy/cleanup permission, emits no trusted proof bit, and does not replace
Types or either ordinary kernel. Unsupported missing consumers remain explicit.

Reserve all actual source/fact walks, copies, comparisons, maps and call
substitutions on the current Expand ledger before growth. This repair adds
necessary work to affected stored-life source constraints; exact earlier and
successor request bounds will be reported on their actual inputs. Default
limits, ABI/schema and product gates do not change.

The source inventory includes aggregate methods with their real host generic
scope; full method ordinals and host ordinals have different owners. Static
function lookup excludes methods with the same spelling. Nominal spellings
resolve to actual current AST declarations before class comparison. Unresolved
whole qualified facts, argument structure or type constructors with free source
classes reject explicitly instead of turning unknown information into equality.
Closed nested forall scopes remain distinct from enclosing binders.

A source alias-use defect was also exposed: generic_alias::Visitor::item used
params(item), which intentionally filters life-only functions for specialization.
That filter is inappropriate for lexical alias argument validation. The visitor
now enters the actual item's life parameters and restores the inherited scope;
alias definitions are still resolved in their own original scope. Thus the
same-class Id<Phantom<'a>> case is accepted and the wrong-class neighbor is checked
by the scoped class constraints instead of being rejected as an undeclared name.

Ordinary outer borrow uppers may intersect. They preserve an unambiguous actual
formal-to-argument result map, while multiple distinct uppers remain unknown.
They are not equated by this source check. Persistent classes in actual qualified
input carriers are invariant. Later uses needing an ambient annotation cannot
silently refine an earlier unknown input into a declared class.
