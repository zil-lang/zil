# Reuse unchanged frontend preparation and move owned syntax

Baseline: 1498bfee9098edc686fbd57374e72ced24eaa8c5. Stage 7 diagnosis identifies whole-project Expand/CT/Types work on a private body edit. Fixed Rust 1.99.1 source shows resolver/lowering are eval_always; shared owner inputs and small query projections, rather than caching an entire expanded AST, are the relevant design reference.

This slice eliminates a second owned AST copy when redistributing normalized/specialized project syntax, preserving all existing budget visits, checks, ordering and restoration. Closure inference gains a borrowing result for unchanged programs while retaining its existing owned entry point and all ordered checks. The driver may carry a private immutable preparation result from CT to Types only if inference returned the *identical input* (not merely a transformed result) and the complete evaluated CoreProgram remains exactly equal, including source positions and declarations, under exactly the same Limits. Such a result is a fixed point of the deterministic inference call. Types can reuse that computation; aggregate resolution, actual type checking, Analyze and current independent Verify still run. Changed CT/closure output or limits falls back to ordinary inference. No serialized preparation proof, public wire change, acceptance/ABI/error/budget change is intended.

Scope: zil-expand/src/modules.rs; zil-types inference/program/lib plus private preparation helper and focused tests; driver project/session and focused real-source controls; research tools/results/evidence. Preserve owned raw APIs, and never use the preparation marker as verification authority. It may live only with the immutable raw Core owner and complete current query key.

Validate current scalar/multi-module results, actual closure and CT changes, exact limit mismatch, malformed input/first diagnostic, and a small paired CLI screen. Reuse the prior Stage 7 baseline binary and selected LLVM library. No repeated old full performance matrix. Persistent module/function semantic caching and red-green result projections are future work; this slice does not claim them.
