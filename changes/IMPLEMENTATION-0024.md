# 024 可执行快照使用同一打开句柄和同一字节缓冲

依据主树 `.task/impl/024.md`；源基线 `34d06f0b07aa25c412784e2aa9ddd766d146beff`。第二次完整门的快照 manifest 摘要对应普通 debug 产物，实际复制字节对应另一份 stripped 产物；原始失败及摘要由集成方保留。实际路径替换者尚未确定，本包不据此声称定位了外部环境的具体行为。

原 `host::freeze` 先按路径求摘要，再 `fs::copy` 重新打开同一路径；两次取得的文件对象可能不同。改为只打开一次，由私有 helper 从该 File 获取 metadata/权限，按既有 128 MiB 上限有界读取一次，摘要和目标写入使用同一个 buffer。目标仍执行原有 manifest/库存/字节校验；公开签名、快照格式、队列合同和语言语义不改。此保证针对实际读到的字节一致性，不将普通 File 句柄描述为冻结了外部原地写入的文件系统快照。

新增一个真实文件替换控制：打开 A，随后原子 rename B 覆盖原路径；冻结须保持 A 的内容与权限，原路径 B 不变，篡改目标仍拒绝。原有 28 项测试保留。工具独立 Cargo 的 dev/test 同设 debug=0，集成方另将正式门的临时 strip 构建改为普通 cargo build，避免两种配置反复占用同一常用可执行路径。

作者仅运行工具限定 tests/fmt/clippy，冻结生产提交和小收据后交非作者审核；不自行合入或重跑统一全量门。
