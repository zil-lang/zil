# Independent full CI for the research LLVM combination

The four-TU LLVM candidate (entry-preserving JumpThreading, grouped SSA update, LVI value indexing and post-IPSCCP CFG cleanup) has reproducible bounded component rebuild tools. Its scoped controls and local benchmark identities do not establish that all repository tests pass with that dynamic library. Add a separate `Research LLVM verification` workflow to provide that missing exact-commit validation.

The official `.github/workflows/verify-main.yml` remains unchanged. The new workflow runs only on pushes to `research/incremental-compilation` or explicit `workflow_dispatch`, has its own concurrency/artifact prefix, and permits 90 minutes for SDK preparation, two four-TU rebuilds and the full existing validation sequence. It copies every workspace, reference-only, native API/allocation-failure, Clippy, text-reference and migration command. Original evidence uploads and conditional post-archive cache/native cleanup remain. No suite, compiler option, budget or product gate is reduced.

After the existing hosted-runner disk preparation, `prepare_headers.py` verifies the pinned `tools/llvm/release-linux-x86_64.json` archive and extracts its exact generated headers. The same archive is passed to `tools/llvm/install.py --archive`; no second SDK download occurs. `toolchain_combination/rebuild.py` receives the checked-out repository, official LLVM prefix and exact header prefix, builds both isolated four-TU libraries with jobs=2, and does not build private CLIs or patch the checkout. Official clang/lld stay on PATH; `ZIL_LLVM_LIB_DIR` and `LD_LIBRARY_PATH` select only the candidate library for repository tests in fresh CI target/cache directories.

The normal `check_toolchain.py` report is checked against the actual candidate DSO SHA/path/version and the successful rebuild/native/SDK/header/source receipts before tests can enter. The identity manifest also binds the exact checkout, source patch, four replacement units and official clang/lld hashes. A failed identity gate must fail the job and prevent test results from being attributed to a fallback library. Tests retain their original continue-after-other-failure conditions once this prerequisite succeeds.

An always-run collector preserves generated original/candidate sources, patches, manifests, build logs and receipts, including partial/failed preparations, and immediately uploads them before testing. It excludes SDK archives/header installation, LLVM component archives/objects/DSOs and Cargo target directories. The existing final receipt upload remains. This is correctness and provenance validation; it neither changes the production default toolchain nor constitutes a compilation-speed measurement.

Only small manifest/collector controls and workflow-structure checks run locally. Full workspace validation runs remotely on the exact pushed commit. Failures, missing setup stages and not-run tests remain explicit; a successful earlier official-toolchain run cannot substitute for this candidate run.
