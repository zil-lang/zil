# G4.4.6.2 — 普通泛型宿主仅供真实 CT 静态调用时的后继消费

状态：同步消费者方案经集成方批准，第一版生产已落独树；未取得新真实 Source 通过证据。

## 原因与目标

`ct6-generated-host-member-lives.zil`、`ct6-generic-host-member-lives.zil` 和 `ct6-generic-host-member-life-shadow.zil` 的普通纯静态成员经真实显式 CT 调用返回合格 nominal 值后，Expand 仍拒绝保留下来的泛型宿主方法。本项保留方法 AST 与原始/生成归属，不重新声明其为 CT-only。普通运行时泛型方法资格仍归 G2.4。

## 源码事实

`Engine::with_budget` 对所有泛型宿主先核 binder/字段，再统一拒绝非 Struct/Package 或任何方法。`Engine::run` 不输出未实例化的普通 generic aggregate；真正的运行时名义实例通过 `instantiate_inner` 独立产生。移动定义 guard 而不补定义检查会漏掉未使用的非法方法。

`generic_trait_methods` 只准备/提升 trait 与 impl；其形式参数合并不适用于宿主与成员各自保留完整 Type/Const/Life owner 的 CT scope。普通 `generic_check` 的 life contract 只从单个 Function 取作用域，不能把捕获宿主 life 的方法当成自由函数检查。

CT compiler 的 `ensure_generic_definition` 已有独立 scratch 编译器，按原 member 构造自身抽象作用域、绑定真实宿主作用域并检查整个正文。ordinary 方法现为实际依赖惰性目录，所以本项须对选定宿主的所有真实保留方法补 universal definition 检查，不能只复用一次具体实例成功。

## 拟定实现合同

保留实际成功 CT 请求中的原调用/完整 host 来源事实，而非 `allowed` 标志、名字集合、Span 或 producer hash。真实调用须先经 Frozen 源消费、CT Verify 和求值成功；未发生该 host 调用的无关 `#(7)` 不产生其资格。

Expand 在模块正常化与别名/模板改写之前，以真实 aligned declaration origin 和实际完整 host AST 请求同步源语义消费。消费者重取 immutable 原/生成 catalog 中的宿主，独立核生成 Emit 链、声明/成员结构位置与完整保留 AST 对应，验证真实调用确实归该 host，并逐所有真实方法进行两 owner 的符号定义检查。此调用执行实际求证；不新增公开布尔权限字段或 Wire 证书。内部保存已完成检查的结构对应仅作本轮缓存，不能从缓存免除新的输入对应检查。

完成该检查的 host 仅作为未实例化的 CT namespace 模板保留。任何真正运行时名义实例化/普通方法调用仍有显式拒门。非 Struct、receiver、资源/指针/外部效果以及不在现 CT 纯值域的正文均保留拒绝。当前不能独证的 materialized method 改写形状明确拒绝，不以 header 相同代替整个正文。

批准的接口是现 `RuntimeCt` 的同步 `check_static_host(definition, actual_item, remaining) -> CompileResult<()>`。normalizer 在克隆之前保存实际原 input 的私有借用对应；adapter 重放同一正常化并逐整个 AST 比较，再把原 input 交给 driver。Engine 定义 guard 即时调用这个实际消费者，没有公开资格位或许可 set。没有 hook 的原路径继续拒绝。额外别名/binder 改写若无法完整重放明确拒绝。

请求内调用记录在独立 `extend_calls`、CT Verify 与 VM 全部成功后才构造，移动保留完整 raw program、完整 call/scope 事实及 FrozenInvocationContext；后续 fresh 消费重走实际 Call、原 callee 的真正 lexical parent、原 host 全 Type/Const/Life 向量、生成 catalog 与原 namespace identity。保留的 raw 表不作为源证明。当前带成员删除的 host namespace 独立完整正文对应尚未实现，明确拒绝。

独审发现“整请求成功 + 静态 IR Call 存在”不能证明分支中的调用执行过。修订为 VM 的实际完成回执：仅启用观察的入口在进入 callee 前保存真实 caller/block/instruction/result/callee，callee 正常 Return 后转入已完成向量；整请求失败不返回回执。Unit 调用由 instruction ordinal 精确区分；循环/递归的多次动态完成保留独立事件。私有 source call 新增 execution `(block,instruction)`，实际 emit 时绑定，prune 精确改 block、删除不可达行。独立源消费者重走 frozen Call/全 actual/真实 callee 后，必须匹配该实际 opcode 和完成回执，禁止 None/任一同 callee 回退，拒绝重复 source occurrence。

观察栈和完成向量每次真实 backing 增长预付完整新分配与旧项搬移，分配后释放旧 backing；VM 外层 cleanup 的成功 keep 包含仍持有的回执 capacity。旧 evaluator 不产生观察向量及其费用。所有 D AST 克隆/完整比较按共享余额逐 node/text 预付；生成 span remap 使用逐操作计费的新可选入口，旧 remap API 不改变。失败扫描不能先遍历后总扣。单源 candidate 导流只选择处理管线，不制造方法资格。

16dec 的独立静审随分支保存于 `docs/validation/G4.4.6.2-16dec-independent-review.json`；其执行证据仅引用集成方拥有的 11 项 9 过 / 2 失败日志，审核者未执行测试。后续窄修：Call 已完整核真实 callee、可见性、arity/参数后，仅实际 Unit 返回允许无 result；非 Unit 与其他指令的 result presence 不变。原源 origins 缺失的普通 entry 延后一次冻结至 fresh source calls 已知，真实调用仅触发 required capture，最后仍由 Frozen/Verify/真实 VM 完成独核；无 calls 回到原冻结，已有 origins/runtime 顺序不变，不吞错误或重复扫描。VM root return 先 drop pending/frame backing 再释放账本，再分配 query receipt，避免实际内存重叠漏峰值。

所有原真实方法先统一登记，再逐方法新建 scratch 两 owner 的符号检查；非函数成员、receiver、未知 attributes、声明体、where/contract 明确拒绝。Type binder 遮蔽按 member 覆盖 host，与现 Const/Life 路径一致，owner 和完整 ordinal 不合并。真正运行时拒门覆盖 `instantiate_inner` 与 `stored_nominal`，包括仅有 life 参数的 Host。

## 最近正反例与资源

原三个 fixture 不删方法、不改 marker，覆盖原源、真实 Emit 生成、host/member life shadow。增加同形错误 host、宿主/成员向量错配、保留正文篡改、错误生成事件与未用非法兄弟定义。原 ordinary generic-host 的 plain `7` / 无关 `#(7)` 对照、真正 runtime Host 值/方法使用仍拒绝。

所有源遍历、完整 AST 比较/克隆、实际调用账本及容器 backing 预付共享剩余额度，失败不留下可复用资格。先限定 no-link 检查，再申请真实 Source/独立 Verify/native 与 N/N-1/恢复窗口。首失败和每次实际 freeze 按原样记录；接口/schema 通过不宣称本项完成。
