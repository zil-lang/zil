# 0122 — 纯 CT 临时声明与运行时析构隔离

## 问题与范围

从已恢复的 draft22 `810346b9c8c7b99dac042c0edc3511904a9cd132` 重新实施。旧114提交不可恢复，旧执行记录不作为本次通过证据。

CT 查询只选择可达函数，却复制了全程序聚合声明中的运行时 teardown 名称。未选中的 Drop 函数不在查询签名表中，于是无关的运行时资源也使纯 Copy 查询报 E-DROP-BINDING。允许纯 CT 与运行时资源共存是现有能力的组合，不授予 CT 资源执行权限。

## 变更

在完整原始声明的有界 preflight 之后，为临时查询复制类型形状并清除副本的 teardown 关联。源 CoreProgram、运行时 Drop 函数、普通 Types/Analyze/Verify 和实际清理不变。独立 verify_ct_program 仍核查每个查询指令和类型，拒绝资源、地址和外部调用；不能因为无 teardown 名称就接受资源操作。

接受性变化明确限于原本错误拒绝的纯查询。包含非法运行时正文的程序可能在原先 CT 假错误被移除后报告其实际运行时类型错误。默认预算和原声明 preflight 保持，包括原 teardown 名称及全部字段类型收费；不会先擦除原声明再计费。schema/wire17、ABI、公开合同、产品门保持。

## 验证

先保留未修改生产代码的实际失败。修复后验证枚举/记录纯查询和有可观察 Drop 的普通返回、拥有 FnOnce、跨模块组合在 O0/O2 的源码至机器结果；CT 资源与 FFI 仍精确拒绝，非法运行时 Drop 仍拒绝。直接 CT collector 测试原声明预算，已有 CT raw/wire/预算回归伴随运行。限定验证通过后由非作者审核精确提交，不自行合入、不冒称全语言或四目标达成。
