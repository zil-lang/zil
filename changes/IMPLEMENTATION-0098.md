# 098：动态字节存储进入 Roam 差分探索

## 问题与范围

现有长期 profile 只有会话热冷一致性、有限标量和资源闭包；动态 ByteBuffer
尚无可生成、可保存和可缩减的独立语义对拍。本片新增工具本地
`zil-byte-buffer-native/1`，不修改生产语义、公共 IR、ABI、预算或锁文件。

每个有界程序由同一具体操作序列分别驱动三种实现：Rust `Vec<u8>` 加逻辑
容量模型、独立 C 有界数组参考、真实 ZIL 动态存储。C 与 ZIL 各在 O0/O2
实际构建运行，逐动作比较成功标志、长度、容量、全部已初始化字节和退出。
参考 C 不接受或抄写模型预期，不是生产 C 后端或安全证明。

## 工具合同与最近反例

- 每程序最多 16 操作，容量 0..64，字节 0..255；每 case 最多 8 程序。
- 操作为 reserve(-1..64)、push、受动态范围检查保护的 fill、唯一转交 relay
  和消费后重建 reset；正常及提前返回分别保留。
- 最近反例包括空/满 push、负 reserve、较小 reserve 不缩容、空范围、无效
  范围不写、填充后再增长，以及 relay/reset 后的完整可观察状态。
- 分配器耗尽不是随机模型输入；自然分配失败导致对拍不通过，不能当成功。
  未安装分配器跟踪，不声称核验 free 次数、泄漏或 OOM 恢复。
- `bytes-omit-push` 仅改变 ZIL 测试发射器，Rust/C 独立预期保持。它证明
  检测与队列通路，必须标注 controlled mutation，不能统计成自然生产缺陷。
- 沿用六态、受监督进程组、工具身份、durable ACK、原件不变、同 property
  重放和有限缩减。已有三个 profile 的合同及 O0 执行选择不改变。
