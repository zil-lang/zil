# 161：嵌套闭包的逐层捕获与责任转交

基线：`e9a604c80d56027a5fb6c28bcb8b58f9c9e84a7b`。规范依据：`ZIL-MODES`、`ZIL-CLEANUP`、第 9.1–9.3 节。本文是实现支持范围变更，不改写终态语义。

## 问题与实现

全源约束推断目前在遇到第二层闭包时返回 Unsupported；局部环境推断只读取内部函数字面量签名，不访问其自由路径。只删除前一个拒绝会漏掉必须穿过外层的捕获，不能作为实现。

1. 全源 Solver 保留独立的闭包 owner、参数、结果变量和词法作用域，开放已有递归遍历；每个表达式仍按原预算计费。
2. 环境 InferBuilder 在同一有限约束图中递归访问内部正文，独立保存/恢复返回上下文、参数作用域和嵌套 move 边界。内部自由路径按源码首次使用顺序进入每层捕获。内部 move 复制 Copy 值时，内部写入不错误升级成对外层原位置的写；拥有载体转移则使持有它的外层具有 FnOnce 要求。
3. 生成真实内部环境时，外层 Managed 捕获仍指向真实隐藏字段。通过现有 `TakeCapture` 转交、通过 `DescribeCapture` 借入；不能把激活内的描述代理当成拥有者，也不能复制头。外层借入 Copy 位置上的 move 快照从真实借入位置读取。
4. 实际环境创建、调用、清理继续经过现有 Types → Analyze → 独立 Verify → LLVM。没有新 opcode、schema、隐式分配、RC 或环境擦除；内部环境不作为 Copy 函数指针发射。

## 交付边界与最近反例

支持有限 Copy 签名、激活内资源/Package 拥有捕获、跨层 Copy/Desc/Managed 路径，以及嵌套同步调用。闭包值作为另一个环境字段、一般闭包返回闭包、拥有错误载荷和动态闭包容器不在本变更中；遇到现有不支持形状必须仍显式拒绝。

必须测试：两级/三级推断、跨层变量和参数遮蔽；move 快照与 nonmove 回写的区别；外层 FnOnce 转移唯一责任；内部不调用仍析构；正常/错误出口析构顺序；转移后再用和外层重复调用拒绝；薄函数指针捕获拒绝；受限预算失败；raw/wire 伪造外层 Fn 或重复资源捕获被独立 Verify 拒绝。所有新结果绑定实际提交，旧159运行数字不重标。
