# Captured Fixed: source producer preconditions

This is a proposal, not an admission change. It binds source318875a45 and
public42 source43881a096 separately. Exact hashes and tool identities are in
[the receipt](../docs/validation/G3.3.2-source-preconditions.json).

## Preserved source boundaries

The small sources are in
[fixed-context-producer](../tests/language-readiness/terminal/342/fixed-context-producer).
`fn/fnmut/fnonce-input-capture.zil` take `left:&Tag<'s>` with a real
`p:&'s i64` field and capture that actual function input. Their annotated
closure parameter also selects `Tag<'s>`. The FnMut body writes a counter;
the FnOnce body transfers an actual resource capture. No local phantom is the
closure's grounding. Each wrong-class neighbor retains the same capture but
calls it with a distinct declared `right:&Tag<'b>` instead of `left`.

Both exact baselines reject all six at Expand, E-UNSUPPORTED:
`annotated closure retained classes need their genuine enclosing definition context`.
This is the existing guard, not proof that the wrong-class call was independently
checked. Fixed candidates never reach Types. Ordinary-address versions verify;
318 Types artifacts independently show actual kinds Fn, FnMut and FnOnce and
storage_life None. The no-closure qualified-input source also verifies.

`qualified-full-nominal-order-control.zil` verifies with
`Tag<T:Copy,#N:usize,life s>` instantiated as `[i64,3usize,'s]`: the nominal
life formal's full ordinal is2, while the enclosing life-only function's s is
full ordinal0. These must not be conflated. The mixed Type/life function
candidate stops earlier at the scoped instance-identity fence; the mixed
Type/Const/life function candidate stops at the existing function-life profile
fence. Neither is claimed as a reached Fixed consumer or a permanent negative.

## Minimal actionable producer patch request for root's interface

1. Retain a paid private lexical scope ledger before header specialization and
   before instantiate_inner filters params. Bind the real original declaration
   Origin plus member/binder-site ancestry to its original full kind vector.
   A lifetime lookup must return `(scope owner, original full ordinal)` alongside
   the internal compact index. Keep the compact-to-full map; do not rename an
   integer and assume it became an ordinal. Extend transformed-expression
   lineage through cloning/lifting/substitution; do not recover it by Span or
   generated spelling. The life-only free-function Definition profile is the
   nearest implementable source slice; hosts/nested/generated/mixed unsupported
   contexts must not get guessed ancestry.
2. At actual specialization, before substitute_item, preserve the complete
   original ordered Type/Const/Life meaning. Non-life actuals are available in
   the current substitution, but life is a retained definition binder, not an
   explicit element of the filtered function-instantiation argument vector.
   Do not pretend the filtered arguments are complete or stamp a caller's life
   from a name. Root must define Definition/Instantiated treatment of retained
   life/callable binders. Scoped Type actuals need an ambient-class map: ordinary
   Type bytes cannot distinguish alpha-equivalent View<'a>/View<'b>.
3. While storage_header and stored_types::contract still have occurrences,
   preserve full-ordinal-to-enclosing-header StorageBinder/class selections.
   For the basic candidate this is scope apply/s/fullordinal0 -> actual
   Parameter0/[Pointee]/class0 -> Fixed0. It is different from the input's outer
   Address borrow row. That elided outer borrow has no generic full ordinal:
   retain its actual enclosing HeaderBorrow/OuterAddress selection, or derive
   its captured Fixed solely from the actual capture. Do not invent a generic
   parameter or equate it to s. A complete closure relation may contain this
   anonymous captured borrow Fixed as well as the named qualified class Fixed.
   Keep every per-use stored_nominal class map at the real parameter/binding/
   constructor use, without placing caller bindings in the canonical shape cache.
4. At the actual closure node, emit only root-published untrusted context data.
   Select actual outer Parameter or binding node plus pattern position, and
   distinguish OuterAddress from qualified class `(type path, local class)`.
   Whole-Binding capture selection is insufficient. Types reconciles these
   selections with actual inferred minimal capture slots/modes and installs a
   complete Parameter/Capture/Result relation in joint canonical order. Existing
   common40 class rows are SignatureLifeClass selectors, never old RetainedClass
   bindings or fabricated physical fields. Nested callable Invocation is a
   barrier; only its free Fixed domain can be associated.
5. At Core lowering, bind the row to the newly minted real containing function
   and closure expression ids using the maintained lineage. Include owner,
   full ordinals/kinds, complete instance meaning and scoped actuals in semantic
   Core/interface/cache keys, independently of node relocation. Per-environment
   Fixed equations must still come from each MakeClosure's actual captured
   values in both kernels; the context table is not a proof flag. Only
   Invocation is fresh at each call, and the actual receiver chooses Fixed.

All discovery, vectors, paths/text, maps, comparisons, cloned trees, scope/parent
links and context substitutions must prepay the same live request ledger before
growth, with independent count/depth/cycle limits. No new default quota.

## Consumer handoff and explicit boundary

The parallel g4 review agrees that capture-grounded runtime relations can reuse
existing ClosureDefinition.storage_life, entry TypedFunction.storage_life and
MakeClosure captures, provided new capture-aware validators/EnvFacts are real.
A helper's role.life must not overwrite a global closure definition. Preserving
full source identity through Typed/Wire/interface/cache is a separate root
publication decision: existing ClosureId and source_fingerprint alone do not
carry it. Core-only data cannot silently claim that full typed identity exists.

The first candidate is anchored by an actual qualified input capture. Context
without physical grounding, or a local phantom class with no Typed creation
binding, remains unsupported. This proposal does not specify an authorized
public schema revision or implement any class/loan/cleanup permission.
