# 203 证据按内容去重

本次工具只整理已经实际产生的证据，不执行 ZIL、不改变任何原测试结论，
也不把组件作者结果替代独立审核或根验收。CLI05、CLI06、原 Fail 和
NotRun 保持各自的来源、命令和路径。

`tools/language/203/compact_evidence.py` 流式读取已冻结原 ZIP 或证据目录，
按 SHA256 在 `records/sha256/` 只保存一份相同内容。
`INDEX.json` 保留组件、原输入、每个原路径、大小、摘要及恢复路径；
各原包的 MANIFEST 本体也逐字收录。已经去重的输入会展开其逻辑文件，
不会把原来的压缩包或内容对象作为一层不可恢复的嵌套。

工具先核原 ZIP 大小及 SHA，再核每个文件及整个读取期的输入身份。
产物使用全新 `.partial`，核全部成员 CRC/SHA、索引引用、路径、大小及
50,000,000 字节上限后，以不覆盖既有文件的方式发布。原包不修改。
可单独 `verify`，或 `restore` 到全新目录；恢复先完整核验，再逐文件
排他创建，支持只选择一个组件。无须展开全部重复 IR 即可核验。

原二进制 Wire（含故意畸形或磁盘耗尽留下的空输入）属于语义证据。
目录中的 ELF/PE/对象等执行产物只保留路径、大小和摘要。源码、IR、
日志及空文件原样保留；不保存原 ZIP 的容器编码、时间戳或执行权限。

## 实际验证

最终小夹具 6/0，原命令及输出在
`run-logs/203-evidence-compact/tool-tests02`：

- 相同内容跨历史包去重，前后 Fail/Pass 文件仍可逐字恢复。
- 原 ZIP 摘要不符、输入未冻结、危险路径和对象篡改均拒绝发布或恢复。
- 既有目标文件及恢复目录拒绝覆盖。
- Wire、空文件和原始源码字节保留，执行产物只登记摘要。
- 已去重包展开后仍保留原逻辑路径及排除摘要，可按组件恢复。

上述是归档工具测试，不计入语言测试或独立语言审核。
独审者仅只读审查工具逻辑，没有重报作者的 6 项执行。
