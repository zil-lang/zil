# G4.4 完整剩余 CT/Type 接受性接续

依据 `_zil_design.md` §16.1/16.7、CT4/CT5；基线 `fd261b22c8a05c5cd1e7bc9cc05d91eeb0f12c95`。本提案先于生产改动记录接受性差异，不改语言规则、默认预算、runtime ABI 或正式产品门。

目前跨 factory 重构仅允许 CtTy::Scalar 字段。扩展到同一实际纯值类型的 Tuple、固定 Array、闭合 Record/Enum 时，仍保留双方原 schema、完整实参及 source binding；按真实字段序恰一次 ExtractField 后 MakeRecord，不转换任何字段位模式。两边各自有界递归证明所有叶是纯标量，拒绝 Type/Syntax/Text/List/反射/资源权限载荷。Record/Enum 图不能靠递归无限证明，循环或超深均明确失败；逐次扫描、递归及类型复制预付同请求余额。最近反例为相同布局不同 nominal、含 Type 的 CT-only 字段和内部有借用权限的值。原 life 端点独立核保持。

带 life Type 构造目前在 compiler_metadata_type_value、CT Verify 的 BorrowedStorage、VM 构造与值分类，以及 TypeApply 的 lifetime 无操作数表示处明确未接通。新增入口必须指向已认证实际联合图，独立核从真实声明验证完整 Type/Const/Lifetime 参数、合法 owner 祖先、Fixed ambient 引用与原 ordinal，VM 只复制通过该核的图；裸图、哈希或 whole-artifact equality 均不能独自授信。不以整数常量模拟 life，不新建空 wrapper 或自由名称。公共操作码/codec/authority 接口先由 root 审阅单写，再迁移生产和消费。

ambient Type 实参必须在联合图中重定位全部 owner 与 ambient class，保留 TypeArgument 的共享类关系；仅在真实 metadata TypeArgument 中开放 BorrowedStorage，不能变成运行时 Address holder。泛型 host/member/generated 必须把实际包围完整实例和生成路径带至 FrozenInvocationContext，而非删去 generic_host 检查或沿 span/name 猜归属。运行时泛型体的 CT 求值在实际参数就绪后进行，定义期符号 bound 义务仍独立检查。

每条新增能力分别需要真实 Source/负控、独立 raw/Wire 拒绝与四余额边界，适用时提供 O0/O2 完整机器结果。未执行的夹具不报 Pass；B 的非标量值复制不自动证明 A/C/D/E。

泛型宿主的静态 CT-only 成员即使自身参数为空，仍是依赖实际宿主的泛型定义，须在宿主真实 Type/Const/Life 符号环境中检查；不得在无宿主实例时作为 concrete free function 入队。宿主和成员同名 binder 按真实最近声明遮蔽，各自完整 ordinal 不拼接。宿主 Const 仅作为有真实定义/ordinal/domain 的符号参数，不使用数值 stand-in。符号 CT 表达式还必须检查其实际调用依赖体，不能只接受签名并丢弃未核队列。
