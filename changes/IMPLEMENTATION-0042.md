# 042 — 独占地址和修改外部状态的闭包

## 当前规范与接受范围

本切片落实 `_zil_design.md` 第 4、9、15 章已有的一层共享/独占地址语义。地址目标限于有限 Copy 值；默认闭包修改外部 Value 时保存其真实独占地址。字段和索引来源仍保守提升到整对象，不声称已经支持不交字段权限、资源责任、FnOnce、dyn、捕获环境逃逸或挂起。

## 公共 IR 与消费者

保留 `BorrowLocal` 的共享含义，增加 `BorrowLocalMut { local }`、`ReborrowAddress { address, mutable }`、`WriteAddress { address, value }` 和 `TakeLocal { local }`。最后一项转交非 Copy 地址或含独占捕获环境并清除源位置初始化；原始 `Load` 不授予可复制的独占资格。字段/索引投影保留地址访问模式。指令进入独立指纹与 wire 编码；集成者统一发布 schema/wire 5 和附件索引。

Types 只构造未核操作。Analyze 产生初始化及来源候选；Verify 独立重建来源、有限窗口父子关系、carrier 活跃性和转交状态，不能调用 Types/Analyze 求证函数。LLVM 从已核 LIR 产生真实栈地址、薄指针和间接 load/store；不添加 `noalias`、堆盒、RC、世代或全局表。CT 对地址操作继续明确拒绝。

## 最近反例和迁移

同源双独占参数、活子窗口期间的父写/读、共享地址升级、源位置转交后使用、含独占捕获环境复制、局部存储逃逸、伪造 raw IR 与来源声明必须被拒绝。原先明确 Unsupported 的安全源码获得贯通支持；旧 schema 字节的迁移由集成者统一版本发布，不悄悄复用旧缓存。

`*p += value` 保留同一个访问资格；稳定局部地址名不引入冻结父窗口的隐式子借用。复杂地址表达式先求值一次并保存，再做读取、右侧求值和写入。没有引入两阶段借用。闭包的参数/结果仍限 Copy 值；raw IR 中地址闭包参数会在独立定义核验中明确 Unsupported，不能借此绕过捕获窗口检查。

默认捕获已有地址依实际读取/修改需求重借；`move` 捕获独占地址转交地址资格。含独占地址的环境要求可变调用位，即使其方法体只读取目标也保守采用 FnMut。重借循环若在有限静态 loan 图产生自依赖则明确拒绝。地址嵌套、捕获地址变量本身的重绑定、环境逃逸与不交字段优化仍未开放。

## 验证与目标判断

实际限定命令、源码/机器结果和反例随 `evidence/impl/042/` 提交。这里不预填成绩。

源码贯通测试检查 `-O0` 与 `clang -O2` 的实际运行值；`examples/impl042/closure.rs` 是相同外部状态行为的惯用 Rust 对照，仅比较行为，不据此声称成本优势。原始失败运行采用独立目录保留，不覆盖。候选 001 的库测试暴露旧 Fn 捕获独占地址的 Unsupported 断言；新核验拒绝为 SafeReject / E-VERIFY-CLOSURE-CALL，该断言仅按准确拒绝码迁移，其余关闭的资源和调用种类保持原边界。

Rust 同类安全仍未覆盖完整资源/并发模型；本切片补上独占窗口和非 Copy 地址转交的实际反例。机器表示维持内联与薄地址，运行/内存的配对产品成本尚未测量。外部状态闭包减少手工环境表达，但完整工程演进优势尚未证明。编译成本与至少一项实质突破仍按既有 product-gates 条件未证明，不以通过案例数替代判断。
