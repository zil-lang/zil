# 101：把有限写效果转移编译为参数事实图

## 实际问题与新命题

097/100减少了反序调用传播的重复扫描，但仍会在每个函数摘要增长后重新解释
函数体。当前Types资源写效果的局部Origin计算不读取待求Writes；摘要仅在
已解析调用的参数写判断中被读取，不影响调用返回的Origin、作用域或循环
Origin闭包。由此可检验更强的有限命题：每个函数的转移是直接写种子与
固定参数来源关系作用于callee写事实的并。它可编译为有限布尔可达图。

先保留原Scan结构及最多两轮原扫描；已经稳定即返回。仍未稳定才进入明确
`#[cold] #[inline(never)]`的慢路径，提取每个函数的局部关系，保留
`(FunctionId, parameter_index)`身份，再传播新事实。慢路径不反复解释AST。
原先已算出的摘要与剩余额度一同传入。没有依赖索引、模式字段或摘要跟踪器
进入早收敛Scan；不按案例名或输入规模选择算法。

## 接受性和预算

普通无限额成功结果保持同一Writes映射，包括空条目；语言接受集合、接口、
机器ABI、Database、Analyze、Verify及默认限额不变。当前求解器保守处理
共享条件、未知调用、外部资源声明和可见闭包体的方式原样保持。

新图的节点、边、提取、存储、队列及传播均在对应分配/工作前计费；总额度
包含前两轮。有限预算下的ResourceLimit阈值允许按实际算法工作改变，需要
明确N/N−1和失败恢复。不能耗尽后给出不完整成功，也不能提高默认上限。
早收敛程序仍沿原预算/诊断路径。
