# 0065 具体环境 helper 的源码与 Analyze

## 先行变更提案

本片消费 0064 的统一公共表示；在原 §9 的 Fn/FnMut/FnOnce 合同内接通一个静态具体环境参数的同步非逃逸 helper。泛型正文先依明确 callable bound 作符号类型检查，展开保留模板；Types 在实参的环境身份和签名确定后实例化普通函数。实例位于定义模块，使用其原名字/导入/可见性上下文，调用者消费结构化接口，不把私有正文内联进调用点。

具体参数分别为 Closure、Address<Closure>。借入调用沿真实环境地址执行，不读取/复制整个拥有环境。环境按值实参使用已有准备临时，全部参数成功后才提交；后续 `?` 失败按真实准备顺序逆序清理。拥有环境未调用仍清理，消费调用后不能重调；共享/独占调用的每次后态、Hold/Call/写效果及 Cleanup 由 Analyze 和独立 Verify 分别重建。

范围为一个 callable 类型参数、有限 Copy 的 callback 参数和结果、同步非逃逸有限调用轨迹。一般递归/循环调用合同、返回/保存环境、动态擦除、多环境组合不在本片范围，不以未知空效果放行。不修改产品性能门或默认预算。

最近反例包括未约束的 generic 调用、错模式借入、拥有环境移动后复用、重复消费、后续参数失败、过期捕获来源、篡改 Call/Hold/Cleanup 与借入环境 Drop。真实命令、受测身份和首个失败保留在本单证据中。

## 实现与边界

泛型模板保留一个 `F: Fn/FnMut/FnOnce(...) -> ...` 及一个 `F`、`&F` 或 `&mut F` 参数。调用点约束回调的有限 Copy 签名，得到具体环境 id 后，按定义模块的名字、导入和可见性上下文生成普通函数实例；同一模板和环境 id 复用实例。Types 输出静态捕获上界与有限 0/1/2 次轨迹，Analyze 用自己的环境来源传播和 CFG 拓扑路径合并重建，Verify 由 0066 独立实现。借入参数通过真实地址调用，不 LoadAddress 成拥有环境副本。

bound 的能力适配为实际 Fn 可请求 Fn/FnMut/FnOnce，实际 FnMut 可请求 FnMut/FnOnce，实际 FnOnce 只请求 FnOnce。声明中的参数绑定仍不可写；本片按值 FnMut 明确 Unsupported，调用 FnMut 使用 `&mut F`，并不暗改参数为 var。共享借入请求 FnMut、借入请求 FnOnce 为模式错误。回调参数和结果、helper 结果限有限 Copy（包括已有 Copy 错误联合）；额外 helper 参数支持有限 Copy、Managed 和完整 Package，其他 Address/Desc 参数尚无封闭效果合同，明确拒绝。

具体 helper 接口的类型指纹包括环境 id、实际 kind、捕获布局、参数和结果；所有环境定义完成后才计算公开接口指纹。相同 id 的捕获类型变化不能与旧 ABI 指纹碰撞。泛型符号检查通过已知 nominal 声明识别具体资源字段，同时对未知 F 的成员保持拒绝。模板使用共享只读快照，实例化前按完整嵌套正文、类型和文本预留深拷贝工作；上下文表和 callable 元数据也先预留完整形状，未提高默认预算。

源面近邻覆盖：拥有环境借入两次后复用；FnMut 外部可写局部/地址经按值 FnOnce helper 零次或一次后重新访问目标；实际 Fn 拥有 Managed，经 `&mut F` 请求 FnMut 两次后继续调用；有限 Copy 错误第一次/第二次调用路径；拥有 callback 与较早 give 实参准备后较晚 `?` 失败；跨模块具体接口及布局指纹；未约束调用、重复消费、消费后复用、活动捕获目标冲突、超过两次调用和额外借入参数拒绝。原生次数、Drop 顺序和机器布局的执行证据由 0064 另记，不能将本片 Verify 成功当作原生执行。

## 与 Rust 四目标的关系

本片让真实同步 helper 消费具体环境及公开安全合同，推进资源安全和可组合表达；不使用隐式 Box、RC、锁或私有正文内联替代接口。实例缓存和共享模板减少重复生成及深拷贝，但这里只核对正确性与限额，没有端到端编译、运行或内存性能比较，不能宣称性能突破。一般逃逸/保存回调、递归和循环合同、多环境泛型、拥有 callback 参数与结果、拥有错误载荷仍未完成；本片不替代 B0 或完整语言终态验收。

## 公开调用边界的窄复核修正

独立审核要求将 helper 调用者对旧私有效果摘要的获取也完全移出 callable 分支。callback 合同已覆盖唯一允许的对外借入效果；其他参数为有限 Copy、Managed give 或完整 Package，返回有限 Copy，原责任转交规则覆盖其消费。Analyze 对有 callable 合同的 Call 只读取公开 envelope，不获取、不遍历该 helper 的 legacy 私有 summary；普通函数保持既有摘要替换。这不放宽额外 Address/Desc 参数，也不省略对 helper 正文与公开声明的一致性检查。旧 9455a50 作者记录保留，修正另行定向复测。

## 跨模块同名实例的身份修正

独立审核在两个模块均声明 `run<F>`、同一 closure 分别传给两个定义时发现全局 Typed 名重复。原实例缓存已按定义 ModuleId、NodeId 和 ClosureId 区分，调用也使用不同 FunctionId，但 Typed 标签错误地复用了模块局部的 `run::<env0>`。现在生成全局标签显式包含这三个定义/环境身份；公开 ScalarFunction 与已核合同的名字仍为模块局部实例名，继续按 FunctionId 指向实现，不将定义正文复制到调用者。

最近源例包含 main、a、b 三模块各自的私有 `local`，a/b 的同名 `run` 接收同一个 closure，并重复调用 a。两种模块输入顺序均须独立 Verify 通过；a/b 保持相同局部公开名字、不同实现 FunctionId、各一个实例合同且签名一致。此修正不更改公共 schema、接口编码、实例缓存键或语言支持边界。原 reviewer 的精确 fb8be7e 失败保留，新候选另行定向复测与独审。
