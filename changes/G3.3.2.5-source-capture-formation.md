# Source capture relation formation

The runtime consumer from G3.3.2 accepts only independently checked existing Typed capture contracts. G3.3.2.5 forms those contracts from root's Core-only original-source context rows. Root's producer has a consumed elaboration ledger; Types adds its own actual creator/expression consumption and checks real header positions and inferred capture LocalIds. No Source name, Span or structurally equal type supplies a binding.

A source signature contains only Parameter/Result rows. Source Fixed ordinals map through their original full generic lifetime ordinal and exact creator header input selection. Captures are inferred first, including the real physical order and borrowing mode. A shared capture of an input Address keeps the creator header variable; an actual borrowed local contributes an anonymous environment Fixed without inventing an original generic parameter. Only capture-established classes may satisfy the proposed free Fixed domain in this finite slice. Named and anonymous classes are then canonicalized together in Parameter/Capture/Result order, with a separate dense Invocation domain. The exact resulting contract is attached to both actual closure entry and definition; independent kernels still prove MakeClosure origins, actual calls, targets, loans and cleanup.

Original free-function Definition with life-only generic kinds is the first Source scope. Type/Const instances, member/generated/nested scopes, aliases without a reconstructed actual input source and general F-bound context bridges remain explicit Unsupported until implemented. Direct creator parameters are the initial capture-source path. Source F bounds cannot be replaced with the closure contract: independent local Fixed numbers lose the full helper-scope/header bridge. That separate producer/consumer obligation is assigned outside this slice.

The current runtime profile is scalar result, scalar or shared scalar/qualified Record/Tuple capture pointees. Existing genuine resource-consuming Once source remains a control: any unsupported owning-resource mixture is reported at its actual layer, not turned into a success or a purported semantic error. Types may reuse its existing class-free owning-resource checks without granting the still-missing runtime integration. No implicit environment allocation, new public representation or broader Source scope is introduced. Source identity can be erased after authentic bounded formation here because the related semantic/incremental cache profiles remain closed; the general full-vector identity work is still incomplete.

New context snapshots and ordered lookups are reserved before allocation/clone and charged from the active Types/inference ledger. Empty tables have no extra scans or charges. Existing no-context consumers and their budget thresholds stay on their original paths. Evidence will distinguish actual Source, raw malformed Core, complete Typed relations, independent kernel/Wire handoff and native execution; models alone do not establish Source admission.
