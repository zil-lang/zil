# 126 有限无环 helper 的完整调用序列

## 问题和语义依据

普通事件批处理 `f(n)+f(n+1)+f(n+2)` 在 Types 被实现中的两次上限拒绝。当前规范 9.3 要求真实次数、顺序和各出口的调用义务，没有规定 Fn/FnMut 最多两次。本单允许有限无环 helper 的更长实际调用序列；FnOnce 仍至多一次，循环、helper 转发和环境逃逸不在范围内。

## 表示、独立核验与资源边界

每个 helper 只有一个具体 callable 参数、一个声明的调用种类，每条真实回调指令都必须与该种类相等。因此在内部用调用次数表示相同种类的序列是精确编码：`(kind, n, exit)` 唯一恢复 `n` 个 kind 和 Return/Trap；不会合并不同种类或出口。公共 `CallableTrace` 仍导出完整向量，schema/wire 17 不变。

Types 保留独立的逐路径有界遍历，携带次数与当前活动块集合，发现回边明确 Unsupported。Analyze 保留自己的来源检查和拓扑传播，传播次数集合。Verify 从已独立核对的函数图重建拓扑、实际指令和次数集合，在传播前拒绝不同调用种类；不调用 Types/Analyze 的函数或复用其结论。次数不截断，FnOnce 的多次使用拒绝。不同路径只有在同次数、同出口时才合并，公共排序等同相同 kind 向量的字典序。

内部次数复制/集合传播按实际元素收费；分支的活动块复制沿用完整计费。公共向量在分配前按完整长度收费，原始合同在指纹前按已有 max_nodes 和工作额度检查。移除二次/六轨迹的偶然形状上限，不替换成另一任意调用次数。默认额度、产品门不变。预算数值可能改变，因为私有算法实际工作改变；接受有限预算改善或提前 ResourceLimit，绝不额度不足后截断成功。Types 仍可能枚举重复语法路径，现有工作额度负责有界退出；本单不声称所有 CFG 的渐近复杂度改善。

## 验收和交付

三次、四次、较长 Fn/FnMut 源程序；不同分支、错误 Return 和 Trap 的完整轨迹；跨模块实际事件累加和资源清理，O0/O2 原生；最近 FnOnce 重复、循环、重复关闭反例；不经过生产求证器的 raw/wire 完整合同、缩短/伪造/重复轨迹和预算拒绝；Types/Analyze/Verify 实际 N/N−1 与失败后重试。旧 impl065 第三次 Unsupported 与 Verify 第三次 scope 测试转为正例及遗漏调用的拒绝，不删除安全反例。

本单源于 ZUI 实际消费者，生产修改仅各阶段的私有 helpers 模块。无新表面语法、拥有布局、隐式 RC/锁/堆分配、ABI 或外部权限变更。独立审核须绑定精确提交，作者不自行验收。

## 集成后发现的额度分类修正（先于修改）

root复核独审的raw255控制发现：只把max_nodes从255降至254，同一合法合同由Pass变成SafeReject。这是资源额度不足，按当前规范§10/§16.1/§20.1必须为ResourceLimit，不能称合同不安全。此前独审记录了实际类别但漏追规范分类，保留原件并用补充审核更正。

将本函数的trace条数、单条调用长度及既有field_count这三个可配置节点额度门统一改为`limit`；真实kind、顺序、出口或权限不符仍SafeReject。收费与指纹前检查顺序不变，默认额度和接受集合不变。限定验证涵盖降低/恢复同一合法输入的额度、未重绑指纹的大claim，以及充足额度下真实篡改继续拒绝。图编译计时窗口结束后再构建和复核，不污染冻结性能样本。
