# G3.3.10 unbounded-by-profile callable roles

Proposal: lift the finite two-role/two-callable-generic implementation ceiling
for existing synchronous helper contracts. Actual request limits still bound
all tables, keys, events, source traversals and child substitutions. The public
ordered Vec<CallableRole> and joint Finite/Flow language remain unchanged.
Other profile restrictions, mode, source, permission and cleanup proofs remain.

Each compiler layer independently reconstructs a singleton-or-mixed provenance
lattice. A role carries its arbitrary actual inventory ordinal, separate from
factory/unknown/local-construction classifications. Distinct supplied roles
join to mixed and are never recovered as a selected role. A mixed value retains
the fact that a supplied role participated, including in aggregate/capture use
restrictions. No consumer accepts legal multi-role unions, so full powersets are
unnecessary. Old two-role classifications will be checked exhaustively against
their existing bit-mask predicates; role3+ cannot overlap classification bits.

Bindings retain the inline two-slot path and use a compiler-internal shared
immutable vector only for further generic ordinals. Prepay physical growth,
copy-on-write and variable key comparisons before container operations. Origins
use a wider fixed-size scalar; any necessary extra physical table charge is
explicit and does not raise default limits. Preserve existing charge paths where
the physical representation remains identical. New scan/copy/key work uses the
same current request allowance before allocation or expansion.

Required real Source evidence uses an existing test target, at least three F
binders, joint order/child substitutions, role3/4 swap, duplicate Once consumption,
actual same-object alias and unused malformed declarations. Raw/Wire forged
events must reject independently. This proposal is implementation scope, not
independent acceptance or a claim to complete G3.3.
