# 0052：资源闭包的独立来源与责任核

状态：施工。依据 `_zil_design.md` §2、§3、§7、§9；公共操作合同见 0053。

Analyze 与 Verify 各自从实际 CFG 重建资源闭包来源、存活与消费，不共享求证算法，不信任候选元数据。拥有环境禁止复制，Managed 捕获逐字段持责；描述捕获仅延续实际来源。Fn 读取拥有字段不升级 Consume，写拥有字段需要 FnMut 或 Consume；经借入 Desc 写目标不改变环境调用种类。Consume 入口可移出字段，正常返回由 CallClosureOnce 按固定捕获顺序清理剩余字段。

本片只接有限 Copy 参数/返回、局部环境和已有有限 Copy 资源 payload。闭包聚合/返回、嵌套拥有环境、可恢复错误展开仍不宣称支持。原有 Address Hold 规则与资源描述分别检查。

反例覆盖未初始化或已消费的环境、Managed/拥有环境复制、重复字段移出、漏责任、同一 SSA 重复消费、旧描述及错误调用种类。限定测试与实际源码整合分别记录，不能用 raw IR 用例代替真实源码贯通。生产候选交非作者审，集成与正式全门由 root 执行。

## 已落地的核与边界

Verify 在资源责任格中增加不可复制环境载体和入口 Managed 捕获字段，来源分为实际局部头、普通参数、拥有捕获和借入捕获。TakeCapture 清字段责任；Fn/FnMut 必须在正常出口保持拥有字段，FnOnce 的剩余字段由已核调用操作交给后端固定顺序清理。没有 Managed 字段的 FnOnce 仍是不可重复消费的载体。资源和环境局部共用逆成功初始化顺序检查。

Analyze 使用另一套稀疏命名 cell、显式生命周期集合和独立 CFG 求解实现诊断。它不消费 Verify 的事实，也不填充可信责任证书。二者分别计算描述的后续使用和实际来源，分别从 WriteDesc、直接调用参数替换以及描述闭包调用推导写效果固定点。纯读 helper 保持 owned Fn；直接或传递写 owned 捕获要求可写入口；外部 Desc 目标写保持 Fn。

原有 Address Hold/独占窗口仍单独核验，新增 actual-local Shared 和 consuming Once 调用都进入该通道。ReadCapture 不得复制 Managed，Load 不得复制拥有或 consuming 环境。源码接入后，部分旧资源反例会在 Analyze 更早拒绝；源码测试不能硬要求必须晚到 Verify，Verify 本身由绕过 Analyze 的 raw 候选测试独立检查。

有限边界：闭包显式参数/返回仍为有限 Copy；不支持资源/描述逃逸返回、嵌套拥有环境和一般持久保存。多个 Desc 捕获的来源与调用写效果采用保守并集，未宣称逐字段最精确的高阶摘要。Trap 仍为 abort，不声称 unwind 或语言级错误传播完成。新的效果固定点受确定性工作预算约束，预算失败不是通过；未做新的编译性能对比，不声称优于 Rust。
