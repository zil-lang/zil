# Byte-compatible SHA-256 with runtime hardware dispatch

Stage13 baseline 4cb3687127a1980b2ace965af9fdc8c8e5de93c5 / production 743c9699e. Machine action hashing is already buffered but the shared SHA-256 compression still runs a handwritten scalar implementation. Adopt the fixed RustCrypto sha2 0.11.1 crate with default-features=false through its safe Digest API. Preserve the private Sha256 new/update/Clone/finish interface, every bounded compiler fingerprint byte and Hasher::finish convention, all input encodings, budget checks and cache/verification authority. No new hash algorithm or shortened identity is introduced.

RustCrypto owns the architecture-specific unsafe intrinsics and runtime feature checks inside the external dependency. ZIL adds no unsafe code and retains workspace/crate forbid(unsafe_code). On x86/x86_64 the default implementation detects sha and sse4.1 at runtime and selects SHA-NI; unavailable features use the upstream portable software backend. AArch64 uses the analogous runtime check. Other documented platform backends remain upstream's responsibility. Do not require target-cpu=native or force hardware features in production. The fixed source audit records dispatch, safe public API, license, dependency scope and the exact release archive checksum; this is source inspection, not a new independent security audit of RustCrypto.

Keep the former scalar implementation byte-for-byte as a cfg(test)-only oracle. Add a small streaming boundary and cloned-stream/observational finish differential control, retaining existing independently generated known-answer, buffered-key/reset and complete-record compatibility tests. Root also runs one software-path control using RUSTFLAGS='--cfg sha2_backend="soft"'. This flag selects software compression without changing caller interfaces or hash bytes; no benchmark number is inferred from instruction support.

stage8_frontend_audit owns zil-base/src/sha256.rs, the test-only scalar reference, necessary lib.rs documentation/module declaration, this proposal/task append and compact fixed-source audit evidence. Root alone changes Cargo.toml/Cargo.lock and delivery/offline dependency documentation and runs builds/tests/timing. The registry dependency is permitted by the existing internal/path dependency checker; do not alter the internal dependency policy or unsafe lint. Normal compiler identity changes still isolate produced caches even though the SHA-256 algorithm and bytes remain compatible.

Compatibility is scoped to existing bounded compiler inputs and the FIPS SHA-256 message-length domain (less than 2^64 bits). The old private implementation explicitly wrapped its length arithmetic; upstream Digest uses ordinary counters/multiplication and can panic with Rust overflow checks on a cumulatively enormous stream at or beyond 2^61 bytes. This proposal does not claim that out-of-domain public FingerprintBuilder streams retain the old wrapping behavior. No such input is reachable through current compiler budgets, and no new limit or acceptance shortcut is added. This extreme API distinction is recorded rather than hidden by an infeasible huge-stream test.
