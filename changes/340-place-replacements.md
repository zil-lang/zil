This stage links the preserved affine-inventory prototypes to real initialization, ownership, actual roots and machine cleanup. It does not treat publication or the prototypes as implementation completion.

A reservation selects actual mutable Local storage or an existing actual mutable Address plus the shared bounded Field/Variant/ErrorArm path. A complete finite Type walk rejects crossing Managed payloads, implicit views or external storage boundaries. The endpoint must be initialized and owning; every required variant/error ancestor must be active. Preparing retains the real base SSA value and its parent authority until Commit/Abort even when ordinary SSA last use would end earlier. It is a position pin rather than an ordinary exclusive endpoint view: legal read-old-to-prepare-new and ending shared RHS windows remain possible. Pins block intersecting writes/takes/drop, storage/tag changes and Store relocation; disjoint real intervals remain usable. A pin cannot manufacture mutable authority or extend an owner lifetime.

Both kernels independently reconstruct the static ticket definition, exact active activation sets, actual selected roots/parents and ordinary callback effects. Reserve is not a ValueId. Exact joins require equal active sets; one static reserve may execute in a loop again only after its previous activation settles. Missing, stale, duplicate, double-commit/abort and live-ticket normal exits reject. Prepared tickets cannot be silently saved across Task suspension. The actual addressed base/ancestors participate in liveness until settlement; a future Commit containing only ReservationId must not release them early.

Commit checks the complete exact new owner and Hold before changing the old position. New Hold cannot borrow the replaced payload; live intersecting child/call/result loans must have ended. All path/tag/initialization and mutable-parent conditions are revalidated or retained by the actual protected epoch. The old owning endpoint is cleaned exactly once in ordinary declaration order, then the new complete value is published with no recoverable failure between drop and store. Existing parent partial-initialization flags, untouched siblings and lexical cleanup age remain. A destructor panic follows fixed abort semantics. Abort leaves the old initialized owner in place and settles only that activation.

Source lowering evaluates the target once before RHS. It must reserve the base/path directly, not manufacture a live exclusive endpoint temporary that would prohibit RHS read-old. Stable repeated source reads may reuse the real prepared base only where ordinary expression evaluation is unchanged; calls/dynamic indices retain their written evaluation counts. Current ticket path rejects self-take as an RHS rather than pretending to restore a value already transferred; the older direct self-transfer path remains separate. Recoverable RHS error, return/break/continue and nested statement cleanup must abort the exact exiting tickets while retaining outer preparations, and clean only actually prepared new responsibilities. Owner rollback does not undo already-performed RHS side effects.

Tickets remain compile-time state: Reserve/Abort need no runtime wrapper, pointer slot or extra exclusive address. The static definition supplies Commit with the already-evaluated base and validated fixed path; the kernels establish its dominance and retained lifetime.
