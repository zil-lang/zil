# 173：组合消费者暴露的已支持错误载荷上下文漏项

三线隔离合并的7b11de8编译器真实运行组合消费者时，先发现消费者把既有 unsafe 语句误写为初始化表达式；4c81b3e只修正样例语法。随后同一编译器在 `collection.insert` 的普通函数签名处给出 Types/Unsupported，尚未进入 Verify。原两个失败及源码摘要分别保留在173组合预检收据。

原因是普通函数签名的 `inference::context_signature` 白名单遗漏既有166的 `errors::owned`，尽管具体类型约束图、普通ABI、Verify与清理都已有该有限合同。一个无关的保存闭包触发项目上下文推导，就会把已有 `Item!void` 普通helper误关掉。

补入同一 `errors::owned` 精确谓词，保留完整类型预收费/深度检查，不开放直接Managed错误载荷、错误联合捕获、非Copy闭包参数、嵌套拥有联合或新的返回模式。组合消费者继续包含真实普通helper、Store失败返回、错误传播和无关的自含保存回调；有限源码/原生与最近捕获反例另作回归和非作者检查。

修复推导后，main/O0 的首个0元素真实执行已得到预期 HZCBA/exit0。随后测试驱动误把共享allocator shim在零分配时没有注册报告的空stderr当成JSON，消费预检03失败。173测试shim现在在main前注册同一个报告函数，从而真实报告零分配；保留旧142源码，不能以空stderr合成零计数。
