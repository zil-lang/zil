# 163 有限资源方法与拥有接收者

依据：`_zil_design.md` 的 ZIL-MODES、ZIL-RECEIVER、ZIL-ACCESS 与第9章闭包规则。
生产基线：`e9a604c80d56027a5fb6c28bcb8b58f9c9e84a7b`；本片在派工提交 `19e5fa4188d0b65929d640618f3d2a098aee9473` 上实施。

## 问题与变更

普通 Builder 已有部分 resource/Package 方法路径，但闭包源面约束及闭包环境推断只识别 Copy Record；ByteBuffer 的既有资源类别也没有进入实例方法查找。因而已有 Desc、give 和实际清理协议不能一致用于方法形式，资源方法写效果也必须计入闭包调用能力。

本片复用现有直接 Call ABI、资源描述/转交指令和独立 Verify，贯通有限资源 Desc 方法、显式 give 消费方法、ByteBuffer 方法及适用 Package 值方法。接收者先于普通参数且仅求值一次；既有责任先暂存，普通参数的传播失败清理已取得的责任。资源 self 默认 Desc，give self 的既有载体必须显式 give；Package self 仍是普通不可 Copy Value 移动。

闭包只按实际签名与可核验的资源写效果选择 Fn/FnMut/FnOnce；读写或消费不得因点号调用漏记。跨模块查找保持公共可见性及实际 FunctionId，私有方法不能由返回值或别名泄漏。ByteBuffer 无用户字段，不能开放头地址、伪造字段或获得额外存储权限。

ByteBuffer 本片只解析本模块声明的 inherent 方法；它没有用户定义模块，不据此建立跨模块扩展方法搜索。跨模块用户 resource/Package 则由原有精确定义模块路径查找公开方法。

Package 方法消费进入现有逐出口槽状态分析：所有可达出口都完整补回时保留 FnMut，传播错误先于补回时只能 FnOnce。资源方法效果包含接收者位置0及后续参数，工作队列记录真实方法依赖；资源的 callable 数据字段保持字段优先及只读接收者效果。

## 保留边界

施工159的原始 `trait Read { fn read(self: &Self) ... }` / resource C 探针涉及真实头地址，仍保留 Unsupported；本片不把 `&Self` 偷换成 Desc。一般 resource/package 头地址需要独立来源、搬迁窗口、调用ABI与 Verify 扩展，不能仅删除前端拒绝。动态分派、任意扩展候选搜索、泛型资源布局与嵌套拥有聚合不在本片。

## 验证约定

交付源码正反例及 O0/O2 真实执行，覆盖借入描述、消费后失效、双消费、共享窗口与写/转交冲突、跨模块权限、闭包的真实写入/唯一清理、待调用参数错误清理。原 &Self 探针单列并保留预期。工具链重新安装为 Rust 1.99.1 / Clang 17.0.6；旧159的 Clang 17.0.0 测量不作为本片结果。

## 四目标边界

安全沿用独立 Verify、无新增隐式 GC/RC/Box；运行路径是已有直接调用和责任协议，不声称实测成本优势。表达增量是现有资源操作可用于普通方法与保存回调。编译性能及 Rust 产品门不在本片，测试数量不代表完整语言或产品突破。
