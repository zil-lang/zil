# Same-thread registration and Task pending close

The public42 interface is now published. This consumer replaces the private synchronous-only cleanup assumption for canonical direct Managed AsyncRegistration slots constructed inside Suspend workers. It adds private request/drain callbacks to actual Verify-derived owner records; only Ready removes the record. A pending automatic cleanup saves its continuation and returns Pending. Await completion saves the moved result before a separate child-close continuation, so Pending close cannot re-run the child or discard the result.

A separately allocated stable record stores the concrete closure and per-site provider functions. OPEN admits one callback, CLOSING rejects every later callback while keeping raw userdata alive. Same-thread state is written before entering request_close. Reentrant close while a callback/provider/cleanup is active returns Pending. Only poll_drain=1 (the unsafe provider no-future promise, covering queued/pre-trampoline/rejected entries and all backend reads) and no active admitted callback permit environment cleanup. finish checks CLOSED before freeing. Other provider statuses trap without free. Failed install returns null only under the existing synchronous no-future promise; allocation failure destroys the moved environment once.

No cross-thread, borrowed frame-port, owning Sum/task-input failure drain, or general scheduler/waker service is admitted by this slice. Tests must distinguish real host queue progress from a synthetic Pending around synchronous close. Source admission and ordinary registration authorization are independently implemented by sibling G8.4.1.2 and must be composed before end-to-end claims.
