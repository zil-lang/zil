# 增量 O2 分区前收缩受限 checked-add 链

状态：研究v3已完成独立432次编译及900次成对原生运行确认，允许继续可选生产整合。随后v4只增加两个必要条件门；其完整变换计划、模型和原首错等价已做模型及真实编译输入对照，最终生产身份和完整Rust矩阵另行确认。当前不宣布普通O2默认推广或通用编译突破。

真实长函数中，每个有检查的加法都引入一个成功延续块。LLVM虽保留共享trap，仍反复处理长串checked-add及控制流。候选在`O2 && incremental_o2`时、现有有限标量求值和分区之前，将严格匹配的连续检查收缩为一次有检查的加法。它保持原标量求值界限，不增加div/rem支持，也不移除溢出检查。

只匹配同宽8/16/32/64位、相同signed/unsigned intrinsic、共享精确trap、单入口成功延续、常数同向且总和可表示的链。中间值不得额外使用，不跨普通调用/内存/效果，也不接受有循环的函数。对于定义的输入，同向部分和单调，因此最终加法通过恰好等价于所有原检查通过；总和越界、混合方向和不符合形状的路径保留原代码。Phi终点保留最后检查块及其原边，仅收缩前缀。所有非空建议在变动前核验完整原Module，失败时保留原模型及原首错；当前独立Program Verify和逐单元机器预检照常执行，包括缓存命中。

原v1的递归Val扫描风险和Phi终点重复扫描问题在v2修复，失败及修复前证据保留。优化自身的Val扫描有128深度、100万节点界限，超限只跳过优化，不改变语言预算或诊断。v3先以无分配必要条件跳过少于两个潜在检查块的函数。真实输入计数又发现普通Call前缀的假阳性，以及互斥分支的两个检查不能相接；v4分别收紧浅层prefix条件，并在已建立的Checks/name索引上查询是否存在任何符合kind/intrinsic/trap/source条件的相邻检查对，避免必无计划时继续构建uses/CFG数据。其它资格、符号、总和、循环和Phi判断保持原逻辑。branch仍构造Checks及name索引，不能称零分配或已证明净时间收益。

v3隔离BUILD为ea978730，ELF为5c955131；基线是84f6/fa79，双方共用7b5 LLVM。432次编译与1296次原生功能观察全部有效，固定六族总体耗时比0.830655，收益主要来自512-body的冷/编辑耗时约降至22%。其余30格描述GM为1.003959，全表17个不利点、两个不利区间仍保留。后续同窗900次原生运行直接比较两版本quality策略，默认/closed总体比0.969717/0.987730；不同机器码仅在长体两个合同出现，其余10对ELF逐字相同。完整数值、限制和原始证据见[STAGE6-RESULTS](../docs/research/incremental-compilation/STAGE6-RESULTS.md)。

生产动作协议须与旧对象缓存隔离，保持普通O2路径和原声明/导入合同。官方与定制LLVM各68项限定测试通过；新的真实源控制确认同向加法顺序交换全命中、会产生中间溢出的修改重建并保留trap、恢复命中以及拒绝不覆盖已有产物。原缓存断言保持，没有因优化而放宽。效果及函数地址控制和最终生产CLI仍按各自实际收据列出。新生产源码、BUILD、实际库加载、限定测试、非作者审核、双LLVM远程验证及完整generated/opaque/real/Rust和运行质量确认分别留证，不能将研究身份倒改为生产身份。

本改动不改变源码接受性、公共schema、ABI、导出合同、语言预算、错误/清理顺序或产品门槛。更一般的affine add/mul区间收缩和poison精化仍是独立静态研究，不属于此实现。
