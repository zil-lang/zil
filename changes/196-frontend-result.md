# 196 多 callable 角色：前端与 Types 作者交付

实现候选为 `f360417bf3de9c5a87164f2ffd87a5f414be5710`，公共表示为 schema 25。本文只记录本作者写集及实际受测结果；主树正式验收、规范 registry、完整语言和产品门由集成方另行记录。

## 本次行为

Expand 区分最多两个 callable 泛型类型与最多两个实际环境参数；同 F 可以对应两个运行时环境，F/G 可以拥有各自的直接 bound，已有一个普通 Copy T 的专门化保留。泛型声明顺序中的类型位置不等于运行时参数位置；重复 F 必须绑定同一实际 ClosureId，两个签名相同而来源不同的闭包表达式不能冒充同一 F。

Types 以固定两个槽的有序实际类型向量作为实例身份，角色来源按实际参数分别传播。每个静态子 helper 调用建立自己的角色映射，所以 `(a,b)` 与 `(b,a)` 两处调用可以共享具体类型实例而保持不同事件顺序。公开合同只有一份联合有限路径或 Flow 图，不把分支路径拆成两个独立轨迹，也不把调用序列压成计数。

第二角色与第一角色同样参与模式、capture envelope、写投影、Cleanup 和预算；普通 Builder 及后续 Analyze/Verify 保留实际来源、权限和责任检查。原 05 的相交独占实参、原 11 的第二角色 Desc 写与活跃共享视图，以及真正非 Copy FnOnce 环境的重复转交均保持 SafeReject。

闭包内部创建两个局部闭包再调用 helper 的实际组合曾暴露捕获扫描缺口，现按每个角色绑定签名和传递模式。捕获扫描中的私有函数签名不成为公开闭包身份。签名复制、角色行及查找先计费，普通地址资格没有放宽。

197 的 `State<T,F>` 按精确块合流，已与本片组合验证。单角色 State 保留；多拥有 State 角色、循环中含 FnOnce 角色、异步/并发、动态擦除和新增逃逸能力仍不在本片开放范围内。

联合角色预算实际临界值为 Types **1181**、Analyze **2555**、Verify **3834**；新增 nested 捕获绑定的 Types 临界值为 **652**。每项实际验证了 N 成功、N−1 ResourceLimit、fresh N 再次成功。默认预算未改；数字只是这份固定输入的测量，不是全语言复杂度上界。

四模块消费者位于 `examples/mainline/callback_roles196`。同一个工厂建立两个各自拥有 Ticket 和 ByteBuffer 的环境 A/B；helper 的两个静态子调用依次映射 `(A,B)`、`(B,A)`，每个活跃循环输出 `ABBA`，每次还核对各环境自己的缓冲长度。显式可写 slice 与普通 Copy Tag 在同一程序组合。输入 `0/1/2/3/7` 分别覆盖零次、一轮、continue、两轮及 break 后三轮，非法输入和 EOF 在建立环境之前退出。

独立 oracle 显式列出角色序列并分别累加 A/B 容量，核对每个实际分配位置的失败前缀、最后一个分配之后的无失败控制、反向局部清理 `ba`、`live=0` 与 `frees=allocated`。Win64 探针还要求 `bad_operations=0`。正常执行使用未经改写的 ZIL 编译产物；C 探针只负责分配观察与故障注入，不替代语言实现。

## 证据与身份

`evidence/impl/196/frontend/SUMMARY.json` 给出作者受测范围；`SOURCE.json` 记录实际源树与 CLI 身份；`FILES.json` 记录归档和外部收据摘要。`runs.tar.gz` 收录原始命令、源输入、诊断、阶段 IR、raw/Wire 候选和运行输出，并附逐文件清单。可执行程序、对象文件及库文件不进入证据归档；它们的摘要仍保留在原命令和构建收据中。

原 12 份预检源输入保持，原 09 只捕获 Copy `i32`，因此复制成两个 FnOnce 实参是原结构 Copy 规则的正控制。前置 Unsupported 不能证明重复 Move 已被安全核拒绝；实际非 Copy 负例另行提供。首轮 17/4、新 nested 输入首轮 0/1 及修复后的成功都保留，未被覆盖。

候选提交包含主树已发布的规范增补，但其 `data/normative-inputs.json` 仍是上一阶段冻结 registry。SOURCE 记录实际文件摘要与旧 registry 的区别，不声称作者候选已通过正式 handoff；集成方在最终 registry 提交上另跑组合回归，不追改本轮旧收据。
