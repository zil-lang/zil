# 022 混合捕获的独立模型与 Rust 行为对照

该片不改语言或编译器，只验证 020 新增能力。独立 Python 整数模型和等价 Rust 程序使用同一输入，ZIL 经完整管线分别执行 O0/O2；校验实际 typed/LLVM 中的地址与捕获操作。模型不调用 ZIL 编译器求值，Rust 只作为外部行为对照，不进入安全核。

固定八组正常输入、两组源变异控制和三组最近拒绝，记录真实命令、输出、源码与可执行摘要。变异仅改变 ZIL 发射的算术，模型和 Rust 原件不变，必须实际执行并被发现。最近拒绝核对 ZIL verify 的 E-BORROW-CONFLICT、Rust 对应 E0506/E0597，不接受任意失败。所有输入在 i64 范围内，不以两语言不同溢出模式制造不等价比较。

成功样本在记录真实可执行摘要和观察后删除三个临时native文件；保留可重建源、模型、命令、LLVM与结果。失败原件保留。避免为有限行为对照在日常包中重复保存Rust和ZIL二进制。

配对程序验证：创建时快照、共享地址值进入环境、地址绑定随后改写不改变已有捕获、闭包复制，以及最后使用后恢复写入。结果比较不计时，不能作为运行性能、编译性能或完整表达优势证据。八组输入是有限域回归，不代表完整借用安全证明。

首次限定运行保留了两个夹具问题：独立裸块不在当前ZIL语法内，改成两边共同的`if true`作用域；先写left再通过已改绑address读取right的顺序被ZIL接受，但Rust报告E0506，因此不满足本片“两边可运行”的配对前提。共同样本将这两条独立更新交换为先完成address最后使用，再写left；模型不变，首次失败不覆盖。原始顺序作为待核对的局部精度差异保留，不据此声明安全证明或产品突破。独审另指出Python优化模式会移除assert，入口现明确拒绝该模式。
