# G1.3.9: owning replacement through real nonlocal positions

Baseline fd261b22 retains the accepted G1.3.4–8 behavior. Complete Package
replacement is currently restricted to one exact body-owned local or one Direct
mutable helper input; other complete endpoints reject even though leaf Commit
already has actual capture, Store, retirement, loan and pin consumers.

Proposed extension admits complete finite Package through actual exclusive
captured addresses and actual borrowed Store elements. Multiple ordinary helper
inputs may coexist when each actual target and simultaneous argument window is
independently checked. The actual owning leaf's provenance is transferred from
the fully staged RHS; no fresh privilege follows from a complete shell, address,
capture identity, parameter index, same Type or may-Commit effect. Existing must
facts remain limited to accepted Direct Unit shape. Borrowed Store replacement
retains its actual complete prefix and invalidates old element descriptions.

Closest controls are a closure replacing *captured_target, a helper called with
one actual Store element, and independent same-Type mutable inputs. Neighbors
retain old Desc after Commit, duplicate exclusive parent, mutate a pinned parent
while preparing RHS, return without Abort, or fail after a prepared owned child.
Source, independently checked raw/Wire and actual machine old-drop/store/failure
traces must establish each newly admitted path. Any shape lacking those consumers
remains unimplemented and cannot be recorded as parent completion.

No public representation, ABI, error/cleanup order, default budget or gate
change. New walks and collections are prepaid. Captures/Store authority comes
from each kernel's actual origins and loan state, separately from endpoint
qualification. Broader Sum/multiple-owning-leaf transfer will be documented here
before implementation if the existing private responsibility representation can
express it; it is not granted by this proposal's shape checks.

The same private representation can preserve multiple direct Managed<CopyRecord>
Package leaves: each existing field debt remains live, each RHS field birth is
read separately, and all old fields clean before whole-value store. The proposed
shape extension admits one or more such leaves with scalar companions; multi-leaf
helpers export may facts only. Complete local Enum arms similarly may contain
multiple direct canonical Managed leaves because the existing actual tagged
Content already records separate children. No nested Package/Store/callable leaf
qualification follows from this extension. The corresponding positive and
nearest independent provenance/partial-cleanup controls are required.

Nonlocal Enum admission uses a distinct private tagged-content may summary.
Unlike leaf Birth rows, this summary preserves actual possible variants and the
separate origins of each staged child. Ordinary calls substitute each actual
root and origin, merge possible committed contents with old contents, and revoke
old tag observations. No path-sensitive or must-Commit Fresh claim is exported.
Both kernels independently derive this summary from actual Commit/CFG; no public
schema or producer proof is consumed. Complete body-local Enum behavior remains
definite. Initial nonlocal tagged endpoints are exact whole Parameter/Capture
addresses, finite Copy results and already admitted complete scalar/Managed
companions. A missing actual child, partial old shell, stale Desc/tag or unpaired
activation is still rejected. Dynamic Store Enum and deep nonlocal Sum endpoints
require their own actual element/deep-content consumers before admission.

Further private consumers: a helper may receive a canonical Store of the same
admitted Package endpoint and borrow its actual element for complete replacement.
Both kernels retain the actual Store parent/invalidation and initialized prefix;
this does not admit capturing an owned Store or erase its canonical definition.
The same tagged-content representation admits several direct Managed children
per local/nonlocal Enum arm; each remains distinct and the machine uses the
existing actual-tag teardown before one full store. These shapes export may
facts only. Singleton loops retain prior logical fees, charging only additional
leaf iterations beyond the old single-leaf operations.

Nested ordinary Package endpoints retain each existing direct child shell debt
and enumerate each actual Managed leaf by its complete Field path. Fully staged
RHS leaf provenance is copied by that path; a nested child is never flattened
into a single Fresh leaf or a second debt. Local definite publication synchronizes
actual Product and optional tagged fact trees. Nonlocal helpers conservatively
merge each actual leaf after root substitution, keeping caller cleanup age and
all old child obligations. Shape admission and old cleanup recurse only through
already admitted ordinary Package/Managed<CopyRecord>/scalar nodes; borrowed
fields, callable/Store leaves and custom whole teardown are not inferred. The
original singleton lane retains its prior work path. Nested Source, independently
checked raw/Wire, old child/leaf description, partial child and machine cleanup
controls are required before claiming this combination.

The existing checked public callable roles and invocation traces identify a
concrete callback environment without a new public replacement schema. At a
public helper call, each kernel selects only roles actually possibly invoked,
then substitutes the caller's real capture mapping into that callback body's
independently solved replacement effects. Helper-private replacement summaries
do not cross this boundary. Missing invocations have no effects; repeated calls
and cyclic traces retain conservative may effects and never grant must-Commit.
Explicit callback argument destinations or owning RHS arguments still require
an actual argument mapping, which current CallEvent does not supply. Closure
receiver address ancestry must name the environment shell independently of its
captured pointees, with captured leaf loans kept live and checked separately.
Positive Source, old-Desc rejection, no-call/repeat controls and raw/Wire
retirement corruption checks are required for this public role consumer.

Ordinary replacement helpers may also return already admitted finite owning
values. The helper's returned responsibility remains independent of the borrowed
destination and uses the existing create/give, actual return, caller cleanup and
error-arm checks. Result admission may contain canonical Managed records,
ordinary Package/Tuple/Enum/ErrorUnion trees and canonical Store values, while
borrows and callable/code carriers remain excluded. Captured/public callback
entries retain their existing Copy-result boundary. Non-Unit results export
may-Commit only; returning an owned value cannot make the destination Fresh.
True Source controls must observe both destination and returned value cleanup,
owning error/Abort paths and an incoming leaf masquerading as create.

Complete whole-root Tuple and ErrorUnion endpoints use the existing ordinary
Sum ownership trees and tagged replacement ledger. They do not add deep Place
selection or callback-parameter/capture eligibility. Both old and staged trees
must be complete, actual leaf origins are preserved, and publication revokes
old tag observations. Ordinary helper effects remain may-only. Machine cleanup
uses the existing tag-aware ordinary Sum drop plan before the one full store.
Finite canonical record and Store leaves remain subject to their existing
independent qualification; new Store element/capture shapes are not inferred.
Whole-root Source, stale descriptions/partial contents, Abort and exact native
old/new cleanup order are required before claiming this combination.

Whole canonical Store replacement is a separate Managed endpoint. The existing
canonical element and complete-prefix admission remains unchanged. Only an
actual whole local or ordinary mutable parameter may select this endpoint;
capture, callback-input, nested-field and Store-element selections remain
closed. Retirement additionally invalidates every old element description from
the actual Store parent family, including when an ordinary helper commits.
The existing canonical Store drop helper destroys the old initialized prefix
before one full header store. Source must cover local/helper publication,
prepared populated Store cleanup on Abort, old element descriptions, distinct
Store survival and ordinary give-result provenance.
