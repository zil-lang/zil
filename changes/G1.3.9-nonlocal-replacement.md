# G1.3.9: owning replacement through real nonlocal positions

Baseline fd261b22 retains the accepted G1.3.4–8 behavior. Complete Package
replacement is currently restricted to one exact body-owned local or one Direct
mutable helper input; other complete endpoints reject even though leaf Commit
already has actual capture, Store, retirement, loan and pin consumers.

Proposed extension admits complete finite Package through actual exclusive
captured addresses and actual borrowed Store elements. Multiple ordinary helper
inputs may coexist when each actual target and simultaneous argument window is
independently checked. The actual owning leaf's provenance is transferred from
the fully staged RHS; no fresh privilege follows from a complete shell, address,
capture identity, parameter index, same Type or may-Commit effect. Existing must
facts remain limited to accepted Direct Unit shape. Borrowed Store replacement
retains its actual complete prefix and invalidates old element descriptions.

Closest controls are a closure replacing *captured_target, a helper called with
one actual Store element, and independent same-Type mutable inputs. Neighbors
retain old Desc after Commit, duplicate exclusive parent, mutate a pinned parent
while preparing RHS, return without Abort, or fail after a prepared owned child.
Source, independently checked raw/Wire and actual machine old-drop/store/failure
traces must establish each newly admitted path. Any shape lacking those consumers
remains unimplemented and cannot be recorded as parent completion.

No public representation, ABI, error/cleanup order, default budget or gate
change. New walks and collections are prepaid. Captures/Store authority comes
from each kernel's actual origins and loan state, separately from endpoint
qualification. Broader Sum/multiple-owning-leaf transfer will be documented here
before implementation if the existing private responsibility representation can
express it; it is not granted by this proposal's shape checks.
