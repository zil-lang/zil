# O2 中提前求值已知实参的有限标量叶函数

状态：v3 获准进入显式 `--incremental-o2` 的生产确认阶段，尚未完成最终生产验收。固定 432 请求窗口的候选/基线耗时几何平均比为 0.925389，暖请求为 0.999047；动态输入的六个暖单元点估计全部不利。18 个动态输入单元共有三个不利置信区间，其中一个是暖请求：branch closed 为 1.067735；另外两个是 512-body default early edit 和 2048-branch closed cold。不能称所有无折叠场景都变快。原 v1、v2 的通用推广均为 NoGo；v2 总体为 0.939693，暖请求为 1.027148，18 个动态输入单元中 15 个不利，全部旧结果与反例保留。

目标是减少 LLVM 重复处理已知结果调用的成本。固定 Rust 对照的实际 MIR 仍保留这些调用，优化后的 LLVM IR 才消除它们；本提案不将提前求值冒称为 Rust 默认 MIR 行为。

生产候选只在 `O2 && incremental_o2` 的机器模型分区前运行。普通 O2 和 O0 完全不调用新 pass。受测 432 请求各臂均显式开启该参数，其算法路径保持；不会把研究中未开启参数的常规 O2 效果外推为生产效果。只对已知整数或 bool 实参、匹配 ABI、无环境的源码叶函数进行有界求值。只替换调用的结果表达式，保留实参求值、控制流、规范定义、地址、导出与现有核验。内存操作、普通嵌套调用、未知值、循环、poison/undef、到达的溢出或 trap 均不折叠。每个叶函数最多 32 块、128 指令、16 参数；每次请求最多执行 100 万步求值。这些是优化自身的界限，不替换或提高语言预算。

v2 先只读原模型，按需缓存叶函数资格并生成替换建议。没有建议时不增加完整模型预检；有建议时，必须先验证完整原模型，成功后才统一修改。失败时丢弃全部建议，保留原模型、原首错和原后端错误路径。现有逐单元核验保持执行，缓存命中不授予安全资格。

v3 在此基础上跳过没有符合来源条件的直接源码调用的函数；检查请求步数耗尽后才做该调用者筛选。未知 intrinsic 实参在构造临时聚合类型前退出。没有新增 LLVM pass 或声明精简，也没有扩大求值范围。正式研究源码 `a9c6810487d13da503f4333465f85e4067b12fa96f5fafbbd890d6006f9e887b`、BUILD `61e18e0bd653e0412a81375a7776fabe24930530a1e890555e731a34f14c30ae` 与 ELF `477fde33ac68ece7b3613bfb24db6b42fee1a2191de16a24ddf4a08d37a41b93` 保留其原身份。

隔离 v2 绑定源码清单 `301852f02cc0dae55f317610d79ab097c86423ff9537af72936680d81304758c`、构建收据 `ca681b8ecbbec5fb5285265b329b0cb4d4be2acd80e6cb7453beb68d837ea7be` 和编译器 `e7f0fe5f54c51d994aa260818cb26faee1c66f83318d22e8731a53a8625f34b8`。独立审核 `2465f40fd9a90273af683be019a4424783d4da80dd7028915f3ac0a7aea34184` 覆盖原实现对照、无效模型、首错、深类型、求值界限、不同实参、真实副作用、trap、缓存编辑及旧产物保全。该审核不代替性能结论。

生产使用独立动作协议 `ZIL-OBJECT-ACTION-212-v3-complete-call-closures-checked-scalar-v3`，防止与旧缓存混用。限定测试同时保留常量与真正未知实参的 600-helper 导入覆盖：将 `x+0` 真实编辑为 `x*1` 时，已知结果不变的消费者应复用，未知调用者仍依赖完整正文；恢复源码应全命中。普通 O2 的未使用外部声明测试保持原 miss 数，并核实分区前侧车中直接调用仍存在。这些预期必须实际验证，不可为通过而放宽。

最终采用仍取决于新生产提交、实际 ELF/工具链/namespace 绑定的限定检查与非作者审核、官方及四 TU 研究 LLVM 双 CI，以及计划的 3480 generated/opaque 请求、同十四真实程序的 336 请求和 900 原生运行观测。新版本 producer/identity/consumer 独立命名，旧工具与旧数据不重写；四 TU LLVM 仍是独立可重建安装，普通官方 SDK 不包含其补丁。隔离 432 数据不会改绑为最终生产数据，计时与正确性层级分别报告。

本提案不改变源码接受性、ABI、错误与发布顺序、公共 schema 或产品门槛。采用与否取决于完整分布，尤其暖请求和无可折叠调用场景，不能只选择有收益的常量样本。
