# 182 集成退回：区分弱描述来源与强地址 Hold

## 真实问题

schema23 合流后的整仓验收发现，182 把所有 Desc 的来源图同时作为公开 Hold 候选和强地址失效窗口。原始普通资源 raw fixtures 的空地址 Hold 被误报 E-VERIFY-HOLD；弱字段描述被粗化为全 Package 强借用，阻止原本安全的兄弟字段替换。另一个 Address<Closure> blanket gate 误拒168已有的局部同步借入自含环境。旧源码、原始责任反例与失败日志全部保留，不降低成功预期。

## 修复合同

1. 私有来源图始终重建受支持 Desc 的来源，并供逐捕获实际效果、动态存储操作与真实贷款核验使用。发现其它资源头不决定语义或准入。
2. 公开 ValueHold 通过独立的地址来源图生成和精确核验。普通用户资源 Desc 不发布地址 Hold；ByteBuffer/Store Desc 仅保留派生窗口所需的稳定来源元数据。MakeClosure 的地址图只合并实际地址依赖，不把弱 Desc 捕获提升为环境强 Hold。
3. 强失效检查消费实际地址关系，排除纯 Desc 载体。弱 Desc 的字段实例、真实使用、给出/清理和失效仍由原独立 resources 核查；不删除存活/责任检查。
4. 恢复原局部 Address<Closure> 捕获准入。真实逃逸继续由既有自含/retained/Hold合同拒绝；逐捕获效果遇到缺少真实嵌套外部来源仍拒绝，不能当空效果。畸形捕获布局也不得替代真实逃逸反例。

不改公开 schema/字段含义，不允许空候选绕过实际地址核验；Analyze 与 Verify 分别实现。完整变更计费，不修改默认预算。整仓验收仍由 root 执行；作者先验证65既有 raw fixtures、072/074/079精确字段、168局部非逃逸及182/窗口邻接，完整失败保留。
