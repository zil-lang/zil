## Ownership correction before first execution

Root review found that the sudo Python process would otherwise create `RUNNER_TEMP/receipts` as root-owned, preventing later ordinary runner steps from writing commit/toolchain/test receipts. The preparation step now executes `mkdir -p "$RUNNER_TEMP/receipts"` as the ordinary runner before invoking sudo. The script’s `mkdir(..., exist_ok=True)` leaves the existing parent ownership unchanged. The root-created JSON is read by artifact upload, while subsequent ordinary steps create separate files in the runner-owned directory. This correction was checked by workflow order/one-line diff assertions and an ordinary-user temporary-directory control; no local cross-UID sudo execution is claimed. Preserve the initial implementation and initial author/independent reviews; the final exact-commit GitHub run remains the actual privileged integration test.

The receipt writer also sets the fixed JSON file to mode `0644` after each save, independent of the invoking umask. A local `077` control showed that relying on the default creation mode could otherwise leave a root-owned `0600` file unreadable to the ordinary artifact-upload step. Only that receipt file mode changes; the precreated parent directory’s owner/mode remain unchanged. This read-access correction has temporary-directory controls, without claiming an actual cross-UID sudo run.
