# 081：u8、显式整数转换和同步 C 借入参数的源面

本提案先于实现。父任务 B0，公共合同锁定 c7b5b088（schema14）；具体语言义务以当前 `_zil_design.md` 与 `spec/interfaces.json` 为准。081 不修改公共 schema、产品门、Verify 或机器后端。

## 变更

u8 进入现有 Copy/聚合/枚举/泛型、局部/捕获、错误联合、范围与索引路径。仅新增 u8 源码后缀，接受十进制及 0x/0o/0b；其它源码整数后缀仍拒绝。无约束字面量默认 i32，有 u8 上下文时检查 0..255；不隐式拓宽整数。已有整数 match 的通配要求保持。u8 半开范围按原先条件与步进逻辑处理，不在最后已退出的迭代额外增加计数。

裸名（允许括号包围）u8/i32/i64 的恰一非展开实参调用降为 `CoreExprKind::IntegerConvert { value, target }`，再生成 `ConvertInteger`。输入独立按其自身上下文求值一次，不从目标反向推断输入类型；例如 u8(256) 是 checked i32→u8 转换，不是把 256 假定成 u8 字面量。转换仅接受 u8/i32/i64，非整数和不合法目标在 Types 拒绝。运行越界及 CT 失败由已核的各消费者执行。

这三个裸值/函数名不能成为普通函数、foreign 函数、普通/闭包参数、局部、范围变量或模式绑定；不生成可取地址的转换函数，不接受泛型 intrinsic。成员名保持普通成员语义，`value.u8` 不变成转换。未实例化泛型模板同样检查预留名、整数约束和字面量范围。

FFI 显式 `provides(noescape(parameter)); effects(ffi);` 解析为排序、唯一的参数序号表。源码未知/重复/畸形合同在 Expand 拒绝；Types 再核对表与全部地址形参精确一致。地址目标只允许 u8/i32/i64 与递归非空固定数组，普通 C 值参数/结果限制不扩张。地址权限、初始化与活性仍由既有 Analyze 候选及独立 Verify 重建；外部实现、动态长度及不保存/不回调/不跨界异常的真实性仍是显式 unsafe wrapper 承诺。

## 预算与依赖

所有 Core 深遍历均访问转换输入与目标类型，不能藏起捕获、错误路径、receiver、CT 或类型深度。新增 foreign 序号与目标类型在相关输入/快照遍历中按实际访问收取费用。Analyze 只改本单写集，资源效果调度文件 resources.rs 由 080 单写；ConvertInteger 的资源操作数注册由 root 整合。不增加默认配额，不复用前端推导结果作为 Verify 权限。

## 限定证据计划

真实源码覆盖三种转换、0/255 高位字节、四进制拼写、闭包/泛型/数组/跨模块接口、u8 半开范围和必要 CT。最近反例覆盖 256/负 u8、混合整数不隐式转换、bool/地址转换、预留名/泛型伪装、FFI 合同漏项/重复/额外标量/未知名及非法指针载荷。无效借用、转换溢出、机器执行与真实 read/write/pipe 由本片集成后的独立 Verify/083 消费者分别验证。限定运行记录真实命令和源码身份，失败原样保留；本单不运行正式全量。
