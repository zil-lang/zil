# 045 从真实输入到多模块原生应用

042 的独占引用和默认可变捕获、043 的跨模块公共类型与有限泛型、044 的显式 C ABI 边界必须在同一个应用中组合。此次增加 `examples/mainline/stream`：从 stdin 逐字节读取有符号十进制 token，经公开 `Option<Result<i32,i32>>` 交给主程序，使用函数指针数组转换有效数据，由默认可变捕获更新外部 `Stats`，最后由普通 ZIL IO 包输出统计。所有运算和格式化均在 ZIL 中执行，C 只提供 getchar/putchar。

应用明确限制为最多 1000 个 token、每个有效数的绝对值不超过 1000000；限制使 i32 统计有可见的界限。非法 token 计入 rejected；超过 token 数量上限退出 2，不输出部分统计。四个阶段中的用户泛型、模块封装、独占别名规则和 unsafe 区域均使用正式编译链，不另建特权执行路径。

CLI 普通 run 已继承 stdin；JSON run 使用 `Command::output()` 时此前默认关闭 stdin，此次显式继承，保留 JSON stdout/stderr 包装。应用测试将真实输入写进 ZIL/Rust 可执行程序，分别在 O0/O2 比较空输入、错误输入、数字边界、ASCII 空白、非 UTF-8 字节和数量上限；CLI 测试覆盖普通与 JSON run 的实际 pipe。

这不是完整标准 IO 库。当前标量 FFI 无法调用需要 FILE 指针的 ferror，getchar 的 EOF 与输入错误不可区分；putchar 当场报告的写入错误会导致退出 3，退出时 C 缓冲区的最终刷新错误不在本演示的错误协议内。没有以示例成功宣称一般资源生命周期、字符串、动态容器、异步或完整标准库已完成。

043 开始落实跨模块字段隐私，上一版固定输入应用主动向外提供的数据声明与字段改为显式 pub；这使旧示例的意图与现行访问规则相符，不放宽私有字段规则。
