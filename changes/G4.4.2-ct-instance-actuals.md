# G4.4.2 CT 完整实例参数向量提案

本提案绑定 2112737，尚无接受性变化。现有 CT wire 已有 `CtScopeInstance::Instantiated(Vec<CtScopeActual>)`，但真正 Source 生产者未接通，不能以枚举存在视为功能完成。

## 真实 Source 与三个断点

`ct5-mixed-runtime-instance.zil` 在 runtime `result<T:Copy,#N:i32,life s>` 的 `#(...)` 使用 `Phantom::<'s,T,N>`，由 `main` 实际调用 `result::<i32,7>(0,&n)`。精确 CLI 报 CT `unknown CT type name`；将 T 改 i32 后报 `nominal scalar value binder is absent`。该 CT prepass 在 Expand 真正特化前逐原始定义执行，未用声明也同样拒绝。内部改闭合 i32/7 后 CT 断点消失，但 Expand 混合 life 准入仍明确 Unsupported。原始 life-only 版本通过 Verify。此路径需要相位重排，不以扫描 main 构造“实际向量”。

首选较窄入口是 `ct5-mixed-ct-factory.zil`：原始 life-only `result<life s>` 的 CT 表达式真正调用 `make::<i32,7,'s>`，callee 为 `make<T:Copy,#N:i32,life a>`，返回 `Phantom<'a,T,N>`。这条调用已经到 CT 编译器，却在 `generic_names` 报 `CT generics require ordinary Copy type binders`。对应返回 scalar、在外层既有 scoped constructor 中使用的控制，仅移除 callee 的 Const/Life binder 和相应显式实参即通过 Verify。因此可优先扩展真正 CT compiler 的实际调用路径，避免先重排 runtime 泛型 body 的整个 materialization。

后续还有两道明确闭门：Driver `FrozenInvocationContext::freeze_inner` 只建立原始 `Definition`；`contextual_key::scope_key` 拒绝 `Instantiated`；独立 CT Verify 同样明确拒绝所有 `Instantiated`。不能只去掉任一道拒绝。

## 首选请求内接口与写集

优先不新增跨 crate 表：Driver 私有 compiler 在解析真实 generic call 时保留完整原序参数种类与实参。内部 `PendingTypes` / selected-instance key 从仅 `Vec<CtTy>` / `Vec<CtTypeRef>` 接续为完整实例结构；Type 接现有数据/元数据类型核，Scalar 接声明的显式标量 domain 和真实 CT 常量求值，Life 从调用者 authentic ambient reference 取得。完整序号包括穿插种类；不从名字、Span、已特化输出下标或生成名字重建 owner。

建议私有编译结果从 `(CtArtifactProgram, Vec<SourceLifeBinding>)` 接续一个 `CompiledContext`：保留现有 schema life bindings，加本次真实调用产生的实例账（原 `CtSymbolId`、完整原 binder inventory、完整 `CtScopeActual`、实际调用来源和作用域依赖）。该账只描述待核数据，不能作为能力 bit。Environment 在原不可变 AST/Index 和既有 lineage 上核每个 owner、参数 domain、调用来源与 Life 引用，再建立本次 FrozenInvocationContext 的 active 实例；raw/cache artifact 不得携带或建立这份授权账。CT Verify 根据当前 invocation authority 独立核 raw 实例完整 arity/kinds/scalar domain/类型图/life 引用及顺序，而非调用 Driver/Types 求证器。

此内部接口不会新增 serialized schema 或反射 snapshot。若实施发现需要扩 `CtArtifactAuthority` 的公共 Rust trait 方法或现有结构字段，先把具体签名交 root；当前提案不预先增加无人消费的公表。root 当前 Core、Expand、物化 lineage 写集不在本片改动范围。

首片明确只接显式完整实际参数的 free CT factory、普通 Copy Type 与现 CT 支持的标量 Const、真实外层原始 Life 引用。省略/推断、generic host/member、生成归属、runtime body 预实例化分别保留具体 Unsupported。普通 main 中 `&local` 没有 source Life formal，不能伪造 caller scope 或用 callee 自引用充当实际引用。本片选择 result.s → make.a 的真实绑定绕开该未定义表示边界，不宣称已解决所有调用生命期。

## 必须保持的约束

- `ensure_generic_definition` 的声明约束不能因 concrete instance 恰好成功而跳过。现 generic type-only 的 producer 内部 symbolic 检查保留；新增 Scalar/Life 的符号检查须独立于实际执行，不以 0、首个实际值或伪造 Type graph 代表任意参数。若现有 CT 表示无法表达所需声明检查，具体 Unsupported，先报缺失前提。
- 作用域依赖须有界、付费、无未授权引用/循环；完整实例不能与 Definition 或不同 Type/Scalar/Life 实例混为一项。context key 只在全部 authentic 值实际验证后编码，Type canonical graph 和 Life 引用重定位保持既有语义。
- 返回 scoped nominal、字段/enum/tuple 子值 reification 必须携带真正 callee instance 的 life 来源。不能沿用旧 `SourceLifeBinding` 的 Definition ordinal 就抹掉实例；现 G4.4.1 子值身份保证不能回退。
- 新扫描/比较/clone/graph/DFS/键字节均在当前请求剩余 work/node/depth/bytes/CT steps 中累计预费，失败退栈；N/N−1、fresh/warm 与多个实例交换/覆盖变化分别验证。
- 首个实际机器值应依赖 Const，并以两个 Type/Const 实例、原 binder 穿插次序、两个真实 Life 引用的最近替换控制核 identity。raw/Wire 未授权实际向量、少项/错种类/错 scalar domain/错 life owner 均由独立 CT Verify 拒绝；这些不能替代 Source 和 native。

## 本 checkpoint 的证据边界

仅精确 CLI Source 定位；没有 native、预算阈值或 raw/Wire 完整实例 Pass。复用 target340，相关 crate 已从 G4.4.2 本树重新编译，避免跨 worktree 假 Fresh。现有 mixed nominal 参数、原始成员自有 life 和 G4.4.1 子值测试仍是各自旧切片，不更名为完整实际向量完成。
