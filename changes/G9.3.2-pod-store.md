# G9.3.2 · Ordinary POD Store elements

Base: e8216ba3ca04a944d3b3f85a0558f7c3c465d198. Parent G9.3; general language before GUI. This proposal intentionally extends the sealed StoreElement bound, including ordinary std.store wrappers, to a disjoint POD Record family. Existing owned Package profiles retain their semantics and exact accounting.

## Frozen contract

A concrete ordinary Record qualifies when its complete finite field tree contains only Unit, Bool, U8, U16, I32, I64, U64, Usize, F32, F64, Record, Tuple and Array, with checked target layout and nonzero total stride bounded by i64::MAX. Nested zero-size fields are permitted; every nested leaf is checked even inside zero-length arrays. Actual aggregate Unit fields/members/array elements use the existing empty-struct representation, size0/align1, as do empty Record/Tuple; ordinary aggregate padding remains. The separate closure capture Unit placeholder is not this ABI. Layout checks preserve these existing rules. Field identities/order and full nominal types remain significant. Enum, ErrorUnion, Address, Desc, Managed, callable/function/foreign/handle types, OwnedStore and BorrowedStorage inside the element are excluded. Generic Copy alone is insufficient. Supported targets retain their real pointer-width layout.

StoreElement does not imply Copy, field access, owns/Managed, give/create or capture permission. Symbolic generic bodies stay conservative; concrete POD values and their existing push/pop ErrorUnion protocols are Copy. Store heads remain real uniquely managed resources; ordinary Store parameters remain descriptions and factory/give rules do not change. No fake owning fields, implicit box, RC or locks.

Reuse full OwnedStore element types and opcodes80–88, runtime schema/Wire43. Canonical resource naming remains @builtin:OwnedStore<{element.name}> together with independently checked complete Type identity. Types, Analyze and Verify each validate actual complete types, unused definitions and instruction metadata; no producer permission bit. Analyze and Verify do not share proof implementations.

Reserve overflow/allocation failure preserves pointer, capacity, length and data. Push is capacity-bounded with no hidden growth: failure returns the complete uninserted value, success writes then increments the initialized prefix. Pop shortens the prefix and returns the actual last value, with the existing empty error protocol. POD elements have no resource debts; Store storage is freed once without an empty per-element destructor loop.

The shared view in this profile is existing store_at -> &Record, not a new contiguous slice operation. Live actual Store windows block reserve/push/pop/give/drop and parent movement even with spare capacity; last-use and distinct Store roots preserve precision. POD OwnedStoreBorrowMut is explicitly rejected without banning ordinary mutable Record references elsewhere. Capture, Package/recursive Product fields owning Store<POD>, owning Tuple/Enum/ErrorUnion containers, arrays of owners and general life/Transfer/Share extensions require their own contracts. Ordinary bare Store factories/create/give remain in scope; Copy Record push/pop error protocols are not owning containers.

Large elements are in scope. Classify the complete push/pop protocol layout independently at the existing 4096-byte Copy threshold, including aligned elements of 4080, 4088 and 4096 bytes (both protocols are 4088 bytes at element4080 and 4096 bytes at element4088). Large Copy results use existing memory snapshots and private pointer/out helpers, without giant SSA bridges or repeated loop allocas. Public ABI and default stack/resource limits stay unchanged.

New type/layout/name comparisons, copies, queues and machine plan/helper work are prepaid from the current request before traversal/allocation. Unaffected Package paths retain old fees, including Analyze Store N=561. New paths require N/N-1/fresh controls; do not preserve old digits by omitting new work.

Acceptance covers ordinary std.store wrappers; nested numeric records/tuples/arrays; complete machine values; capacity/overflow/injected allocation failure preservation; pop order and final release; actual shared view last-use/conflicts/distinct roots; large/protocol-threshold O0/O2; forged canonical/full-type/op metadata, forbidden nested types, zero/overflow layout, mutable Store view, unused definitions and Wire. Keep old owned Store controls and unchanged product gates. This finite slice is not a full standard library or Rust competitiveness claim.

## Private convergence and stack refinements

Actual Source consumers exposed repeated forward-join processing in the resource/Sum analysis and permanent per-SSA snapshot stack inflation. Within modules containing the newly admitted POD Store family, the existing resource fixed-point may use a prepaid reverse-postorder priority worklist: retain the same reachable graph, transfer/join functions, state obligations, queue deduplication and cyclic convergence checks; only redundant scheduling changes. Compute/allocate CFG ranks and queue operations from current remaining work before traversal/growth. Never skip a backedge, accept an unfinished solution or raise defaults. Old non-POD scheduling and exact fees stay unchanged. The actual original numeric/protocol inputs must pass, with old/new scheduling cross-checks on bounded facts and nearest counterexamples.

Private large-Copy snapshot slots in these modules may share storage only when closed definition-through-last-use intervals in a valid acyclic CFG topological order do not overlap. Include return operands and all actual snapshot consumers; result and final-use input at the same instruction interfere. A cycle or unclassified instruction falls back to independent slots for the entire function. Preserve source local storage, private pointer nonescape/callee copy-in, byte capacity/max alignment and existing public ABI; pay CFG/rank/operand/placement work before it occurs. No hidden heap or increased stack limits. Default-stack execution of the original 262144-byte consumer must prove the repaired peak; slot sharing by itself is not acceptance.

Independent Verify may likewise remove repeated no-op tag invalidation work within the new POD profile. Prepay an index of locals whose independently constructed Content can actually retain Sum/route facts; recursive Tuple/Package and Enum/ErrorUnion candidates keep the original complete invalidation operation at exactly the original invalidating instructions. Copy/Leaf terminal state carries no such tag facts and can be excluded only from this operation, not from raw admission, resource obligations, missing-state or other checks. Pay index construction, type decisions, storage and each indexed access from the current request; preserve old non-POD scans/fees. Cross-check complete resulting facts and nearest invalidation rejections against the original all-local traversal on identical bounded IR. This is independently implemented in Verify, not a trusted Analyze plan.
