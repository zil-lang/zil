# G2.4.2 proposal: ordinary static trait associated factories

Status: implementation contract frozen 2026-11-07. Base 812d4659f56f7d4734e17d9b6444fda3e220aacf. This is a proposed finite successor to G2.4.1, not an implementation or acceptance receipt. It does not change compiler source, public schema, defaults, or the goal board. The two CLI observations below were supplied by root; this author did not run Cargo or the CLI.

## Actual Source boundary

The current concrete probe is `/workspace/.zil-env/G2.4.1-next-foundations/static-factory.zil`:

```zil
trait Factory { fn make<T:Copy>(value:T)->Self; }
struct Cell { n:i32 }
impl Factory for Cell {
    fn make<T:Copy>(value:T)->Self { return Cell{n:7} }
}
fn main()->i32 { return Cell.make::<i32>(3).n-7 }
```

The CLI reports `Unsupported/Expand: generic method without receiver`. `generic_trait_methods.rs::method_call_selected` selects a witness and provider, then requires parameter zero to be `self` (currently around line 1071). A second unchanged probe, `/workspace/.zil-env/G2.4.1-next-foundations/symbolic-factory.zil`, adds `fn build<F:Factory>()->F{return F.make::<i32>(3)}` and calls `build::<Cell>()`; it reports `SafeReject/Expand: unknown value F in generic body`. The generic definition checker treats the type binder `F` as an ordinary value name before a static-host lookup. Both are real Source failures, not missing syntax.

## Proposed first slice

Admit receiver-free associated functions through the existing ordinary static trait/impl system and its already supported type-only generic method binders and where premises. A method may have zero or multiple method-local type binders, zero or multiple ordinary value parameters, and any result shape already legal for an ordinary static function, including `Self`. Ordered type actuals may be explicit or follow an existing supported inference path; this batch does not invent a new inference rule. Trait and method names are arbitrary: `Factory.make` is only the smallest observed probe. A declared trait's existing supported type parameters, nominal impl hosts, bounds and associated equations retain their current rules; this batch does not add new trait/impl families or a new capability. The supplied `Cell.make::<i32>(3)` and symbolic `F.make::<i32>(3)` with exact lexical `F:Factory` are required baseline consumers, not the complete shape definition.

The selected callable is a plain static function. It has zero receiver parameters, does not evaluate the type host as a runtime value, and evaluates each ordinary value argument once in source order. Its result substitutes the witness's actual `Self` and any declared associated equations under the existing ordinary value-return/cleanup path. A nominal trait bound or a method-local `U:Copy` grants only its already declared capabilities: it does not imply `Self:Copy`, arithmetic on `U`, access to hidden fields, `StoreElement`, an owned-resource result mode, or a borrow root. Existing supported nominal impl hosts and result shapes stay eligible on their own current terms; non-Copy/resource results still face the existing ownership/result-mode checks. This slice introduces no new method life/const semantics, trait default bodies, dyn dispatch, blanket/primitive/enum impl families, richer associated projection rules, or ABI.

The compiler must distinguish a type-qualified host from a local value before checking a call. A local named `F` keeps normal value-name precedence and cannot gain the type binder's authority. A symbolic static call is valid only when its current definition bounds contain the exact trait application; a concrete call needs a committed, unique impl witness. The rewrite uses the existing origin-backed provider identity and substitutes ordered method and outer actuals. It emits the existing ordinary Core function/Call form; neither a spelling prefix nor an untrusted annotation authorizes a call or return.

Definition-time obligations remain complete when no call occurs. Validate every trait method header, every impl method's binder alpha-equivalence and ordered type/parameter/result relation, existing where premises, body result and each method-local bound in its own lexical scope. Preserve exact nominal trait/impl identity, visibility, ambiguity and provider origin across specialization. An invalid unused generic body must fail rather than waiting for a concrete host to instantiate it. Do not erase where clauses, inject a synthetic receiver, or treat an opaque symbolic `F` as Copy.

## Nearest controls and acceptance

Positive Source controls: both supplied probes unchanged; a public trait/impl/caller split across modules; different trait/method names; two concrete nominal hosts with distinct selected providers; a receiver-free method with two type-only binders and two value parameters; one static method returning a scalar and another returning `Self`. Include a current supported generic trait application/where premise rather than hardcoding the nongeneric `Factory` shape. The resulting values must run through both native backends at O0/O2 using ordinary Call/return. Existing receiver-method and lending tests must continue to pass.

For example, a second independent control can declare `trait Measure<Tag:Copy>{fn score<A:Copy,B:Copy>(a:A,b:B,tag:Tag)->i32;}`, implement it on a nominal host, then call `Cell.score::<i32,bool>(3,true,7)` and `H.score::<i32,bool>(3,true,7)` from `fn run<H:Measure<i32>>()->i32`. This checks the same static selection path with three runtime arguments, two ordered method type actuals, a trait type actual, a non-`Self` result, and different identifiers.

Nearest rejects: no required bound on the symbolic host; two candidate traits/impls for the same unqualified static member; calling a receiver-free function through a value `cell.make::<i32>(3)` as if it had `self`; wrong ordered type/value arity, mismatched impl result or binder; a method-local `U:Copy` body performing numeric arithmetic on `U`; unused invalid method body or where clause; private foreign trait/impl; a local value named `F` shadowing the type host; a raw or decoded-Wire Core call whose target, argument, return type, or provider identity disagrees with the actual declaration. Non-Copy/resource result controls must follow their pre-existing ownership/result-mode outcomes, without a new factory exemption.

The new path must prepay candidate scans, bounds and identity comparisons, type-host recognition, all ordered type/value-actual vector and provider-key growth, substitutions and call rewrite before allocation. Include exact N/N−1/fresh budget controls for concrete, symbolic and two-binder/two-parameter calls. Preserve the old receiver-method fee schedule when no static associated call is selected. Existing Analyze and Verify independently validate the resulting ordinary Core Call and return; do not use Expand's witness as a proof bit in either kernel.

## Parallel implementation boundary

Author A owns trait/provider selection and static call rewrite: `crates/zil-expand/src/generic_trait_methods.rs`, `generic_trait_solver.rs`, `generic_trait_instances.rs`, and `generic_trait_impls.rs` (and `static_traits.rs` only if its existing finite declaration gate actually blocks the frozen input). Author B owns lexical symbolic type-host admission and definition checking: `generic_check.rs`, `generic_trait_constants.rs` or a dedicated private host helper, and `generic_expr_call.rs`. Root owns the frozen probes, cross-module/native/raw/Wire consumers, public contract, and final integration. Keep `generics.rs` and `generic_trait_bounds.rs` integration-only unless one author obtains an explicit exclusive handoff; these are shared high-traffic files.

Before parallel edits, freeze a small private interface: a host classifier returns either an actual nominal host or a current lexical type-binder host with its exact bound reference, never a value expression or a capability; selection returns a unique witness, receiver-free signature and origin-backed provider target. Author A consumes that classifier in the rewrite, while Author B applies the same host classification in unused symbolic body checking. This allows the two write sets to proceed independently until root connects and tests the interface. Any new Core node/schema or borrowed-result relation requires a new contract rather than an implicit expansion of this slice.
