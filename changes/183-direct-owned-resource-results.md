# 183 直接拥有资源成功载荷纵切

依据当前 `_zil_design.md` §8.1/8.3 与公共提案
`changes/183-owned-success-mode.md`，在 schema 22 的现有错误联合和资源指令上开放
`Sum(Copy E, Managed R)`。本片不增加公共 IR 字段或 opcode，不改变默认 Desc 分类。

## 实现边界

- `result(create/give)` 只把错误联合的成功侧解析为资源拥有载荷；外层联合仍是普通非 Copy Value。
- 首批实际载荷为 ByteBuffer、有限 Copy 字段的名义用户资源，以及已支持完整元素的 Store；Store 必须有独立真实机器与失败清理用例才能列入完成。
- Analyze 与独立 Verify 分别守恒联合与载荷的责任，保留真实 tag 分支证据、来源出生/转交类别与每个正常/错误退出的清理；不从前端标注取得权限。
- Lower 和 LLVM 对唯一活动载荷执行直接资源清理。读取不能代替消费，失败侧不读取或释放成功槽。既有 Copy/Package 两侧行为保留。
- 普通参数的成功侧拥有模式等待 root 对显式 `give` 的同构解释，默认 `E!R` 仍不推断为拥有。语义明确前不改变该参数接受性。

## 限定验收

保留原 159 `owned-error-result` 探针原字节。新增跨模块工厂、成功/失败注入、`?`、成功/错误直接丢弃、普通联合转交、晚实参失败、局部清理顺序、借入存活及重复移动近邻。O0/O2 核对用户 Drop 轨迹与真实 ByteBuffer/Store 分配、增长失败、释放计数。raw/Wire 从真实源候选变异：错 tag/载荷、无成功模式、伪造 create 来源、重复 Take/Load、漏清、错误分支投影及携带旧描述。

限定运行使用独立 `author183` target、offline/locked、两构建线程和两测试线程。默认预算、产品门、公共 schema、主树工单均不改；原失败记录保留，最终受测源码和测试/机器观测绑定精确提交后交非作者独审。
