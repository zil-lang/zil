# G4.4.7 runtime generic body CT phase

现 Driver materialize 在普通泛型 specialization 前运行，真实运行时函数体 `#(Phantom::<'s,T,N>{...})` 看不到实际 T/N。不能以 Unit 替 T 或忽略整个泛型定义规避。

新增受限实例回调在实际 substitution 后、Engine 递归展开 body 前执行。整体 specialization 后回调过晚：内部名义类型已经改为卫生实例名，不能再当原源认证。原定义、真实调用结构 site、完整原序 Type/Const/Life 参数与 parent 实例作为未授信 recipe 运输；CT 消费者从 immutable original/generated catalog 恢复原 Call 和原 CT 表达式，独核 actual 后才编译执行。

运行时实例仍对 life 参数化。CT6 同声明 base Definition row 保原 life ordinal，runtime Instantiated row 全向量包含 Type/Const 实际及回引 base Definition 的 Life；不把 main 局部借用当作泛型定义 life，不把单态 clone 宣称 Original。未用定义的 CT 合法性和普通泛型体义务仍须在实例执行前核验。

最近反例：同形 sibling Call/site 盗用、改 Type/Const、错 life ordinal/声明、无实际调用的伪实例、未用定义非法 runtime capture、CT 剩余节点泄漏、预算不足后部分改写。阶段失败停止生成 Core/机器产物。新行为仅在两个实际 Driver 入口接通并验证后报告支持；仅新增 recipe 无接受性结论。

独立 Verify 默认不接受 runtime scope 根。`runtime_scope_root_count` 仅提供完整图比较计价上界，`authorized_runtime_scope_root` 仅能由 frozen consumer 在原 Call、callee Definition、完整 Type/Const/Life 实参和 CT 子表达式根全部独核后授予精确 base/instance 行。无 life 参数的真实实例适用相同规则。所有行仍通过原完整参数种类、依赖图、有限深度、无环、first-use 和 unused-row 检查；仅精确授信根可补充图外的 scope first-use。根比较、查找和遍历须预付，不能从 producer recipe 或同形图获得权限。最近负控包括同形异声明、无实际 Call 的额外行、完整向量重排、life ordinal 改写和删改 no-life 行。该迁移只涉及 CT6，运行时 Wire 不变。

实际首轮 Source 暴露既有 `copy_life` 形状过滤器把独立 scalar Const binder 一并拒绝。沿已有一 Copy Type + life 普通函数 profile 接受附带 Const formals；每个 Const domain、符号定义和具体实际值仍经过既有 const checker，完整 life binder 检查、trait/extern/where 拒绝不变，不让 Const 形成 runtime life 权限。

符号 CT 产生的 qualified nominal 用原函数 `Scope` 做定义局部全 ordinal 比较，复用既有声明类关系键；不能送进擦除 life 的普通泛型缓存键。只有真实 computed CT 类型输入启用该局部比较；Types/Analyze/Verify 的实际 runtime 消费者不从它获得权限。
