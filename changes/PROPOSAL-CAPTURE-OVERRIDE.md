# 可选局部捕获覆盖：候选，未进入主线

## 问题与当前路径

整体`move`在创建环境时统一按值捕获，不能直接指定仅一项取快照。普通捕获仍应自动推导，不恢复必须列出每个捕获的清单。020先补显式共享引用：`let borrowed = &source; let f = move () => *borrowed + snapshot;`。地址值进入环境仍保留原来源寿命，不表示拥有其指向的对象。

[Rust闭包参考](https://doc.rust-lang.org/reference/types/closure.html)区分每个捕获路径的模式以及调用时的Fn/FnMut/FnOnce；[闭包表达式](https://doc.rust-lang.org/reference/expressions/closure-expr.html)的整体move也不等于一次性调用。普通闭包可以根据正文分别借用或拥有不同值。Copy值在正文被复制不保证在创建时形成快照，不能靠正文中的一个move/give拼写含糊解决时点。

## 两种候选

| 候选 | 规则 | 成本与判断 |
|---|---|---|
| `move[snapshot] () => snapshot + live` | 仅列出路径在创建时按值捕获；其他路径继续自动推导 | 优先候选。复用move，局部覆盖短，不需要重复默认借用 |
| `[move snapshot, &live] () => snapshot + live` | 列表覆盖指定策略；未列出路径仍自动推导 | 表达能力更强，但引入新闭包头，与数组起始消歧，并需要验证显式策略与正文用途一致 |

`move[a,b]`只选择已存在的合法捕获路径，不运行初始化器、索引求值、getter或任意用户表达式；需要提前计算的值先普通绑定。重叠路径要诊断或按唯一精确捕获规则合并，不能重复移动。`live`若被借用，外部写入仍受借用约束，不因为名称或局部覆盖而放宽。

当前只选择优先评估方向，不改EBNF、AST、规范或接受性。后续需要和显式引用绑定比较完整程序的阅读及样板成本，并覆盖Copy快照、非Copy所有权、字段路径、可变使用和清理时点。先运行020支持路径，再决定是否用局部覆盖糖减少预绑定；不要等候选收敛才推进引用与质量工具。
