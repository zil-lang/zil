# G3.3 consumer integration contract

This integrates the prior G3.3.9 and G3.3.10 proposals into the current
normative helper profile. The original two-role implementation limit and
blanket owning-backedge rejection are superseded by bounded actual-role
inventories and independently checked cyclic responsibility flow. Public
CallableRole/Finite/Flow and runtime Wire representations do not change.

Different supplied roles remain different runtime positions even for equal
ClosureId. Origins cannot recover a singleton from a mixed join. Physical
storage and variable comparisons are prepaid; wider compiler metadata has
explicit N/N-1/fresh migration rather than artificially retaining old N.
Successful old DAG proofs remain; fallback requires a real cycle, never a
budget failure or a second attempt at a failed acyclic proof. Source and hostile
raw/Wire consumers must verify these combined obligations after integration.

G3.3 also retains the pre-existing section 9.3 rule that owning captures alone
do not imply FnOnce. A qualified helper receiving an already legal scalar
Managed environment through Fn/FnMut must preserve the actual owner through
repeated non-consuming calls and clean it exactly once when the environment
ends. The old qualified true-FnOnce implementation boundary cannot exclude
that existing mode rule. This does not grant new capture shapes, State/dyn
storage, asynchronous escape, or multi-role lending eligibility.

Single-role environment lending must keep the real receiver and its parent
loan alive until the returned address's last use. Existing shared-pointer ABI
may be reused only after each kernel reconstructs the actual returned capture
fields; matching metadata or equal capture types are insufficient. User Drop
and Managed companion transfers use the existing resource ledger and actual
registered teardown. Scalar foreign observations retain independent lexical
unsafe/foreign checks and introduce no pointer or resource permission.

This is a contract migration, not acceptance. The goal board remains partial
until independent exact-source review, combined Source/raw/Wire/native
consumers, budget controls and required integration gates pass. Rust product
comparison remains separately unmeasured.
