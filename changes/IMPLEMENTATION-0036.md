# 036 闭包与函数指针的高阶组合

在 030/033 共同基线上扩展现有私有有限约束图：FunctionPointer shape 连接 callee、参数和结果变量，并沿既有类型预算、发生检查和唯一类型约束求解。类型无歧义时，省略注解的闭包参数可以从调用端或函数指针签名获得完整类型；不能以未解变量默认成某种 callable。

具名函数作为值进入同一 Copy 值约束，支持闭包参数、返回、分支和聚合字段；直接调用仍保留既有共享地址合同，间接函数指针签名仍仅纯 Copy。前置 source Solver 与实际 closure InferBuilder 同时实现，后者生成的普通 TypedCFG 继续进入独立 verify，不获得任何新权限。

本单不把带环境闭包转换成函数指针，不增加运行时表、堆盒或 RC。已有函数指针 ABI、FnMut 本地环境位置和 Copy 聚合布局不改。新约束克隆与展开在预算内，最近反例覆盖不兼容 callable 签名、自应用递归约束、参数歧义和闭包环境擦除。

与 037 的条件模式绑定分工：本单拥有 Name/Member/Call 与 Graph 的函数指针 shape；037 拥有 pattern_bind 与 IfLet/WhileLet 遍历。034 后续 Ascribed 必须在两层推导中再次绑定声明类型与实际值。

## 组合修复与既有权限

按集成方追加派工，普通函数前半及闭包体中的 enum 构造器同样进入本包。两层推导读取已解析的模块内枚举定义，先检查局部同名遮蔽，再按变体名称和载荷签名约束；零载荷成员值与有载荷调用保持现有语法。参数化类型的名义身份和函数指针签名完整保留。037 单独处理 `match`、`if let`、`while let` 的模式作用域，本包不复制模式推导。

默认只读捕获扩展至已有纯 Copy 聚合/函数指针，使用已有共享地址与整体位置 Hold；`move` 共享地址允许指向既有纯 Copy 目标。默认捕获期间的任意字段写入仍须通过独立借入核验。函数指针间接调用仍不接收含地址的签名，也不把闭包环境转为函数指针。无环境闭包 coercion 的 CL13 留给邻接包038。

## 作者限定结果

9 个专项测试覆盖 9 个实际源码程序的 O0/O2 执行（18 次），包括完整高阶数据处理、跨模块值、静态方法、返回函数的工厂、Unit ABI、共享和 move 捕获、enum 回调载荷。最近反例检查 arity、签名冲突、未解参数、自应用递归、环境擦除、借入冲突、错误变体与载荷；原始 wire 的捕获签名伪造继续由独立 verify 拒绝。有限旧回归包含闭包前端、共享闭包、030、033 和029；真实命令和失败的测试语法尝试另见收据。

## 本轮 Rust 目标复核

| 目标 | 当前判断与证据 | 仍缺 |
|---|---|---|
| 同类安全 | 新组合仍经独立 verify；默认聚合捕获保留整体 Hold，伪造捕获类型被拒绝 | 全资源、清理、独占借入与并发语言范围未完成 |
| 运行与内存同级 | 函数值仍为实际 thin pointer；FnMut 环境原地更新；新增程序无 malloc/隐式 RC | 没有同工作 Rust 的受控运行/峰值内存测量 |
| 表达与维护 | `let apply=(f,x)=>f(x)` 可从调用端获得函数签名；函数、字段、数组和闭包复用同一约束规则 | 完整项目的人力/维护收益与无环境闭包 coercion 尚未证明 |
| 编译成本更低 | 发生检查、深度与展开工作预算限制函数签名 DAG；有限例正确失败 | 没有配对冷构建、编辑和内存增长率测量 |
| 至少一项实质突破 | 本包推进可运行高阶组合，没有证明超越 Rust | 按既有产品门完成配对实证，不能用测试数量代替 |
