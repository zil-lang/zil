# 独立 goal 分支与实施文档

2026-11-05用户决定：使用单独的`goal`分支，以`goal.md`为当前任务分配和看板，暂不用Projects；实施说明留在各任务分支，重要决策和验收随源码进入main。

- `goal:goal.md`独占当前能力拆分、优先级、工作状态、接续负责人和阻塞。采用稳定任务ID；“实现待验”与“已合入”分开。初期由root集中应用各代理按ID提交的增量，不维护第二份JSON状态库或同步服务。
- `_zil_design.md`、具名附件和product-gates继续定义语言及验收，goal只引用。源码/独审/验收记录证明实际结果；改看板不会制造接受性或通过结论。
- 任务分支`.task`保存Goal ID、父合同、基线/规范身份、写集、实现决策和交付要求。其继承的历史状态按原提交解释，当前状态只读goal。main既有`.task`不再追加日常状态；保留工程合同及历史验收，规范迁移或实际交付时仍可更新相应工程记录，不能删掉原验收条件。
- main的`_zil_goal.md`作为稳定入口。历史进度快照注明源码版本，不能当实时看板。handoff/check-plan继续检查工程记录，不读取goal内容、不代表全部开发分支；工具输出必须明示这一边界。
- goal采用轻量独立历史，永不合入main。源码分支也不merge进goal；采用单独worktree，普通fetch/pull/commit/push。不同任务的并发更新重新应用小补丁，同字段冲突不得强推覆盖。
- 阶段源码备份仍保存各分支和真实WIP。计划另行push并核回完整SHA；离线bundle须显式携带`refs/heads/goal`。只备份main不能恢复当前计划。
- 交付时只保留有价值的实施合同、决策和复核/验收记录，不把聊天、日常状态往来和整份goal提交合入main。已经在历史中的文件不改写或批量删除。

本决定替代旧“主树.task是唯一当前状态源/分树工单不读不改”的工作流约定，不改语言规范、安全核或验收门。
