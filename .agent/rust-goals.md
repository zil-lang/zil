# 每轮交付必须对照 Rust 的目标

2026-10-23 用户明确要求每次提交交付前反思是否兑现 Rust 对照目标。该要求适用于每轮阶段包，不能等到最终产品验收才首次核对。

每轮报告固定回答：安全是否达到同等边界；运行性能及内存是否同级；完整任务的表达与演进是否更简单；冷/增量编译是否更快；至少一项突破是否已被同语义、可重复的证据证明。量化标准只引用 validation/product-gates.json，不另定宽松标准。

明确区分已实现子集、设计义务、受限探针和已达成产品目标。少写几个符号、通过更多测试、采用LLVM或没有堆分配，都不能单独证明优于Rust。合理Rust基线允许惯用安全封装、Cell/GhostCell、索引和Arena；不以弱化对手或缩小ZIL语义范围制造优势。

报告写出本轮推进了什么、尚缺什么、有没有结构性退步，以及下一步最便宜的证伪实验。未测直接写未测，未达成写未达成。保留一张简表即可，不为反思另加长审批链或每轮重跑全部产品基准。
