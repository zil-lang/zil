# 失败证据与续接

## 决策

每次探索创建新的运行目录，拒绝覆盖已有目录。保留第一次失败、后续修复验证、缩减结果和故障注入控制组；不把旧 Fail 改写成 Pass。整体通过必须有实际执行步骤，且全部计划步骤完成。基础设施异常单独记录，不算语言反例，也不能忽略后继续报通过。

## 最小交接内容

工单只追加开工、范围调整、交付、独立审核、退回和合入。长期约束保存在 `.agent/`，实现及精确版本保存在 Git，验收收据、独立审核及关键失败小文本保存在 `evidence/`。新运行的原始动作、完整观察和可重建产物默认放在被忽略的 `out/runs/<领域>/<RunId>/`，由集成者选择本轮运行归档；不需要保存整段聊天作为下一轮的阅读前置。

日常源码包保留紧凑证据，原始产物放在独立审计ZIP，Git历史使用旁置bundle。`PACKAGE.json`绑定二者的文件名、SHA-256和范围；审计ZIP的清单绑定每个原始文件，保留失败原件及冻结程序。源码包中的路径引用可以指向审计包，未恢复raw时不能声称具备完整历史回放环境。详见`docs/DELIVERY.md`。

已提交的旧 `evidence/` 和历史不批删、不改写；旧runner的默认目录尚未全部迁移。打包工具默认封存完整旧evidence，只将显式`--raw-run`选择的新运行加入审计包，不扫描整个out。每次成功构建的bin、展开IR和重复源码快照不再自动进入主源码ZIP。这一变化只改变保存与交付位置，不改变测试判据。

失败记录应带领域 contract、propertyId（若适用）、具体动作与初始态、种子、实际运行命令、输入/输出、二进制与工具身份、原始失败、缩减停止原因及未变异控制结果。种子用于追溯，具体动作才是回放依据。相同 propertyId 不自动意味着同一根因，需保留诊断并人工裁决。

## 本轮宿主异常

最初算术运行 `evidence/oracle/20261022T152655523Z-4b3ff821` 执行 0 步，保留为 Fail。Node `spawnSync` 的默认 pipe 在当前宿主出现 `EPERM` 与退出码 0 同时存在的组合；适配器改用明确文件描述符捕获 stdout/stderr，并把任何 `error` 视作异常。没有跳过测试或把该运行重标通过。后续成功运行保存在不同目录。

## 操作入口

先按 `AGENTS.md` 找到当前 main 主树与权威工单，再核对已审核提交和证据。运行 oracle 前按 `README.md` 的快速构建说明及 `rust-toolchain.toml` 准备 Rust/clang，执行 `cargo build --offline --locked -p zil-cli`，再执行 `node tools/run-oracle.mjs --seed 14327 --cases 64`。Node v24.19.0 的 TypeScript transform 是宿主适配要求，会输出实验性功能提示。
