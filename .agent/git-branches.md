# ZIL Git 分支命名与离线 Bundle 集成（2026-10-29）

## 唯一分支规则

- `main`：唯一正式集成主干；不得由施工 Sandbox 或 Bundle 导入脚本直接更新。
- `task/<ID>`：所有施工任务统一命名，包括语言、LLVM、图研究、工具链与编号切片；实际工单号以主树 `.task/` 为准。例如 `task/135`、`task/203`。不再按 `impl/`、`research/`、`goal/`、`delivery/`、`sync/` 等会话/运输方式创建常规分支。
- `archive/<ID>-<来源>`：仅供 Git 标签（`refs/tags/`），不创建长期归档分支；合并方式改变了原提交身份或候选未合入时，可保留精确提交引用。
- 临时 `ops/*`、`integration/*` 只能用于限定时间的运维/合并预演；验证完成清理，不作为新的长期施工路线。

分支只反映一个具体任务的 Git 提交；对话、Sandbox、Bundle 是传输/执行环境，不是新的分支层级。一个任务一个 worktree 和任务分支，按 `docs/WORKFLOW.md` 的写集与审查规程执行。

## Bundle 与远端同步

- 施工交付 Bundle 优先发布 `refs/heads/task/<ID>`（可同时包含多个明确任务引用）。
- 同步工具先读取 Bundle 中实际引用；默认将每个非 `main` 源分支映射到 GitHub 同名分支。多引用可以交互更改目标；空输入保持默认映射。
- 新分支正常创建；已有分支仅允许快进或确认已经包含；分叉不得强推、自动覆盖、擅自创建长期 `sync/*` 兜底分支。
- Bundle 即使公布 `refs/heads/main`，也不直接推送正式 `main`；需由用户明确映射到独立任务分支后审核。
- 同步输出必须逐分支报告精确 SHA、CREATED/UPDATED/ALREADY/DIVERGED/FAILED/SKIPPED，以及整体退出状态。网络失败不代表已同步。
- Bundle 导入与正式代码集成是两种操作：前者只更新任务引用，后者需独立审核、冲突处理与新组合树的真实回归；保留已审核实现提交，原则采用 Merge Commit（非 Squash/Rebase）。
