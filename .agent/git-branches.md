# ZIL Git 分支命名与离线 Bundle 集成（2026-10-30）

## 分支用途与命名

- `main`：唯一正式集成主干。按用户2026-10-29授权，集成 Sandbox 可在完成冲突处理、独立审核与组合回归后直接快进更新；Bundle脚本可同步已集成main。
- `task/<ID>`：单次施工任务的默认命名，包括语言、LLVM、工具链与编号切片；实际工单号以主树 `.task/` 为准。例如 `task/135`、`task/203`。会话、运输方式和交付包不另设长期分支。
- `research/<topic>`：用户明确授权的长期研究线。本轮按用户清理授权退役已结项 CP 在线研究枝，原历史见标签 `archive/cp-245-20261102` 与 `evidence/maintenance/cp-cleanup/receipt.json`；仅保留仍有独有在途成果的 `task/cp25-reactive-session`。以后新增长期研究线须明确派工。
- `archive/<日期>/<任务或来源>`：仅供 Git 标签（`refs/tags/`），不创建长期归档分支；合并方式改变了原提交身份或候选未合入时，可保留精确提交引用。
- 临时运维与合并预演也使用派定的 `task/<ID>`；验证完成删除，不再增加 `ops/*`、`integration/*` 等命名分支。

单次任务一个 worktree 和任务分支，长期研究线按其已登记方向保留独立 Git 历史；二者都遵守 `docs/WORKFLOW.md` 的写集与审查规程。对话、Sandbox、Bundle 是传输/执行环境。用户另行指定的一次性运维名称在对应工单记录，例如已验收并删除的 `chore/llvm-23-upgrade`；保留真实历史，不为统一展示改写旧引用。

## 可恢复的施工检查点

形成可编译或限定测试通过的阶段检查点后，主模型集中推送可恢复的源码检查点，再进行长时间全量检查、审查或大证据打包。日常状态和往来由主模型归并，不逐条 commit/push；正式交付和验收记录按检查点提交。远端检查点仍按实际状态标为施工/待验，不能因已推送就视为 `main` 已验收。

推送完成要读回精确远端 SHA；本地 commit、工具调用已发起和待上传 bundle 都不算远端交付。单次传输超过连接器体积限制时，可固定分块顺序并在接收端核对完整 SHA 与 `git bundle verify`，不能省略核对。任务源码和最小重放输入先可恢复，大型原始证据另按实际归档位置绑定；避免唯一副本长期停留在临时 Sandbox。

本规则来自 218 未完成持久化发布的实际恢复检查，见 `docs/STATUS-20261030.md`，不改写其历史结果为新的通过证据。

## Bundle 与远端同步

- 施工交付 Bundle 优先发布 `refs/heads/task/<ID>`（可同时包含多个明确任务引用）。
- 同步工具先读取 Bundle 中实际引用；默认将每个源分支（包括 `main`）映射到 GitHub 同名分支。多引用可以交互更改目标；空输入保持默认映射。
- 新分支正常创建；已有分支仅允许快进或确认已经包含；分叉不得强推、自动覆盖、擅自创建长期 `sync/*` 兜底分支。
- Bundle 公布 `refs/heads/main` 时可直接快进正式 `main`。`-MainOnly` 在推送前必须证明包内其余分支头均为main祖先；存在独有工作则停止，不能仅凭存在main忽略其他分支。脚本只传输既成集成结果，不负责语言合并或解决冲突。
- 同步输出必须逐分支报告精确 SHA、CREATED/UPDATED/ALREADY/DIVERGED/FAILED/SKIPPED，以及整体退出状态。网络失败不代表已同步。
- Bundle 导入与正式代码集成是两种操作：前者只更新任务引用，后者需独立审核、冲突处理与新组合树的真实回归；保留已审核实现提交，原则采用 Merge Commit（非 Squash/Rebase）。

## 任务完成与旧分支退役

1. 合入前确认目标 `main` 的实际最新 SHA、任务精确提交、规范身份、写集、独立审核和适用的 CI/原生回归。
2. 合并后删除已无用途的单次来源分支；用户授权的长期研究线继续保留。若原提交未被 main 历史引用且仍有审计价值，应先创建不可移动的归档标签。
3. 完全被 `main` 包含的旧导入分支可直接删除；没有完成验收的研究候选不得以“减少分支”为由强行合并或丢弃。
4. 旧语言202和203检查点在语言206的真实历史中均已包含，206与LLVM212合流并通过验证后可退役。131纯研究目录经限定审核可保留，132旧文本候选和135旧CI已被新主线替代，136生产算法保持NotEligible；独有历史先保存精确archive标签，再按远端期望SHA删除分支。
5. 清理依据真实提交拓扑、实际差异和审查收据；分支时间、编号高低或聊天结论都不单独作为删除依据。远端SHA变化时停止该分支清理并重新核对。

本规范仅约束 Git 工作流，不改写语言行为、测试门及独立核验边界。
